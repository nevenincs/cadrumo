The filing application has a local draft, review, approval, and export path. It also has separate authenticated read paths that capture what AEAT appears to hold. The two must stay separate: a locally approved draft or rendered return is not a submitted declaration, a remote read is an observation rather than an update to AEAT, and a justificante counts as filing evidence only after receipt and taxpayer coordinates have been checked. These distinctions are visible across [045](../articles/045-filing-draft-approval-and-local-export-pipeline.md), [046](../articles/046-filing-envelope-integrity-export-parity-and-producer-values.md), [047](../articles/047-filing-producer-facts-repeated-record-projection-and-runtime-schema.md), [063](../articles/063-live-snapshots-and-filed-data-capture-operations.md), [064](../articles/064-filed-declaration-capture-evidence-enrollment-and-history-sweep.md), [065](../articles/065-iva-receipt-and-notification-evidence-surfaces.md), and [066](../articles/066-notifications-verification-and-shared-live-state-contracts.md).

## Draft and local artifact

Draft construction takes a typed filing coordinate, taxpayer profile, raw casilla inputs, and a generation-pinned registry schema. It rejects unknown/noncanonical keys, routes decimal/text/enum/date/boolean/relation channels, runs registry formulas, and keeps provenance for input, computed, inherited, and empty values. Approval requires a ready draft and fresh validation; its basis hashes draft and findings with transaction, invoice, prior observation, profile, category, schema, and formula surfaces. A later refresh expires approval when those fingerprints move. The draft-level exporter checks approved status and schema but does not itself recompute the approval basis, so the work-unit caller's refresh ordering remains a necessary integration check. Draft construction (`src/cadrumo/application/filing/draft_construction.py`) Approval basis and refresh (`src/cadrumo/application/filing/draft_review.py`) Export admission (`src/cadrumo/application/filing/export.py`) ([045](../articles/045-filing-draft-approval-and-local-export-pipeline.md))

Export chooses a snapshot-owned official layout, binds model/year/period, taxpayer identity and producer digest, then projects typed headers, elections, accounts and repeated rows. The fixed-width path checks field lengths, nonoverlapping byte positions, record order and required occurrences. Its parity gate derives representable casillas from the selected layout and refuses missing required/formula results, while XML dictionary rendering orders children by XSD sequence and uses hardened XML parsing. A local writer atomically writes bytes, records SHA-256 and size, and re-reads non-envelope artifacts through the registry parser. Parser read-back `MATCH` means checked casillas matched; unchecked casillas remain listed, and pre-write parity is the separate completeness gate. No part of this export path submits to AEAT. Envelope binding (`src/cadrumo/application/filing/export_envelope.py`) Fixed-width parity (`src/cadrumo/application/filing/export_parity.py`) XML renderer (`src/cadrumo/application/filing/_export_xml_dictionary.py`) Read-back (`src/cadrumo/application/filing/export_verification.py`) ([045](../articles/045-filing-draft-approval-and-local-export-pipeline.md), [046](../articles/046-filing-envelope-integrity-export-parity-and-producer-values.md))

Producer facts are a strict snapshot with separate taxpayer, presenter and contact roles and disposition-aware account selection. M303 additionally ties period arrivals and investment/prorrata evidence to calculated state. Model support is uneven: M200's many repeated row families are operator supplied; M210 has a typed but optional fact surface whose required caller population needs tracing; M296 detail may still be hand populated despite withholding observations; M202 refuses snapshot construction for enumerated unsupported producer fields. A named registry layout or parser does not remove those producer limits. The XML non-casilla helper also documents a header fallback but actually reads only `dictionary_values`, so required values must be present in that channel or export can refuse. ## Remote observations and evidence promotion

Live reads use an active verified session after a live-read gate. Censo reads take taxpayer identity from that session and return an observation for separate review and adoption. Borrador 100 PDF import pins an extraction profile, checks parser receipt/digest/coverage, and stores a content-addressed snapshot with explicit blanks; it does not prove that every field was extracted. Declaration-register and notification captures place remote observations in local encrypted, bucket-bound snapshots, with separate local list/show/latest operations. Notification detail intentionally exposes sensitive names, NIFs, concepts, dates and read state under whole-profile access, while inventory views expose less. Read-only NIF-IVA and TGVI/GROI checks persist observations and omit raw evidence locators from public results. Live session gate (`src/cadrumo/application/live/session.py`) Censo observation (`src/cadrumo/application/live/censo.py`) Borrador import (`src/cadrumo/application/live/borrador_100_import.py`) Notifications (`src/cadrumo/application/live/notifications.py`) Verification records (`src/cadrumo/application/live/verify.py`) ([063](../articles/063-live-snapshots-and-filed-data-capture-operations.md), [066](../articles/066-notifications-verification-and-shared-live-state-contracts.md))

Filed-history acquisition supports single and bulk walks only where the pinned registry declares a filed-declarations read surface. It records attempted/completed/reached/captured counts separately, preserving failed queries as failures rather than empty history. A bulk dry run still performs remote reads but avoids local artifacts, evidence enrollment, IVA-wallet and notification stages. Discovery unions profile-expected model/year pairs with register-offered pairs and hedges any inference about register completeness. A normal capture stores manifests and artifacts, compares overlapping numeric casillas to prior capture with registry tolerance, and enrolls calculation observations; M303 uses a dedicated co-persistence path for IVA history. An onboarding sweep also attempts independent wallet and notification stages. This is capture of remote state, not filing submission. Query planning and accounting (`src/cadrumo/application/live/filed_data_capture.py`) Dry-run boundary (`src/cadrumo/application/live/filed_data_capture.py`) Observation persistence (`src/cadrumo/application/live/filed_observation_persistence.py`) ([063](../articles/063-live-snapshots-and-filed-data-capture-operations.md), [064](../articles/064-filed-declaration-capture-evidence-enrollment-and-history-sweep.md))

Receipt custody is more demanding than capture. Justificante selection requires a matching period-bearing expediente; the encrypted snapshot binds CSV, PDF digest and filing coordinate. Cotejo authenticity has `NOT_CHECKED`, `CONFIRMED`, `DENIED`, and `UNAVAILABLE` states. Filing evidence is stamped only after PDF byte/digest checks, receipt CSV and model/period checks, authenticated taxpayer matching, and reconciliation with the current local filing record. A downloaded PDF alone is not confirmation. IVA remote-state acquisition similarly reports filed-history and wallet surfaces independently, retaining failure modes and selected authority in a manifest. Notification-document custody requires a content guard, encrypted content-addressed bytes, an exact certificate identity, and either a parsed reading or explicit parse refusal. ## Assessment

The strongest design is promotion through evidence gates: local drafts, rendered bytes, remote rows, captured PDFs, authenticated receipts and reconciled filing records remain distinct. Exact-profile operation access, guarded local writes after remote reads, typed effect reports, and public projections that omit raw PDFs or casilla values reduce accidental disclosure. Concrete adapter encryption, browser behavior, AEAT availability and receipt-host dispatch were not executed. A scoped capture issue is that discovered model/year pairs are reduced to model set plus min/max years before bulk capture; a ragged discovery set can expand to a Cartesian product and make aggregate counts cover undiscussed pairs. Several live result projectors discard their terminal receipt; their executors and host may still enforce matching receipts, so reachability must be checked before calling that a disclosure bypass. Finally, retention snapshots fail closed when absent, but a failed update can leave a valid old snapshot; freshness must be resolved before treating it as current deletion authority.
