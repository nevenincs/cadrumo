The application layer connects profile-bound work, local model provisioning, diagnostics, interactive flows, evidence retrieval, and several export and inventory operations. It generally treats an observation, a proposed action, and a recorded external effect as different states. Most surfaces are registered operations that bind a request to an exact profile and project a restricted public result; lower-level services rely on composition ports for storage, network transport, and authority. This is a static map of those contracts, not proof that a deployed runtime, provider, or legal corpus works. The detailed evidence is in [026](../articles/026-configuration-reset-diagnostics-and-consent-gated-telemetry.md), [027](../articles/027-local-reader-provisioning-workstation-health-and-application-contracts.md), [028](../articles/028-runtime-admission-canonical-state-and-storage-route-policy.md), [029](../articles/029-installed-workbench-generations-and-workstation-checks.md), [030](../articles/030-activity-asset-claims-and-aeat-sync-workspace-projection.md), [044](../articles/044-offline-search-evidence-bundles-and-export-boundaries.md), and [048](../articles/048-interactive-flows-and-profile-bound-inventory-operations.md).

## Operator state, health, and recovery

The canonical state projection combines active-profile health, redacted authentication readiness, workspace counts, obligations, and per-Modelo readiness. The latter keeps profile, authority registry, calculation binding, and conditional ledger checks separate, so a ready parser or available source does not imply a complete declaration. Its stable capture coordinate includes profile content and pinned registry generation. The installed workbench then composes Home, Ledger, Declarations, AEAT Sync, Modelo, calendar, and search from secure readers. It distinguishes `AVAILABLE`, `STALE`, `LOCKED`, `NEVER_CAPTURED`, and `UNAVAILABLE`, and rereads source revisions before publishing a generation. A search generation is refused if necessary source projections are missing. Calendar reuse is limited to an authenticated session and keyed by local date, authority and local-source revisions, and AEAT evidence digest. State and readiness (`src/cadrumo/application/state_projection.py`) Workbench capture (`src/cadrumo/application/workbench_generation.py`) Session memo (`src/cadrumo/application/workbench_capture_memory.py`) ([028](../articles/028-runtime-admission-canonical-state-and-storage-route-policy.md), [029](../articles/029-installed-workbench-generations-and-workstation-checks.md))

Workstation checks gather effective capabilities, dependencies, preflight results, and hardware contention for one profile, rechecking active-bucket identity between stages. Repair diagnostics inspect package/logging posture, secure state, profile/auth readiness, and stored-object decryptability without unlocking a profile to force success. Their typed warnings and failures have an operator action or an explicit no-recovery verdict. Local LLM run health uses outcome and timing rows, with no prompts or responses in those rows. The registered diagnostic read operation retains a private report until a successful receipt matching the profile and requested kind allows projection. These are useful operational controls, although a secure-object probe that cannot reach its repository reports an empty OK integrity row; another storage warning can still disclose the outage. Deadline calculation errors likewise collapse to an empty pending-obligations list in state projection. Consumers need an availability signal to avoid treating those empty values as proof of health. All-profile configuration reset has a durable journal and explicit confirmation. It records discovered targets, retention decisions, auth-clearance mode, pointer reconciliation, deletion marker, and phase. Retained records block unless the operator acknowledges an override with a reason; on resume, changed pointers or target fingerprints pause for renewed review, and a growing retained set drops the old override. Locked profiles have an explicitly unknown count of external certificate-secret residues. A deletion marker lets resume distinguish a completed capsule removal from an ambiguous crash. The multi-profile action is not atomic and the journal is not cryptographically authenticated; its careful phase checks reduce, but cannot remove, concurrent mutation and crash-recovery uncertainty. ## Local reader, flows, and domain work

Local-reader status resolves configured models per role, separating installed text extraction from vision and other roles. Selection uses catalog context, licence, and measured memory; loading requires free capacity in the relevant system or single accelerator device. Unknown memory refuses load unless the explicit unmeasurable-state override applies. Pull, load, verify, unload, and remove have separate boundaries and rereads where practical; setup stops at the first failed step and reports later steps as unreached, without rollback. Runtime startup refuses a non-loopback spawn endpoint, and package installation requires its supervised consent path. A fitness verdict is keyed to model/runtime digest so mere installation is not represented as grounded extraction capability. The readiness probe's one-token generation may itself cold-load a model without passing the normal load-admission path; that is a concrete boundary to reconcile. Optional resident byte sizes can also make contention attribution incomplete. The reusable flow engine validates page definitions, computes visible questions from canonical answers, keeps newly hidden answers as stale, and blocks submission on required, invalid, stale, or deferred material. Resume revalidates saved answers under the current definition. Secret widgets mask display, but a post-commit callback receives the raw canonical value and must be trusted; checkpoint encryption is a port contract delegated to the domain store. The inventory service uses revision-guarded bucket ledgers for movement and FIFO/PMP valuation; its registered workers bind subject and profile, mark an uncertain effect before mutation, and project acquisition evidence as fingerprints rather than contents. Asset amortization similarly retains revision and claim history, recomputes a forecast before accepting a claim, and uses a repository compare-and-swap expectation. Those are calculated and recorded claims, not evidence of an official filing. ## Knowledge, export, and external effects

Authority retrieval is offline and bounded: an exact citation ID resolves through a pinned signed registry projection, while an ordinary phrase searches an extracted normative HTML index. Cache identity includes source bytes, and rebuild stages a new index before atomic replacement. This establishes reproducible lookup to bundled material, not current-law validity. Evidence bundles hash bucket-local object references and verify reachability and digest before ZIP export; failed verification blocks export and incomplete export needs an explicit override. The legal-hold snapshot fails closed if missing or malformed, but its known producer writes an empty snapshot at registration and has no demonstrated refresh on later cases, so a valid old snapshot is not proof of current clearance. Citation lookup (`src/cadrumo/application/corpus_search/citation_lookup.py`) Index refresh (`src/cadrumo/application/corpus_search/runtime.py`) Bundle export (`src/cadrumo/application/evidence/service.py`) Hold producer (`src/cadrumo/application/evidence/profile_legal_hold.py`) ([044](../articles/044-offline-search-evidence-bundles-and-export-boundaries.md))

AEAT Sync's local workspace represents sources and discrepancy states separately. Before a remote pull, AEAT rows are `NEVER_CAPTURED`; its projection performs no network read. A comparison zone with local data and never-captured AEAT data can currently receive zone-level `UNAVAILABLE`, despite the source rows preserving the more precise state. Telemetry similarly separates preview from actual dispatch: payload fields are allowlisted aggregates, and send requires deployment opt-in, enabled tier, gestor mode off, an acknowledgement, and an endpoint. An attempted handoff is recorded as such, not confirmed delivery. Supervised Google workbook export binds a profile and registry plan and records `UNKNOWN` before mutation and `UPDATED` after its port returns; actual remote adapter behavior lies outside this application layer. Tabular CSV/JSONL/XLSX output validates metadata but CSV does not neutralize formula-leading text, a concern if arbitrary ledger strings reach a spreadsheet. The principal strength is explicit state and effect vocabulary: unknown, unavailable, stale, and attempted actions are often preserved rather than silently promoted. Verification should focus on the cited degradation paths, reset crash points, checkpoint implementation, model-readiness admission, legal-hold freshness, and spreadsheet text handling. No runtime or external-service result was established by these reports.
