Inbound adapters convert Modelo 100 drafts, filed-declaration PDFs, AEAT receipts, notification acts, structured e-invoices and financial files into typed observations. Borrador extraction supports printed casilla rows; filed-declaration extraction uses registry snapshot profiles; CII/UBL/Facturae parse into a neutral invoice DTO; provider files produce provenance-bearing raw transactions. The censal certificate parser explicitly refuses all documents pending a specimen-backed layout. Recognizing SII or VERI*FACTU shape does not mean that e-invoice parser accepts it. [Full synthesis](document-and-financial-imports.md), declaration parser (`src/cadrumo/adapters/inbound/declaracion/parser.py`), e-invoice dispatch (`src/cadrumo/adapters/inbound/einvoice/shape.py`), censal refusal (`src/cadrumo/adapters/inbound/censo/parser.py`), [detail](../articles/002-inbound-document-and-financial-adapters.md).

Knowledge comes from printed document values, provider row fields and the bundled extraction/notification registry. Digests and registry references preserve provenance, but a parsed receipt does not authenticate its AEAT CSV or URL; notification reduction fact selection uses the present Madrid date by default, a historical applicability question. XML has hardened parsing and a 32 MiB limit, while PDF attachments are read before that bound. PDF bytes routes can keep decrypted evidence in memory, and a digest-derived `.secure-source` reference is only a name until secure custody stores it. Notification parser (`src/cadrumo/adapters/inbound/notificacion/sancion.py`), XML guard (`src/cadrumo/adapters/inbound/einvoice/xml.py`), provenance (`src/cadrumo/adapters/inbound/pdf/source_provenance.py`), [detail](../articles/003-financial-providers-receipts-and-notification-pdfs.md), [detail](../articles/004-shared-pdf-text-and-provenance-boundary.md).

Scoped quality findings: borrador `OBSERVED` mode still applies a supplied coverage profile despite its description; declaration parser checks an injected snapshot against the template only by model ID and hides tolerated missing targets. The financial 64 MiB guard can run after auto-detection or some parser validation reads, and hash-then-reopen flows risk digest/content mismatch if a path changes. These local facts warrant tests and caller tracing; no runtime accuracy or document authenticity was established. Borrador mode (`src/cadrumo/adapters/inbound/borrador/parser.py`), snapshot check (`src/cadrumo/adapters/inbound/declaracion/parser.py`), financial detection (`src/cadrumo/adapters/inbound/financial/providers/detection.py`), [detail](../articles/002-inbound-document-and-financial-adapters.md), [detail](../articles/003-financial-providers-receipts-and-notification-pdfs.md).

## What enters the product

The inbound layer turns locally supplied or previously captured documents into typed observations for application workflows. It covers Modelo 100 draft PDFs, filed-declaration PDFs, AEAT justificantes, sanction/liquidation notification PDFs, structured e-invoices, and financial statement files. The package namespace describes inbound adapters as infrastructure and has no parsing behavior itself. A parsed observation is a statement about bytes and an interpretation profile; it is not proof that a document is authentic, that an AEAT CSV has been verified online, or that imported facts have passed a later tax calculation gate. Package boundary (`src/cadrumo/adapters/__init__.py`), borrador parser (`src/cadrumo/adapters/inbound/borrador/parser.py`), declaration parser (`src/cadrumo/adapters/inbound/declaracion/parser.py`), financial router (`src/cadrumo/adapters/inbound/financial/ledger_import.py`), [analyses](../articles/001-package-namespaces.md), [analysis](../articles/002-inbound-document-and-financial-adapters.md).

For Modelo 100, the borrador adapter detects preview, filed declaration or draft markers, then extracts printed four-digit casilla and amount rows. It retains the first duplicate and warns about later duplicates or unreadable amounts. A caller can supply an extraction profile and minimum coverage. The year registry currently maps 2021–2025 to the same observed-row extractor; the default year is 2025. Those facts describe parser support and a static default, not current-year validity. The extractor reports page 1 and confidence 1.0 for every matched row even after concatenating page text, so those spatial/confidence fields should not be treated as measured location or statistical confidence. More concretely, `OBSERVED` mode is documented as not enforcing profile coverage, yet supplying a profile still filters and enforces the minimum because the public parser passes it to the extractor. Detection (`src/cadrumo/adapters/inbound/borrador/_detect.py`), extractor (`src/cadrumo/adapters/inbound/borrador/_extractors/modelo_100_summary_v2025.py`), mode route (`src/cadrumo/adapters/inbound/borrador/parser.py`), [analysis](../articles/002-inbound-document-and-financial-adapters.md).

The filed-declaration parser takes either a path or decrypted bytes in memory. It detects or accepts a model/year/revision coordinate, resolves a period and registry snapshot, then selects the snapshot's `declaracion_pdf` extraction profile. Numeric casillas, named labels and bounding boxes are supported; malformed or ambiguous targets fail, while missing targets fail only below profile coverage. It stamps the source digest, template/reference and provisional-layout flag. A supplied snapshot is locally compared with the detected template only by model ID, so year, revision and period incompatibility could be admitted if a caller supplies mismatched coordinates. When coverage remains above threshold, missing targets are currently omitted from success warnings, making a tolerated partial extraction look complete to a consumer unless it separately checks the profile. The path fast parser is guarded by declaration canaries and falls back to pdfplumber. Snapshot selection (`src/cadrumo/adapters/inbound/declaracion/parser.py`), supplied snapshot check (`src/cadrumo/adapters/inbound/declaracion/parser.py`), target handling (`src/cadrumo/adapters/inbound/declaracion/parser.py`), [analysis](../articles/002-inbound-document-and-financial-adapters.md).

The censal certificate parser is explicitly unsupported: after distinguishing PDF magic from invalid input, it refuses both with separate errors because no specimen-backed layout was available to its author. That refusal is more reliable than turning unidentified fields into profile facts. Reconciliation composition lazily binds filed-declaration and justificante parsers; its bytes path can pass the already-selected registry snapshot, whereas its path method loads authority through the parser. Censal refusal (`src/cadrumo/adapters/inbound/censo/parser.py`), reconciliation port (`src/cadrumo/adapters/inbound/reconciliation_parser.py`), [analyses](../articles/002-inbound-document-and-financial-adapters.md), [analysis](../articles/004-shared-pdf-text-and-provenance-boundary.md).

Structured e-invoice ingestion accepts CII, UBL and Facturae XML, including PDF/A-3 containers with embedded invoice XML. It maps seller/buyer roles, tax IDs, dates, lines, tax bands and totals to a syntax-neutral DTO, then copies that into application ledger contracts. A shape probe recognizes SII and VERI*FACTU families, but this parser has no dispatch implementation for them; recognition is not acceptance. XML uses `defusedxml`, a 32 MiB payload cap and nesting bound, while PDF attachment contents are read into memory before that XML cap applies. The container itself has no local byte cap. Party IDs can fall back to a broad shape heuristic rather than checksum validation, and absent fields may remain `None`; downstream invoice confirmation must decide completeness and authenticity. E-invoice parser (`src/cadrumo/adapters/inbound/einvoice/parsers.py`), shape dispatch (`src/cadrumo/adapters/inbound/einvoice/shape.py`), XML guard (`src/cadrumo/adapters/inbound/einvoice/xml.py`), application mapping (`src/cadrumo/adapters/inbound/einvoice/application_translation.py`), [analysis](../articles/002-inbound-document-and-financial-adapters.md).

Financial imports normalize a bank movement to positive magnitude plus explicit incoming/outgoing direction and retain provider, row, source path and SHA-256 provenance. Auto-detection offers CSV layouts for N26, BBVA, Santander, CaixaBank and Revolut; OFX/QFX; N26 statement PDF; XLS/XLSX; and an otherwise-unclaimed mapped-table fallback. OFX's optional `ofxtools` dependency is loaded lazily; XLSX refuses formula cells in selected data rows. The mapped-table lane requires date and amount column roles, processes rows independently and reports mapping/rejection diagnostics. Its fixture basis is declared provisional rather than presenting the parser as specimen-complete. The base helper rejects symlinks, missing paths and files over 64 MiB, but auto-detection and OFX/N26 PDF/XLSX validation can read or parse before reaching that guard; this is a confirmed local resource-limit gap. Several providers hash then reopen a path for parsing, so concurrent replacement could make digest and parsed content diverge. Provider base (`src/cadrumo/adapters/inbound/financial/providers/base.py`), detection (`src/cadrumo/adapters/inbound/financial/providers/detection.py`), CSV (`src/cadrumo/adapters/inbound/financial/providers/csv.py`), OFX (`src/cadrumo/adapters/inbound/financial/providers/ofx.py`), mapped fallback (`src/cadrumo/adapters/inbound/financial/providers/_mapped_tabular.py`), [analyses](../articles/002-inbound-document-and-financial-adapters.md), [analysis](../articles/003-financial-providers-receipts-and-notification-pdfs.md).

Justificante parsing extracts receipt identity and timestamp, model/period/taxpayer, optional payment figures and a verification URL using structured required-field errors. It parses printed money as `Decimal` and refuses ambiguous punctuation. It reads the receipt's statement; `AnyHttpUrl` checks URL syntax and does not establish AEAT host trust or independently validate its CSV. Notification document reading likewise parses already-fetched bytes, checks conflicting printed figures and cent-level arithmetic, and takes reduction facts from a pinned governed registry. It defaults the fact date to the present Madrid date; whether a historical act should instead use its own effective date is unresolved. These parsers do no network navigation themselves. Justificante parser (`src/cadrumo/adapters/inbound/justificante/parser.py`), notification parser (`src/cadrumo/adapters/inbound/notificacion/sancion.py`), reader (`src/cadrumo/adapters/inbound/notificacion/document_reader.py`), [analysis](../articles/003-financial-providers-receipts-and-notification-pdfs.md).

Shared PDF extraction retains page slots and offers an in-memory bytes route for decrypted evidence. Digest-derived `.secure-source/<digest>.pdf` references and a generic `<input-pdf>` diagnostic label limit successful path disclosure, but the reference helper does not create or encrypt an object. The primitive has no PDF size/page cap; caller and library guards must cover hostile or scan-only PDFs. Across the inbound layer, source provenance and structured failures are useful strengths. Static inspection cannot establish extraction accuracy against live specimens, authority freshness, document authenticity, test coverage, or safe persistence. Priority verification is to align parser snapshot coordinates, expose tolerated missing targets, impose resource guards before detection, and bind digest to the exact bytes parsed. Page extraction (`src/cadrumo/adapters/inbound/pdf/page_text_extraction.py`), provenance (`src/cadrumo/adapters/inbound/pdf/source_provenance.py`), [analysis](../articles/004-shared-pdf-text-and-provenance-boundary.md).
