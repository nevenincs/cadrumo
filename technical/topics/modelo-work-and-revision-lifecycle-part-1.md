This part follows a declaration from profile-bound work unit through calculation, review, verification, local export, local filing, external evidence reconciliation, and amendment. The stages have distinct authority: a calculated draft records a result, a verified revision is filing grade under local checks, an export is a local artifact, a local filing record remains pending AEAT confirmation, and an external receipt or register observation can later support reconciliation. The application registers operations around these existing service authorities, generally binding exact profile, selected period, revision and operation receipt. ## Calculation and work inspection

Calculation preparation chooses an active work unit and law-selected, pinned registry snapshot; it validates canonical casilla and binding channels, detail rows, profile readiness, source-sensitive ledger preflight, and for Modelo 303 an IVA-wallet decision. The source mesh composes ledger IVA/Renta, invoices, withholding, inventory, foreign assets, prior filings, relations and model-specific sources. Ownership rules reject competing source values; caller overrides are limited to declared carry/manual policy. The formula engine emits typed observations with operands, legal/source references and an operator-layer replay payload, then persists a content-addressed BORRADOR revision and ledger fact anchor. Registry route tables check that executable resolvers are enrolled once. This produces a calculation, not an export or filing. ## Verification, artifacts, and filing authority

Verification rechecks current work/revision, law-selected filing-grade authority, required manual inputs, row templates, model-specific predicates, source evidence, IVA wallet, cross-period conditions and ledger drift. For a granting report, it stamps the revision verified and co-writes the transaction participation index. Refused attempts also receive a report. A saved granting report and later revision transition are separate repository steps, so interruption recovery needs verification. Selection prefers the current filed revision, then current verified revision; a current draft prevents silent fallback to an older result. Verification gate (`src/cadrumo/application/modelo/verification_actions.py`) Grant and participation (`src/cadrumo/application/modelo/verification_actions.py`) Selection (`src/cadrumo/application/modelo/selectors.py`) ([083](../articles/083-revision-selection-settlement-presentation-and-verification.md))

Local export replays the sealed revision into an approved filing draft, rebuilds model producer facts and applies schema, profile, ledger, cross-period and special-model gates before selecting the official layout. It stages a BOE artifact beside the chosen destination, appends an export event, publishes bytes and verifies the landed size/digest. A publication failure after the event could leave history for a file that never appeared; this is a sequencing risk to test. Calculation-report CSV/PDF is a different local artifact: the canonical report carries provenance and its PDF can receive a domain-separated Ed25519 signature with `aeat_official=false`. Document-only validation yields `valid_unpinned`; profile-store verification pins the key and rebuilds the report. Neither artifact is AEAT acceptance. Spreadsheet export/pull/verify is another supervised surface and remote parity work can modify Google Sheets; the workbook plan and registered effect accounting do not make it an official filing. Local filing requires the exact verification report and rechecks readiness and evidence. It persists a PRESENTADO revision with a filing record whose AEAT status is PENDIENTE, co-writing pointers, participation, events and app-filing observations. Such local observations can inform future calculations but remain nonofficial for dependent filing gates. External import instead needs registry-grounded values and receipt/register evidence matching model, period and taxpayer; reconciliation promotes a pending chain only on comparable matching evidence, otherwise records discrepancy or unverifiable status. An amendment starts only from a current AEAT-confirmed, externally evidenced filing baseline, creates a new local pending correction and still requires external confirmation later. ## Review collaboration and assessment

A verified or filed revision can become an accountant review-package ZIP containing the rendered artifact and calculation evidence. Checksums protect member integrity; Ed25519 signatures are verified against independently supplied trusted keys, and recipient encryption uses a registered public key fingerprint for out-of-band checking. Plain ZIPs and decrypted output remain operator-chosen local files. Recipient registry changes are written before separate audit events, so partial effect is possible. Feedback import does not visibly consume the replay nonce that the direct decrypt route consumes; whether an adapter does so elsewhere remains open. Package build (`src/cadrumo/application/modelo/review_package.py`) Signature (`src/cadrumo/application/modelo/review_package_signing.py`) Recipient registry (`src/cadrumo/application/modelo/review_package_recipient_registry.py`) Feedback replay path (`src/cadrumo/application/modelo/review_package_exchange_operation.py`) ([081](../articles/081-reconciliation-filing-disposition-and-accountant-review-packages.md), [082](../articles/082-review-package-exchange-and-modelo-revision-persistence.md))

Quickfile sequences readiness, work creation/resume, calculation, verification and local export with stage-specific stop/partial effect accounting; it never submits. M100-from-M130 projection is an ephemeral estimate using latest cumulative quarter values and an explicit early-year extrapolation, not a filed M100. Reconciliation of local PDFs is enrolled only for selected Modelos and reports missing amount anchors instead of overstating an identity match. Quickfile (`src/cadrumo/application/modelo/quickfile.py`) M100 projection (`src/cadrumo/application/modelo/projection.py`) PDF reconciliation (`src/cadrumo/application/modelo/reconciliation.py`) ([080](../articles/080-modelo-projections-queries-quickfile-and-recipient-encryption.md), [081](../articles/081-reconciliation-filing-disposition-and-accountant-review-packages.md))

The main strengths are pinned registry coordinates, separated source and operator layers, typed provenance, blocked unsupported paths, exact-profile operation admission, and explicit local-versus-official evidence. Scoped verification priorities are the error-after-persistence ordering in calculation, cross-store verification/export recovery, authority helpers that reopen bundled generations, wallet override freshness, recipient feedback replay, and display of process-local advisories. No runtime or legal accuracy claim follows from this static review.
