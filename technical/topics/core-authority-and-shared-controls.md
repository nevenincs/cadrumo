## What this layer supplies

The core is a set of typed boundaries shared by the command, application, domain and adapter layers. It does not itself perform most business workflows. Its value is that a caller can distinguish a validated wire shape from registry membership, observed evidence from inferred value, a local file from a remote handle, and an authorized result from a merely serializable object. Much of the assurance is therefore compositional: the declaring module makes a constraint expressible, while the consumer must invoke it at the correct trust boundary. This packet covers settings and storage routing, durable writes and locks, record and provenance vocabularies, legal-corpus handling, output/errors/redaction, optional telemetry, localization and shared parsing. The evidence is static inspection only; current AEAT rules, portal selectors, model pricing/licences and filesystem behavior were not independently verified. Settings (`src/cadrumo/core/config.py`), classification (`src/cadrumo/core/classification/policies.py`), [analyses](../articles/111-core-configuration-profile-selection-and-durable-writes.md), [112](../articles/112-settings-storage-routing-corpus-citations-and-credentials.md), [118](../articles/118-live-access-policy-corpus-integrity-and-decimal-contracts.md).

## Configuration, local custody and durability

`Settings` is the environment authority, but it deliberately rejects an environment-supplied active profile. The selected profile comes from the durable bucket pointer or an explicit process-scoped override. The settings cache keys the pointer state and revision, so a login/logout transition changes the derived bucket database route; a root override recomputes derived paths while preserving explicit values. Routes are classified as an explicit URL, cold root fallback or selected bucket, and retired `aeat` state is refused rather than silently adopted. Off-host evidence reading defaults off and requires deployment permission plus per-invocation acknowledgement, with gestor mode blocking it. Remote telemetry has a separate opt-in. Local and cloud LLM settings are role-specific, with a memory floor and default refusal when local headroom cannot be measured. These are configuration postures: the respective call sites still have to enforce them. Pointer-sensitive settings (`src/cadrumo/core/config.py`), route classification (`src/cadrumo/core/config_storage_route.py`), privacy defaults (`src/cadrumo/core/config.py`), model settings (`src/cadrumo/core/config_llm_fields.py`), [analysis](../articles/112-settings-storage-routing-corpus-citations-and-credentials.md).

The pointer is a strict selection or tombstone with a transition revision. Reads reject link-like, oversized, partial, changing or malformed files; a missing file means revision-zero absence. A narrow repair context can treat corruption as no selection for discovery, but transitions still refuse it. The caller must hold the owner lock consistently. Shared atomic writers stage next to the target, fsync, replace and best-effort sync the directory; hardened staging uses restrictive, unpredictable, exclusive names and handles short writes. A lower-durability batch is expressly for re-derivable/content-addressed data, excluding keys, pointers and session records. The storage taxonomy inventories root, bucket and keystore locations with lifecycle and fingerprint policy, and materialization is explicit. `bucket_scoped_storage_path` checks only nonblank bucket IDs before joining; safe identifier grammar remains a caller premise. Pointer (`src/cadrumo/core/bucket_pointer.py`), hardened writer (`src/cadrumo/core/atomic_write.py`), storage taxonomy (`src/cadrumo/core/storage_taxonomy.py`), bucket path (`src/cadrumo/core/storage_taxonomy_locations.py`), [analyses](../articles/111-core-configuration-profile-selection-and-durable-writes.md), [116](../articles/116-identity-profile-sessions-result-disposition-and-storage-taxonomy.md).

Core locks serve different purposes. An OS sidecar lock offers cooperating-writer exclusion without stale PID reclamation; the separate recoverable PID lockfile path retries a live holder's unlink on Windows because premature release can strand a live lock. The PID probe treats uncertain liveness as alive, preventing unsafe reclamation. The OS-lock acquisition helper currently treats any `OSError` like contention, so a permission or descriptor failure can surface as a timeout; this is a local diagnostic weakness unless a caller preserves the original error elsewhere. Link-safety and path-resolution helpers are primitives, not complete containment checks. `file_permissions` hardens account access on POSIX/Windows but its public helper swallows failure and returns no success witness. Consumers that need a hard guarantee must establish it separately. OS lock (`src/cadrumo/core/locks.py`), PID lock unlink (`src/cadrumo/core/lockfile_unlink.py`), permission helper (`src/cadrumo/core/file_permissions.py`), [analyses](../articles/113-external-service-constants-field-provenance-and-filing-producers.md), [114](../articles/114-filing-projections-workflow-state-and-json-output-contracts.md), [115](../articles/115-logging-output-privacy-model-selection-and-periods.md).

## Knowledge and data semantics

Core identities and registries deliberately avoid claiming more than their shape proves. `Modelo`, casilla and `TaxDomain` syntaxes do not establish current catalogue membership; an opaque `RegistryToken` needs registry projection. `Period` separates actual filing periods from administrative censo and symbolic event selectors, and gives date spans only to cadences where one is defined. `ValidityWindow` has explicit inclusive endpoints and no implicit current date. Spanish tax-ID validation consumes authority-supplied format tables and checksum partitions; a structural predicate is only syntax. NIF-IVA existence is not inferred from a shaped token. Shared date parsers distinguish a permissive ISO parser from a strict extended `YYYY-MM-DD` gate. Two ISO currency/jurisdiction normalizers currently accept non-ASCII alphabetic letters, despite their alpha-code names, so strict ASCII admission should be checked at the outer schema. Period (`src/cadrumo/core/period.py`), validity (`src/cadrumo/core/validity_window.py`), identity (`src/cadrumo/core/identity/documents.py`), ISO helpers (`src/cadrumo/core/parsing/codes.py`), [analyses](../articles/115-logging-output-privacy-model-selection-and-periods.md), [117](../articles/117-text-normalization-legal-categories-and-validity-contracts.md), [121](../articles/121-localization-identity-validation-run-traces-and-date-parsing.md).

Calculation and import contracts retain provenance and uncertainty instead of promoting a missing field to zero or an unverified claim to official evidence. Aggregation vocabularies separate binding source, row grouping, capture lineage and quality; income may use a declared substrate or weaker cash fallback, and invoice devengo can rest on a declared operation date or an issue-date proxy. `FieldOrigin` distinguishes structured bytes, text/rules, vision, table mapping, operator entry and derivation; `FieldGroundingOutcome` separately records what independent check ran. A failed or unavailable citation anchor remains distinct from verified grounding. Filed-history discovery from an AEAT option list widens a walk but is not proof that the list is taxpayer-specific. Missing casillas require a named zero assumption; digit-looking observed text carries a value kind before numeric interpretation. Aggregation quality (`src/cadrumo/core/aggregation.py`), field origin (`src/cadrumo/core/field_origin.py`), grounding (`src/cadrumo/core/field_grounding.py`), history signal (`src/cadrumo/core/filed_history_discovery_signal.py`), [analyses](../articles/111-core-configuration-profile-selection-and-durable-writes.md), [113](../articles/113-external-service-constants-field-provenance-and-filing-producers.md).

Document and financial parsers also refuse semantic shortcuts. Content-based `DocumentShape` distinguishes structured single invoices, PDFs with embedded XML, scans and text-layer PDFs, excluding collection submissions such as SII from a one-invoice path. The legacy `.xls` reader marks formula coordinates so cached results can be rejected by the shared workbook policy. Tabular normalization detects a rectangular dialect, retains source lines and cells, and reports ambiguous decimals without assigning columns a meaning; role mapping belongs downstream. Monetary text has separate tolerant, strict, finite European, canonical human-entry and fixed-width filing grammars. Ambiguous `1.234` is left for operator confirmation instead of a thousandfold guess. Filing projection references have closed form-specific row and party shapes, and result-disposition rules distinguish a refund from the separate need to put an account in the file. Producer identities cover many model-specific outputs, but the key source documents a notable integration gap: 200 of 238 pre-existing keys lack a runtime producer. That does not mean every supported form is unusable; actual impact depends on the selected registry revision and its producer requirements. An export exemption reason can identify a genuinely absent or unmodelled block rather than hiding it. Registry authority grades and revision-review states are declared/pinned claims, not automatic legal certification. Bundled external constants contain AEAT routes, Cl@ve selectors and Google scopes; the volatile wallet section validates lazily, and a notification detail action is documented as potentially service-changing, so a constant cannot authorize its use. The corpus layer resolves citations to one exact extracted unit and refuses missing or duplicate anchors. A manifest records path-safe per-file SHA-256 digests and an internally consistent ZIP bundle; this verifies integrity relative to the included manifest, not publisher authenticity when both manifest and files can be replaced. Verification reads members into memory and reduces names to a set, leaving ZIP size limits and duplicate-member handling to downstream installation policy. `AeatAccessGate` permits guarded live reads under their own checks and makes outbound submission an unconditional typed refusal; the stated product workflow is local filing artefacts for operator upload. Call-site coverage must still be traced before claiming every write-shaped path hits the gate. ## Output, privacy and diagnostic controls

The shared JSON contract validates registered success results, typed notices and action references through strict serialization; executable follow-up is a structured action, not prose disguised as a command. Errors use seven stable categories with code, retryability, translation and exit behavior. The registry loads lazily, rejects duplicate codes/class ownership and refuses an undeclared subclass rather than assigning a fallback. Context redaction removes sensitive values and record-fault projection avoids raw Pydantic input. A conditional message gap remains: rendered error text can interpolate original context or fall back to `error.args[0]` even when the separate context field is scrubbed. Translation templates and exception constructors need a targeted review before any actual disclosure can be claimed. The `BaseSeverity` string enum also documents `INFO < WARNING < ERROR` but lacks an explicit rank, making native lexical sorting inconsistent with that order if consumers rely on it. JSON result (`src/cadrumo/core/json_contract.py`), error registry (`src/cadrumo/core/errors/error_codes.py`), message resolution (`src/cadrumo/core/errors/error_codes.py`), severity (`src/cadrumo/core/errors/severity.py`), [analyses](../articles/114-filing-projections-workflow-state-and-json-output-contracts.md), [119](../articles/119-error-contracts-renderers-and-record-fault-projection.md), [120](../articles/120-error-registry-catalogues-and-severity.md).

Redaction is layered for flat text, structured values, logs/errors and public CLI output. Identity and IBAN matching use checksum or authority admission where possible and conservative shape fallback when that authority is unavailable. CLI output may explicitly reveal opaque profile/bucket IDs, while tax IDs, URLs, tokens and object keys remain redacted. This is pseudonymization, not anonymity: an eight-hex deterministic tax-ID prefix can be dictionary-guessed, and a bounded process cache retains short original strings until eviction/exit. Logs and run traces are another boundary. The logger scrubs structured arguments and exceptions; output rendering returns only redacted text. Yet run JSON/JSONL traces can contain tax-return amounts and arbitrary diagnostics and are written without encryption by this module. The direct event-append path lacks an event-run-ID versus directory-run-ID check, and the run-sink attachment does not visibly install the third-party DEBUG filter used on other disk handlers. These scoped paths merit consumer-level checks, not a blanket assertion that all logs leak. Redaction (`src/cadrumo/core/redaction/rules.py`), cache (`src/cadrumo/core/redaction/rules.py`), logging (`src/cadrumo/core/logging.py`), event append (`src/cadrumo/core/observability/store.py`), [analyses](../articles/115-logging-output-privacy-model-selection-and-periods.md), [121](../articles/121-localization-identity-validation-run-traces-and-date-parsing.md), [122](../articles/122-redaction-bundled-resources-telemetry-and-time-contracts.md).

Telemetry defaults to a no-op sink and requires several opt-ins before an HTTP sink can post a typed payload. The local tier contract, however, is weaker than its label: `CRASH_ONLY` promises to exclude timings, while the consent gate currently distinguishes only `OFF` from other tiers and the schema allows a duration metric. `error_kind` is bounded in length but not actually a closed code, and `command` is a free nonempty string. A producer could pass user data there; actual transmission depends on a real caller, endpoint and all consent gates. The stable, unsalted workspace-path hash can link runs and is not proof of anonymity. Classification policy similarly declares retention ages, but `max_age` and `archive_after` are not consumed by repositories/gates, so a seven-day diagnostic value is not an implemented purge. Consent (`src/cadrumo/core/telemetry/consent.py`), schema (`src/cadrumo/core/telemetry/schema.py`), workspace hash (`src/cadrumo/core/telemetry/workspace.py`), retention (`src/cadrumo/core/classification/policies.py`), [analyses](../articles/118-live-access-policy-corpus-integrity-and-decimal-contracts.md), [122](../articles/122-redaction-bundled-resources-telemetry-and-time-contracts.md).

Localization loads safe YAML shards and can capture a process-scoped digest across a stable file window. Production missing keys become humanized labels while strict test modes raise. If packaged YAML can change inside a running process, the cached translation value could be paired with a newer file digest; immutable-package/restart semantics or cache invalidation would settle that conditional gap. Shared time helpers require aware UTC for true instants, provide Madrid civil-date calculation and scoped frozen clocks, and validate inclusive ranges. Their statutory-time rationale, like notification-service intervals and model catalogue metadata, remains product-supplied knowledge rather than external validation in this review. Locale capture (`src/cadrumo/core/i18n/locale_catalogue.py`), cached catalogue (`src/cadrumo/core/i18n/_lazy_catalogue.py`), UTC (`src/cadrumo/core/time/utc.py`), [analysis](../articles/121-localization-identity-validation-run-traces-and-date-parsing.md), [analysis](../articles/122-redaction-bundled-resources-telemetry-and-time-contracts.md).
