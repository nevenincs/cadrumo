## Work and evidence flow

This part connects a Modelo target to its revision, form, review and cross-period evidence. Work addressing accepts a natural model/year/period target or exact work/revision IDs, selects the law-applicable registry revision and checks optional requested and stored revision assertions. Its captured work catalogue and profile pointer are rechecked under bounded retries, so a changed active profile cannot silently retarget the same command. Creation validates exact profile readiness, regional applicability, period and selected revision before a revision-guarded work/event co-commit. Reusing an unchanged target has `NONE` effect; new work or rename has `UPDATED`; uncertain prepublication phases stay `UNKNOWN`. Discard retains history instead of deleting it, and the derived work ID prevents simply recreating the same discarded natural target. Addressing (`src/cadrumo/application/modelo/work_addressing.py`), capture (`src/cadrumo/application/modelo/work_addressing.py`), create operation (`src/cadrumo/application/modelo/work_create_operation.py`), lifecycle (`src/cadrumo/application/modelo/work_lifecycle.py`), [analyses](../articles/084-cross-period-checks-verification-reports-and-work-addressing.md), [analysis](../articles/085-work-creation-form-editing-and-inventory.md), [analysis](../articles/086-work-lifecycle-review-wizard-and-workflow-gate.md).

The work form is a canonical read model over the pinned registry layout, saved calculation, operator-entry layer, verification findings, profile facts, source provenance and deadline calendar. It accounts for each declared casilla exactly once; when layout data are absent or mismatched it falls back to read-only inspection. Origins distinguish entered, imported, calculated, needed, cleared, not-applicable, failed and default-to-confirm values. It labels a value operator-entered only when the persisted operator layer supports that claim; held required or nonzero figures without attribution invite confirmation. Repeating rows are shown as known empty only when a saved channel explicitly says so. Printed rates are displayed only under declared scale/source rules, and settlement direction comes from official disposition metadata rather than a numeric sign guess. The form also marks incomplete holiday coverage and calls a locally recorded filing exactly that; it does not imply AEAT submission. Form layout (`src/cadrumo/application/modelo/work_form.py`), field state (`src/cadrumo/application/modelo/work_form_field_state.py`), rows (`src/cadrumo/application/modelo/work_form_records.py`), result (`src/cadrumo/application/modelo/work_form_result.py`), filing state (`src/cadrumo/application/modelo/work_form_models.py`), [analysis](../articles/085-work-creation-form-editing-and-inventory.md).

Verification assembles registry-authored predicates and cross-period dependencies from prior filing records, calculation revisions, verification reports, justificantes, wallet decisions and profile/member evidence. An economic-activity conditional source is suppressed only when positive applicability is established; uncertainty keeps its blocker. Missing prior evidence can add an activity-start question to distinguish a genuine first filer. A Modelo 303 carry is covered only by a matching unblocked wallet decision with selected amount and allowed authority/source. Withholding annual summaries have a dedicated false-zero gate: an empty per-perceptor store requires quarterly absence attestations and is blocked when liability evidence contradicts them. That gate explicitly does not prove completeness when a nonempty store has too few rows. Every blocking finding carries one typed precondition identity, while report reads are profile/revision bound and size-limited. Cross-period gate (`src/cadrumo/application/modelo/verification_cross_period.py`), wallet correlation (`src/cadrumo/application/modelo/verification_cross_period.py`), withholding gate (`src/cadrumo/application/modelo/withholding_detail_gate.py`), report read (`src/cadrumo/application/modelo/verification_report_read_operation.py`), [analysis](../articles/084-cross-period-checks-verification-reports-and-work-addressing.md).

The workbench's registered operations expose form/help, baseline renewal, edit preflight and one-time prerequisite retrieval as human-only, no-effect reads scoped to an exact work unit and period. Its public mirror round-trips to the canonical form and requires exact equality before release. The workflow gate replays a calculation revision to a draft, performs purpose-specific validation, and persists the workflow result before returning; `VERIFY` is independent of filing-window dates, while `FILE` retains local window/late policy. A successful gate is not itself the later verification or internal filing transition. The wizard asks grounded questions for manual casillas/bindings and turns only a typed missing-binding refusal into another input step; other failures propagate. Preparation may already have written migrations or wallet decisions, so the wizard correctly reports `UNKNOWN` before an actual revision is published. ## Workspace projection and implementation assessment

The workspace service presents two read-only modes for an exact target: static registry inspection, and a calculation-grade snapshot with materialization, provenance, bounded review and readiness. Static mode exposes schema, formulas and relationships while marking calculation, verification and filing readiness unmeasured. Graded mode requires matching work, registry, calculation, review and readiness contributors; it labels each capability only to the grade actually evidenced. It keeps `None` distinct from an empty list where grounding or constraints were not measured. Facet cursors bind baseline, schema, revision and contributor epochs, and stale/foreign captures refuse. A fail-closed schema manifest inventories public type leaves and detects declared projection drift. Workspace static assembly (`src/cadrumo/application/modelo/workspace.py`), graded assembly (`src/cadrumo/application/modelo/workspace.py`), cursor (`src/cadrumo/application/modelo/workspace.py`), manifest (`src/cadrumo/application/modelo/workspace_manifest.py`), [analysis](../articles/087-modelo-workspace-read-projection.md).

Each workspace contributor supplies a projection, schema-derived contract stamp and owner-scoped epoch. Epoch equality requires the same owner and comparison domain, so reused generation numbers across process incarnations do not make old captures current. Native producers still own the truth of their atomic-read and generation promises; the assembler checks currentness but does not open one transaction over all repositories. The module header in `workspace.py` says static/graded assembly is unfinished even though both paths are implemented, a concrete stale documentation defect. Producer contracts (`src/cadrumo/application/modelo/workspace_producers.py`), epoch comparison (`src/cadrumo/application/modelo/workspace_producers.py`), workspace implementations (`src/cadrumo/application/modelo/workspace.py`), [analyses](../articles/087-modelo-workspace-read-projection.md), [analysis](../articles/088-workspace-producer-contracts-and-capture-ports.md).

Several bounded implementation questions remain. Unknown blocking-predicate syntax evaluates as satisfied locally, so all registry-loading paths must enforce DSL validation before runtime. A nullable cross-period snapshot helper returns no findings when it cannot resolve calculation-grade authority; normal verification resolves a higher grade earlier, but direct callers must preserve that precondition. Wizard discovery lacks a current revision input and may present already-entered manual casillas. One-time prerequisite retrieval consumes its private projection before subsequent resolution, so an exception could impair retry. These are local contracts whose user-visible reachability needs tracing, not proof that a filed return skips verification. Static inspection did not run tests, calculate a return, certify registry law, or exercise persistence races. Predicate dispatch (`src/cadrumo/application/modelo/verification_predicates.py`), cross-period helper (`src/cadrumo/application/modelo/verification_cross_period.py`), wizard discovery (`src/cadrumo/application/modelo/work_wizard.py`), prerequisite read (`src/cadrumo/application/modelo/workbench_operations.py`), [analyses](../articles/084-cross-period-checks-verification-reports-and-work-addressing.md), [analysis](../articles/086-work-lifecycle-review-wizard-and-workflow-gate.md).
