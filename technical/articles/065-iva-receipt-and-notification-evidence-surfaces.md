## Justificante custody and evidence matching

Justificante capture resolves the correct expediente through the period-bearing declarations register, preferring an accepted `ALTA` row and then the latest presentation; it refuses when no matching declaration or procedure-tree entry exists rather than falling back to a different period. Snapshots bind model/year/period, expediente, CSV, raw-PDF digest and PDF bytes encoded inside the encrypted snapshot envelope. The content-addressed ID makes an identical receipt idempotent, while a new PDF on the same filing axis supersedes the prior active snapshot. Snapshot validation re-decodes the PDF and checks its digest. Period-to-expediente resolution (`src/cadrumo/application/live/justificante.py`) Snapshot integrity and content identity (`src/cadrumo/application/live/justificante.py`) Lifecycle and secure repository (`src/cadrumo/application/live/justificante.py`)

Authenticity is a four-state advisory (`NOT_CHECKED`, `CONFIRMED`, `DENIED`, `UNAVAILABLE`), not a boolean: an incomplete cotejo round trip is not reported as AEAT denial. The captured receipt is retained even when cotejo is unavailable. Parsed metadata is registered only after its CSV matches the capture and its model/year/period axis agrees. Filing-evidence stamping additionally loads the current local filing, resolves expected taxpayer identity from the record or profile, requires the receipt to match that record, refuses to overwrite evidence for a different CSV, then reconciles and verifies that the persisted record is accepted. This separates receipt custody, receipt parsing, and filing confirmation. ## Notification-document custody and reads

Notification custody requires an injected content guard before work and again before the Sede fetch; the adapter fetch contract also requires its own read-state check before bytes cross the wire. Fetched bytes stay in memory until written to the encrypted, content-addressed attachment store; the separate encrypted record binds the attachment digest, certificate ID, byte size, source URL, and parsed result or refusal. One certificate has one record. Re-fetching identical content is an explicit no-op; a disagreement in bucket, digest, size, or source URL refuses instead of replacing stored evidence. The record validator requires exactly one of a parsed sanction/liquidation or a parse refusal, so unreadable content cannot look like zeroed financial data. The capture operation is exact-profile, owns the browser process, fences custody, and expects `NONE` for an already-held document or `UPDATED` for new custody. It publishes no PDF bytes. Local view returns allowlisted metadata, an optional parsed sanction with decimal values preserved as strings, or the explicit parse refusal; history returns only parsed readings. These result models tie sanction/certificate/digest identities and counts together. View disclosure is profile and tax data; history disclosure is tax data. ## Assessment and follow-up

The clearest strength is evidence matching at each boundary: model/period before receipt selection, independent CSV and filing identity before justificante stamping, certificate identity before document custody, and a visible reading refusal when a notification document cannot be parsed. Raw documents stay in encrypted stores and public schemas expose metadata or structured readings rather than PDF bytes. The primary cross-module follow-up is receipt enforcement for the IVA/source result projectors; resolve it against the operation host before assigning reachability or severity.

One additional event-loop invariant deserves confirmation. Combined IVA acquisition installs a filter for two known Playwright shutdown messages and calls that context with `restore_on_exit=effect_guard is not None`; without an effect guard, the prior loop handler is not restored on exit. This may be intentional to absorb delayed cancellation noise, but the call can affect later code on the same event loop and should be checked against the lifecycle of direct callers. Document/attachment and PDF snapshot writes are also separate local persistence steps; interruption can leave an unreferenced content-addressed attachment or orphan receipt, though the inspected code avoids writing a record that points to missing bytes. No tests were reviewed or run, and the provider adapters, storage transactions, host receipt dispatch, and frontend policy were not exercised.
