## Binding and revision capabilities

`RetencionesAggregationProvider` gives the withholding aggregation selectors a typed registry representation while using narrow protocols for resolved aggregation and Modelo 180 row data. Its binding validator separates scalar selectors from row selectors, checks the relevant field/key shape, and restricts row-set cardinality so a row collection cannot be mistaken for a scalar terminal value. Resolution supports overall totals, per-scheme rollups, and Modelo 180 type-2 row values. The type-2 path checks that it is used for Modelo 180 and constructs values from recipient identity, property details, and structured address components. Scheme filtering resolves the allowed withholding schemes from governed mapping facts rather than trusting arbitrary selector text. Revision contracts make predecessor status explicit: a revision may name a predecessor or declare a reason it has none. Projection helpers turn those declarations into temporal windows and predecessor edges; validators reject self-links, cycles, invalid forests, date disagreement, and overlapping period scopes where a predecessor chain cannot be reconciled. The separate ordering helpers distinguish selector overlap from temporal coexistence, so a shared period token alone does not imply that two editions are simultaneously valid. This is an important boundary for choosing an edition without conflating a revision's calendar window with its period selector. ## Central schema, governance, and validation

`ModeloRevision` is the typed declaration boundary for revision-owned families: casillas, formulas, bindings, export and form layouts, extraction profiles, verification expectations, schedules, applicability, and related declarations. Markers distinguish manifest-only claims, governance-stamp fields, coverage-bearing schema families, and chain statements. Validators refuse dispositions against unknown or populated families; restatements require an actual predecessor, unique family entries, and content in the restated family. Identity-keyed families reject duplicate IDs, while governance and review validators require coherent sign-off fields and valid review references. An undeclared authority grade reads at the lowest, fail-closed grade, while `is_graded` preserves whether a grade was explicitly stated. Storage deltas for keyed families require known family names, unique clearances/scopes, scoped operations to be declared, and a baseline or predecessor. There is a potential edge case in this last test: it checks only whether `revision.predecessor is None`, while the revision contract also represents a root as a non-`None` `NoPredecessor` declaration. A root carrying storage operations may therefore pass this specific baseline guard without naming a storage baseline. Whether the later merge layer accepts or rejects that state is outside the assigned modules; this is a concrete invariant worth verifying against that consumer. ## Quality, security, and limits

The strongest design properties are immutability, explicit provenance placement, closed selector vocabularies, cross-reference checks, and fail-closed handling of missing authority or verification declarations. The public mechanisms here are data validation and projection, not request execution; the assigned modules contain no network client, credential handling, or arbitrary expression evaluator. A personal-data boundary is still visible: the withholding row protocol includes NIFs, names, addresses, and cadastral references. The binding resolver carries those values into declared outputs and shows no redaction or access-control policy locally, so callers must apply the product's sensitivity and export controls around these projections. This is a data-handling observation, not evidence of an exposed endpoint.

Static review did not run registry fixtures or tests. In particular, the storage-baseline edge case needs merge-layer confirmation; the snapshot consistency check intentionally does not cover administrative and symbolic period coordinates; and the completeness behavior of runtime catalogues depends on callers invoking the explicit completeness gate. This chunk does not show UI/CLI behavior, persistence, downstream merging, or legal-content accuracy.
