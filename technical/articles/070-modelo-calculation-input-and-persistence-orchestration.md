## Product capabilities and flow

The application boundary turns operator input into a typed calculation request. `build_work_calculate_input_bundle` selects the active work unit, resolves its calculation-grade registry revision under a pinned authority operation, validates the typed detail rows, and separates decimal casillas, text casillas, decimal and enum bindings, relation values, and optional Modelo 100 draft and Modelo 303 filing evidence (input builder (`src/cadrumo/application/modelo/calculate_input.py`), input bundle (`src/cadrumo/application/modelo/calculate_input.py`)). Casilla IDs must be declared canonical IDs. Printed or ambiguous aliases are rejected; row-template casillas cannot be set as scalar inputs. String casillas pass their registry-declared scalar validator (including specialized NIF or IBAN handling); enum bindings follow the formula-consumed enum channel, date-sourced bindings are refused, and decimal values use a canonical decimal parser that rejects ambiguous forms such as scientific notation and non-finite values (casilla routing (`src/cadrumo/application/modelo/calculate_input.py`), binding routing (`src/cadrumo/application/modelo/calculate_input.py`), decimal parser (`src/cadrumo/application/modelo/calculate_input.py`)). The service also validates M184 share totals, M347 thresholds, and M349 identifiers and country-prefix context using the pinned governed-fact scope (detail validation (`src/cadrumo/application/modelo/calculate_input.py`)).

The input builder applies backend-owned shortcuts for maternity/paternity benefits, maternity deductions, pension-rescue reductions, special reserve allocations, and a Modelo 303 autoconsumption binding. Shortcut casillas are found by registry semantic role rather than fixed box numbers. Incomplete grouped values are rejected. Pension rescue reductions are withheld when a declared transition window is proven closed; an absent contingency year allows calculation but yields a diagnostic. Maternity logic can withhold or qualify deductions when eligibility facts, historic contribution ceilings, or relationship details are unresolved, and emits non-blocking diagnostics (shortcut routing (`src/cadrumo/application/modelo/calculate_input.py`), shortcut contributions (`src/cadrumo/application/modelo/calculate_input.py`), shortcut entrypoint (`src/cadrumo/application/modelo/calculate_input.py`), DT12 decision (`src/cadrumo/application/modelo/calculate_input.py`)). These are code paths and declared rule behavior; this chunk does not independently verify the underlying tax interpretation.

`calculate_modelo_work_revision` forwards the bundle to the bucket-aggregation action and packages the persisted revision with its work unit, publication state, optional Modelo 202 modality, and source/plazo diagnostics (service wrapper (`src/cadrumo/application/modelo/calculate_input.py`)). The main action builds one source mesh from bucket-local repositories and explicit foreign-asset observations. Enrolled resolvers cover ledger IVA and renta, invoice sources, retenciones and withholding, OSS/IOSS, inventory, foreign assets, attribution members, prior filings, relation prefill, IVA compensation partitioning, and a simplified-regime annual handoff. A calculation-scoped transaction cache lets mesh resolution and the ledger anchor share reads (mesh construction (`src/cadrumo/application/modelo/calculation_actions.py`), aggregation entrypoint (`src/cadrumo/application/modelo/calculation_actions.py`)). Source-owned binding and bound-casilla collisions are rejected; caller overrides remain allowed for declared carry sources where policy permits. Novel scalar source kinds fail unless explicitly enrolled or registered as deferred/non-runtime (source-kind gate (`src/cadrumo/application/modelo/calculation_actions.py`), override gate (`src/cadrumo/application/modelo/calculation_actions.py`)).

After source and profile channels are merged, the registry formula runtime calculates values. Missing-input registry failures are translated into the application missing-input error. The action creates replay payloads, typed observations, drops row-template scalar outputs, validates filing-instance evidence and lifecycle ordering, then persists a BORRADOR revision. Persistence receives source transaction IDs, source provenance, eligible durable source issues, detail rows, the actor, and an optional secure-object-write factory; the draft also records a tax-fact ledger snapshot for later drift checks (engine and persistence flow (`src/cadrumo/application/modelo/calculation_actions.py`), ledger anchor (`src/cadrumo/application/modelo/calculation_actions.py`)). Verification and filing are separate lifecycle actions outside this chunk.

The post-calculation coordinator adds advisory checks for unpopulated official boxes, prior-payment carry, settlement completeness, descendant/minimum facts, childcare, rate-box coverage, capital-goods regularization, and prorrata regularization (collector (`src/cadrumo/application/modelo/calculation_diagnostics.py`)). These diagnostics are appended to source-mesh and override diagnostics and recorded in calculation notes. A deliberately narrower subset of absent-source conditions is converted to persisted `CalculationSourceIssue` entries for later lifecycle gates; other messages are calculate-time feedback (durable issue projection (`src/cadrumo/application/modelo/calculation_actions.py`), issue creation (`src/cadrumo/application/modelo/calculation_actions.py`)).

## Knowledge, data, and trust boundaries

The registry revision and a `PinnedAuthorityOperation` provide the declared types, semantic roles, formula channels, and dated mapping facts used at the calculation boundary. For example, the official Modelo 210 income code is retained separately from its formula rate-concept projection so distinct declarations do not collapse into one ledger-selection key (M210 text validation (`src/cadrumo/application/modelo/calculate_input.py`)). Date facts are tied to the work unit’s filing year; M347 threshold and M349 validation explicitly enter governed-fact scopes. Profile facts, prior filing observations, ledger rows, invoices, and register data arrive through injected repositories and source resolvers. This chunk shows the orchestration and provenance projection, not the repositories’ encryption, access control, backup, or retention policies.

`CalculationActionPorts` is an immutable capability bundle containing the required repository and service protocols for one bucket, including work units, calculation revisions, events, transactions, invoices, profiles, IVA and prorrata registers, observations, and source-specific stores (ports (`src/cadrumo/application/modelo/calculation_action_ports.py`)). This explicit injection makes dependencies reviewable and avoids silent global-store construction within these actions. The separate capture module observes both calculation-catalogue and work-unit catalogue revisions around a read; later readers can compare that coordinate, and visible-value functions re-confirm canonical revision coordinates (capture (`src/cadrumo/application/modelo/calculation.py`), capture entrypoint (`src/cadrumo/application/modelo/calculation.py`), visible values (`src/cadrumo/application/modelo/calculation.py`)).

Advisory transport uses strict, frozen Pydantic snapshots with bounded fields. It revalidates source diagnostics through their canonical model and preserves an explicit `unassessed` status for a rate-only recargo preview; a preview must correspond to an overdue posture (diagnostic snapshot (`src/cadrumo/application/modelo/calculation_advisory_projection.py`), preview validation (`src/cadrumo/application/modelo/calculation_advisory_projection.py`), advisory projection (`src/cadrumo/application/modelo/calculation_advisory_projection.py`)). This preserves structured operator-facing information without asserting a liability assessment.

## Security, safety, and quality

Concrete safeguards include strict registry membership and scalar-type validation, refusal of caller substitutions for source-owned values, validation of special row evidence, calculation-revision coordinate checks, and a ledger fingerprint anchor that allows a later verification stage to detect changed tax facts. Explicit clears are rejected if an upstream source immediately refills the same casilla. The action uses typed actor and persistence interfaces but this chunk contains no actor authentication or authorization decision; those protections, if present, must be established elsewhere. It handles tax and identity data but does not implement the storage adapters here, so confidentiality at rest and access boundaries remain unresolved at this scope.

There is a narrow privacy signal in input error handling: malformed IBAN text is omitted from the validation error context, while other malformed typed text can be included as the raw value. That may expose invalid NIF or other user-entered text if an upstream renderer or logger persists exception context; whether it does so is outside this chunk (typed text errors (`src/cadrumo/application/modelo/calculate_input.py`)). Decimal input errors also carry the rejected value. The advisory models impose message size limits but do not themselves redact arbitrary diagnostic messages.

The main quality strengths are explicit ports, pinned registry facts, centralized input channels, source ownership checks, typed persisted observations, and durable lineage/drift evidence. The action is large and coordinates many repositories, though resolver enrollment and source policy are separately named. One conditional operational risk is visible in ordering: the revision is persisted before the advisory collectors and profile-text diagnostic projection run; exceptions in those later reads are not caught here. A caller could therefore receive an error after the draft has already been published. Relation override migration also runs before calculation and may write before a later validation failure, a behavior called out by the action’s own comments. These are failure-mode risks to resolve with surrounding transaction/idempotency behavior, which this chunk does not establish.

No tests are included in this chunk, and no test command was run. Cross-module review should confirm that source resolver ownership and persistence guarantees agree with the domain models, that revision migration is safe on failed calculations, and that CLI or API surfaces preserve advisory and exception privacy semantics.
