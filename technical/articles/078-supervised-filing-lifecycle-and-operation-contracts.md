## Product capabilities and execution

This slice contains the registered-operation layer for the Modelo work lifecycle. Its stated design is to supervise existing calculation, verification, filing, export, amendment, edit, and lifecycle authorities rather than reimplement their policy. It builds a fixed population of eight definitions and pairs each with the stable request/result schemas, access resolver, and, where relevant, workspace-refresh target derived from the settled receipt. Canonical definition population and registrations (`src/cadrumo/application/modelo/operation_definitions.py`), spreadsheet definitions (`src/cadrumo/application/modelo/modelo_spreadsheet_operation.py`)

Calculation has two explicit caller-context modes. The normal workspace recalculation replays the current calculation head's operator layer, including entered values, overrides, clears, detail rows, Modelo 303 evidence, Modelo 210 selections, and borrador snapshot. An explicit calculation uses only the inputs carried by that request; mixing explicit inputs into replay mode is refused. A pre-layer head is treated as unknown rather than as an empty set, preserving uncertainty across recalculation. Preparation binds a bucket-scoped repository and active work unit, then constructs the canonical input bundle; the synchronous calculation runs in a worker thread and its result validator cross-checks the returned work-unit, revision, period, model, and registry coordinates. Sensitive requests use secure-reference custody, and the operation brackets the calculation with effect and cancellation handling. Request semantics (`src/cadrumo/application/modelo/operation_definitions.py`), preparation and head replay (`src/cadrumo/application/modelo/operation_definitions.py`), registered calculation executor (`src/cadrumo/application/modelo/operation_definitions.py`)

Rename and discard requests carry the observed name/update timestamp that the operator approved; execution rereads the work unit and refuses stale approvals before calling the canonical writer. Discard requires an exact approval baseline and captures a reason. Verify resolves the taxpayer profile at execution time rather than freezing it in the request, prepares lifecycle advisories, and delegates to the verification authority. Filing similarly binds approval to both a calculation revision and the verification report that justified it, then calls the local filing authority with the operator's elections. Its result requires handoff to the operator; it does not submit to AEAT. Stale rename check (`src/cadrumo/application/modelo/operation_definitions.py`), discard approval baseline (`src/cadrumo/application/modelo/operation_definitions.py`), stale discard check (`src/cadrumo/application/modelo/operation_definitions.py`), live verification profile and executor (`src/cadrumo/application/modelo/operation_definitions.py`), exact filing approval (`src/cadrumo/application/modelo/operation_definitions.py`), local handoff result (`src/cadrumo/application/modelo/operation_definitions.py`)

Export accepts an absolute output path and an explicit choice of Fichero BOE or calculation report. The request journals the destination, never the output bytes; the settled secure receipt is projected only after it matches the terminal operation receipt. Fichero BOE and report results expose the service's file path, size, digest, and relevant evidence/completeness status. CSV and PDF report formats are supported here; PDF generation depends on the injected writer, and report signing is delegated through a supplied key-pair capability. The module characterizes the export as local, requiring a person to carry the artifact to the authority. export request (`src/cadrumo/application/modelo/operation_definitions.py`), terminal-receipt projection (`src/cadrumo/application/modelo/operation_definitions.py`), local export executor and report delegation (`src/cadrumo/application/modelo/operation_definitions.py`), terminal-receipt checks (`src/cadrumo/application/modelo/operation_definitions.py`)

Amendment starts from a specific existing filing record, requires at least one distinct casilla override and a stated reason, and can include up to 20,000 detail rows. The operation delegates legal baseline and amendment-kind checks to the amendment authority, then returns the local amendment record and the source filing identity; submission remains an operator handoff. Edit apply translates payload-safe wire mirrors back into domain intents and delegates a guarded compare-and-swap. It reports only the resulting receipt ID publicly; a no-effect refusal sets the operation effect to NONE and exposes only the registered refusal family. Manual detail-row identity components are carried separately because the domain's joined natural key cannot always be split without guessing. A domain submission containing detail-row intents therefore cannot be converted back by the generic from-submission helper; callers must construct those wire addresses while the original components are available. Amendment request constraints (`src/cadrumo/application/modelo/operation_definitions.py`), amendment delegation (`src/cadrumo/application/modelo/operation_definitions.py`), wire submission and detail-row limitation (`src/cadrumo/application/modelo/operation_definitions.py`), guarded edit operation (`src/cadrumo/application/modelo/operation_definitions.py`)

The operation definitions use strict request/result models, per-operation durability, replay, cancellation, conflict, and effect policies, and CLI/TUI admission where appropriate. The shared operator-input types carry revision selectors, filing elections, destination paths, and review notes. The spreadsheet contracts in this chunk define four CLI operations—export, pull, calculate, and verify—with closed refusal/result variants. Pull projections can disclose taxpayer and counterparty IDs/names, financial values, relation provenance, and assembled withholding or information-return rows, so they are explicitly private projections. Rows and observation text are bounded; pull result validators require counts to agree with all returned rows, and terminal projection validates result coordinates and effect against its receipt. Spreadsheet request/outcome contracts (`src/cadrumo/application/modelo/modelo_spreadsheet_operation_contracts.py`), bounded private projections (`src/cadrumo/application/modelo/modelo_spreadsheet_operation_projections.py`), closed withholding observation (`src/cadrumo/application/modelo/modelo_spreadsheet_observations.py`), receipt-bound public projection (`src/cadrumo/application/modelo/modelo_spreadsheet_registration.py`)

The scenario decoder maps JSON inputs, bindings, relations, and expected values to the existing parity-harness scenario model after the executor has established source identity. Spreadsheet observation projection accepts only exact known canonical row types and copies their validated JSON shape into closed wire models; it does not add a second business-policy layer. ## Knowledge, safety, and implementation assessment

Preconditions are represented as locale-neutral identities: subject leaf, declared condition, scenario, evidence, provenance, action/recovery, and no-recovery outcome. The registry distinguishes operator-recoverable cases from terminal ones, checks that failure identities are declared, requires action arguments to match the action catalogue exactly, and rejects duplicate profiles at module construction. Its entries cover lifecycle state, authority-grade failures, cross-period dependencies, ledger readiness, Modelo 303 evidence, withholding, IVA-wallet decisions, and other filing-specific gates. This makes refusals typed and catalogue-backed rather than freeform explanations invented by each executor. Profile catalogue and uniqueness (`src/cadrumo/application/modelo/preconditions.py`), scenario-to-verdict construction (`src/cadrumo/application/modelo/preconditions.py`), closed profile-derived failure builder (`src/cadrumo/application/modelo/preconditions.py`)

A useful derived-data capability rebuilds the transaction participation index from finalized calculation revisions. It joins each sealed revision to its work-unit coordinate and, for filed states, to its filing record and imported justificante reference. Draft/discarded revisions are excluded; replacing the full index also prunes entries no longer represented in authoritative catalogues. The repository receives version digests for calculation, work-unit, and filing sources, so the adapter can reject a rebuild if its source snapshot changed. Rebuild algorithm (`src/cadrumo/application/modelo/participation_index_rebuild.py`), source-revision and replacement contract (`src/cadrumo/application/modelo/participation_index_rebuild_ports.py`)

One concrete progress-reporting gap is explicit in the operation module. Verify, file, export, and amend each declare an inner phase that the executor cannot observe because the canonical authority runs both phases inside a single call; each executor emits only its entry phase, while the definition still advertises both. The source comments call the second phase unbacked. This does not show a tax or persistence error, but clients can be given a phase vocabulary that never occurs. The authority would need to emit the inner transition or the declaration should omit it. Documented phase gap (`src/cadrumo/application/modelo/operation_definitions.py`), verify's declared phases (`src/cadrumo/application/modelo/operation_definitions.py`), file (`src/cadrumo/application/modelo/operation_definitions.py`), export (`src/cadrumo/application/modelo/operation_definitions.py`), amend (`src/cadrumo/application/modelo/operation_definitions.py`)

A second integration seam is the manual-override financial operand: this module declares a bounded EUR operand but says no executor can call its broker because OperationExecutorContext has no accessor. The request model therefore duplicates the declared money bounds for admitted edit intents. The inline validator makes that specific bound effective on this route, but it is a contract duplication to reconcile when the broker becomes reachable. Operand declaration (`src/cadrumo/application/modelo/operation_definitions.py`), request-bound substitute (`src/cadrumo/application/modelo/operation_definitions.py`)

No test files are in this chunk. Comments describe specific past regression modes and intended guarantees, but they are not evidence that current races or operation receipts have been tested. Cross-layer verification should follow the delegated writers, attachment and filing stores, receipt projector, and operation platform; this report cannot certify those behaviors or current legal correctness.
