## Capabilities and mechanisms

Portable profile custody uses a sealed archive wrapper around the profile’s already-encrypted database and custody material. It does not add a second encryption layer. The archive validates its manifest and payload digest before parsing members, binds the payload to the expected profile identity, and caps payload size. Its unencrypted header exposes a narrow set of metadata (profile UUID, schema, time, digest); it omits the human-readable label. A fixed-width recovery slot is always empty, so archive transport does not silently carry an enrolled recovery secret. Archive format and writer (`src/cadrumo/application/user_profile/capsule_archive.py`)

The profile record is stored as one authenticated secure-object row alongside a durable bucket-event witness. `ProfileRecordSession` binds record decoding and writes to an envelope digest, password generation, DEK epoch, and profile; it owns mutable key material and closes by clearing it. Reads check the exact row count and key, strict payload schema, write provenance, and linked event lineage. Replacement uses compare-and-swap over both row and event-history revisions and commits the row and event in one secure-object batch. A legacy schema migration authenticates the old row before replacing it and records which facts were cleared; passphrase rewrapping advances lineage while preserving record content. Record session and repository (`src/cadrumo/application/user_profile/capsule_record.py`), migration and reheading (`src/cadrumo/application/user_profile/capsule_record.py`)

Restore accepts an unpublished capsule directory or already parsed archive material, proves the capsule’s own password against its sentinel, validates the staged database, and then delegates publication to the shared capsule lifecycle. The result explicitly reports that recovery was not enrolled. The password-only path does not consult an ambient master key, provider, environment value, or recovery secret; the record session closes in a `finally` path. Source parsing and restore outcome (`src/cadrumo/application/user_profile/capsule_restore.py`), password proof and lifecycle handoff (`src/cadrumo/application/user_profile/capsule_restore.py`)

Custody carry normalizes a closed set of operator selections and asks the bound custody port for carried objects, exclusions, namespace counts, and unknown namespaces. Selecting full coverage fails closed if any namespace is unclassified; a successful result includes an explicit coverage manifest. The export-operation journal is separate from the artifact and bucket, contains identity/digest facts rather than the bundle, passphrase, or tax ID, and uses prepared/completed states for recovery. This gives export coordination a recoverable local operation record without making it a substitute for the archive payload. Coverage policy (`src/cadrumo/application/user_profile/custody_carry.py`), export journal contract (`src/cadrumo/application/user_profile/bundle_export_operation.py`)

The censal feature family separates three outcomes. A credential-free prepare operation reads the exact active profile and produces a bounded projection of every adoptable field as unset, cleared, or set, together with default review choices. A provider-backed preview obtains one live AEAT observation, reconciles it against the requested profile revision, and returns adopted, unchanged, and divergent values with `applied: false`; it does not mutate the profile. The separate resumable review operation persists its full observation and complete canonical field-intent set as a secure operand, projects only reviewed values to the frontend, and resumes from the durable checkpoint. Before applying, it rechecks profile ID, record revision, and digest. A rejection settles a typed result; an approval applies through the one cotejo authority. Prepare projection (`src/cadrumo/application/user_profile/censal_prepare_operation.py`), non-mutating preview (`src/cadrumo/application/user_profile/censal_preview_operation.py`), reviewed operand and executor (`src/cadrumo/application/user_profile/censal_operation.py`), checkpoint application (`src/cadrumo/application/user_profile/censal_operation.py`)

The live review routes through the canonical browser/session and censal-fetch ports, records possible session writes, owns browser or acquisition cleanup, and publishes one durable review instead of keeping a process-local handle for resume. Its access contract binds work to one exact profile and period-independent request; result and review disclosures require their registered schemas. Prepare requires no provider; live preview/review declares provider readiness at start. The shared access helper rejects terminal actions whose admitted submit belongs to a different profile or operation. Shared admitted-request check (`src/cadrumo/application/user_profile/censal_access.py`), preview access and provider policy (`src/cadrumo/application/user_profile/censal_preview_operation.py`)

The certificate-file import is a separate CLI-only secure-input mutation. Its request restricts paths to fiscal address and indexed activity description/IAE fields, requires one fiscal address, unique paths, canonical ordering, nonblank values, and complete contiguous activity rows. It binds the profile to the active bucket and passes all facts through `apply_cotejo`, returning only a receipt of applied paths. The request validates the provenance enum and shape, but the shown operation does not itself parse or cryptographically authenticate the certificate; that assurance belongs to the upstream adapter that constructs the secure input. Import request validation (`src/cadrumo/application/user_profile/censal_file_import_operation.py`), profile check and single apply path (`src/cadrumo/application/user_profile/censal_file_import_operation.py`)

## Knowledge, security, and assessment

The censal observation model retains bounded identity and decomposed address fields, capture time, source URL, and a literal read mode. The synchronizer derives only three adoptable paths: composed fiscal address, postcode, and cadastral reference. It uses the read’s tax ID solely to establish ownership and refuses if either identity is missing, malformed, or differs after canonical Spanish-tax-ID validation. It does not infer name splits from AEAT’s combined name field. Existing operator values are protected; previously imported official values can refresh; operator-cleared values remain cleared. Comparisons are whitespace-trimmed but otherwise exact, avoiding unsupported equivalence assumptions. Observation shape (`src/cadrumo/application/user_profile/censal_observation.py`), identity ownership gate (`src/cadrumo/application/user_profile/censo_sync.py`), projection and reconciliation (`src/cadrumo/application/user_profile/censo_sync.py`)

The provenance distinction is material: live read facts carry the AEAT-read token, while certificate artefacts use a non-official token. Cotejo stores deferred disagreements in indexed divergence facts, clears stale divergence rows when replacing the set, and emits one `CENSO_APPLIED` event for the transaction. Profile reads can surface an open-divergence warning. Adopted facts still pass the profile schema and setup-completeness validation; AEAT authority over taxpayer data is not treated as authority over the application’s schema. Cotejo transaction and validation (`src/cadrumo/application/user_profile/cotejo_apply.py`), divergence projection and notice (`src/cadrumo/application/user_profile/cotejo_apply.py`)

The same synchronizer also exposes the operator-declared home-office ratio used by ledger consumers. It returns no value for missing, non-decimal, zero, negative, or out-of-range square-metre values, and binds profile decoding to the caller’s pinned authority operation. Separately, completeness rules calculate conditional filing prerequisites from validated taxpayer facts and published registries: examples include Cl@ve mobile route, Modelo IVA fields, legal-entity form/name, IRNR residence-country and representative fields, and socio-country values that are both required and prohibited according to the declared clave. Shared whitespace presence and repeatable-row logic keep validation and display surfaces aligned. `ProfilePreflightReport` records whether per-operation requirements were assessed, preventing a partial assessment from reading as a full pass. Ratio validation (`src/cadrumo/application/user_profile/censo_sync.py`), conditional profile requirements (`src/cadrumo/application/user_profile/completeness.py`), repeatable rows (`src/cadrumo/application/user_profile/completeness.py`), preflight assessment contract (`src/cadrumo/application/user_profile/commands.py`)

The principal strengths are the explicit separation between live preview, reviewed mutation, and artefact import; secure-reference persistence for resumable review; revision-bound approvals; independent ownership checks; and atomic event-linked profile updates. Important trust boundaries remain outside this chunk: the concrete secure-object/custody adapters, archive filesystem handling, actual AEAT parser/session implementations, and frontend enforcement of registered disclosure projections. The file-import contract makes the parser boundary especially important because the application operation accepts well-shaped caller facts with artefact provenance. Static inspection cannot verify those adapters, cryptographic implementation, crash behavior, browser-process containment, or live AEAT semantics. The `capabilities.py` policy and export journal define additional gates and recovery metadata, but their end-to-end enforcement must be traced through the operation owner and concrete persistence adapters. Capability policy (`src/cadrumo/application/user_profile/capabilities.py`), journal recovery states (`src/cadrumo/application/user_profile/bundle_export_operation.py`)

## Dependencies and follow-up

Trace archive restore and export through `ProfileCapsuleLifecycle`, the custody ports, secure-object repository, filesystem publisher, and event-history adapter. Verify archive tamper rejection and publication recovery under interruption. For censal work, follow the AEAT browser/session adapter, profile-record repository, operation checkpoint/operand store, disclosure projection layer, and workflow persistence around `apply_cotejo`. Test stale-baseline races, cancellation around remote session writes, cleanup on browser failure, invalid or hostile certificate inputs, unknown custody namespaces, and recovery after interrupted archive publication. Confirm that only the certificate parser can mint the secure file-import request and provenance claim. No test execution was performed here.
