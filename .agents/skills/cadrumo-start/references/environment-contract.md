# Process environment contract

`native/application-environment.toml` is the package's only declaration of the process environment of every packaged image. It declares each name with a `kind` and a `role` (`location`, `operator`, `package`, `pin`, `fixed`, `slot`, `pass`) under `[names]`. It also declares the admission groups, the per-OS base names, pins, cleared host classes, the native host's reserved exit statuses, the storage-root rule, `PATH` composition, the launch profiles of each image and exact invocation tables. `dev/packaging/native/application_environment.py` validates it, and the `native_contract` target compiles it into `contract.json`, `contract.rs` and `contract.h`, which the Rust crates and the C hosts read. A name the file does not declare for a profile never reaches that profile's process ([header](../../../../native/application-environment.toml#L1), [names](../../../../native/application-environment.toml#L25), [generator](../../../../dev/packaging/native/application_environment.py), [contract inputs](../../../../native/cmake/Contract.cmake#L12), [outputs](../../../../native/cmake/Contract.cmake#L51)).

| Profile | Image | Takes from the caller |
|---|---|---|
| `python`, `aeat`, `cadrumo-mcp` | same | base groups `system`, `session`, `terminal`, `display`, `network`; the operator groups `presentation`, `remote`, `package`; pins; the package `PATH`; the optional `CADRUMO_PROFILE_ROOT` slot. Only `python` also passes `CADRUMO_PROXY_URL`, `CADRUMO_PROXY_USERNAME`, `CADRUMO_PROXY_BYPASS`, `CADRUMO_EVIDENCE_CLOUD_UPLOAD_PERMITTED` and `CADRUMO_EVIDENCE_GESTOR_MODE` |
| `cadrumo-runtime` | same | base groups without `terminal`; pins; no operator group; the pass names `CADRUMO_CLI_REVEAL_IDENTIFIERS`, the three proxy names and the two evidence-posture names; no agent/relay image paths |
| `cadrumo-agent-service` | same | `system`, `session`, `display` and `network` base; the `presentation` and `package` operator groups; pins; the two evidence-posture pass names; fixed agent/relay/AEAT/Python paths; the optional local-AI demand slots |
| `agent-gateway`, `agent-worker` | `cadrumo-agent` | `system` base only; temporary and authority pins; the pass name `CADRUMO_EXTERNAL_BIN_DIRS`; every admitted name under the agent prefix; the optional storage-root, profile-root, hosted-root and port slots |
| `agent-providers` | `cadrumo-agent` | `system` base only, no pins; the exact `providers --declared --json` invocation |
| `agent-auth` | `cadrumo-agent` | `system`, `session`, `terminal`, `display` and `network` base; the pass name `CADRUMO_EXTERNAL_BIN_DIRS`; a temporary pin; a required hosted-root slot and an optional browser slot; the `auth` invocations |
| `kdf-child` | `python` | the caller's whole environment (`base = "inherit"`), selected only by its exact invocation |

Each packaged image defines its environment before Python starts. The C host calls `cadrumo_platform_define`, which selects a profile and then defines the environment and applies it once. Selection matches a declared invocation, falls back to the image's default profile, and refuses an image with no default. A refused launch writes one refusal line (`launch_value_missing`, `launch_value_malformed` or `invocation_undeclared`) and exits with a reserved status in 120-125, 125 for a refused invocation. `define_environment` composes base groups, operator groups, pins, fixed values, validated slots and `PATH`, with each later name replacing an earlier one. Nothing ambient passes through except under `kdf-child`'s declared inheritance. The agent image declares the gateway's `serve`, `stores-state`, `setup`, `migrate`, `preflight` and `version --json`, the worker's `-m cadrumo_agent.worker` and `_tool_bridge_stdio <scope>`, the exact `providers --declared --json` invocation on its minimal profile, and the `auth status`, `auth login`, `auth logout`, `auth providers` and `auth connect` invocations on the `agent-auth` profile. The `TEMP`, `TMP` and `TMPDIR` pins resolve to the `tmp` member beneath the pinned storage root; no variable relocates it, and an ambient `CADRUMO_TEMP_DIR` is dropped. `CADRUMO_AUTHORITY_ROOT` is a fixed pin. `prepared_environment` computes the same result for a caller such as the desktop shell without starting Python or changing its own environment. A strict child filter clears the `PYTHON`, `LD_`, `DYLD_`, `AEAT_`, `FINANCIAL_` and `SITE_HEALTH_` prefixes, the virtual-environment names, and every `CADRUMO_` name except a host-inherited pin ([define](../../../../native/platform/src/lib.rs#L328), [select](../../../../native/platform/src/launch.rs#L232), [compose](../../../../native/platform/src/launch.rs#L409), [refusal status](../../../../native/application-environment.toml#L274), [profiles](../../../../native/application-environment.toml#L410), [invocations](../../../../native/application-environment.toml#L565), [prepared](../../../../native/platform/src/lib.rs#L198), [cleared](../../../../native/platform/src/storage.rs#L464)).

The storage root follows one rule with one variable, `CADRUMO_STORAGE_ROOT`. The variable names an absolute directory or is unset (a blank value is unset); a leading `~` expands against the current user's home, and a relative value is refused. No rule knows the tree the product was built from: there is no checkout marker, no `var/storage` default in the product and no second variable. `CADRUMO_LOCAL_STORAGE_ROOT`, `CADRUMO_LOG_DIR` and the other retired storage names are refused in a Release package by its image scan. Without an override the root is the per-user default: the local application data folder on Windows (the native host asks the shell for it, Python reads `LOCALAPPDATA`), `XDG_DATA_HOME` or `~/.local/share` on Linux (mode 0700), and `~/Library/Application Support` on macOS, in a `cadrumo` folder for the stable channel and `cadrumo-<channel>` otherwise. A packaged host resolves and pins the root for its own channel before Python starts; Python reads that pin and resolves only the stable channel itself. The root is the one control over where the product stores anything: every member sits at a fixed subpath beneath it, including the desktop's browser data (`webview`), which both the startup window and the workspace window use, so a redirected root leaves nothing in the identifier's default folder under local application data. Only a launch whose root is refused has no such directory, and its startup page reports the refusal. In development the justfile supplies `<repo>/var/storage` through the same variable. Python settings use the `CADRUMO_` prefix and ignore empty values. `CADRUMO_ACTIVE_PROFILE` can never come from the environment, because profile selection is the on-disk pointer ([root rule](../../../../native/application-environment.toml#L324), [members](../../../../native/application-environment.toml#L288), [Python declaration](../../../../src/cadrumo/core/storage_environment.py#L137), [Python resolver](../../../../src/cadrumo/core/storage_environment.py#L345), [native resolver](../../../../native/platform/src/storage.rs#L438), [startup browser directory](../../../../native/desktop/src-tauri/src/shell/webview_environment.rs#L207), [retired names](../../../../dev/packaging/native/retired_storage_variables.toml), [image scan](../../../../dev/packaging/native/release_image_scan.py#L29), [prefix](../../../../src/cadrumo/core/product_identity.py#L50), [selection](../../../../src/cadrumo/core/config.py#L81)).

The agent's names belong to its hosting contract. Only agent gateway/worker profiles admit the declared agent prefix; never-admitted environment-file/legacy hosted-program names remain refused. The separate service supplies hosted root, ephemeral ports and forwarded storage root as slots, then advertises its packaged programs/tool server/arguments/skills/rules under the agent's own prefix. The obsolete hosted-relay slot is absent. Agent worker wiring follows agent-owned prefix admission; provider credentials use a protected stdin/pipe frame, never the environment. The worker launch vector also expects the gateway-supplied names `CADRUMO_AGENT_INTERNAL_TOKEN` and `CADRUMO_AGENT_GATEWAY_LIFETIME_ID` in the worker environment; the gateway code is outside this repository, so check how it delivers them before relying on "tokens never in the environment". Generic Python/runtime images contain no agent location/composer; service's fixed profile owns those paths. [Profiles and prefix policy](../../../../native/application-environment.toml), [service composer](../../../../src/cadrumo_agent_service/host/launch_environment.py).

Two CTests check the declaration against the assembled package. `bundle.environment-conformance` asks the package's own interpreter what the command line, runtime and bundled agent declare, and fails on any disagreement. It changes nothing. `bundle.environment-launch` uses the service-owned composer to start the declared agent image. It checks the refusal of an undeclared invocation, the store invocations, the gateway's hosting answer and the worker's port, and confirms that the generic interpreter clears agent-only names. The hand-written `[[launch_vectors]]` pin expected environments and refusals ([conformance](../../../../dev/packaging/native/environment_conformance.py#L421), [CTests](../../../../native/cmake/Packaging.cmake#L315), [probe](../../../../native/tests/environment_launch_probe.py#L1), [vectors](../../../../native/application-environment.toml#L813)).

The build reads its own variables outside this contract. CMake cache options include:
- `CADRUMO_PACKAGE_AGENT_SOURCE_DIR`, the local agent project, which never comes from the environment.
- `CADRUMO_RUST_ROOT`, `CADRUMO_INCLUDE_DEVELOPMENT_BINARY` (default `OFF`) and `CADRUMO_CONFIGURE_PAYLOAD` (default `ON`).
- For the desktop project, `CADRUMO_NATIVE_CONTRACT` and `CADRUMO_DESKTOP_PACKAGE_ROOT` (a cache option defaulting to the staged application tree). CMake itself sets `CADRUMO_CMAKE_BINARY_DIR` for the desktop npm commands.
- `CADRUMO_BUILD_NUMBER`, `_ID` and `_DATE`, `CADRUMO_MSVC_VERSION`, `CADRUMO_WINDOWS_SDK_VERSION`, `CADRUMO_CARGO_DENY`, `CADRUMO_PACKAGE_USER_DOCS` and `CADRUMO_DOCS_SHARED_CACHE`; `native/CONTRACT.md` lists the rest (toolchain, signing and installer variables).

Development-only names include `CADRUMO_DEV_CACHE_ROOT`, `CADRUMO_TEST_LOG_ROOT`, `CADRUMO_DEV_ARTIFACTS_DIR`, `CADRUMO_DEV_AGENT_CHECKOUT`, `CADRUMO_PYTEST_WORKERS`, `CADRUMO_GATE_BUDGET`, `CADRUMO_CI_REPORTS_DIR` and the documentation gate names `CADRUMO_DOCS_SEQUENCE_JOBS`, `CADRUMO_DOCS_STRICT_BUILD_RECORD`, `CADRUMO_DOCS_SKIP_SEQUENCE_CHECK` and `CADRUMO_DOCS_FORCE_SEQUENCE_CHECK` (see [testing lanes and the local gate](dev-testing-lanes-and-gate.md)). The justfile exports `CADRUMO_STORAGE_ROOT` (default `<repo>/var/storage`; an operator-supplied value wins), `CADRUMO_DOCS_BUILD_ROOT` (default `<repo>/build/docs`) and `CADRUMO_AUTHORITY_ROOT` (default `<repo>/.authority`) to every recipe. Of these, only `CADRUMO_STORAGE_ROOT` is a declared packaged name.

Product code also reads names that are not declared packaged names, so packaged children never receive them: `CADRUMO_DATABASE_URL`, `CADRUMO_SECRET_PASSPHRASE`, `CADRUMO_WALLET_DIAGNOSTIC_DUMP_DIR`, `CADRUMO_LIVE_TESTS_ENABLED` and `_GOOGLE`, `CADRUMO_CERTIFICATE_PASSWORD_SECRET`, `CADRUMO_MCP_REQUIRED_VERSION`, the AEAT `CADRUMO_CLAVE_*` credentials and the `CADRUMO_*_CACHE_DIR` development overrides ([agent folder](../../../../native/cmake/Agent.cmake#L4), [Rust root](../../../../native/cmake/RustToolchain.cmake#L4), [options](../../../../CMakeLists.txt#L140), [desktop](../../../../native/desktop/CMakeLists.txt#L48), [binary dir](../../../../native/desktop/frontend/README.md#L55), [dev cache](../../../../dev/cache_root.py#L37), [test logs](../../../../dev/test_runs/paths.py#L49)).

## Working notes

- To add a packaged variable, declare it in `[names]` with its kind and role, then admit it through a group, pin, fixed value, slot or pass on each profile that needs it. Rebuild `native_contract`, and update any hand-kept Python copy, such as the agent composer's base-name lists. Then run the conformance and launch CTests. Do not read a new environment name ad hoc in product code ([groups](../../../../native/application-environment.toml#L140), [Python copy](../../../../src/cadrumo_agent_service/host/launch_environment.py#L81)).
- `contract.*` files are generated. Change the TOML or the generator, never the output.
- A new agent invocation needs its own `[[invocations]]` entry; anything undeclared is refused before Python starts.
- The `launch_vectors` are authored by hand. Change them together with the profile they test.
- Covering tests: [conformance](../../../../dev/packaging/native/tests/test_environment_conformance.py), [agent composer](../../../../src/cadrumo_agent_service/host/tests/test_launch_environment.py), [env reference](../../../../dev/docs/tests/test_env_reference.py), the coordinated import-linter boundaries.
