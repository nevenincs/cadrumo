# Tauri desktop shell

The desktop shell is the `cadrumo` host binary (crate `cadrumo-desktop`) in `native/desktop/src-tauri`, with a React frontend in `native/desktop/frontend`. Launch selection has three modes. `--check-health [--hold-seconds N]` asks the manager to make the runtime ready and reports health without a window. `--headless`, any other arguments, or a missing desktop forward to the installed Python CLI. No arguments on an interactive desktop open one window, and `--gui` forces the window, failing with the desktop-unavailable exit code when there is no desktop. The shell presents, launches and relays. It holds no runtime connection, session, profile credential or authority; the one secret it holds is the agent host's in-memory gateway bearer described below. Sign-in is a short-lived child of the packaged CLI, and the per-user manager alone starts the runtime. Windows (WebView2) has every feature. On Linux the window, docs, logs, terminal and instance lock exist, but sign-in, context menus and manager dispatch return `unsupported`. macOS is refused when the window starts. [entry](../../../../native/desktop/src-tauri/src/main.rs#L31), [modes](../../../../native/desktop/src-tauri/src/launch.rs#L28), [health](../../../../native/desktop/src-tauri/src/main.rs#L92), [macOS](../../../../native/desktop/src-tauri/src/app.rs#L105), [contract](../../../../native/CONTRACT.md#L1037).

The desktop is a standalone CMake project: `cmake -S native/desktop --preset desktop-windows-x64` configures into `build/<preset>`, and the source build adds it only when a desktop image is staged. It needs `CADRUMO_NATIVE_CONTRACT` and `CADRUMO_DESKTOP_PACKAGE_ROOT`. Targets are `desktop-frontend-*` (install, build, check, test), `desktop-host-*` (prepare, build, test, clippy), `desktop-run` and test targets. Under `scripts/`, `frontend-install.mjs` runs `npm ci` only when the tree differs from the lockfile, `content-build.mjs` fingerprints inputs, `backend-snapshot.mjs` copies the crate and path crates into the build tree, and `tauri.mjs` writes `tauri.conf.json` there and runs the pinned Tauri CLI (`build --no-bundle -- --locked`), refusing a Cargo binary that differs from the image CMake declares. `tauri.conf.json.in` is read as plain JSON by `tauri.mjs`, not configured by CMake; `configuration.mjs` adds identity, a relative `frontendDist`, icons and a `frame-src` set to the docs origin, and refuses a template that does not frame exactly that origin. The crate uses Tauri 2, `portable-pty` and a clipboard plugin through its Rust API only; `build.rs` copies the generated contract into `OUT_DIR`. `just dev` publishes the registry authority if stale, then serves the frontend in a browser and compiles no Rust. [CMake](../../../../native/desktop/CMakeLists.txt#L69), [presets](../../../../native/desktop/CMakePresets.json#L10), [tauri.mjs](../../../../native/desktop/scripts/tauri.mjs#L149), [configuration](../../../../native/desktop/scripts/configuration.mjs#L113), [crate](../../../../native/desktop/src-tauri/Cargo.toml#L1), [dev](../../../../justfile#L93).

The host uses request/response commands plus Tauri `Channel` streams and emits no events. Each module declares commands with `commands!`; `app.rs` composes them behind a per-launch token, handed once by an init script to the top frame on a shell origin and presented as a `token` argument or `x-cadrumo-token` header. Modules are `shell`, `docs`, `logs`, `terminal`, `manager`, `agent`, `environment` and `startup_logging`. The shell module serves the environment, `https:`/`mailto:` links, a bounded clipboard, a Windows-only context menu, window controls and the single-instance lock, and holds the `sign_in`, `provider_settings` and `agent_access` submodules. Sign-in commands run the packaged `aeat` CLI after a digest check, with the password on stdin. `provider_settings` reports masked key status and sets, removes or resets a key through the same CLI, writing the key once to the child's stdin under `--secrets-stdin`; `agent_access` lists, issues and revokes the keys the signed-in profile gives to agents outside Cadrumo. The `docs` module serves a read-only `cadrumo-docs` scheme from a manifest allow-list with containment checks, a per-response CSP and the shell origins as frame ancestors, and declares no app commands. The `logs` module tails the Python log, manager JSONL and host diagnostics on a 100 ms tick into a ring feeding a bounded set of channels. The `terminal` module opens one PTY per kind (console, Python, TUI) with tagged binary frames and credit backpressure. The `manager` module requests manager launch through the existing Explorer desktop via a Python shim and owns or stops no manager or runtime process. Installing a manager is explicit: the sign-in view asks for `manager_install` with User or Machine scope, and the manager stays the sole runtime supervisor. The `agent` module hosts the agent column. It runs `aeat app agent serve` through the digest-verified packaged CLI as one long-lived child inside a kill-on-close Job Object, the only Job Object the desktop crate uses. It mints a 64-hex-character gateway bearer in memory, writes it once to the child's stdin as `{"bearer": ...}` and keeps stdin open; closing stdin is the stop request. The child answers with JSON event lines of at most 4096 bytes: `agent_ready` (gateway port, agent version, lane, workspace root), `agent_refused` (code) or `agent_stopped` (reason), and anything else is a violation. Calls then go to the loopback gateway at `127.0.0.1:<port>/v1` with the bearer. The commands are `agent_status`, `agent_status_subscribe`/`unsubscribe`, `agent_provider_catalog`, `agent_conversation_start`, `agent_send`, `agent_cancel`, `agent_pending`, `agent_questions_answer`, `agent_approval_decide`, `agent_observe`/`unobserve`, `agent_conversations`, `agent_history` and `agent_documents` (which always refuses); status updates and run streams travel on two `Channel`s. Which providers the agent serves is read from the agent, not decided here. The launcher side, frames and refusals are covered in [agent integration](agent-integration.md). Build-script tests are `node --test` files run by `desktop-paths-test`, `desktop-configuration-test` and `desktop-build-test`. Rust tests run through `desktop-host-test` (feature `live-package-tests`, needs a built package) or `tests/run-backend.ps1`. `desktop-headless-test` compares CLI passthrough with the interpreter. `desktop-packaged-test` runs `node --test tests/packaged.test.mjs`, which drives `tests/run-packaged.ps1`; that harness needs an assembled package with documentation and an interactive, non-Session-0 desktop, builds a separate host with `webview2-remote-debugging`, drives WebView2 over DevTools, and sends real keys and clicks while the window is foreground. Browser-level frontend tests run against a simulated host, so they show nothing about the token, scheme, WebView2, PTYs or window lifecycle. Observations to check against current code. The macOS preset exists while the window refuses macOS. The terminal sources hold no Job Object or process-group code and kill the direct child, while the manual checklist expects window close to end every terminal child. The contract's command tables omit `manager_*` and the `agent_*` commands, and its desktop section does not describe manager installation. `agent_documents` is typed in the frontend contract to return records while the host always refuses. The agent host accepts only a ready line whose lane is `development`, and no build-profile gate was found around the agent host. A killed install can leave `.cadrumo-npm.lock`. ## Working notes

- New command: add it to its module's `commands!` list (names must be distinct across modules, checked at startup), then mirror it in the frontend `HostCommands` map and `tauriHost.ts`; agent commands hang off `tauriAgent`. [composition](../../../../native/desktop/src-tauri/src/app.rs#L24), [contract](../../../../native/desktop/frontend/src/ipc/contract.ts#L702).
- The token is read once and never posted to the docs frame, a URL, storage or a log. [contract](../../../../native/desktop/frontend/src/ipc/contract.ts#L32).
- The gateway bearer and provider keys never reach the webview, a command line, a file or a log; keys travel only on a child's stdin. [provider settings](../../../../native/desktop/src-tauri/src/shell/provider_settings/mod.rs#L1).
- Ports come from `development-server.json`; an occupied port is an error. [README](../../../../native/desktop/frontend/README.md#L11).
- The shell policy must frame exactly the docs origin; the build refuses otherwise. [contract](../../../../native/CONTRACT.md#L1109), [CSP](../../../../native/CONTRACT.md#L1176).
- `CADRUMO_DESKTOP_DOCS_ROOT` applies only in development builds. [docs](../../../../native/desktop/src-tauri/src/docs/mod.rs#L30).
- Packaged builds refuse `WEBVIEW2_*` overrides; `webview2-remote-debugging` admits only one remote-debugging argument and is never for distributed builds. [overrides](../../../../native/desktop/src-tauri/src/shell/webview_environment.rs#L1).
- Session 0 has no window station; check the window from an interactive logon. [contract](../../../../native/CONTRACT.md#L1558).
