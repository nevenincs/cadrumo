# Generated artefacts: what goes stale and how to regenerate it

Cadrumo keeps many derived files beside their sources: some committed, some produced on demand. A change that leaves one stale fails a check, sometimes far from the edit and sometimes only in the full gate. This reference lists each one with its trigger, its regenerate command and the check that catches it. Generated files are never edited by hand: change the source or the generator and regenerate.

## Start from your change

| You changed | Regenerate | Then verify |
|---|---|---|
| Added, moved, renamed or removed a non-test Python module | `just generate-import-load-targets` | `just check-import-boundaries` |
| A registered operation, or its request or result schema | `just generate-operation-contract-manifest` | `just check-operation-contract-manifest` |
| A command, or what a command submits | `python -m dev.operation_contract_manifest.command_operation_derivation --connection-requests` | tests under `dev/operation_contract_manifest/tests/` |
| A Python model the desktop frontend mirrors | the matching `node scripts/<name>-contract.mjs` in `native/desktop/frontend` | `just check-frontend` |
| Registry TOML or source evidence | `just registry-publish-authority-if-authority-stale` | `just check-registry-gate` |
| Registry compiler or publication code | `just registry-publish-authority` | `just check-registry-gate` |
| Export mappings or render profiles for a registry target | `just registry-publish-target MODELO REVISION SOURCE_REF FILING_YEAR PERIOD` | `just check-registry-target-current ...`, `just check-registry` |
| Personas, a fixture producer, or anything a producer reads | `just fixtures-seed` | `just fixtures-status`, `just fixtures-check` |
| A translation key used in code | `just locales-scaffold`, then `just locales-set-batch MANIFEST` | `just check-locales` |
| CLI output shown in the documentation | `just docs-generate-sequences` | `just docs-sequences-check` |
| Documentation source text | `just docs-generate-catalogs` | `just docs-check` |
| A corpus PDF, HTML or workbook source | `just generate-corpus-text`, `just generate-corpus-sidecars` | `just check-corpus-text`, `just check-corpus-sidecars` |
| `native/application-environment.toml`, package layout, platform files | build the `native_contract` target (any native build does) | the conformance and launch CTests |
| A pinned archive (browser, local model program, llama.cpp) | `just pin-browser-archives`, `just pin-local-ai-program`, `just pin-llamacpp-program` | the same recipe with `--check` |
| A dependency in `pyproject.toml` | `uv lock`, then `just setup` | `just check-dependency-declarations`, `just test-packaging-dependencies` |
| Removed the last occurrence a ratchet baseline records | the baseline's shrink command (below) | the baseline's own check |
| A rule or skill under `.vaultspec/` | `vaultspec-core sync` | review the provider copies in the same change |

Of the artefacts listed here, `just check-code` checks only the import load targets, the operation contract manifest, the year-literal and surface-redeclaration baselines and the frontend contract files. Registry, fixture, locale, corpus and documentation freshness have their own checks, which the full gate runs; run the one for your change yourself and do not rely on `check-code` to find it.

## Committed artefacts

**Operation contract manifest.** `src/cadrumo/_data/operations/contract_manifest.json`, shipped as package data and rendered from the registered production operations. A stale manifest is refused at run time when its operation group is composed, so the symptom can be an unavailable operation in a native or frontend test and not a manifest error. `build-distributions` depends on the check ([generator](../../../../dev/operation_contract_manifest/generate.py#L32), [recipes](../../../../justfile#L415)).

**Import load targets.** `dev/quality/metadata/import_load_targets.json` and one file per root package. They are path enumerations of governed non-test modules, so they change only when a module is added, moved or removed, not when one is edited. The import gate refuses a stale set with a message that names the recipe ([probe](../../../../dev/quality/import_load_probe.py#L99), [recipe](../../../../justfile#L487)).

**Frontend contract types.** `native/desktop/frontend/src/shell/*Contract.ts`, written by a pair of scripts per contract in `native/desktop/frontend/scripts/` (a Python reader of the backend model and a Node writer). The files carry a "do not edit" header. There is no `just` recipe to write them: run `node scripts/<name>-contract.mjs` in the frontend folder; `npm run check`, reached through `just check-frontend`, runs every script with `--check`. The Modelo contract files under `src/shell/modeloContract/` belong to the `modelo-wire-types` fixture family and are regenerated by `just fixtures-seed modelo-wire-types` ([scripts](../../../../native/desktop/frontend/scripts), [check script](../../../../native/desktop/frontend/package.json#L10)).

**Registry target trees.** Per-revision generated trees such as an `export/` folder with its provenance file, under `src/cadrumo/_data/registry/aeat/modelos/<modelo>/revisions/<revision>/`. They are per-edition generated claims and are regenerated only for an edition whose official design or mapping changed. Publishing is transactional; republishing an existing target needs the reviewed manifest digest (`just registry-republish-target ... EXPECTED_MANIFEST_SHA256`). After a publish, check the target and republish the authority ([recipes](../../../../justfile#L1009)).

**Locale catalogues.** YAML under `src/cadrumo/locales/` for each supported language, maintained only through `dev.locales`. See the string workflow in [the development loop](dev-change-workflow.md). `check-locales` is not part of `check-code`; orthography tests need the dictionaries from `just setup-locale-spelling` ([audit recipe](../../../../justfile#L339)).

**Documentation sequence goldens.** `docs/_sequences/<page>/<id>.json` beside the authored `.seq` sources: the recorded output of real CLI runs shown in the documentation. Regenerating rewrites committed files, so review the diff; a changed golden is a claim that the CLI's behaviour changed on purpose. After editing a `.seq` file, a refresh alone can leave a result frame without its payload, which the documentation build refuses, so run the documentation checks as well. The goldens gate reuses clean verdicts and never turns a divergence green ([recipes](../../../../justfile#L1922)).

**Documentation translation catalogues.** `docs/locales/<lang>/*.po`, regenerated by `just docs-generate-catalogs` and filled through `just docs-locales-set-batch MANIFEST`; a drift test in the documentation tests catches a stale catalogue. The CLI reference, glossary, API pages and `cli-tree.json` are built on demand and ignored, so they cannot go stale; `just check-docs-api` verifies API coverage.

**Corpus sidecars.** `src/cadrumo/_data/manual_corpus_text/*.corpus_text.json`, keyed on the source PDF's hash, and the extracted HTML and workbook sidecars under `src/cadrumo/_data/corpus/`. They are evidence for registry validation, and regenerating writes committed derived state ([recipes](../../../../justfile#L624)).

**Pins.** `native/component-pins/browser_archives.toml`, `native/component-pins/local_ai_program.toml` and `native/llamacpp-pins.json` record external archives by hash; each `pin-*` recipe rewrites its file and takes `--check`. The agent interface pin under `src/cadrumo_agent_service/_data/agent_api/` records the bundled agent's interface and commit; a native build refuses a bundle that does not match it ([pin recipes](../../../../justfile#L184), [agent pin](../../../../dev/packaging/native/agent_api_pin.py)).

**Shrink-only baselines.** These record existing findings and may only get smaller. When your change removes a finding, shrink the baseline in the same change; when your change adds one, fix the code, because writing the baseline is not a fix.

| Baseline | Check | Shrink command |
|---|---|---|
| `dev/quality/metadata/year_literal_baseline.json` | `just check-year-literals` | `python -m dev.quality.year_literals --shrink-baseline` |
| `dev/quality/metadata/surface_redeclaration_baseline.json` | `just check-surface-redeclaration` | `python -m dev.quality.surface_redeclaration --write-baseline` (refuses new keys) |
| `dev/quality/metadata/refusal_shape_ratchet.json` | `dev/quality/tests/test_refusal_shape_gate.py` | `python -m dev.quality.refusal_shape --write` |
| `dev/registry/analysis/year_independence_baseline.txt` | `just check-registry-year-independence` | `python -m dev.registry.analysis.year_independence_gate --write-baseline` (rewrites from current findings and does not refuse additions: read the diff) |

Run each as `uv run --no-sync python -m ...`.

**Provider copies of rules and skills.** `.claude/` and `.agents/` hold committed copies of the sources under `.vaultspec/`. Edit the source, run `vaultspec-core sync` (preview with `--dry-run`), and commit source and copies together. Nothing checks them automatically.

## Produced on demand, not committed

| Artefact | Where | Produced by |
|---|---|---|
| Published registry authority | `.authority/` | `just registry-publish-authority-if-authority-stale` |
| Fixture window projections | `build/<preset>/fixtures/window` | `just fixtures-seed` |
| Native contract (`contract.json`, `contract.rs`, `contract.h`) | the CMake build tree | the `native_contract` target, re-run by CMake when an input changes |
| Frontend generated inputs (chrome strings, palette, icons, navigation, settings) | the CMake build tree | the `desktop-frontend-generated` target |
| Generated documentation pages | `docs/cli/`, `docs/_generated/`, `docs/api/` | the documentation build |
| Compiled registry copy and validation verdicts | the development cache | written and validated automatically |
| Gate records and code-quality verdicts | `var/gate-runs/`, `var/gate-verdicts/` | `just gate-local` |

The first two are covered in [authority and fixture staleness](dev-authority-and-fixture-staleness.md). Never commit `.authority/`.

## Working notes

- Regenerate, read the diff, and commit the regenerated file in the same change as its cause. A regenerated file with a diff you cannot explain means a source changed that you did not expect.
- Regenerate on a still tree. Generators that read the source tree while it changes write an inconsistent result, and the import gate fails outright.
- Do not run two generators that write the same place at once, and do not regenerate during a gate: the gate invalidates itself when a source file changes.
- When a check says "stale", prefer the recipe it names over hand repair.
