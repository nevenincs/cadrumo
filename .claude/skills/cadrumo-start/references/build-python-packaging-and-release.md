# Python build, packaging and release

Ordinary wheel and sdist builds consume an existing published authority and refuse a missing pair; publish it explicitly before artifact builds. Editable environment setup retains its missing-authority bootstrap. Native builds validate currency and stage authority inside their build snapshot. [Authority hook](../../../../packaging/authority/hatch_build.py), [native admission](../../../../dev/packaging/native/authority_build.py).

Distribution products, cohort snapshots, staging, archives and application build scratch use `build/`. `build_storage` binds application storage/cache/temp controls while leaving uv and machine tool homes untouched; the ordinary system uv owns its isolation. Cohort output admission rejects lexical traversal and links before recreation. Release source snapshots are retained for manual review if their parent's death leaves child liveness unknown. [Storage context](../../../../dev/packaging/build_storage.py), [path and scratch ownership](../../../../dev/packaging/build_scratch_reclaim.py), [release parent](../../../../dev/packaging/release_cohort.py).

Cadrumo is one Python distribution, `cadrumo`, built with Hatchling and managed by uv from a committed lockfile. `requires-python` is `>=3.13`; two interpreter pins coexist on purpose: `.python-version` names only the development minor, while `dev/packaging/release-python-version` holds the exact patch that the release cohort, native builder and bundled CPython must equal. The wheel carries distinct `cadrumo`, `cadrumo_client`, `cadrumo_runtime`, `cadrumo_harness` and `cadrumo_agent_service` roots. Scripts are `aeat`, `cadrumo-mcp = cadrumo_harness.mcp.main:main`, `cadrumo-runtime = cadrumo_runtime.host.bootstrap:main` and `cadrumo-agent-service = cadrumo_agent_service.main:main`. Shared distribution does not merge their import/authority boundaries; no optional agent extra owns harness material. Lazily imported optional extras (`[project.optional-dependencies]`, among them `llm`, `pdf`, `browser`, `google`, `ofx`, `workbook-windows` and `all`) and the `registry` and `dev` groups sit beside it. The sdist is deny-by-default, the wheel sheds tests, authored registry source and corpus source binaries, and a hook force-includes the published authority from the gitignored `.authority/`. Corpus binaries ship in exact-version companion distributions that `tool.uv.sources` resolves from `packaging/` in development only ([project](../../../../pyproject.toml#L1), [extras](../../../../pyproject.toml#L153), [sdist](../../../../pyproject.toml#L283), [wheel](../../../../pyproject.toml#L355), [release pin](../../../../dev/packaging/release-python-version)).

`just` is the entry point, and recipes run Python as `uv run --no-sync python -m dev...`, so a check never re-syncs the environment. `just setup` converges it; `just init` adds browsers, search and authority publication. Static checks are `check-style`, `check-format`, `check-types` (ty over `src`; pyrefly and basedpyright over the strict subset in `pyproject.toml`), `check-import-boundaries` and `check-dependency-declarations`; `check-code` aggregates them with the reachability and usage censuses and further gates in `dev/quality/suite.py`, among them `check-operation-contract-manifest`, which fails when the committed operation contract manifest drifts from `dev.operation_contract_manifest` output (regenerate with `generate-operation-contract-manifest`); `check-registry-gate` is separate. Pytest `testpaths` classify the declared tax/client/runtime/harness/service source roots under a default `unit` marker expression, so tests under `dev/` and `native/tests` run only through recipes that restate the markers (`test-test-policy`, `test-repository-contracts`, `test-release-tooling`, `test-ci-contracts-gate`, `docs-check`). `dev.ci.change_scope` maps changed paths to pytest targets for `test-gate`: no list selects the full tree, while a change it cannot narrow (`pyproject.toml`, `uv.lock`, a `conftest.py`, `cadrumo.core`, more targets than its cap) runs only a fixed contract set behind a banner `test-gate` has separate Unix and Windows recipe bodies ([check-code](../../../../justfile#L264), [manifest gate](../../../../justfile#L377), [suite](../../../../dev/quality/suite.py#L96), [test-gate](../../../../justfile#L1170), [scope](../../../../dev/ci/change_scope.py#L59)).

`build-distributions` runs `uv build` for the root and each companion, then `dev.packaging.distribution_cap` refuses any file at or over the package index size limit. Releases go through `python_cohort`, which snapshots the tree, stages the authority, builds the wheels and sdists, and writes a wheelhouse and digest manifest. `test-packaging-preflight` runs `dependency_surface` (extras and frozen `uv export` against wheel metadata), `source_preflight` (shipped data against the wheel payload) and the packaging contract tests. The wheelhouse is a zip of lock-selected, hash-checked wheels per runtime and target; the native package does not unpack it, because native provisioning calls the same `runtime_wheel_selection` planner itself. `release_cohort` rebuilds from a clean snapshot, requires the pinned CPython, and declares Python, Scoop and Homebrew artifacts but no native desktop artifact. The `acquire_*` modules reinstall published bytes and run the installed `aeat` oracle; `campaign` runs the `smoke_*` modules ([distributions](../../../../justfile#L555), [python_cohort](../../../../dev/packaging/python_cohort.py#L347), [artifacts](../../../../dev/packaging/cohort_manifest.py#L146)).

CMake owns the native graph and calls Python: `cmake_build` dispatches the `sdk`, `provision`, `tools`, `product`, `assemble`, `run` and `agent` actions, while `generate`, `identity`, `metadata`, `authority_build`, `docs_build`, `docs_stage`, `artifact_verify` and the installer authors run directly. Shared actions are fingerprinted over inputs and pins, locked, and refuse their receipt if an input changed mid-run. Provisioning fetches the pinned CPython SDK (the NuGet SDK on Windows, Python Build Standalone elsewhere, both hash-checked) and installs hash-required wheels; `stdlib` compiles bytecode only under the exact patch; `assemble` relocates native modules; `authority_build` validates existing authority currency without publication; missing or stale inputs require explicit source authoring. MSI and Linux packages are marked `installable: false` behind maintenance gates, and Windows acceptance needs a disposable interactive runner and two built releases (Session 0 is insufficient). Observations to check: builds use the system uv binary without repository cache/environment overrides, and the `assemble` command line passes no provenance, so Linux and macOS assembly works only through `cmake_build` ([actions](../../../../dev/packaging/native/cmake_build.py#L179), [Windows SDK](../../../../dev/packaging/native/platforms/windows.py#L152), [POSIX SDK](../../../../dev/packaging/native/platforms/posix.py#L37), [MSI gate](../../../../dev/packaging/native/windows_msi.py#L646), [Linux gate](../../../../dev/packaging/native/linux_packages.py#L176)).

Service source/locales/typing artifacts follow wheel/sdist inclusion policy and sibling test exclusions. Private agent wheel remains native-only, built by CMake rather than published or installed by a runtime client. First-party source inventories derive their roots from `dev/first_party_source.py`; import-load partitions and entrypoint inventories follow the owning generators. Desktop chrome merges service catalogues independently, preserving tax auth-provider/extraction resources. [Source inclusion](../../../../pyproject.toml), [first-party policy](../../../../dev/first_party_source.py), [locale transfer](../../../../dev/locales/service_catalogues.py), [desktop merge](../../../../dev/locales/desktop_chrome.py).

User documentation is Sphinx (MyST, Furo) configured at `docs/conf.py` and driven by `dev/docs`; `docs-build` and `docs-check` build and test it. The CLI reference, glossary, API stubs and `cli-tree.json` are generated at build time and gitignored. The desktop path is separate: `Docs.cmake` calls `dev/packaging/native/docs_build.py`, one strict `compile_once --flavor desktop` for the languages in `native/package-layout.json` with one Pagefind index, cached by input identity. `docs_stage` refuses remote references and inline handlers, then writes the manifest `assemble` verifies. `docs-publish` is a hosted-site deployment, not part of the package ([generated pages](../../../../.gitignore#L85), [Docs.cmake](../../../../native/cmake/Docs.cmake#L33), [docs-build](../../../../justfile#L1567), [docs-check](../../../../justfile#L1670)).

`merge-gate.yml` gates pull requests on self-hosted Linux x64: `lint` (style, format, types, workflows), `gate` (semgrep, registry gate, import boundaries, `test-gate` over changed paths read from the forge API, sequence goldens) and a fork-refusing `verdict`. The setup action pins `just` and uv and runs `just setup`. Release-please proposes and tags; `release.yml` is dispatch-only. Its prove phase runs the gate, the full suite on the supported and next interpreters and conformance, builds and seals the cohort once, and proves it on Linux, Windows and macOS; its publish phase verifies the sealed digest, refuses burned versions, attests and uploads the unchanged bytes to PyPI by Trusted Publishing, updates Homebrew and Scoop, reacquires each channel and publishes docs. A green prove run is a validated candidate, not a published release, and nothing here submits a return. Observations to check: the pull-request gate selects owning tests only under `src/`, so packaging suites run in release prove, and RELEASING.md says hosted runners though jobs use self-hosted labels. Development runtime lifecycle tests start a test-owned manager inside a kill-on-close job on a fresh root, create no login-start registration and reap the job ([merge gate](../../../../.github/workflows/merge-gate.yml#L42), [release](../../../../.github/workflows/release.yml#L327), [lifecycle](../../../../dev/runtime_lifecycle/README.md#L58)).

## Working notes

- Native builds add the private `cadrumo-agent` wheel, built with `uv build --no-sources` from the folder named by the CMake cache variable `CADRUMO_PACKAGE_AGENT_SOURCE_DIR` (no default, environment never read), and the target-specific hashed closure in `native/agent/<target>.txt`. For a dependency both locks name, the agent lock's specifier string must equal the root lock's. The lock digests and the built wheel checksum are recorded in native provenance; no Python index publication or development-checkout import supplies the agent. The hosting protocol, launch path and lanes are in [agent integration](agent-integration.md); the agent images' process environments are in [the environment contract](environment-contract.md) ([owner](../../../../native/cmake/Agent.cmake#L4), [lock check](../../../../dev/packaging/native/agent.py#L58), [provenance](../../../../dev/packaging/native/provision.py#L143), [probe](../../../../native/tests/agent_smoke.py)).

- Pins: `.python-version` must stay a minor ([test](../../../../dev/ci/tests/test_python_version_pin.py#L37)); version surfaces belong to release-please ([config](../../../../release-please-config.json#L16)).
- Before finishing: `just check-code`, `just check-registry-gate`, `just test-gate`, then read `just report-code-health`; a failure on untouched code is reported, not fixed ([CONTRIBUTING](../../../../CONTRIBUTING.md#L97)).
- Generated files are never hand-edited and `.authority/` is never committed; after registry edits publish with `just registry-publish-authority-if-authority-stale` ([standards](../../../../CONTRIBUTING.md#L89), [recipe](../../../../justfile#L827)).
- A test no lane selects fails the reachability gate, so a new test directory needs a lane path ([gate](../../../../dev/tests/test_lane_reachability.py#L1)). Repository code never launches Git ([test](../../../../dev/quality/tests/test_no_git_cli.py#L1)).
- `just clean` only reports; `clean-apply` deletes irreversibly, outside the worktree too ([clean](../../../../justfile#L249), [clean-apply](../../../../justfile#L254)).
- Refusals: oversized distribution files, release builds off the pinned CPython, product builds without the OAuth client ([pin check](../../../../dev/packaging/release_cohort.py#L319), [OAuth](../../../../dev/packaging/google_oauth.py#L61)).
