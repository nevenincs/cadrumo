These are retained review leads from the original analysis. The cross-cutting assessments record the synthesized conclusions.

These are review leads from completed detailed reports, not final defect findings. The Sol synthesis pass should resolve them where source evidence permits and retain conditions where it cannot.

- **Authentication verification and side effects.** [008](../articles/008-aeat-certificate-and-cl-ve-browser-authentication.md) identifies separate fresh-login and verification predicates, diagnostic probing that may dispatch a Cl@ve challenge when landing metadata is absent, broad JavaScript-dialog acceptance, and raw URL/error logging. Trace application authentication orchestration, browser navigation policy, logging filters, and credential/session persistence before describing reachability or confidentiality impact.
- **Errors after persistence.** [070](../articles/070-modelo-calculation-input-and-persistence-orchestration.md) observes draft persistence before later advisory work. Trace transaction boundaries, action result handling, retry/idempotency behavior, and revision discovery before concluding that operators can receive misleading outcomes or create duplicate work.
- **Opening IVA credit and wallet totals.** [145](../articles/145-iva-compensation-carry-forward-and-filing-receipts.md) identifies a local opening-balance carry concern. [010](../articles/010-censal-reads-filed-declaration-capture-and-groi-checks.md) separately observes a `refunded=False` assumption in captured Modelo 303 compensation derivation. Connect those contracts to wallet construction, actual refund evidence, and calculation consumers. Distinguish behavior of isolated functions from invariants established by callers.
- **Taxpayer identity and remote evidence provenance.** [010](../articles/010-censal-reads-filed-declaration-capture-and-groi-checks.md) asks whether censal reads bind the requested taxpayer to the authenticated session and whether pre-redirect URLs accurately represent captured evidence. Trace session admission, representation authority, and evidence consumers before inferring unauthorized access or incorrect attribution.
- **Stored family facts.** [139](../articles/139-taxpayer-and-family-domain-records.md) distinguishes strict CLI parsing from permissive stored booleans and ignored incomplete descendant rows. Inspect the write/read schema boundary and allowed producers before claiming corrupted facts can reach calculations.
- **Registry time and generation.** [143](../articles/143-iva-classification-and-evidence-substrate.md) and [146](../articles/146-modelo-calculation-evidence-and-filing-lifecycle.md) identify date/generation selection questions. Resolve pinned-operation semantics, current-date versus filing-period choices, and whether apparent asymmetries are deliberate compatibility rules.
- **Typed revision identity and amendment graphs.** [146](../articles/146-modelo-calculation-evidence-and-filing-lifecycle.md) flags a transaction-ID annotation mismatch and asks whether amendment links are guaranteed acyclic with a current tip. Trace persistence and mutation boundaries before inferring runtime failure.
- **Actual capability levels.** Keep fact capture, parser support, calculation support, official export layout, attempted remote submission, and confirmed filing evidence separate. An operator command or registry entry alone does not establish every stage.
- **LLM evidence consent and cloud contracts.** [014](../articles/014-llm-dispatch-consent-and-invoice-reading-pipeline.md) reports a missing generic dispatch-time content-address comparison, but its follow-up trace found that the canonical ledger caller requires stored evidence and per-call acknowledgement, fresh-mints under bucket/profile/settings checks, binds the token to the source hash, and hashes resolved bytes before routing. A reachable authorization bypass is therefore unproven; preserve the enforced canonical path alongside the generic caller contract. Check other callers only where evidence supports doing so. [013](../articles/013-google-sheets-readback-drive-evidence-and-google-credentials.md) identifies cloud credential/hash contract questions; distinguish locally permissive API parameters from values production callers can actually supply.

- **Calendar projection defect.** [155](../articles/155-entrypoint-operation-and-read-composition.md) identifies an always-false `bucket_id != bucket_id` filter in `_calendar_other_profiles`, caused by comprehension variable shadowing. Verify the precise user-visible effect and rank this concrete local defect separately from speculative hardening opportunities.
- **Declared operation effects.** Trace effect admission and runtime containment before claiming that a command effect declaration that mismatches worker behavior bypasses enforcement. Such distinctions apply to censal preview receipt categories in [168](../articles/168-profile-custody-provisioning-and-runtime-configuration.md).
- **Rejected-input logging.** [170](../articles/170-cli-error-handling-ledger-actions-and-modelo-work.md) identifies Pydantic validation details passed to logging, which can include rejected input. Coordinator tracing found recursive argument/mapping scrubbing in logging.py (`src/cadrumo/core/logging.py`), a record filter (`src/cadrumo/core/logging.py`), and configured handler installation (`src/cadrumo/core/logging.py`). Thus the raw logging call does not prove raw values reach disk. Investigate whether arbitrary rejected text under generic `input` keys loses the sensitive-field hint carried separately in `loc`; also trace destinations and visibility before concluding that credentials or taxpayer information are disclosed.
- **Internal declaration validation.** Permissive enum/default constructors or missing duplicate validation in internal typed helpers are not automatically product defects. Establish permitted producers and the actual admission boundary; if the boundary is sound, describe the helper's trust contract instead.
- **LLM-extracted identity grounding.** [056](../articles/056-document-grounding-evidence-routing-history-and-import-export.md) traces a draft tax-ID candidate whose missing/refused anchor can fall back to its value while separately accepted role text contributes to an `ANCHORED` classification. Check exact producer validation, downstream blockers, and operator review before determining whether an ungrounded identity can become accepted ledger evidence. Keep model output, deterministic grounding, and human acceptance distinct.

Static inspection does not establish current AEAT behavior, installed third-party versions, runtime success, legal correctness, or test coverage. Findings should describe concrete code behavior with source links and label end-to-end conditions explicitly.
