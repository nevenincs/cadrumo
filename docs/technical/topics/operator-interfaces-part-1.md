<!-- preserved:summary -->
The CLI is Cadrumo's primary operator surface. Declarative command fragments expose parameters, secrets, effect policies and output schemas, and demand-load handlers. The composed operation registry binds exact-profile repositories, secure writers and pinned tax authority. Ledger, invoice, evidence, Modelo, live-capture, overview and profile-management commands turn application results into typed text/JSON envelopes. A local calculation, verification, internal filing record, exported file and observed AEAT receipt are distinct states; none alone proves live submission. [Full synthesis](operator-interfaces-part-1.md), graph (`src/cadrumo/entrypoints/cli/command_graph.py`), composition (`src/cadrumo/entrypoints/operation_composition.py`), [detail](../articles/154-entrypoint-adapter-composition.md), [detail](../articles/165-prorrata-review-root-cli-and-command-authority.md).

The knowledge displayed to operators comes from profile facts, pinned registries, ledger/evidence records and captured remote observations. Discovery names source categories and legal references without establishing their present legal validity. Off-host document extraction requires explicit consent and digest-bound review; model classification remains a proposal until accepted, with registry logic supplying regulated arithmetic. Live capture reports partial/empty/refused outcomes, and notification-document fetch is guarded by captured read state. Evidence (`src/cadrumo/entrypoints/cli/_ledger_evidence_cli.py`), Modelo discovery (`src/cadrumo/entrypoints/cli/_modelo_discovery_cli.py`), notification guard (`src/cadrumo/entrypoints/cli/_app_live_notifications_cli.py`), [detail](../articles/157-live-aeat-cli-capture-and-snapshot-surfaces.md), [detail](../articles/159-ledger-invoice-and-document-evidence-operator-flows.md).

The strongest visible controls are exact-profile preflight, secret channels, request/result correlation, typed envelopes, explicit confirmation and local-versus-official provenance. A confirmed `bucket_id != bucket_id` predicate makes the locked-other-profile calendar collection empty. The IVA capture count validator permits a positive failure count with an empty list. Lower-level IVA composition and consent metadata reads have local profile-scope gaps whose reachability depends on worker and repository paths. Calendar (`src/cadrumo/entrypoints/overview_read_composition.py`), [detail](../articles/155-entrypoint-operation-and-read-composition.md), [detail](../articles/156-cli-command-contracts-and-operator-surfaces.md).

The map records these as scoped interface findings. It does not claim that a calendar omission changes filing state or that a consent read grants permission for an off-host dispatch.

## Capability and architecture

Cadrumo's principal operator surface is a Typer CLI assembled from declarative command fragments. A `CommandSpec` records command identity, arguments, secret channels, effect policy, result schema, and a deferred handler target. The graph loads a selected family on demand, while help and schema discovery can inspect declarations without constructing profile storage or browser adapters. At invocation, the runtime materializes the target, applies profile preflight and an authority scope, and rejects declared live writes before importing the handler. The command graph therefore provides a useful, inspectable account of intended effects, but actual authority depends on the registered operation and worker behind each handler. Command graph (`src/cadrumo/entrypoints/cli/command_graph.py`), dispatch (`src/cadrumo/entrypoints/cli/_command_runtime.py`), policy (`src/cadrumo/entrypoints/cli/_command_policy.py`), [analysis](../articles/158-cli-contracts-execution-projection-diagnostics-and-evidence-notices.md), [analysis](../articles/165-prorrata-review-root-cli-and-command-authority.md).

The composition root binds profile repositories, identity admission, authority pins, remote readers, and secure-object writers for operation families. It delays heavy imports, owns bound dependency lifetimes through an `ExitStack`, and passes a retained `PinnedAuthorityOperation` to calculation services. The production registry combines sorted definitions and public registrations with journal, lease, secure operand custody, and execution bounds. Specialized builders bind Google Sheets, profile archive, review-package exchange, overview, workbench, and local checks to the same exact profile. This is the principal route from CLI intent to application services and adapters, rather than a second set of business rules in the CLI. Composition root (`src/cadrumo/entrypoints/adapter_composition.py`), registry (`src/cadrumo/entrypoints/operation_composition.py`), [analysis](../articles/154-entrypoint-adapter-composition.md), [analysis](../articles/155-entrypoint-operation-and-read-composition.md).

The operator can build ledger transactions, classify them manually, by rule, or through a model suggestion, manage a content-identified invoice catalogue, import CSV/XLSX invoices and bank statements, attach evidence, and inspect checks and participation. Import outcomes separate created, duplicate, refused, pending-review, and deferred rows; a statement import offers dry run and file-count limits. Model classification is a proposal until explicit apply or reject, and applied receipts are correlated to the reviewed digest and transaction. In saturated IVA and autosplit paths, the model proposes categories or proportions while regulated amounts come from registry calculations. This keeps model judgment and deterministic tax arithmetic distinct. Ledger declarations (`src/cadrumo/entrypoints/cli/_app_ledger_command_specs.py`), invoice import (`src/cadrumo/entrypoints/cli/_ledger_business_invoice_cli.py`), evidence batch (`src/cadrumo/entrypoints/cli/_ledger_evidence_batch_cli.py`), model review (`src/cadrumo/entrypoints/cli/_ledger_llm_cli.py`), [analyses](../articles/156-cli-command-contracts-and-operator-surfaces.md), [analysis](../articles/159-ledger-invoice-and-document-evidence-operator-flows.md), [analysis](../articles/160-ledger-review-imports-rules-inventory-and-read-surfaces.md).

Evidence extraction is a particularly consequential boundary. An off-host reader requires classified provider consent and a persisted evidence identity; its result records source and review digests. Confirmation requires the digests that the operator saw. The review queue exposes every candidate, grounding result, anchor, discrepancy, and blocker, and requires individual resolution of blocking findings. Consent history acknowledges that transmitted bytes cannot be recalled. These CLI checks support review, while the worker's hash comparison, saved consent token, and provider dispatch are separate enforcement points. Extraction and confirmation (`src/cadrumo/entrypoints/cli/_ledger_evidence_cli.py`), review resolution (`src/cadrumo/entrypoints/cli/_ledger_evidence_review_cli.py`), consent history (`src/cadrumo/entrypoints/cli/_ledger_evidence_consent_cli.py`), [analyses](../articles/159-ledger-invoice-and-document-evidence-operator-flows.md), [analysis](../articles/160-ledger-review-imports-rules-inventory-and-read-surfaces.md).

Modelo commands expose discovery of models, casillas, bindings, requirements, source references, formula inputs, local work revisions, comparison, calculation, verification, amendment, reconciliation, filing evidence, and export. They accept typed casilla and detail-row overrides, canonical decimal strings, year/period scope, and revision selectors. Discovery distinguishes manual, ledger, profile, prior-filing, relation and live-observation sources. A calculation saves a draft revision; verification persists a separate report; `work file` creates an internal filing record when verification grants it. Export writes a local artifact and reports its hash and software-identity grade. Neither an internal filing record nor a local export is an AEAT submission. Local M036 records and M145 payer communications have similarly bounded meanings. Discovery (`src/cadrumo/entrypoints/cli/_modelo_discovery_cli.py`), input parser (`src/cadrumo/entrypoints/cli/_modelo_cli_support.py`), verification and file (`src/cadrumo/entrypoints/cli/_modelo_work_verification_cli.py`), export (`src/cadrumo/entrypoints/cli/_modelo_export_cli.py`), M036/M145 (`src/cadrumo/entrypoints/cli/_modelo_m036_cli.py`), [analyses](../articles/161-modelo-command-support-discovery-amendment-and-export-surfaces.md), [analysis](../articles/162-modelo-local-records-wallet-preview-and-non-work-command-contracts.md), [analysis](../articles/163-modelo-projection-readiness-filing-evidence-and-sharing-surfaces.md), [analysis](../articles/164-work-inspection-overview-verification-and-profile-authentication.md).

Readiness, overview, and quickfile are decision aids rather than blanket certification. Modelo readiness names its scope as profile/source preflight and excludes manual casilla completeness. Quickfile strings together readiness, calculation, verification, and local export and returns stage outcomes and an artifact receipt. Calendar and agenda blend scheduled obligations with local work, filing, and AEAT evidence, distinguishing local filing state, observed submission, and verified justificante. Workbench generation grades a work unit before falling back to static inspection on a taxpayer-facing refusal. Readiness (`src/cadrumo/entrypoints/cli/_modelo_readiness_cli.py`), quickfile (`src/cadrumo/entrypoints/cli/_app_quickfile.py`), calendar contract (`src/cadrumo/entrypoints/cli/_overview_payloads.py`), workbench (`src/cadrumo/entrypoints/workbench_generation_composition.py`), [analyses](../articles/155-entrypoint-operation-and-read-composition.md), [analysis](../articles/158-cli-contracts-execution-projection-diagnostics-and-evidence-notices.md), [analysis](../articles/164-work-inspection-overview-verification-and-profile-authentication.md).

The live CLI is framed as observation. It can capture filed-history, IVA wallet, expedientes, justificantes, DEHú notifications, and verification observations, then read stored snapshots locally. The notification-document route requires a prior snapshot and AEAT-read state before fetching a served document; it disclaims performing comparecencia. Filed-history discovery retains both profile-expected and portal-offered pairs because the latter's taxpayer scoping is unconfirmed. Bulk capture reports attempted, completed, refused, empty and limited work without converting partial observation to a coverage percentage. A local Modelo 100 draft-PDF import is a separate snapshot path. Live family (`src/cadrumo/entrypoints/cli/_app_live_command_specs.py`), guarded notification pull (`src/cadrumo/entrypoints/cli/_app_live_notifications_cli.py`), filed discovery (`src/cadrumo/entrypoints/cli/_app_live.py`), [analysis](../articles/157-live-aeat-cli-capture-and-snapshot-surfaces.md).

## Trust and implementation assessment

Profile preflight resolves a named or ambient identity to a UUID bucket, reads root and leaf secrets from distinct bounded channels, and avoids consuming supplied secrets when a serving session already exists. The CLI refuses a synthetic placeholder tax ID for filing output. Output envelopes and terminal failures are typed and localized; parse-time JSON errors can be rendered without opening profile storage. Sensitive taxpayer amounts, identifiers, source paths, and field-level evidence notices still appear in authorized output, so downstream terminal and JSON retention remains a real data boundary. Profile gate (`src/cadrumo/entrypoints/cli/_profile_authentication_gate.py`), session gate (`src/cadrumo/entrypoints/cli/_profile_session_gate.py`), identity refusal (`src/cadrumo/entrypoints/cli/common.py`), terminal errors (`src/cadrumo/entrypoints/cli/_terminal_errors.py`), [analyses](../articles/164-work-inspection-overview-verification-and-profile-authentication.md), [analysis](../articles/165-prorrata-review-root-cli-and-command-authority.md), [analysis](../articles/166-shared-cli-transport-and-profile-configuration-surfaces.md).

The visible CLI and composition code has concrete quality gaps of different scope. A calendar survey's `bucket_id != bucket_id` predicate is always false, so its locked-other-profile collection is empty; it does not invalidate the active profile's filing rows. The IVA capture-history schema permits a positive failure count with an empty named-failures list. An invalid `--autoconsumo-promotor-base` receives a SAL-reserve parser label. Lower-level IVA live-state composition does not itself compare its explicit bucket to the active worker, and a consent follow-up reader does not filter returned entries by bucket; those are local contracts whose actual exposure depends on callers and repository scoping. Calendar predicate (`src/cadrumo/entrypoints/overview_read_composition.py`), failure validator (`src/cadrumo/entrypoints/cli/_app_live_iva_wallet_payloads.py`), diagnostic label (`src/cadrumo/entrypoints/cli/_modelo_work_calculate_cli.py`), IVA composition (`src/cadrumo/entrypoints/live_state_composition.py`), consent reader (`src/cadrumo/entrypoints/evidence_followup_operation_composition.py`), [analyses](../articles/154-entrypoint-adapter-composition.md), [analysis](../articles/155-entrypoint-operation-and-read-composition.md), [analysis](../articles/156-cli-command-contracts-and-operator-surfaces.md), [analysis](../articles/157-live-aeat-cli-capture-and-snapshot-surfaces.md), [analysis](../articles/163-modelo-projection-readiness-filing-evidence-and-sharing-surfaces.md).

Profile maintenance includes revision-and-digest compare-and-swap edits, explicit deletion preflights, journalled archive reconciliation, recovery possession proof, typed runtime access receipts, and closely correlated Google consent exchanges. Google probe receipt checking locally permits an `UPDATED` effect even for a read-only request, and censal preview receipt checking permits `UPDATED`; neither rule alone proves a reachable mutation because the worker contract can be stricter. Censal file import is labeled non-official and its inbound certificate parser currently refuses documents; live censal pull adopts only reviewed identity/address facts. Apoderado live verification explicitly refuses because it is unwired. Profile mutation (`src/cadrumo/entrypoints/cli/config/_runtime_profile_mutation.py`), deletion (`src/cadrumo/entrypoints/cli/config/_profile_delete.py`), recovery (`src/cadrumo/entrypoints/cli/config/recovery.py`), Google consent (`src/cadrumo/entrypoints/cli/config/google_consent_exchange.py`), probe correlation (`src/cadrumo/entrypoints/cli/config/google_configuration_receipt_correlation.py`), censal preview (`src/cadrumo/entrypoints/cli/config/runtime_censal_preview.py`), censal transport (`src/cadrumo/entrypoints/cli/config/_censo_transport.py`), apoderado (`src/cadrumo/entrypoints/cli/config/_apoderado.py`), [analyses](../articles/166-shared-cli-transport-and-profile-configuration-surfaces.md), [analysis](../articles/167-profile-maintenance-repair-and-google-operations.md), [analysis](../articles/168-profile-custody-provisioning-and-runtime-configuration.md).

This synthesis describes the on-disk command and composition contracts. It does not establish running CLI behavior, browser/provider success, current legal accuracy, or comprehensive tests; the supplied snapshot was reviewed statically. The most useful verification work is to compare public command effects with registered operation effects, exercise the calendar filter with a locked second profile, and test the cited DTO and receipt branches against real producers.
