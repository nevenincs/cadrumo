## Runtime and operating-system boundary

The installed runtime gives CLI, TUI and MCP frontends an exact-profile operation channel rather than direct ambient access to private repositories. A frontend client binds storage identity, native connection, frontend kind, profile and session; document and secret frames are separate, size bounded and correlated to boot/request/connection IDs. A secret is sent only after an exact ready signal. Runtime launch first tries the verified endpoint and starts only a matching configured manager, without implicitly enabling autostart. POSIX sockets use owner/root inode and peer credentials; Windows pipes use a restricted owner SID and retained peer process/token checks. Worker construction verifies an isolated child and opens separate custody, operation and authorization channels before transferring leases. Frontend client (`src/cadrumo/adapters/local_runtime/frontend_client.py`), framing (`src/cadrumo/adapters/local_runtime/framing.py`), startup (`src/cadrumo/adapters/local_runtime/startup.py`), POSIX endpoint (`src/cadrumo/adapters/local_runtime/posix.py`), Windows endpoint (`src/cadrumo/adapters/local_runtime/windows.py`), worker process (`src/cadrumo/adapters/local_runtime/profile_worker.py`), [analyses](../articles/005-local-runtime-clients-and-native-os-bindings.md), [analysis](../articles/006-local-runtime-transport-worker-custody-and-lifecycle.md).

Native service management and desktop login evidence are deliberately distinct from application authority. Linux systemd, macOS LaunchAgent and Windows Task Scheduler configuration compare exact owner/root/executable state before starting; configured, running, authenticated and operation-settled are separate statuses. Linux worker containment uses cgroups and pidfds; Windows children are assigned to a kill-on-close Job Object at process creation. Login observations bind peer process and OS session/desktop facts, but unsupported or incomplete readings remain unknown rather than granting a positive unlocked state. These are strong source-level checks that still rely on kernel, D-Bus, WTS/LSA, scheduler and manager behavior. Windows inventory has a two-second iteration budget that cannot interrupt a blocking native call. An authorization-server cleanup path can lose a semaphore slot if channel close raises before release. Linux worker (`src/cadrumo/adapters/local_runtime/linux_worker_process.py`), Windows process (`src/cadrumo/adapters/local_runtime/windows_process.py`), Windows login (`src/cadrumo/adapters/local_runtime/windows_login.py`), worker authority (`src/cadrumo/adapters/local_runtime/worker_authorization.py`), [analyses](../articles/005-local-runtime-clients-and-native-os-bindings.md), [analysis](../articles/006-local-runtime-transport-worker-custody-and-lifecycle.md), [analysis](../articles/007-windows-login-task-control-and-worker-authority.md).

## AEAT read adapters and provenance

AEAT authentication supports certificate, Cl@ve Móvil and Cl@ve Permanente routes. Certificate state is bound to thumbprint, subject, derived NIF, idle/hash metadata and a canonical protected-resource probe; expired or organization-shaped certificates are refused. Cl@ve routes operate browser challenges and persist encrypted browser state, with later verification against authenticated AEAT landing predicates. The Sede readers use remote-action policies and actual post-navigation host/path checks because a browser form click may send a POST beyond a generic HTTP guard. They distinguish site maintenance, WAF and rate limits and keep browser downloads in memory for guarded refetch. Certificate (`src/cadrumo/adapters/outbound/aeat/auth/certificate.py`), Cl@ve Móvil (`src/cadrumo/adapters/outbound/aeat/auth/clave_movil.py`), Cl@ve Permanente (`src/cadrumo/adapters/outbound/aeat/auth/clave_permanente.py`), landing guard (`src/cadrumo/adapters/outbound/aeat/sede/_adapter_utils.py`), browser health (`src/cadrumo/adapters/outbound/aeat/browser/session.py`), [analyses](../articles/008-aeat-certificate-and-cl-ve-browser-authentication.md), [analysis](../articles/009-cl-ve-permanente-browser-support-and-sede-read-primitives.md).

The live readers capture censal identity/address, filed-declaration register rows and artefacts, GROI and EU NIF-IVA checks, an IVA compensation wallet, notifications, and expediente tree records. Captured declarations prefer submitted data interpreted against a generation-pinned export layout, use a declaration PDF as fallback, and preserve row/artefact hashes, source locators and registry references. A browser register's offered model/year controls are explicitly an availability clue, not proof of taxpayer-specific completeness. An authenticated notification document fetch is guarded by a prior record whose `leida` value is exactly true because opening an unread notice can have legal effect; the adapter itself does not re-fetch or bind that row cryptographically, so safe reachability depends on the application passing a fresh, same-taxpayer snapshot. The IVA wallet parses only an executed table or explicit zero, but its optional taxpayer label is not locally compared to session identity. Both are caller-boundary questions, not proven unauthorized reads. Censal read (`src/cadrumo/adapters/outbound/aeat/sede/censal_datos.py`), declaration capture (`src/cadrumo/adapters/outbound/aeat/sede/declarations_capture.py`), wallet (`src/cadrumo/adapters/outbound/aeat/sede/iva_compensation_wallet.py`), notification guard (`src/cadrumo/adapters/outbound/aeat/sede/notifications.py`), [analyses](../articles/010-censal-reads-filed-declaration-capture-and-groi-checks.md), [analysis](../articles/011-iva-wallet-notifications-vies-checks-and-expediente-reads.md).

Important uncertainty remains in browser authentication: a fresh Cl@ve login accepts a matching target-path pattern before the stronger canonical-host verifier, and a diagnostic persisted-session probe with missing landing metadata may traverse a selector hook that starts a new challenge. This does not establish that protected application reads run without later verification; caller order must decide that. Móvil auto-accepts any JavaScript dialog and some diagnostic paths log raw URLs/errors despite other URL redaction. In captured Modelo 303 history, derivation assumes `refunded=False`; a refunded period could make derived carry too high unless later reconciliation uses refund evidence. Censal capture also stamps the requested URL rather than the actual redirected URL as source in one path. Móvil probe (`src/cadrumo/adapters/outbound/aeat/auth/clave_movil.py`), fresh landing (`src/cadrumo/adapters/outbound/aeat/auth/_clave_movil_page_flow.py`), 303 derivation (`src/cadrumo/adapters/outbound/aeat/sede/declarations_observations.py`), censal provenance (`src/cadrumo/adapters/outbound/aeat/sede/censal_datos.py`), [analyses](../articles/008-aeat-certificate-and-cl-ve-browser-authentication.md), [analysis](../articles/010-censal-reads-filed-declaration-capture-and-groi-checks.md).

## Google, reporting, rates and model assistance

Google Sheets export is a real remote write into an app-owned Drive hierarchy. It creates or reuses managed tabs, writes values and formulas, clears stale cells, formats/protects ranges and stamps registry identity. Readback checks the ownership marker and model/year/period/revision/engine/registry hash *before* reading operator edits; it then calls the local Decimal runtime without persisting the pulled values. Blank numeric cells become zero in that computation, a user-visible semantic choice. Offline XLSX uses the same export plan and deterministic workbook construction; worksheet protection is an editing aid, not confidentiality. A Sheets apply spans multiple Google requests, so interruption can leave mixed generations. The structural batch is declared replay-safe even though `createDeveloperMetadata` can duplicate metadata after a lost response; literal strings are sent with `USER_ENTERED`, creating a conditional formula-injection question if untrusted values start with `=`. Sheets apply (`src/cadrumo/adapters/outbound/google/calc_sheets_apply.py`), pull gate (`src/cadrumo/adapters/outbound/google/calc_sheets_pull.py`), XLSX (`src/cadrumo/adapters/outbound/workbook/calc_sheets_xlsx.py`), [analyses](../articles/012-pdf-summaries-ecb-rates-and-google-sheets-exports.md), [analysis](../articles/013-google-sheets-readback-drive-ownership-and-google-sign-in.md), [analysis](../articles/016-local-storage-remote-ciphertext-mirroring-and-offline-workbooks.md).

Google OAuth uses interactive Desktop consent with the single client the installation carries, scope/audience checks and per-profile secret storage of the refresh token. A consent that returns no refresh token is refused, and a stored token is used only with the client it was minted for. Signing in creates the profile's Drive folder, and a stored folder ID is used only while Drive still shows it as a folder the application created. Drive mirror storage receives encrypted bytes only, names objects with HMAC-derived identifiers, checks full digest/length on read and publishes namespace manifests after successful object writes. Push checks revision ancestry and withholds a manifest on partial failure; cleanup failure remains visible. Direct provider `put` methods accept nonblank noncanonical hash strings, while the normal mirror producer supplies SHA-256, so this is a local contract gap rather than established production unreadability. OAuth flow (`src/cadrumo/adapters/outbound/google/oauth_flow.py`), profile folder (`src/cadrumo/adapters/outbound/google/root_folder.py`), mirror push (`src/cadrumo/adapters/outbound/storage/mirror_push.py`), Drive read (`src/cadrumo/adapters/outbound/storage/_google_drive.py`), [analyses](../articles/013-google-sheets-readback-drive-ownership-and-google-sign-in.md), [analysis](../articles/015-llm-provider-adapters-and-google-drive-storage.md), [analysis](../articles/016-local-storage-remote-ciphertext-mirroring-and-offline-workbooks.md).

The PDF summary writer builds tagged output and embeds its source report/CSV, with a matching reader that hashes the visible layer. PDF/A and PDF/UA identifiers do not constitute external conformance certification. ECB conversion fetches a prior published EUR-base rate within fourteen days and returns a Decimal multiplier; its instance cache also retains a missing observation for the process lifetime. PDF summary (`src/cadrumo/adapters/outbound/calculation_summary_pdf/summary_container.py`), ECB rates (`src/cadrumo/adapters/outbound/fx/ecb_provider.py`), [analysis](../articles/012-pdf-summaries-ecb-rates-and-google-sheets-exports.md).

LLM adapters support local and optional hosted providers for column-role mapping, invoice text/vision reading, classification and advisory supply-nature proposals. Requests normalize provider results and errors, meter usage/cost and apply local memory admission and retry pacing. Invoice extraction treats anchors as unverified until later source-text corroboration and uses deterministic tax-ID/date/amount grounding. Off-host evidence dispatch requires consent; the canonical ledger path resolves stored bytes, obtains fresh per-invocation acknowledgement, mints a token under profile/settings checks, compares source hash and audits before dispatch. The generic client alone checks token presence/address, not content equality, so direct callers require their own trusted contract; the reviewed canonical path supplies it. Some convenience wrappers offer a provider override but cannot pass a token, so hosted use safely refuses through them. Rate-limit pacing can resume after a budget-sized wait before the full provider pause expires. LLM dispatch (`src/cadrumo/adapters/outbound/llm/client.py`), canonical source binding (`src/cadrumo/application/ledger/invoice_evidence_extract_operation.py`), grounding (`src/cadrumo/adapters/outbound/llm/invoice_field_grounding.py`), [analyses](../articles/014-llm-dispatch-consent-and-invoice-reading-pipeline.md), [analysis](../articles/015-llm-provider-adapters-and-google-drive-storage.md).

These integrations are implemented as typed adapters with significant fail-closed checks, but no live AEAT/Google/ECB/provider/OS behavior was exercised. Their current external compatibility, legal accuracy, real PDF conformance, cryptographic storage, and race behavior cannot be certified from this snapshot.
