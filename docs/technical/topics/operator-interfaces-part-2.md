The registered-operation bridge is the common CLI-to-worker protocol: it validates a typed request against a definition, binds profile/frontend/session identity, observes settlement, checks result/effect/schema, and correlates review replies. Timeout and incomplete observations stay `UNKNOWN`, which matters for mutations that may have committed. Ledger, Modelo, spreadsheet, review-package, live-capture and profile commands reuse this mechanism. A capture receipt proves that the local operation reported evidence; it does not independently authenticate current AEAT state or establish a submitted return. Exact-profile runtime admission and invocation-owned client cleanup constrain lifetime; immutable decoded strings and native credential handling are outside the wipe claim. Profile edits carry revision/content-digest preconditions and preserve “committed but readback failed” outcomes. Local file input and provider effects are delegated to workers, so CLI path normalization does not by itself prove filesystem containment. ## The CLI to worker boundary

The second operator-interface slice shows how the declarative command tree becomes a profile-bound request. `main()` builds Typer callbacks lazily, admits shipped authority for ordinary invocations, and applies a shared failure boundary; help/version and command-surface introspection avoid heavy profile work. A command-specific bridge then admits a typed registered request, sends it through the retained frontend client, observes settlement under a deadline, checks the result schema and effect, and correlates any review response with the exact pending operation. A timeout or incomplete observation remains `UNKNOWN`; the CLI does not convert it to a safe-to-retry refusal. This is a meaningful safeguard for commands that may have committed before transport failed. CLI root (`src/cadrumo/entrypoints/cli/main.py`), registered admission (`src/cadrumo/entrypoints/cli/registered_operation_admission.py`), completion (`src/cadrumo/entrypoints/cli/registered_operation_completion.py`), runner (`src/cadrumo/entrypoints/cli/runtime_registered_operation.py`), [analyses](../articles/170-cli-error-handling-ledger-actions-and-modelo-work.md), [analysis](../articles/171-cli-period-registered-operation-and-ledger-bridges.md), [analysis](../articles/173-modelo-discovery-review-exchange-profile-admission-and-workflow-reads.md).

These bridges make a broad operator surface concrete. Ledger requests cover transaction additions and corrections, allocation, classification, invoice links and evidence, import/export, lifecycle changes, split/merge, rules, ratios, inventory and diagnostics. They compare the returned profile and coordinates with the request, often compare every changed field, and require effect/event agreement. Destructive ledger operations can preview with `NONE` and require an `UPDATED` receipt after actual mutation; manual and model-assisted split/merge require explicit confirmation. File import limits count and carries selected provider/period/dry-run/verification state, but its CLI adapter calls `absolute()` rather than resolving symlinks, leaving actual file opening and path policy to the worker. Ledger lifecycle (`src/cadrumo/entrypoints/cli/ledger_lifecycle_cli.py`), mutation correlation (`src/cadrumo/entrypoints/cli/runtime_ledger_update.py`), import (`src/cadrumo/entrypoints/cli/runtime_ledger_import.py`), split (`src/cadrumo/entrypoints/cli/runtime_ledger_split.py`), [analyses](../articles/170-cli-error-handling-ledger-actions-and-modelo-work.md), [analysis](../articles/171-cli-period-registered-operation-and-ledger-bridges.md), [analysis](../articles/172-ledger-and-modelo-cli-operations.md).

Modelo bridges use the same protocol for work creation, calculation, revision reads, verification, local filing records, reconciliation, amendments, registry queries, workbook exchange, review packages and wallet observations. A calculation can wait for up to 1,800 seconds, then checks the returned revision against the work unit's published revision before rendering stored casillas and formula traces. Filing import distinguishes an external evidence kind/reference from a local observation overlay. Workbook `pull`/`calculate` are treated as reads in this bridge, whereas export and verification can write; dry-run push expects no effect. Review-package import correlates profile, revision, recipient and verified countersignature state, while cryptographic guarantees remain downstream. These are separate capability levels: a registry query, a calculation, an official-layout export, a captured receipt and AEAT acceptance cannot be inferred from one another. Calculation bridge (`src/cadrumo/entrypoints/cli/runtime_modelo_calculation.py`), filing import (`src/cadrumo/entrypoints/cli/runtime_modelo_filing_record_import.py`), spreadsheet bridge (`src/cadrumo/entrypoints/cli/runtime_modelo_spreadsheet.py`), review package (`src/cadrumo/entrypoints/cli/runtime_modelo_review_package_exchange.py`), [analyses](../articles/170-cli-error-handling-ledger-actions-and-modelo-work.md), [analysis](../articles/172-ledger-and-modelo-cli-operations.md), [analysis](../articles/173-modelo-discovery-review-exchange-profile-admission-and-workflow-reads.md).

Live AEAT-related bridges distinguish capture from stored reads for filed returns, justificantes, IVA wallet/state, notifications and identity checks. Their receipts bind profile, period, row counts and effect; a successful local capture reports an observed/saved snapshot, not independent legal validation or an AEAT write. Reconciliation can pull a captured justificante or import a local file. One local selector correlation gap remains: an import with a 12-character work-unit selector skips equality and does not check the returned ID's prefix. A unique-selector invariant in the worker may resolve this, so its reachability must be traced before assigning end-to-end impact. Filed capture (`src/cadrumo/entrypoints/cli/runtime_filed_bulk.py`), notification capture (`src/cadrumo/entrypoints/cli/runtime_notifications_capture.py`), reconciliation import (`src/cadrumo/entrypoints/cli/runtime_modelo_reconciliation_import.py`), [analyses](../articles/171-cli-period-registered-operation-and-ledger-bridges.md), [analysis](../articles/173-modelo-discovery-review-exchange-profile-admission-and-workflow-reads.md).

## Secret, profile and error boundaries

The CLI's secure-input helper accepts exactly one stdin or descriptor channel, limits it to 8,192 bytes, rejects duplicate JSON keys and extra fields, and closes descriptors and wipes mutable input buffers. It refuses a prompt without a real console. Scripted profile creation validates facts first and uses a strict secret payload or no-echo prompt, with recovery enrollment optional after creation. Runtime profile admission opens one native connection, authenticates with a password/API key or eligible receipt, and binds the exact profile UUID and frontend client to the invocation. The bound client is closed on exit, including synchronous-CLI execution inside an event loop; cleanup errors do not overwrite a previously rendered command error. These are tangible memory and lifetime controls, but immutable decoded Python strings and the native credential protocol lie outside the buffer-wipe claim. Secure input (`src/cadrumo/entrypoints/cli/config/secure_input.py`), scripted registration (`src/cadrumo/entrypoints/cli/config/scripted_registration.py`), runtime admission (`src/cadrumo/entrypoints/cli/runtime_profile_admission.py`), client binding (`src/cadrumo/entrypoints/cli/runtime_profile_binding.py`), [analyses](../articles/169-secure-cli-input-profile-bridges-and-storage-controls.md), [analysis](../articles/173-modelo-discovery-review-exchange-profile-admission-and-workflow-reads.md).

Profile view, wizard edits, and descendant updates are revision-bound operations: they read one baseline, submit its revision/content digest with the patch, and check the settled readback. If the write committed but readback failed, the CLI reports that distinction and the operation ID. Certificate registration binds a source path to the active profile and passes its passphrase as a one-shot secret. Google client registration bounds JSON size, hashes public bytes, sends the content as protected input, and routes human OAuth consent through a correlated interaction. Censal review likewise checks the baseline and proposal digest before an apply/reject response. Local storage commands can inspect, materialize and reclaim declared areas, but relocation is manual through `CADRUMO_LOCAL_STORAGE_ROOT`; root-permission status and retained entries are reported rather than assumed. Profile patch (`src/cadrumo/entrypoints/cli/config/runtime_profile_patch.py`), descendants (`src/cadrumo/entrypoints/cli/config/runtime_descendants.py`), Google registration (`src/cadrumo/entrypoints/cli/config/runtime_google_registration.py`), censal review (`src/cadrumo/entrypoints/cli/config/runtime_censal_review.py`), storage commands (`src/cadrumo/entrypoints/cli/config/storage_cli.py`), [analysis](../articles/169-secure-cli-input-profile-bridges-and-storage-controls.md).

Failure presentation preserves typed product errors and maps unexpected exceptions to a generic internal response. Parser errors can be localized and emitted as JSON without opening storage. A Pydantic validation error is passed to logging, but configured `SecretScrubbingFilter` recursively processes records and handlers, so the raw call does not prove a secret reaches disk. A narrower unresolved question is whether rejected values under a generic `input` key retain the sensitive-field hint from their separate `loc` path. The source supports targeted tests of that shape and of all configured destinations, not a claim of an observed leak. Validation projection (`src/cadrumo/entrypoints/cli/errors.py`), scrubber (`src/cadrumo/core/logging.py`), record filter (`src/cadrumo/core/logging.py`), handler installation (`src/cadrumo/core/logging.py`), [analysis](../articles/170-cli-error-handling-ledger-actions-and-modelo-work.md).

The command-surface reconciler compares live callback aliases, inputs, policies and schemas with graph projections. It helps detect authored metadata drift but cannot prove that a worker's effects match the declaration. Runtime correctness, storage isolation, provider behavior, tax calculation, current legal authority and test coverage remain outside static inspection of these adapters. Priority follow-up is to test receipt ambiguity and retry behavior, inspect the worker-side file and profile boundaries, and verify the 12-character reconciliation selector against the shared resolver. Surface reconciliation (`src/cadrumo/entrypoints/cli/operator_surface_reconciliation.py`), [analysis](../articles/170-cli-error-handling-ledger-actions-and-modelo-work.md).
