# Cadrumo product capability map

[Technical overview](../architecture.md) · [Article index](../articles/catalogue.md) · [Snapshot and reading guide](../reading-guide.md)

> This page describes the analyzed source snapshot. Its findings and limitations are not a certification of the current branch.

<!-- preserved:assessment -->
Cadrumo is a local-first Spanish tax workbench for an operator managing a taxpayer profile, financial source records, Modelo calculations, local filing artefacts and observed AEAT state. The principal interface is a declarative Typer CLI. An installed Textual workbench and a bounded MCP harness use the same profile-bound runtime operations; agent personas and skills are guidance, not an independent filing authority. The project ships substantial dated registry and corpus material, but a bundled layout, a calculated result, a local `PRESENTADO` record and an AEAT-confirmed submission are different claims. CLI graph (`src/cadrumo/entrypoints/cli/command_graph.py`), runtime (`src/cadrumo/entrypoints/runtime/operation_authority.py`), [knowledge inventory](../topics/bundled-knowledge-and-localization.md), [interface analysis](../articles/158-cli-contracts-execution-projection-diagnostics-and-evidence-notices.md).

**Status vocabulary.** “Implemented” below means a concrete source path and typed contract were found in the checked-in snapshot; it does not mean the path was executed in this review. “Conditional” means the path depends on a profile, provider, registry grade, evidence, consent, or populated producer facts. “Refused” names a visible deliberate stop. “Unverified” describes current law, live portal success, platform behavior, or other claims static inspection cannot establish. A parser accepting a document is not a canonical invoice; a formula yielding a value is not export readiness; an export is a local file; a remote read is an observation; an attempted submission would be a separate effect; and a confirmed filing needs matched external evidence. [Draft/export](../topics/filing-and-live-state.md), [filing lifecycle](../topics/modelo-work-and-revision-lifecycle-part-1.md), receipt gate (`src/cadrumo/application/live/filed_observation_persistence.py`), [analysis](../articles/064-filed-declaration-capture-evidence-enrollment-and-history-sweep.md).

Several important functions are **explicitly unsupported or refused**. The core live-access gate raises for outbound submission, and the workflow engine records `submission_id=None`; the supported path produces files for a human to upload through AEAT. The inbound censal certificate parser refuses pending a specimen-backed layout, while live censal read/review is a separate implemented path. The local apoderado configuration surface exists, but live representation verification is unwired. M145 is a payer communication, not an AEAT filing; Modelo 721 registry applicability does not by itself imply a complete filing service. These refusals should remain visible when describing breadth rather than being hidden behind a count of model schemas or commands. No-submit gate (`src/cadrumo/core/access_gate/gate.py`), local workflow (`src/cadrumo/application/workflow/engine.py`), censal parser (`src/cadrumo/adapters/inbound/censo/parser.py`), apoderado (`src/cadrumo/application/auth/apoderado_service.py`), M145 (`src/cadrumo/application/modelo/m145_communication.py`), [analyses](../articles/118-live-access-policy-corpus-integrity-and-decimal-contracts.md), [037](../articles/037-authentication-certificate-sources-and-diagnostic-privacy.md).

A typical end-to-end journey therefore starts by proving access to one profile and reviewing its setup, imports transactions or invoices with provenance, resolves evidence and classification, creates a Modelo work unit for one period, calculates a draft from pinned sources, and verifies the exact revision. The operator can then produce a local official-layout file and upload it through AEAT outside Cadrumo. Later, authenticated read/capture and receipt reconciliation may establish whether the external system recorded that return. At any point, an incomplete profile, stale ledger, missing casilla, unsupported producer, absent live session or ambiguous receipt can stop promotion to the next grade. The product has useful read-only inspection paths at many of those stops; those paths should be described as guidance, not as a completed filing. Preparation (`src/cadrumo/application/modelo/_calculation_preparation.py`), verification (`src/cadrumo/application/modelo/verification_actions.py`), local artifact (`src/cadrumo/application/modelo/export.py`), reconciliation (`src/cadrumo/application/modelo/filing_chain_reconciliation.py`), [full topic](../topics/modelo-work-and-revision-lifecycle-part-1.md).

The knowledge bundle has 58 model identifiers and 68 named revisions in 2,140 registry files, alongside official artefacts, manuals, normative text, examples, terminology and four locale trees. This is strong evidence of authored scope, not evidence that every model has complete live producers or a current accepted export. The declared year policy has a 2022 floor and 2026 advisory horizon, and the 2026 Modelo 303 revision candidly lacks a fresh-render reproduction and legal attestation. The source review was representative for large assets and did not perform current-law validation, live AEAT transactions or product tests. Read each capability together with its specific source, registry revision and evidence grade.
