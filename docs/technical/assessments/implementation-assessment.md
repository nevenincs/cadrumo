## Judgment and evidence level

Cadrumo is thoughtfully structured and unusually explicit about uncertainty, authority and custody. The reviewed source has a coherent progression from typed inbound observations, profile and ledger facts, a pinned versioned registry, calculation and verification, local export, and separately authenticated AEAT observations. It uses exact-profile operations, immutable domain records, revision-guarded storage, legal/source references and named refusal states rather than treating every parsed value as filing-ready. That is a positive implementation assessment for the *design and inspected code*. It is not a certification of calculations, current law, deployed security or live integrations. The snapshot review read 206 bounded Stage 2 reports and produced 18 topic syntheses; a static AST pass parsed 3,025 Python files without parse errors or unresolved internal module import targets, and 2,141 registry syntax files parsed. These checks establish coverage and syntax, not executing behavior or semantic correctness ([review scope](../evidence/run.json), [architecture of authority](../topics/tax-calculation-domain.md), [core contracts](../topics/core-authority-and-shared-controls.md)).

The most convincing strengths are concrete. The installed runtime binds native peer, profile, session and operation authority at multiple points; the operation supervisor records uncertain effects rather than pretending interrupted work failed safely. Encrypted secure objects use namespace/key/schema associated data and compare-and-swap writes. The registry selects one read-only, digest-checked generation for a filing snapshot; formula results retain operands and legal/source traces, and unsupported producers or missing facts can refuse. Ledger/invoice workflows distinguish imported bytes, model proposal, deterministic grounding, operator confirmation, local draft, official-format file, local filing and externally supported receipt. These are actual source-level gates and types, not merely prompt advice (runtime authority (`src/cadrumo/entrypoints/runtime/operation_authority.py`), operation settlement (`src/cadrumo/application/operations/_supervisor_settlement.py`), secure write (`src/cadrumo/adapters/persistence/storage/sql/_secure_object_writes.py`), registry snapshot (`src/cadrumo/domain/calculations/registry/snapshot.py`), invoice confirmation (`src/cadrumo/application/ledger/invoice_confirmation.py`), [runtime synthesis](../topics/runtime-tui-and-agent-harness.md), [ledger synthesis](../topics/ledger-invoices-and-registers.md)).

Scope is also communicated candidly in many places. A censal certificate parser refuses pending source-backed layout, agricultural simplified-regime rows refuse the missing official code crosswalk, M123 and M193 have explicit calculation/export gates, and the live AEAT write gate is an unconditional refusal. Google workbook sync is a remote write with potentially uncertain partial effect, while local XLSX/export is a file. A reviewed corpus or generated form layout is not external legal certification. This refusal vocabulary materially reduces overclaiming, provided every UI and worker preserves it (censal refusal (`src/cadrumo/adapters/inbound/censo/parser.py`), agricultural refusal (`src/cadrumo/domain/iva/regimen_simplificado_rows.py`), M123 gate (`src/cadrumo/application/modelo/m123_count_authority_gate.py`), AEAT write gate (`src/cadrumo/core/access_gate/gate.py`), [model lifecycle synthesis](../topics/modelo-work-and-revision-lifecycle-part-1.md), [knowledge synthesis](../topics/bundled-knowledge-and-localization.md)).

## Prioritized findings

The following are the strongest actionable code findings after preserving known mitigations. “Local” means the behavior follows from the named function; a user-visible or filing impact still depends on the stated producer and caller path. They are ordered by the combination of certainty and practical consequence, not by a numerical severity score.

| Prioritized finding, evidence and scope | Verification or correction |
| --- | --- |
| **1. Locked-other-profile calendar rows are omitted.** In `_calendar_other_profiles`, the comprehension shadows the input `bucket_id` and tests `bucket_id != bucket_id`, which is always false. The returned locked-profile collection is empty whenever this helper is used. This does not invalidate the active profile's filing rows or prove an obligation was missed, but it removes the promised visibility of other locked profiles from that survey. High confidence local defect (source (`src/cadrumo/entrypoints/overview_read_composition.py`), [Stage 2](../articles/155-entrypoint-operation-and-read-composition.md), [operator topic](../topics/operator-interfaces-part-1.md)). | Compare the iterated key with the outer selected profile ID, then exercise a survey containing one active and one locked profile. Check the resulting operator label and count. |
| **2. A reused opening IVA credit can disappear from one balance projection.** The carry-forward builder consumes an `opening_balance` against applications but returns only current/generated lots and `opening_applied_amount`; unused `opening_remaining` is not in the report. A positive opening argument with no states therefore produces no balance lot. A separate operator-declared state can create a lot, so the result is not universally wrong; the impact is conditional on callers treating the returned lot sum as the complete wallet without independently carrying prior credit. The AEAT 303 capture adapter's `refunded=False` assumption is a separate provenance issue that reconciliation must resolve. High confidence local arithmetic/reporting gap; end-to-end impact unproven (builder (`src/cadrumo/domain/iva_compensation/carry_forward.py`), balance (`src/cadrumo/domain/iva_compensation/balance.py`), operator-declared lot (`src/cadrumo/domain/iva_compensation/carry_forward.py`), capture assumption (`src/cadrumo/adapters/outbound/aeat/sede/declarations_observations.py`), [Stage 2](../articles/145-iva-compensation-carry-forward-and-filing-receipts.md), [business topic](../topics/business-and-taxpayer-domain.md)). | Trace every wallet caller and opening source. Add cases with opening greater than, equal to and less than applications, with and without period states; represent remaining prior credit explicitly or document a required separate input. Test refund evidence in captured 303 history. |
| **3. Authentication lock recovery can remove a replacement lock.** `_remove_lock_file_if_unchanged` compares contents only when `expected` is not `None`. If the first inspection was unreadable, a later readable lock can be removed without a byte comparison under the stale verdict. That interleaving can undermine exclusion even though session acquisition probes before and after locking. High confidence in the local race; frequency and production effect require concurrent-process testing (source (`src/cadrumo/application/auth/acquisition_lock.py`), session probes (`src/cadrumo/application/auth/sessions.py`), [Stage 2](../articles/039-authenticated-session-lifecycle-and-identity-binding.md), [auth topic](../topics/authentication-and-storage-management.md)). | Refuse removal when expected bytes are unavailable and current bytes are readable, or make replacement generation/inode part of the witness. Exercise unreadable → peer replacement → recovery on target platforms. |
| **4. “Unchanged” ledger evidence needs a field-set-qualified verdict.** New application snapshots use V2 fingerprints, adding IVA deduction classification, prorrata and related fields that V1 omitted; unknown versions refuse. That is an existing mitigation. Older V1 snapshots cannot truthfully assert those later fields were unchanged. The domain `diff_ledger_fingerprints` builds a verdict without setting `covers_current_fact_set`, whose model default is `True`, so a direct call can overstate V1 coverage unless an application wrapper corrects it. Medium-high confidence local compatibility defect; check the actual caller's override before claiming a misleading filing verdict (V1/V2 sets (`src/cadrumo/application/aggregation/ledger_filing_snapshot.py`), domain default/diff (`src/cadrumo/domain/modelos/ledger_filing_snapshot.py`), [Stage 2](../articles/147-ledger-evidence-detail-rows-and-modelo-verification.md), [aggregation topic](../topics/aggregation-and-calculation-services.md)). | Pass snapshot field-set version into the verdict or compute coverage in the diff. Test a V1 snapshot whose `input_classification` changes while monetary fields stay constant, plus a V2 control. |
| **5. Some unavailable reads become healthy-looking emptiness.** Pending-obligation projection logs a schedule error then returns an empty tuple; a secure-object integrity probe can yield an empty `OK` row when its repository cannot be reached, although a separate warning may reveal the outage. A review source can similarly appear empty after a tax-ID resolution failure. These are local presentation choices, not proof that workflow filing gates ignore a real obligation. Medium confidence risk of operator misinterpretation, dependent on whether the surrounding status is rendered prominently (schedule fallback (`src/cadrumo/application/state_projection.py`), repair report (`src/cadrumo/application/diagnostics.py`), review adapter (`src/cadrumo/application/review/source_adapters.py`), [Stage 2](../articles/028-runtime-admission-canonical-state-and-storage-route-policy.md), [application topic](../topics/application-orchestration-and-diagnostics.md)). | Carry `UNAVAILABLE` through the public result and test storage/schedule exceptions in CLI and TUI, including the difference between no rows and a failed source. |
| **6. Derived financial values need exact source pairing at admission.** The Renta deductible-expense observation builder checks category and eligibility but not result transaction ID, invoice ID or profile year against its supplied fact; it can combine the fact's identity with another result's amount. The transaction model checks FX rate/value co-presence but not `native amount × rate = rounded EUR`; an importer may enforce that equation first. These are distinct local contracts illustrating the same integration requirement: derived monetary evidence must be joined to its exact source and date before a filing-grade binding. Medium-high confidence local omissions, conditional production reachability (expense builder (`src/cadrumo/domain/renta/ledger_expenses.py`), FX validator (`src/cadrumo/domain/transactions/models.py`), [Stage 2 expense](../articles/149-renta-expense-rules-and-activity-asset-amortization.md), [Stage 2 transactions](../articles/151-transaction-ledger-domain-and-classifier-contracts.md), [business topic](../topics/business-and-taxpayer-domain.md)). | Add identity/year and rounded-currency equation checks at the public boundary, then test mismatched paired results and imported FX rows through actual application callers. |

Other local findings are real but less suitable as product-wide conclusions without an admission trace. The formula runtime's named external Decimal guard is a no-op and the Gasto193 nonnegative method is not an active model validator; type-correct, upstream-validated callers may still protect the path. Stored descendant hydration accepts permissive boolean values and can omit incomplete rows, while its CLI parser is strict; the profile write/decode boundary decides whether malformed stored rows can reach calculation. A Modelo 720 row materializer chooses one set cohort if multiple asset-class filters coexist, but the selected registry revision may enforce one cohort. These should be regression tests at the producer/consumer join, not unsupported statements that filed returns are wrong (Decimal guard (`src/cadrumo/domain/calculations/registry/formula_runtime_ops.py`), stored family facts (`src/cadrumo/domain/contribuyente/descendant_facts.py`), 720 cohort (`src/cadrumo/domain/calculations/registry/detail_record_bindings.py`), [tax-domain topic](../topics/tax-calculation-domain.md), [Stage 2](../articles/129-formula-evaluation-traceability-and-row-source-bindings.md), [Stage 2](../articles/139-taxpayer-and-family-domain-records.md)).

The same restraint applies to security and cloud leads. Generic LLM dispatch does not itself compare consent token to bytes, but the canonical ledger operation does bind stored evidence, fresh acknowledgement, source hash and loaded-byte digest; no reachable bypass was shown. Pydantic validation details may contain rejected input at a logging call, but recursive scrubbing and handler filters stand between that call and disk. A telemetry CLI effect label omits network even though the actual send has consent and endpoint gates; metadata mismatch is established, enforcement escape is not. Prompt rules, schema descriptions, source citations and typed helper constructors are useful documentation or contracts, not proof every caller enforces them (canonical consent (`src/cadrumo/application/ledger/invoice_evidence_extract_operation.py`), log filter (`src/cadrumo/core/logging.py`), telemetry command (`src/cadrumo/entrypoints/cli/_app_diagnostics_command_specs.py`), [review leads](../evidence/review-questions.md), [security synthesis](security-and-trust-boundaries.md)).

## What remains to validate

The most valuable next evidence is targeted execution of the six conditions above through production composition, followed by crash/race exercises for acquisition locks, profile custody, multi-store invoice confirmation and Google multi-request writes. Registry publication should validate source provenance and recent generated layouts against the exact official edition; a successful syntax parse or agent review token is not legal attestation. Application tests should verify that the operator sees `UNKNOWN`, `UNAVAILABLE`, partial remote effects, stale authority and refused model coverage rather than a plausible empty/success state. These recommendations arise from the reviewed boundaries, not an assertion that the test suite or build process was absent from the original project (registry review note (`src/cadrumo/_data/registry/aeat/modelos/303/revisions/2026-y-siguientes/revision.toml`), uncertain operation state (`src/cadrumo/application/operations/_supervisor_reconciliation.py`), Google apply (`src/cadrumo/adapters/outbound/google/calc_sheets_apply.py`), [method](../evidence/run.json)).
