## Scope and sampling method

This chunk inventories 876 files totaling 290,532,686 bytes (about 290.5 MB) under `corpus/aeat_official`. The inventory metadata was parsed for every file; I did not load the full PDF, Excel, or extracted-text collection into context. I sampled across the record-design archive, current calendar and procedure pages, official blank forms, SII/VERI*FACTU schemas, identity references, GROI response fixtures, retired-model notice, tax-law update notice, and Renta Web Open page. Within the workbook subset I sampled a current Modelo 303 layout and a large Modelo 200 layout, including bounded parts of their generated sidecars. The complete source-link appendix is generated from the chunk manifest; it is inventory coverage, not a claim that all 876 contents received semantic review.

## Corpus capabilities and sampled behavior

The largest section is `disenos_registro`: 731 files and about 271.8 MB. Its top-level catalog identifies 58 model directories and 254 source artifacts, while the larger on-disk count includes original workbooks/PDFs, extracted JSON/Markdown sidecars, correction metadata, and per-model manifests. The catalog records source pages, retrieval dates, file names, sizes, and SHA-256 values. It spans current and historical model layouts. For example, the archived 2026-and-later Modelo 303 record design defines a fixed-width exchange with record/page discriminators, field positions and lengths, field types, validations, and permitted period shapes; it also marks its use from exercise 2026. Its generated extraction is divided into seven sections. The sidecar reports `status: ok`, and its source hash matches the archived workbook. The 2025 Modelo 200 archive similarly includes a 11.5 MB XLS workbook and an extraction with 77 sections whose source hash matches; older annual models are retained as PDF revisions. These formats can support reading and producing official filing exchange layouts, but this chunk does not establish which parser/exporter consumes them or whether the extracted fields agree with every source page. See the record-design catalog (`src/cadrumo/_data/corpus/aeat_official/disenos_registro/manifest.json`), Modelo 303 manifest (`src/cadrumo/_data/corpus/aeat_official/disenos_registro/modelo_303/manifest.json`), archived 2026 Modelo 303 workbook (`src/cadrumo/_data/corpus/aeat_official/disenos_registro/modelo_303/files/01-303-ejercicio-2026-y-siguientes-actualizado-28-01-26-378-kb-xlsx.xlsx`), its extracted record-layout text (`src/cadrumo/_data/corpus/aeat_official/disenos_registro/modelo_303/files/01-303-ejercicio-2026-y-siguientes-actualizado-28-01-26-378-kb-xlsx.xlsx.extracted.md`), and the 2025 Modelo 200 package (`src/cadrumo/_data/corpus/aeat_official/disenos_registro/modelo_200/manifest.json`).

The 112 files in `instructions` (about 7.4 MB) and nine calendar files (about 10.2 MB) supply operational references. A sampled AEAT 2026 domiciliation page distinguishes monthly from quarterly models and gives separate bank-debit and filing windows; its table includes monthly and quarterly Modelo 303/353 cases, illustrating why cadence and payment method must be read from the dated calendar rather than assumed. The Modelo 303 procedure page is an AEAT workflow/links page rather than a machine schema. The archive also has 121 PDFs and many captured HTML sources and extracted derivatives. Retrieval and publication dates make the material traceable, but the repository snapshot is not a live deadline service. See the 2026 domiciliation calendar (`src/cadrumo/_data/corpus/aeat_official/calendars/files/calendario-contribuyente-2026-domiciliacion.html`) and Modelo 303 procedure page (`src/cadrumo/_data/corpus/aeat_official/instructions/modelo_303/files/modelo-303-procedure.html`).

Ten published-form files include blank Modelo 145 and 840 PDFs with extracted text and provenance manifests. The sampled Modelo 145 form communicates a recipient's personal/family circumstances to a payer for withholding; the 840 form covers IAE registration/change/withdrawal. They are document templates and field guidance, not evidence about any taxpayer. A separate `renta_web_open` page expressly describes Renta Web Open as a simulator that does not validate the NIF and cannot submit a return. That distinction helps prevent a simulation from being represented as filing. See the Modelo 145 extraction (`src/cadrumo/_data/corpus/aeat_official/formularios_publicados/modelo_145/files/mod145_es_es.pdf.extracted.md`), Modelo 840 extraction (`src/cadrumo/_data/corpus/aeat_official/formularios_publicados/modelo_840/files/01-840-modelo-declaracion-iae-alta-variacion-baja-pdf.pdf.extracted.md`), and Renta Web Open page (`src/cadrumo/_data/corpus/aeat_official/renta_web_open/renta-web-open.html`).

The five-file `einvoice_record_schemas` directory is more precisely a set of SII and VERI*FACTU AEAT record-supply web-service schemas, not document-level e-invoice formats; the manifest points to the separate Facturae corpus for that. The manifest says the exact family directory and original filenames are load-bearing because both families import `SuministroInformacion.xsd` by relative name. Static XML parsing confirmed that each family has its own same-named base schema and target namespace, and that each `SuministroLR.xsd` imports its local base. SII's envelope declares 17 top-level record elements; the sampled VERI*FACTU envelope declares one. The manifest dates this single snapshot to 2026-08-07 and notes that the schemas expose no version attribute, so the bundle cannot independently identify a later protocol revision. I checked XML well-formedness and the import structure only; no XML Schema engine or remote imports were executed. The manifest says VERI*FACTU is included for a refusal path rather than a product capability, which is a stated scope rationale rather than independently verified consumer behavior. See the schema manifest (`src/cadrumo/_data/corpus/aeat_official/einvoice_record_schemas/manifest.json`), SII envelope (`src/cadrumo/_data/corpus/aeat_official/einvoice_record_schemas/sii/SuministroLR.xsd`), and VERI*FACTU envelope (`src/cadrumo/_data/corpus/aeat_official/einvoice_record_schemas/verifactu/SuministroLR.xsd`).

The sampled 2022 Modelo 220 `.xlsm` has an external-workbook relationship targeting `DR220e22_5.xlsm`; that target is not among the archived Modelo 220 files. The ZIP package did not contain a `vbaProject.bin`, so this sample did not show an embedded VBA project, but spreadsheet software could still offer or attempt to refresh the external link. Any preview/import workflow should suppress automatic link updates and keep parsing isolated. This observation is limited to one workbook and is not evidence that a product path opens it. See the archived 2022 Modelo 220 workbook (`src/cadrumo/_data/corpus/aeat_official/disenos_registro/modelo_220/files/02-220-ejercicio-2022.xlsm`).

The three identity pages provide NIF/NIE composition and check-digit guidance. Two are AEAT pages; the third is a DGOJ page stored under the AEAT corpus directory. That DGOJ HTML contains inline JavaScript and a remote Matomo tracker URL. Nothing here proves that the product renders the page, but any path that opens it as active HTML should treat it as executable remote-origin content rather than passive text. The 3-file GROI sample set is more explicit about provenance: its audit note says the small response fragments were captured from the authenticated AEAT service on 2026-05-07 and that raw capture artifacts are not committed. The sample set includes a positive operator response and an invalid-NIF refusal, which can help anchor parser behavior but does not cover the service's complete response vocabulary. See the identity references (`src/cadrumo/_data/corpus/aeat_official/identity/aeat-nif-personas-fisicas.html`), DGOJ reference (`src/cadrumo/_data/corpus/aeat_official/identity/dgoj-nif-nie-control.html`), and GROI provenance (`src/cadrumo/_data/corpus/aeat_official/groi_response_samples/PROVENANCE.md`).

The corpus also contains one retired-Modelo-037 notice, one April 2026 AEAT note about the tax effects of two Royal Decree-Laws, and other official forms and service pages. These are time-sensitive references. The retired-model notice is stored as a 24,141-byte single-line `.txt` file that fails strict UTF-8 decoding (a replacement decoder reports 134 replacement characters); its initial text contains a BOE page and HTML entities. A consumer must not assume this particular file is clean, line-oriented UTF-8 without checking its actual decoding path. See the retirement notice (`src/cadrumo/_data/corpus/aeat_official/historical_retired_modelos/modelo_037/files/BOE-A-2025-410-orden-hac-1526-2024-supresion-m037.txt`) and 2026 tax-effects note (`src/cadrumo/_data/corpus/aeat_official/notices/aeat-nota-efectos-rdl-16-2025-rdl-2-2026.html`).
