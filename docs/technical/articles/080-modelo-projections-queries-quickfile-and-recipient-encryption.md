## Capabilities and mechanisms

The projection service gives an operator a locally calculated Modelo 100 estimate based on Modelo 130 quarter work, and lets them compare saved calculations from two years. For the estimate, it resolves a dated `modelo-100-m130-projection-mapping` under the pinned registry authority and gathers the latest calculated revision for eligible Modelo 130 work units. It treats casillas 01/02/03 as cumulative year-to-date quantities, takes the latest available quarter rather than adding cumulative snapshots, and sums quarterly casilla 19 payments. When the latest quarter is before Q4, it annualizes accumulated net income by `4 / quarter ordinal` and marks the result as extrapolated. It then assembles a synthetic Modelo 100 0A snapshot, resolves revision-declared and profile-derived bindings, applies caller overrides, and runs the canonical snapshot calculation. The output carries the selected source revisions and calculation provenance; it is a projection, not a filed return or a persisted M100 work revision. Quarter selection and projection inputs (`src/cadrumo/application/modelo/projection.py`), annualization (`src/cadrumo/application/modelo/projection.py`), M100 snapshot projection (`src/cadrumo/application/modelo/projection.py`)

Year comparison requires exactly two years and chooses each year's latest `VERIFICADO_COMPLETO` revision when one exists, otherwise its latest `BORRADOR` revision. It reports per-casilla values, deltas, percentage changes and provenance; an absent casilla is treated as zero, and a zero baseline has no percentage change. This compares local calculation history rather than independently retrieved official filings. Revision choice (`src/cadrumo/application/modelo/projection.py`), year-pair comparison (`src/cadrumo/application/modelo/projection.py`), comparison result assembly (`src/cadrumo/application/modelo/projection.py`)

The project and compare operation wrappers expose typed, credential-free requests and result projections. Before either read, they prepare a legacy projection-revision migration plan across the stored revision catalogue, conditionally commit a changed plan with compare-and-swap, and guard against reading while legacy rows remain. This makes these operations capable of a storage mutation despite their projection purpose; their access declaration consequently requires all periods, and the recorded effect distinguishes no change, completed update, or uncertain outcome. The migration boundary itself is a port, keeping repository implementation outside this service. Migration plan contract (`src/cadrumo/application/modelo/projection_migration_ports.py`), read guard and migration commit (`src/cadrumo/application/modelo/projection_operation.py`), operation preparation and executors (`src/cadrumo/application/modelo/projection_operation.py`)

The prorrata module contributes targeted diagnostics to quarterly and annual Modelo 303 work. It can identify missing carry-forward data for later periods, resolve the prior year's official definitive percentage, and provide a Q4/annual regularization advisory from the current-year ledger and registry-selected casillas. Where prior percentage or source classifications are unavailable, it returns a pending or classification diagnostic rather than inventing a settlement value. It separately checks whether annual classified activity triggers the mandatory special-prorrata threshold and only invokes the canonical calculation advisory when its inputs are adequately classified. Sectorized and unresolved-total cases have explicit v1 deferrals. Annual settlement diagnostics (`src/cadrumo/application/modelo/prorrata_regularizacion_advisory.py`), combined diagnostics (`src/cadrumo/application/modelo/prorrata_regularizacion_advisory.py`), mandatory special-prorrata check (`src/cadrumo/application/modelo/prorrata_regularizacion_advisory.py`), missing carry diagnostics (`src/cadrumo/application/modelo/prorrata_regularizacion_advisory.py`)

Pulled-filing reconciliation answers a narrower question than calculation-engine drift: for casillas with separately supplied local evidence, does the current local calculation agree with this profile's pulled official filing observation? It validates the observation envelope, resolves the selected law snapshot, and uses the verification tolerance policy for each populated comparison. It emits no finding when there is no pulled filing, no resolved snapshot, or no local evidence population, avoiding a broad comparison full of unsupported differences. Pulled filing value validation (`src/cadrumo/application/modelo/pulled_filing_reconcile.py`), scoped divergence findings (`src/cadrumo/application/modelo/pulled_filing_reconcile.py`)

The query operations expose four operator reads: list declared bindings, preview a binding resolution with unsaved overrides, inventory what a model requires, and calculate filing readiness. The list can filter by model/year/period/as-of and missing status; resolve is exact to a filing period, accepts only unique declared override IDs and does not save them. The requirements inventory groups manual, ledger, profile-derived, prior-filing, relationship-prefill, live-observation and unresolved-profile inputs. Readiness pins the selected revision and combines its requirements with profile and ledger diagnostics. When a missing-only filter cannot resolve a profile read, the list errs toward showing the binding as missing. Binding list and resolution (`src/cadrumo/application/modelo/query_read_operation.py`), unsaved resolve preview (`src/cadrumo/application/modelo/query_read_operation.py`), requirements and readiness (`src/cadrumo/application/modelo/query_read_operation.py`), profile-scoped period authorization (`src/cadrumo/application/modelo/query_read_operation.py`)

Quickfile sequences readiness, create-or-resume, calculate, verify, and local export by delegating to the existing stage services. Readiness failure is a warning and does not itself stop the chain; a typed access refusal still escapes, while a later calculation can satisfy required inputs through caller overrides. A refusal halts the chain and marks later stages skipped. Verification must grant `VERIFICADO_COMPLETO` before export. The terminal output is a local fichero-BOE file for a human to file; the orchestrator does not submit it to AEAT. Stage order and outcomes (`src/cadrumo/application/modelo/quickfile.py`), chain entrypoint (`src/cadrumo/application/modelo/quickfile.py`), stage services and gates (`src/cadrumo/application/modelo/quickfile.py`), verify and export stages (`src/cadrumo/application/modelo/quickfile.py`)

The public quickfile operation is CLI-only and bound to one profile and natural filing period. Its hidden-input request requires an absolute local output path, constrains the model code, and carries only declared calculation channels; Modelo 303 requires ordinary-filing evidence that is authored from the supplied attachment store. A commit fence counts completed local writes, preserving `PARTIAL` if a later stage refuses and `UNKNOWN` after an uncertain write. The public projection omits raw exception prose and arbitrary context, publishing registered error identities and typed recovery verdicts instead. It validates the complete stage order, stop/skipped pattern, profile/model/period consistency, output and verification targets, and operation receipt/effect before disclosure. Request contract (`src/cadrumo/application/modelo/quickfile_operation_contracts.py`), M303 evidence and profile-bound inputs (`src/cadrumo/application/modelo/quickfile_operation.py`), write accounting and executor (`src/cadrumo/application/modelo/quickfile_operation.py`), public result invariants (`src/cadrumo/application/modelo/quickfile_operation_projections.py`), human-only scoped registration (`src/cadrumo/application/modelo/quickfile_operation.py`)

Recipient encryption defines the application boundary used by review-package flows: bucket-scoped keypair acquisition, sealing bytes for a recipient public key, and opening an envelope with private key material. Its versioned DTO checks 64-character hex key/nonce fields, non-empty ciphertext, optional expiry after issue time, and JSON ciphertext serialization as hex. The protocol leaves persistence and cryptographic implementation to an outward adapter, so this contract alone does not establish an algorithm, authentication guarantee, key rotation policy, or enforcement of expiry during decryption. Envelope and validation rules (`src/cadrumo/application/modelo/recipient_encryption.py`), capability and adapter boundary (`src/cadrumo/application/modelo/recipient_encryption.py`)

## Knowledge, safety, and implementation assessment

These capabilities depend on the pinned calculation registry, dated mappings, profile bindings, work revisions, ledgers, and pulled official observations. Their legal identifiers and comments were not checked against current law. The projections make provenance visible, and the query surfaces are deliberately read-only except for the projection migration. Quickfile adds strong local controls: exact profile/period admission, human authorization, per-stage re-admission, separated mutation admission, concrete write accounting, encrypted request custody, and a closed public result schema. It still writes a user-selected path; this chunk checks that the path is absolute but does not itself establish that it is inside an application-managed directory. The actual export service's filesystem policy is a cross-module dependency to verify.

The projection's `quarters_filed` field is populated from the number of usable quarter revisions found in work-unit history, while the source path is described as selecting `BORRADOR` work units. That name can be read as evidence of filed quarters even though this path is local work-unit availability; consumers should treat it as a count of available inputs unless another layer establishes filing status. Early-year linear annualization is explicitly marked, but remains a rough estimate whose usefulness depends on seasonal activity and the supplied binding/override population. Comparison's missing-as-zero rule is clear but collapses “not recorded” and a genuine zero in its displayed delta. Quarter-source selection (`src/cadrumo/application/modelo/projection.py`), comparison row computation (`src/cadrumo/application/modelo/projection.py`)

The reconciliation path is intentionally conservative, but its observation-envelope validation and law snapshot resolution use separately resolved authority reads in this module; confirm that callers keep them on a coherent generation or that cross-generation observations are rejected. Prorrata's explicit sectorized/unclassified deferrals need to stay visible to the operator for the advisory to be useful. The query capability declarations also matter to frontend reach: binding list and requirements are explicitly exposed to MCP, while binding resolution and readiness use the default CLI/TUI set. The recipient encryption DTO's validation is useful shape checking, not proof of cryptographic security; those claims require inspection of the concrete adapter and review-package callers.

Important follow-up edges are projection-to-registry/work-revision provenance, prorrata-to-ledger classification and official-observation freshness, reconciliation-to-authority-generation selection, quickfile-to-export filesystem safeguards and stage repositories, and the encryption contract's concrete storage/crypto adapter. The chunk contains no tests, so none of these behaviors was exercised in this pass.
