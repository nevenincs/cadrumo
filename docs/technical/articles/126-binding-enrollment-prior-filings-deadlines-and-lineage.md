## Binding enrollment and authored contracts

`BindingProviderRegistration` is a single domain table that associates each closed binding-provider union member with its model, build-time validator, value channels, aggregation operations, terminal-origin classes, output shape, filing disposition, route owner, and authoring support. It explicitly distinguishes filing-grade providers, the non-runtime manual/design-constant pseudo-owners, and providers whose routes are deferred. Import-time checks require exact union coverage, unique kinds, model/tag agreement, coherent channels/output, nonempty operation/origin declarations, and a disposition consistent with route ownership. A second recursive structural check refuses provider fields that pin absolute years, dates, or revision IDs, except the provider's purpose-built temporal member and named layout coordinates. Application route-table agreement is intentionally checked across the domain/application boundary elsewhere. ## Source resolution, provenance, and temporal folds

Binding value contracts keep legal data type separate from transport channel, with a fixed mapping (e.g. money travels as decimal) and an optional row-grouping axis. Terminal-origin expectations say what provenance nodes a resolved value must rest on; defaults derive from provider registration and distinguish exactly-one from one-or-more origins and when a fingerprint is required. Reverse target indexing reports casilla, formula, date-formula, export-field, and binding-record consumers, returning empty consumer tuples for true orphans. `CasillaObservation` preserves typed values and formula operand/legal/source traces; `RegistryModeloObservation` ties observed casilla values to model/year/period. Alternate bound sources are accepted only when every available value agrees exactly, and the numeric projection skips text casillas. Previous-filing bindings derive source anchors relative to the target context, collect typed fold requirements with binding IDs, casilla IDs, legal/source references, and dependency treatment, then resolve against observed filed declarations. A missing whole filing is an unsatisfied input, not a malformed-registry error; a duplicate matching filing or missing required source casilla refuses. If any required anchor is absent, the binding yields no partial sum. A source period wholly before activity start can be scoped out as neutral zeros. The specialized `prior_pagos_fraccionados` fold processes per-quarter `(casilla 07, casilla 16)` pairs as `sum(max(0, 07)) - sum(16)`, after build-time cardinality checks. The deadline CCAA catalogue resolves a dated territorial set broader than tax residence, then validates its explicit one-to-one mapping from common-regime tax-residence tokens to autonomous communities. ## Assessment and follow-up

The strongest local design is the use of linked contracts rather than parallel informal tables: a provider is typed, enrolled, checked against permitted value/origin shapes, routed or explicitly deferred, then audited against runtime provenance. Relative temporal selectors and whole-binding refusal on incomplete anchors reduce accidental cross-period substitution and partial undercounting. Security here is primarily registry-data integrity and consistency; the files do not authenticate taxpayers or perform filing actions. They handle financial/tax identifiers and official record coordinates but contain no credential or live-network surface. Import-time structural checks and validators are defined, but this review did not execute them.

Synthesis should connect the registration table to the application route map and verification/audit consumers, confirm that deferred providers cannot be selected for filing-grade calculations, examine every use of the Unicode alpha helper, and decide whether `run_digest` needs a digest-specific type or merely clearer “run token” naming. It should also verify exception-set maintenance and the separate checks that assess grounded lineage and origin evidence. Embedded tax and design references remain unverified claims from code comments.
