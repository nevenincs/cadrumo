## Capabilities and flow

`fetch_censal_datos` loads the authenticated browser state and visits the access selector. It is designed to read the taxpayer’s identity and fiscal/notification addresses from AEAT’s rendered tables. The parser distinguishes three table families by their `title`, folds label accents and qualifiers, supports row-paired identity fields and column-aligned addresses, parses birth date and notification flags, then validates a typed `CensalObservation` with capture time and source URL. The live route allows one selector authorization click, then requests the censal page and checks the actual landing for known modification-path markers before parsing. It treats an empty parse as a wrong service/auth/maintenance landing unless the rendered page also carries a censal heading marker; it does not treat that case as an ordinary empty record (censal_datos.py (`src/cadrumo/adapters/outbound/aeat/sede/censal_datos.py`), censal_datos.py (`src/cadrumo/adapters/outbound/aeat/sede/censal_datos.py`), censal_datos.py (`src/cadrumo/adapters/outbound/aeat/sede/censal_datos.py`), censal_datos.py (`src/cadrumo/adapters/outbound/aeat/sede/censal_datos.py`)).

## Evidence, security, and assessment

The Sede adapters rely on `RemoteStateGuardPolicy` for explicit HTTP/browser-action allow-lists, but form controls cross a separate boundary: browser POSTs do not pass through an HTTP request guard. The GROI driver addresses this by checking both the declared form action before clicking and the actual post-submit landing. Declarations checks the landing after `Buscar` and restricts it through a per-surface path prefix. Censal permits only the selector’s authorization control and never clicks or fills controls on the censal page; its runtime marker rule identifies known write siblings, including the M036 launcher and address-modification paths. The censal host policy allows AEAT subdomains because the selector dispatches to a numbered host pool; the module documents that the pool has not yet been measured for this route (censal_datos.py (`src/cadrumo/adapters/outbound/aeat/sede/censal_datos.py`), censal_datos.py (`src/cadrumo/adapters/outbound/aeat/sede/censal_datos.py`), declarations.py (`src/cadrumo/adapters/outbound/aeat/sede/declarations.py`), groi_check.py (`src/cadrumo/adapters/outbound/aeat/sede/groi_check.py`)).

Registry capture preserves provenance at several levels: artefacts carry hashes and capture time; extracted fields carry source type, source locator, and value kind; registry observations are rebound to a selected revision’s casilla definitions and references. Submitted payload coordinates are checked against the declaration row before values are accepted. Application ports stage deferred artefact bytes and expose them for one-time persistence only after the caller enters its effect fence; the port also obtains an active verified session under operator-scope/effect-guard inputs. Persistence adapters wrap a secure-object-backed observation store, and IVA state uses the dedicated calculation-envelope/history co-commit path. The cryptographic and storage implementation of those repositories is outside this chunk. Two censal-data boundaries merit caller-level review. First, `taxpayer_nif` is documented as the authenticated taxpayer’s own identifier, but this module accepts it as an argument and does not compare it with `session.identity_nif`; the caller binding is therefore not established here. Second, after checking the real landed URL, `_navigate_and_parse` passes the earlier requested URL into `parse_censal_datos` as `source_url`. If AEAT redirects the page to another allowed host while retaining a valid read page, the recorded provenance can name the requested host rather than the host that answered. The register’s post-search wait is a configured fixed delay before the page is parsed.
