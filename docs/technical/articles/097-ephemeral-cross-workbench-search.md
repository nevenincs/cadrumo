## Capabilities and mechanisms

This package assembles a search snapshot from already-loaded, already-admitted Ledger, declarations, AEAT-sync, and Modelo workspace projections. It does not fetch data or determine destination access. The one-shot assembler requires the supplied admissions to name `workbench.ledger`, `workbench.declarations`, and `workbench.aeat_sync`; callers create a fresh snapshot when new workspace projections become authoritative. Snapshot assembly (`src/cadrumo/application/search/installed_workbench.py`), input generation and destination checks (`src/cadrumo/application/search/installed_workbench.py`), assembly entry point (`src/cadrumo/application/search/installed_workbench.py`)

The installed projection covers ledger entries and stale evidence; declarations, calculation revisions, filings, and filing history; AEAT reconciliation findings and notifications; and each Modelo workspace. It derives closed status codes from source projection fields and uses natural Modelo/year/period addresses for case-like records. Ledger rows are searchable by counterparty, description, date, amount, and currency, while their transaction IDs remain private identity material. Filing-evidence, lifecycle, reconciliation, and notification IDs likewise remain in the private identity basis rather than the matchable terms. Ledger terms and private IDs (`src/cadrumo/application/search/installed_workbench.py`), declaration, revision, filing, and history projections (`src/cadrumo/application/search/installed_workbench.py`), AEAT-sync projections (`src/cadrumo/application/search/installed_workbench.py`), Modelo availability projection (`src/cadrumo/application/search/installed_workbench.py`)

The query service accepts only closed kinds, sources, statuses, labels, natural-address variants, destination-admission states, and optional action-candidate identifiers. Validators require the kind/source/status/label vocabulary to agree, require exact address types, bind each address year to its period, and require an opaque private identity basis only for multi-record families without natural IDs. Available destinations cannot carry a refusal reason; every non-available destination must carry one and cannot expose an action candidate. Projection vocabulary and addresses (`src/cadrumo/application/search/workbench.py`), cross-field projection validation (`src/cadrumo/application/search/workbench.py`), private identity requirements (`src/cadrumo/application/search/workbench.py`)

Queries are transient strings stripped of surrounding whitespace, limited to 200 characters, rejected if they contain control characters, and required to contain at least one token after Unicode phrase folding. The service tokenizes both query and safe document terms; a match occurs when the normalized phrase is in the label or all query tokens occur among the document terms. Exact and partial label matches score above non-label matches, with additional per-token label weight. Results sort by descending score and then an opaque keyed identity; the caller can request at most 100 results. The response contains only ranked metadata and total match count, never the query or its hashed terms. Transient query validation (`src/cadrumo/application/search/workbench.py`), matching and ranking (`src/cadrumo/application/search/workbench.py`), service snapshot and result construction (`src/cadrumo/application/search/workbench.py`), closed response shape (`src/cadrumo/application/search/workbench.py`)

Identity derivation joins the kind and source with either the natural address coordinates or a secret-wrapped identity basis, then HMACs the canonical UTF-8 coordinate with the module’s private random key. The service captures validated document objects at construction, refuses duplicate derived IDs, and sorts that snapshot once; each request only ranks the captured set. Thus a search call cannot pull in late repository changes, while rebuilding from a refreshed workspace makes a new search generation. Identity coordinate and keyed digest (`src/cadrumo/application/search/workbench.py`), snapshot capture and duplicate check (`src/cadrumo/application/search/workbench.py`)

## Knowledge, security, and implementation assessment

The search service knows only what the composition root placed into its immutable document tuple. It has no repository, persistence, network, localization, or authority dependency. The installed builder carries already-computed readiness and admission facts forward rather than inferring them from raw business records. This keeps search as discovery over a snapshot; opening a result and deciding whether an action is permitted remain destination responsibilities. Installed snapshot boundary (`src/cadrumo/application/search/installed_workbench.py`), destination admission contract (`src/cadrumo/application/search/workbench.py`)

Useful protections include in-memory-only installed snapshots, non-serializable ephemeral snapshot wrappers, secret-wrapped and excluded opaque identity inputs, process-keyed HMAC result IDs, strict closed projection vocabularies, hidden query representations, bounded query and result counts, and response fields that omit search terms. Private identities are derived from either a natural address or an opaque basis; providers cannot assert the outward result ID. Duplicate derived identities refuse service construction. Memory-only installed snapshot (`src/cadrumo/application/search/installed_workbench.py`), identity-keyed construction (`src/cadrumo/application/search/workbench.py`), private identity field and document validation (`src/cadrumo/application/search/workbench.py`), derived result ID (`src/cadrumo/application/search/workbench.py`)

Two limits matter when interpreting “safe projection.” First, `stable_id` is stable only under the current module-process key: the key is randomly generated at import, so IDs are unlinkable across process restarts. That is compatible with an ephemeral palette but unsuitable as a durable bookmark or cross-session identifier. Second, `content_terms` holds the actual counterparty and description strings in the private document. The response omits them and the installed snapshot wrapper refuses Python pickling, but `content_terms` is not itself excluded from the Pydantic document’s ordinary serialization, and this model does not set local length or tuple-count bounds. Callers should not generically dump or log private search documents; source projection bounds and any serialization paths need confirmation. Process-local key (`src/cadrumo/application/search/workbench.py`), document terms and identity field (`src/cadrumo/application/search/workbench.py`), response omission of content terms (`src/cadrumo/application/search/workbench.py`)

This implementation also intentionally does not resolve action candidates or construct navigation links. Search results report the admitted destination and optional candidate token, so the frontend still needs to map the result to a destination and re-check current authority when opening it. Ranking is deliberately simple: there is no typo tolerance, stemming, field weighting beyond title matches, or returned match explanation. No assigned tests were run, so Unicode folding, score ordering, and privacy behavior are assessed from the static code only.
