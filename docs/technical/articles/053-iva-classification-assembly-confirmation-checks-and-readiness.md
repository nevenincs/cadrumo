## Classification and evidence resolution

`classification_assembly` decides whether the domain IVA rule table has enough evidenced facts to run; the rule table itself remains the sole classifier. Each criterion fact can carry its value and source (document evidence, profile authority, or operator assertion). The assembler derives territorial establishment from country evidence, requires Spanish postal evidence to distinguish Spanish IVA territories, and treats an absent country as unresolved rather than silently assuming mainland Spain. It keeps party establishment separate from Member State IVA identification: a printed IVA identifier may establish the latter but does not establish where the party operates. Missing-input demands are mostly lazy: candidate customer-status and supply-kind values are run through the selected, pinned rule table, and an input is demanded when those branches can change the result. Party identification is demanded when a reachable rule says it consumes that fact, even if the category itself stays the same. If earlier placement is incomplete, status and supply nature are reported with the other gaps, while identification waits until the relevant branch is known. A supplied value can be an explicit operator assertion, but it is not silently invented by this module. For ingestion, a machine-readable document category is carried as a declared fact, then compared with the table result and charged domestic rate tier. The resolution can be classified, corroborated, declared, contradicted, unresolved, rate-inferred, or unsupported relief. Contradictions and unsupported relief withhold a category; a relief assertion may be withheld when the evidence has not established the counterparty territory. Rate inference can provide a category when the table cannot place the operation and a charged rate is available. The module explicitly says that this inferred status is not yet persisted or emitted as an operator-visible distinction, so a downstream confirm/result surface should be traced before assuming users can tell that weaker basis from a rule-table classification. `confirm_establishment` is the path that joins both parties to classification: the counterparty’s territory comes from the establishment ladder, the filer’s from profile authority, and direction maps those two facts into issuer/customer slots. It also resolves supply nature from operator assertion, printed citation, or category implication and then assembles/classifies with the same pinned registry operation. If neither profile nor ladder settles an establishment question, it creates a typed review blocker rather than defaulting a territory. However, the module says those review items are currently constructed but no production caller reads them; the category withholding may still be visible through a separate decomposition error, but the explanatory question itself is not surfaced by this function’s consumer. Party identity checks make operator-supplied counterparty NIF an assertion against extracted evidence when both exist; disagreement refuses without echoing either tax ID. Comparison accepts punctuation variants and only discounts the country prefix belonging to that counterparty’s own country. Separate guards refuse a counterparty equal to the filer and an issued invoice whose supplier is not the filer. These latter checks decline to judge when the profile or relevant identifier cannot be loaded, so protection depends on profile setup and the caller actually invoking them. ## Operator operations and readiness

Single classification is a CLI operation with a closed, hidden-input request and explicit `patch_fields` omission mask. It accepts canonical decimal/country values and registry-resolves category, deduction, state, and spending-category codes; it excludes pipeline-owned classification states. The executor resolves the bucket row, computes the canonical patch under the pinned authority, validates a bounded projection before the write, then delegates to the shared update service with an expected-current snapshot. The related operator IVA action starts from a user-selected category and delegates substrate derivation to the existing guarded service; it does not itself select a category with a model. Classify request constraints (`src/cadrumo/application/ledger/classify_operation.py`) Canonical patch mapping (`src/cadrumo/application/ledger/classify_operation.py`) Classify executor (`src/cadrumo/application/ledger/classify_operation.py`) Operator-selected IVA derivation (`src/cadrumo/application/ledger/classify_operation.py`)

Bulk CSV classification uses the same canonical classification service, bounded encrypted request custody, exact profile ports, and a revision-guarded repository. Its commit fence waits at the concrete persistence call rather than fencing the whole calculation; it distinguishes pre-write validation refusals, successful writes, retryable conflicts, and uncertain writer failures before returning a receipt-backed result. This helps avoid reporting a validation refusal after persistence might already have begun. The ledger check is read-only and exact-profile. It runs the readiness preflight for the selected period, or for every year represented by transaction dates when no period is given, and independently checks bidirectional invoice links. `ready` is true only when both findings sets are empty. Even when a period is selected, link inconsistencies are bucket-wide, so the access resolver requests whole-profile authority rather than period-only disclosure. The check is available through CLI, TUI, and MCP registrations. Arithmetic closure checks report internal document disagreements at read time: total against base plus IVA/recargo/suplidos, cash against total less withholding in the corresponding draft path, per-tier and flat-rate identities, and per-rate sums against the flat totals. Missing terms suppress a check rather than being treated as evidence of zero. Tolerance is a fixed cent per stated contributing term; the result is “these identities that could be checked agree,” not proof that the document or transcription is correct. ## Knowledge, trust, and assessment

The semantic column-role module is an inward port: an outer composition scope may bind a resolver through a context variable, and financial adapters can decline inference by returning `None`. No semantic inference implementation is provided here. Classification facts likewise preserve whether evidence was printed, supplied by profile, or asserted by the operator instead of merging those trust sources. Column-role port and binding (`src/cadrumo/application/ledger/column_roles.py`) Profile/evidence collection (`src/cadrumo/application/ledger/classifier_inputs.py`)

The main strength is that uncertain or absent facts remain explicit and that lazy demands consult the same dated rule table that will classify the operation. The code separates establishment from registration, the counterparty from the filer, and a document’s stated category from the category established by rules. Readiness similarly unifies calculation issues and cross-catalogue link consistency. The concrete-write fence and bounded operation projections are substantive transaction-safety and data-boundary controls, subject to adapter/caller behavior.

Two scoped follow-ups matter. First, `ConfirmedEstablishment.review_items` is produced but stated to have no production reader, and RATE_INFERRED is locally distinguished but stated not to be persisted/emitted. Trace the confirm executor and operator projection to learn whether these distinctions are shown elsewhere; if not, a person may see a missing category without the fact needed to settle it or the weaker evidential basis of an inferred category. Second, the two self/direction identity guards skip when profile data is unavailable and this chunk does not show their call sites. Confirm the production confirmation chain invokes both after the correct party-role resolution. The unavailable profile case is not an authorization bypass by itself; it is a conditional loss of a content-validation check. No tests were inspected or run, and no legal rule was independently validated.
