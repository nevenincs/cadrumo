## IVA compensation history and decision flow

The application stores IVA compensation period states alongside calculation observations and exposes a repository-backed FIFO balance query. Historical manual seeding refuses to overwrite an existing period; correction refuses to create a missing period. Both stamp the M303 revision selected for that period. The module documents that sealed-filing and taxpayer guards belong in the higher-level modelo facade, so these primitives should only be reached through that caller. For captured M303 envelopes, state construction first requires canonical disposition-aware carry evidence. A combined persistence function checks that observation and history repositories share one secure-object repository and commits both prepared writes in one batch, avoiding half-written observation/history state. The annual Modelo 390 partition reconstructs same-year Modelo 303 period states from filed envelopes. Each envelope is revalidated against the pinned revision and canonical casilla set. Missing source periods leave declared partition bindings unresolved; in particular, when the opening earlier-year balance cannot be established from the first period’s available/pending evidence, it stays unknown rather than being treated as zero. The pure FIFO report then supplies the annual boxes with contributor provenance. ## M303 carry evidence and observation storage

M303 carry ingress converts the submitted declaration-type header (or the typed equivalent from an app filing) into one canonical carry basis. Official AEAT envelopes require exactly one selected header; app-origin envelopes require an app-filing disposition. The disposition must be registry-admitted and agree with the result sign. The available/generated pair is normalized from supported casilla operands, validated against any supplied pair, and tied to the formula declared by the pinned revision. Contradictions attach explicit safety precondition evidence; incomplete evidence remains a correctable typed refusal. Downstream history readers validate the canonical envelope rather than independently choosing a result. Registry mapping and disposition policy (`src/cadrumo/application/calculations/m303_carry_ingress.py`) Envelope normalization (`src/cadrumo/application/calculations/m303_carry_ingress.py`) Sign and pair checks (`src/cadrumo/application/calculations/m303_carry_ingress.py`) Formula match (`src/cadrumo/application/calculations/m303_carry_ingress.py`)

Observation envelopes separate calculation values from provenance: capture time, source taxonomy, stamped registry revision, member identity, source metadata, source-header facts, disposition, compensation basis and prior-domiciliation election. M303 envelopes without normalized disposition and basis are rejected outside the explicit ingress-construction path. Official and pending-local layers can coexist; calculation readers see pending local first, but its source kind remains non-official for filing readiness. An override records the actor, reason, time and replaced values without destroying the official layer. Observation keys validate model/period/year components; member and wallet keys hash normalized taxpayer identifiers so NIF/NIE values do not appear in natural keys. ## Additional calculation services

The simplified-regime M303 calculation validates filing year, selected annual Orden and row shape, then calculates module quotas, optional DANA and Lorca reductions, difficult-justification deductions and minimum quota with cent rounding and source/legal references. DANA eligibility is accepted only when the pinned authority says the reduction is authored for the filing date; Lorca evidence is required when the annual authority applies, and the code refuses combined Lorca and DANA eligibility pending reviewed authority. M303 simplified calculation (`src/cadrumo/application/calculations/m303_regimen_simplificado.py`) Authored DANA check and row validation (`src/cadrumo/application/calculations/m303_regimen_simplificado.py`) Lorca and DANA rule (`src/cadrumo/application/calculations/m303_regimen_simplificado.py`)

Modelo 390 receives an immutable simplified-regime handoff from exactly one same-profile M303 4T work unit. The source must be the current filed calculation revision with a matching VIGENTE filing record and persisted M303 filing evidence; source/target registry coordinates are re-confirmed. It maps a fixed set of M303 51–58 values to the annual section, recomputes the activity result from stored calculated evidence, checks arithmetic coherence, and re-resolves the handoff again before target verification/filing/export. Agricultural simplified rows remain unsupported until their annual Orden authority is resolved. Annual source resolver (`src/cadrumo/application/calculations/m303_regimen_simplificado_annual_summary.py`) Exact filed source validation (`src/cadrumo/application/calculations/m303_regimen_simplificado_annual_summary.py`) Handoff revalidation (`src/cadrumo/application/calculations/m303_regimen_simplificado_annual_summary.py`)

Maritime-worker orchestration independently checks a DA 41 inactive condition and RETMAR mandatory-filing condition, then emits typed, grounded Art. 7.p) and REBECA observations only when eligible and required facts are present. RETMAR completeness is surfaced separately for the caller to handle; it does not suppress eligible exemption calculations. M111 and M115 period helpers read explicit profile attestations; invalid tokens attest nothing. M111 suppression is additionally limited to a period declared in the selected registry schedule, while the M115 predicate only checks exact membership and quarterly token form, so its caller must ensure it is applied only to a scheduled M115 period. Maritime resolver (`src/cadrumo/application/calculations/maritime_exemption_service.py`) M111 schedule check (`src/cadrumo/application/calculations/m111_no_retenciones.py`) M115 attestation parsing (`src/cadrumo/application/calculations/m115_no_relevant_payments.py`)

## Implementation assessment

Strong points include one canonical disposition-aware M303 carry contract, provenance-bearing observation layers, dual-write atomicity for observation/history, explicit unknown-vs-zero handling, and exact source/target checks on the annual handoff. The main conditional follow-up is the caller’s authority over the first-period and unusable-evidence flags; the M115 schedule check is another caller invariant. No confirmed local defect is established here. The assigned modules contain no tests; storage encryption, backend transaction behavior, and actual wallet capture/parsing remain outside this static pass.
