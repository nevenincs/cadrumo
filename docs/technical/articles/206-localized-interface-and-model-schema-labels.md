## Scope and method

This reference-data chunk contains 332 YAML files totaling 20,987,833 bytes. It mirrors 83 relative paths in each of four locale trees (`ca`, `en`, `es`, `hu`): nine general catalogs, one `modelo/general.yml`, and 73 `modelo/schema/*.yml` files per locale. The four path sets match exactly, although their translated content and sizes differ. All assets are YAML and occupy three directory shapes: locale root, locale/model, and locale/model/schema.

I inspected the four complete `modelo/general.yml` files (6,539 bytes combined), then took bounded structural and text samples from the four locales’ Modelo 303 and Modelo 100 schema YAMLs. The Modelo 303 sample covered the form title, revision labels, the latest-revision casilla count, the continuity namespace, and four selected labels/help values. The Modelo 100 sample covered the title, revision range, counts for 2020 and 2025, and a bounded key-presence comparison for 2020. The large model files were sampled through selected paths; this report does not claim semantic review of all 332 translations. The group’s full paths and byte sizes are inventoried below. No application code was run.

## Capability and content shape

The files supply locale-specific interface text and labels for model forms. The general model catalog includes shared column names such as taxable base, tax amount, pro-rata, totals, and territory (Catalan (`src/cadrumo/locales/ca/modelo/general.yml`), English (`src/cadrumo/locales/en/modelo/general.yml`), Spanish (`src/cadrumo/locales/es/modelo/general.yml`), Hungarian (`src/cadrumo/locales/hu/modelo/general.yml`)). For example, the same `territorio_estado` identifier is rendered as “State (AGE)” in English, “Estado” in Spanish, and “Állami adóhatóság” in Hungarian. Such catalogs let shared model data display in the user’s selected language; these strings are data, not translation-selection logic.

Each sampled Modelo 303 locale file has revisions 2022, 2023, 2024, 2025, and `2026-y-siguientes`. The latest revision contains 117 casilla labels/help entries in each locale, and the continuous record-design namespace has 229 entries in each. The sampled strings cover VAT rates and return boxes; e.g. `dr303-01` labels the taxable base at the 4% super-reduced rate and `dr303-09` labels the 21% amount (Catalan (`src/cadrumo/locales/ca/modelo/schema/303.yml`), English (`src/cadrumo/locales/en/modelo/schema/303.yml`), Spanish (`src/cadrumo/locales/es/modelo/schema/303.yml`), Hungarian (`src/cadrumo/locales/hu/modelo/schema/303.yml`)). Their 2026-and-later labels establish a text revision horizon in these files, not by themselves a supported filing year or an authoritative tax rule.

The sampled Modelo 100 files cover revisions 2020 through 2025. All four contain 865 casilla entries for 2025. The 2020 counts differ: 711 Catalan, 711 English, 709 Spanish, and 720 Hungarian. A bounded key comparison also found different key sets: `0108` is present in English and absent in the other three, while Catalan and Hungarian contain some 2020 keys not present in the English baseline (Catalan (`src/cadrumo/locales/ca/modelo/schema/100.yml`), English (`src/cadrumo/locales/en/modelo/schema/100.yml`), Spanish (`src/cadrumo/locales/es/modelo/schema/100.yml`), Hungarian (`src/cadrumo/locales/hu/modelo/schema/100.yml`)). This is an observable localization-data difference, not proof of a broken screen: a consumer may intentionally fall back to a base label or omit a field by revision. Synthesis should inspect the locale resolver and compare these revision-specific keys with the registry’s intended box set before classifying it as a defect.

## Provenance, freshness, and limits

The sampled YAML structures provide localized `official_name`, `title`, `label`, and `help` values nested under model, schema, form, and revision keys. Their sampled rows do not contain per-string citation, translator, approval, or source-date metadata. The version key records which displayed text is associated with a model-year revision; it does not prove the translation was reviewed against a particular official design. In a regulated filing workflow, registry/year matching and a safe locale fallback are therefore as important as translation coverage. The underlying authority and supported-year policy must be established from the registry and consuming code, not inferred from a translation label.

The data files contain interface wording rather than live taxpayer records or executable behavior. Static inspection of these catalogs establishes available text and some structural variation only. It does not verify string interpolation, escaping, locale selection, formatting of amounts/dates, accessibility, or whether missing translations can expose misleading fallback text. No tests are present in this chunk.

## Dependencies and follow-up

Synthesis should trace locale discovery and fallback, the schema-label resolver, year/revision selection, and checks that translation key sets match the registry. The 2020 Modelo 100 differences merit a bounded comparison against the authoritative key set and the product’s fallback policy; the displayed labels themselves require source/version review outside these locale assets.
