## Capabilities and mechanisms

The workspace layer assembles a read-only, revision-pinned view of a Modelo target in two modes: static registry inspection and grade-admitted calculation snapshot. It presents schema, work review, materialization, provenance, readiness, and capability assessments through typed V1 results. A projection is explicitly described as having no mutation authority; requests can end in one typed refusal instead of a partial projection. The service code implements both successful assembly paths, even though the module header still says that only the capture/assertion core has landed and that the two assemblies are not built. That stale statement is a concrete documentation defect, not evidence that the implementations are absent. Contradictory module status and implemented resolvers (`src/cadrumo/application/modelo/workspace.py`), static result assembly (`src/cadrumo/application/modelo/workspace.py`), graded result assembly (`src/cadrumo/application/modelo/workspace.py`)

Target requests are converted into the existing pure work selector's exact request form; no selector policy is duplicated here. The resolver takes the law-selected revision and independently records optional requested and stored revision assertions as `MATCHED`, `MISMATCHED`, or `NOT_PRESENT`. It captures work first and derives the registry capture from the resolved work coordinate, retaining the registry generation and producer stamps for later freshness checks. Selector adapter and revision axes (`src/cadrumo/application/modelo/workspace.py`), single work-then-registry capture (`src/cadrumo/application/modelo/workspace.py`), resolved target capture (`src/cadrumo/application/modelo/workspace.py`)

Locale resolution batches requested keys against a captured catalogue. It chooses the requested language when present, falls back to Spanish where available, and otherwise marks the value suppressed; it retains a digest of the locale data so translated labels are part of the read coordinate. Technical labels and canonical identities are carried separately. This helps a client render schema labels without interpreting compiler objects or silently treating missing localization as an empty label. Static inspection exposes registry schema and explicit evidence boundaries without pretending to have a calculation. It projects casillas, bindings, formulas and parameters; walks formula expressions into typed operand references; joins continuity declarations, relation endpoints and export exposure to canonical IDs. Applicability is not falsely attached to each casilla: its identity is modeled separately because it applies at revision scope. Static casilla rows mark legal grounding and constraints unavailable (`None`) where the inspection source lacks those declarations, preserving the distinction from an observed empty tuple. Static capability rows make only schema inspection available; calculation, verification and filing-readiness are unmeasured because those contributors are structurally absent. Graded snapshots add richer casilla constraints and legal/source references, scalar and repeated-row materialization, and calculation provenance. Repeated values are grouped by binding only when row provenance supplies an index; missing provenance is treated as a refusal condition rather than flattening unrelated values. Provenance records retain unlinked calculation sources with a null subject, so missing attribution does not erase the source itself. Capability assessment uses the captured review and lifecycle evidence: schema comes from the registry; calculation is available only when the captured revision belongs to the current target; verification requires the same revision in review and a completed verification state; filing readiness is exposed as measured only when readiness reports ready. These are evidence-sensitive projections, not a claim that the underlying filings have been transmitted. ## Knowledge, security, and implementation assessment

The public model set is strict, bounded, discriminated and frontend-neutral. It separates static and graded admission, closes the allowed target/facet/refusal types, bounds text and record counts, enforces unique identities and facts, and checks that baselines, cursors, facets, capabilities and projections refer to the same selected revision and schema coordinate. `None` versus an empty collection carries a deliberate evidence meaning for unmeasured legal grounding, constraints, provenance subjects and readiness. These validations prevent a consumer from mistaking unsupported knowledge for a clean negative answer, though they do not establish correctness of producer data. Closed admission and refusal vocabulary (`src/cadrumo/application/modelo/workspace_models.py`), revision assertion and target invariants (`src/cadrumo/application/modelo/workspace_models.py`), baseline and cursor coordinate checks (`src/cadrumo/application/modelo/workspace_models.py`), projection admission checks (`src/cadrumo/application/modelo/workspace_models.py`)

`workspace_manifest.py` builds a fail-closed public-schema denominator by walking Python type annotations from the registry and selector provider roots. It classifies leaves as projected, derived, or backend-only, records paths and destinations, rejects unsupported/unresolved shapes, and imposes a 10,000-entry bound before publishing the digest. Static inspection roots are kept separate from graded registry-snapshot roots. Manifest captures are tied to process/domain and generation coordinates; currentness is checked by regenerating the manifest digest, so a forked, foreign, or superseded capture is not silently accepted. This is a useful schema-drift alarm, but it fingerprints the enumerated type universe rather than proving a serialized response round-trips or that every runtime path emits every declared field. Manifest generation and distinct roots (`src/cadrumo/application/modelo/workspace_manifest.py`), typed annotation traversal and fail-closed classification (`src/cadrumo/application/modelo/workspace_manifest.py`), capture/currentness model (`src/cadrumo/application/modelo/workspace_manifest.py`), current-coordinate verification (`src/cadrumo/application/modelo/workspace_manifest.py`)

The concrete safety boundary here is read-only projection plus exact evidence coordinates, bounded DTOs, typed refusal, recovery-action references, and contributor freshness checks. The assigned files do not show direct filesystem or network operations, credential handling, external legal validation, or mutation APIs. Those absences apply only to this chunk. The assembly validates contributor currentness before returning, but the files alone do not demonstrate a single atomic transaction spanning all underlying repositories; the consistency guarantees of the capture adapters and the race window after the last check remain cross-module questions. The most notable local quality issue is the stale top-level status comment. No tests were present in these assigned files, so validation boundaries and stale-read behavior remain unexercised in this report.

## Dependencies and follow-up

Synthesis should trace the selector, work capture, registry capture, locale catalogue, calculation, review, readiness and action-catalogue implementations to verify that their version stamps and typed refusals mean what this assembler assumes. It should also confirm whether static inspection's fixed unmeasured capabilities and the graded readiness rule match product expectations, and check the manifest capture lifecycle under concurrent registry updates. The manifest's typed schema walker should be connected to whatever CI or contract test consumes its digest; this chunk does not itself show that enforcement.
