## Capabilities and mechanisms

Printed-box resolution gives operator-facing surfaces a single answer to whether a casilla appears as a numbered form box. A same-revision form placement wins, then the casilla's declared form number, then its numeric identifier; a working figure with no printable number remains unnumbered. Layout placements from a different revision are ignored, and the snapshot helper resolves the selected revision's layout through the pinned authority. This lets diagnostics distinguish “value exists in calculation” from “value is printed on the form.” Box-number selection (`src/cadrumo/application/modelo/printed_boxes.py`), revision-aware layout projection (`src/cadrumo/application/modelo/printed_boxes.py`)

The prior-domiciliation resolver protects Modelo 303's “cancel or modify” election for an earlier direct debit. KEEP is neutral. The exceptional election is accepted only for a rectificativa linked to a specific filing record, where that record is AEAT-accepted and externally evidenced, matches the current bucket/model/year/period, and joins to an official same-coordinate observation whose justificante CSV is exactly the filing record's evidence reference. It then requires exactly one matching declaration-type header with value U and a result-disposition projection derived from that same header locator. A computed current amount, profile fact, or older local export cannot establish this baseline fact. Rectificativa and evidence chain (`src/cadrumo/application/modelo/prior_domiciliation.py`), official observation and U-header checks (`src/cadrumo/application/modelo/prior_domiciliation.py`), final election resolution (`src/cadrumo/application/modelo/prior_domiciliation.py`)

The Modelo 130 prior-payment module emits two non-blocking diagnostics; it does not calculate the carry. It resolves casilla identities from a dated registry mapping for the selected revision and checks current official observation envelopes. For a later quarter, it warns when cumulative income is positive, the current prior-payment casilla is zero, and a prior same-year quarter was filed. It separately warns when a carried prior filing contains a positive part but no minoración entry; a filed zero remains distinct from a missing value. A first quarter or a quarter without a stored prior filing produces neither warning. Missing prior payment (`src/cadrumo/application/modelo/prior_payment_advisory.py`), missing minoración entry (`src/cadrumo/application/modelo/prior_payment_advisory.py`)

The profile binding resolver is a shared source path between calculation and export. It selects profile-sourced bindings declared by the pinned revision only when formulas, numeric casillas, date consumers, or calculation-only selectors use them. Caller-supplied binding IDs take precedence. It reads the bucket profile through the caller's schema context, derives selected family and taxpayer facts in an ephemeral fact index, then routes values to Decimal, enum, date, or boolean channels. Boolean routing follows the binding's declared value contract and rejects numeric stand-ins; date/enum consumer shape is cross-checked against the declaration. Unknown/missing facts remain unresolved so a required formula can surface the gap rather than receiving a fabricated value. Successful profile values carry a bucket/binding source reference and a fingerprint of the loaded profile record. Selected bindings and derived facts (`src/cadrumo/application/modelo/profile_binding.py`), profile fact loading (`src/cadrumo/application/modelo/profile_binding.py`), strict channel routing (`src/cadrumo/application/modelo/profile_binding.py`), provenance-bearing resolution (`src/cadrumo/application/modelo/profile_binding.py`)

Derived Renta facts include marital-year/month values, family/minimum-descendant aggregates, annualities eligibility, maternity months and the nursery-school increment. The injectors use the revision's declared selectors and authority parameters instead of hardcoded year tables, overwrite stale/hand-planted synthetic values in the transient calculation index, and leave a value absent when the governing thresholds or cap cannot be established. For pre-2023 filings, maternity is withheld because the required contribution ceiling is not represented. The minimum-descendant aggregation applies registry thresholds and second-filer proration. Anualidades eligibility shares that same descendant predicate and explicitly handles shared custody. The Madrid birth/adoption deduction defaults the binding inputs to zero but only injects an eligible count for an unambiguous Madrid single/monoparental case; it declines to infer the missing spouse base for married or joint filers. Minimum and annualities derivation (`src/cadrumo/application/modelo/profile_binding.py`), nursery increment derivation (`src/cadrumo/application/modelo/profile_binding.py`), maternity-month derivation (`src/cadrumo/application/modelo/profile_binding.py`), Madrid deduction derivation (`src/cadrumo/application/modelo/profile_binding.py`), family fact reconstruction (`src/cadrumo/application/modelo/profile_binding.py`)

The export-side resolver reuses the same profile value logic and adds dictionary-field formatting. It honors conditional profile gates, composes surnames-first natural-person names in one place, distinguishes individual identity from entity legal names, and resolves the presenter and declaration contact separately. For required profile-bound text casillas it emits a grounded gap diagnostic rather than a placeholder. Conditional spouse identity rows are suppressed unless the profile affirmatively satisfies their gate, preventing spouse details from being copied onto an individual return. Bound text casillas and gaps (`src/cadrumo/application/modelo/profile_export_binding.py`), conditional export gate (`src/cadrumo/application/modelo/profile_export_binding.py`), dictionary-field resolution (`src/cadrumo/application/modelo/profile_export_binding.py`), presenter/taxpayer identity (`src/cadrumo/application/modelo/profile_export_binding.py`), declaration contact (`src/cadrumo/application/modelo/profile_export_binding.py`)

Profile readiness combines universal or target-aware baseline fields, profile-schema validation, and the selected revision's required profile selectors. It can expose grounded missing-field rows for readiness surfaces or raise before filing-grade work. It also refuses inapplicable local work and, for Modelo 130/303, periods ending before the effective censo activity-start date. Existing work units re-run the gate against the current profile. The start date is read through the canonical profile projection, which orders validity windows chronologically rather than trusting record declaration order. Setup-incomplete profiles produce a typed setup verdict and missing field list. Target-specific baseline (`src/cadrumo/application/modelo/profile_readiness_gate.py`), preflight report (`src/cadrumo/application/modelo/profile_readiness_gate.py`), applicability and period gates (`src/cadrumo/application/modelo/profile_readiness_gate.py`), current-profile work-unit gate (`src/cadrumo/application/modelo/profile_readiness_gate.py`), activity-start date projection (`src/cadrumo/application/modelo/profile_readiness_gate.py`), existing work-unit recheck (`src/cadrumo/application/modelo/profile_readiness_gate.py`)

## Knowledge, safety, and limitations

These modules rely on registry-selected revisions, dated governed facts, profile-schema decoding, and persisted official filing observations. Code comments and legal identifiers describe intended product authority but were not independently checked against current law. The strongest controls in this slice are the exact filing-evidence join for prior domiciliation, the explicit separation of typed value channels, one shared family reconstruction, suppression of gated spouse disclosures, and readiness checks repeated against the live profile before work proceeds.

There are explicit coverage limits. The current autonomous minimum-descendant table wires Madrid's divergent figures and mirrors state figures for other CCAA; the module names other regions' divergent tables as follow-up, so the fallback needs legal/registry review before being treated as universal parity. The Madrid nacimiento/adopción injector cannot evaluate the spouse's joint-unit income ceiling and withholds a positive amount on those cases; a separate advisory must make that indeterminacy visible. Profile export skips repeating bindings because the production profile writer does not populate the corresponding arrays and the current dictionary writer would overwrite repeated tags. This is a known structural gap, not a promise that all declared repeating export bindings work. Madrid-only divergent table (`src/cadrumo/application/modelo/profile_binding.py`), indeterminate joint-unit guard (`src/cadrumo/application/modelo/profile_binding.py`), repeating export binding limitation (`src/cadrumo/application/modelo/profile_export_binding.py`)

The annualities helper deliberately treats an unreadable amount as undeclared, which leaves dependency assimilation available. Its comments state that each assimilation is disclosed, but this is a conscious fail-open rule that depends on the downstream advisory staying present and legible. The prior-payment diagnostics open a fresh bundled authority operation when no pinned operation is supplied; callers that pass their operation preserve generation consistency, while standalone use is a cross-layer point to verify. The profile-binding entrypoints themselves require the caller-held operation. No tests are part of these six implementation files, so none of the stated behavior was exercised during this pass.
