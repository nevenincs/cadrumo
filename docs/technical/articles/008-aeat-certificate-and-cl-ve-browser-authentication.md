## Capabilities and flow

The adapters provide two ways to authenticate a natural-person profile to AEAT Sede. Certificate authentication loads a configured PKCS#12 bundle, derives the taxpayer identity from its X.509 subject, provisions client-certificate material to a browser context through the injected browser-session factory, and verifies a canonical protected resource. Cl@ve Móvil starts an operator-mediated phone challenge, optionally uses a configured DNI/NIE contrast form instead of QR, captures the authenticated browser state, and resumes later from encrypted state. The provider package keeps Playwright optional at import time; the actual live launch remains behind the browser-extra factory (_playwright.py (`src/cadrumo/adapters/outbound/aeat/_playwright.py`), authenticator.py (`src/cadrumo/adapters/outbound/aeat/auth/authenticator.py`), clave_movil.py (`src/cadrumo/adapters/outbound/aeat/auth/clave_movil.py`)).

Certificate loading validates the passphrase before file access, decodes PKCS#12 with `cryptography`, requires an end-entity certificate, computes the SHA-256 thumbprint, stores the key, raw bundle bytes, and passphrase in model-private attributes, and refuses expired certificates. Health checks return OK/WARN/CRITICAL/EXPIRED based on configured thresholds. NIF/NIE extraction parses RFC 4514 subject names and delegates identity classification/checksum to the project registry; it accepts individual identifiers from `serialNumber` or a trailing CN identifier and refuses CIF-shaped organization identity rather than guessing. The browser assertion requires a successful response, exact scheme/host/path match to the certificate-protected resource, and a nonempty identity; assertion URLs drop query and fragment before serialization (certificate.py (`src/cadrumo/adapters/outbound/aeat/auth/certificate.py`), certificate.py (`src/cadrumo/adapters/outbound/aeat/auth/certificate.py`), certificate.py (`src/cadrumo/adapters/outbound/aeat/auth/certificate.py`), authenticator.py (`src/cadrumo/adapters/outbound/aeat/auth/authenticator.py`)).

`AeatAuthenticator.authenticate` first tries the encrypted persisted browser state. Resume verifies the state hash, idle deadline, certificate thumbprint, subject, and derived NIF, builds a certificate-enabled context, then repeats the protected-resource probe before refreshing the state. Invalid state is deleted and the code falls back to a fresh certificate-backed login. Fresh login does not mark a session active until that same canonical probe passes. `verify` additionally requires the exact active certificate session and coordinates in-flight pages with a close-intent barrier. The authenticator is explicitly single-event-loop; `reauthenticate` is single-shot and not atomic across close then authenticate. Session persistence here relies on the imported session-store implementation; this chunk establishes how it is called and validates its metadata, not the storage substrate’s cryptographic implementation (authenticator.py (`src/cadrumo/adapters/outbound/aeat/auth/authenticator.py`), authenticator.py (`src/cadrumo/adapters/outbound/aeat/auth/authenticator.py`), authenticator.py (`src/cadrumo/adapters/outbound/aeat/auth/authenticator.py`), authenticator.py (`src/cadrumo/adapters/outbound/aeat/auth/authenticator.py`), authenticator_persistence.py (`src/cadrumo/adapters/outbound/aeat/auth/authenticator_persistence.py`), browser_lifecycle.py (`src/cadrumo/adapters/outbound/aeat/auth/browser_lifecycle.py`)).

The Cl@ve provider tries a stored session before opening a fresh challenge. It may drive a QR browser visibly or use DNI/NIE, birth-date/support data, and a configured non-QR route. It detects an AEAT pending-request refusal, extracts the displayed verification code, requires an observed wait state, and waits for the requested post-auth path. On timeout it captures diagnostics and attempts bounded best-effort cancellation; it does not infer whether the operator accepted the phone prompt from a browser timeout. A failed post-auth navigation can salvage cookie-bearing state, but records a landing URL only when the predicate identifies an authenticated AEAT landing. Reuse probes check the encrypted state hash and idle deadline, navigate and classify the landing, then refresh stored idle time after a valid probe. Diagnostic context uses fingerprints for configured identity and profile tax ID. When a profile record is read for diagnostics, code first checks that the current active bucket’s own session can decrypt it; it does not borrow another profile’s session (_clave_movil_page_flow.py (`src/cadrumo/adapters/outbound/aeat/auth/_clave_movil_page_flow.py`), _clave_movil_page_flow.py (`src/cadrumo/adapters/outbound/aeat/auth/_clave_movil_page_flow.py`), _clave_movil_salvage.py (`src/cadrumo/adapters/outbound/aeat/auth/_clave_movil_salvage.py`), clave_movil.py (`src/cadrumo/adapters/outbound/aeat/auth/clave_movil.py`), clave_movil.py (`src/cadrumo/adapters/outbound/aeat/auth/clave_movil.py`), clave_movil.py (`src/cadrumo/adapters/outbound/aeat/auth/clave_movil.py`), clave_movil_metadata.py (`src/cadrumo/adapters/outbound/aeat/auth/clave_movil_metadata.py`)).

The shared landing predicate resolves the canonical remote hostname and accepts only the current AEAT host, rejects the auth-gate and mid-Cl@ve paths, and checks the target AEAT application path. The shared pre303 representation helper tries configured own-name selector variants, refuses representative radio selection, and applies a remote-operation action policy before continuing in the authenticated user’s own name. Its alert helper clicks only when the modal element is present and carries the `show` class. The implementation’s own evidence caveat says no real AEAT capture of the modal in shown and hidden states is recorded here; a hidden-but-required modal may therefore go undismissed. This removes the earlier hidden-modal over-click behavior but leaves the real-page predicate unresolved (_clave_provider_common.py (`src/cadrumo/adapters/outbound/aeat/auth/_clave_provider_common.py`), _clave_movil_page_flow.py (`src/cadrumo/adapters/outbound/aeat/auth/_clave_movil_page_flow.py`), _representation_gate.py (`src/cadrumo/adapters/outbound/aeat/_representation_gate.py`), _representation_gate.py (`src/cadrumo/adapters/outbound/aeat/_representation_gate.py`)).

## Knowledge, security, and implementation assessment

The adapters consume externally configured AEAT URLs, selectors, path markers, wait text, and timeout values; provider identity and certificate subject are checked against the project’s runtime identity registry. The 18-minute idle TTL and any expected AEAT wait/idle behavior are implementation constants/comments, not independently verified current service guarantees. Cl@ve metadata stores identity, state hash, fallback mode, optional verification code, and post-auth landing URL alongside the encrypted browser state. Certificate metadata binds the state to certificate thumbprint/subject/NIF, hash, schema version, and a canonical protected resource. The secure session-store implementation and AEAT’s live behavior are outside this chunk.

Several controls are concrete: certificate passwords are `SecretStr`; private key and PKCS#12 bytes are excluded from model dumps/repr; certificate probes pin the final resource; persisted state must match both its digest and current certificate identity; Cl@ve URL diagnostics retain host/path/query-key names but drop query values; full page HTML and screenshots are stored through the session-class encrypted-object repository; and browser teardown is bounded while retaining failed resource references for retry. The Cl@ve flow also records operator-visible verification codes and clearly labels phone state as unknown when no authenticated transition is observed. However, `_attach_dialog_autodismiss` accepts any JavaScript dialog without checking its text/type, and debug logging includes the dialog message. That is broader than a narrowly identified cookie or representation prompt. `_dump_diagnostic` stores a raw URL in the encrypted payload and logs it unredacted in its success warning; pending-request and cancellation logging can also include raw URL/exception values. These paths deserve secret/query review because URL diagnostics elsewhere deliberately strip query values (certificate.py (`src/cadrumo/adapters/outbound/aeat/auth/certificate.py`), certificate.py (`src/cadrumo/adapters/outbound/aeat/auth/certificate.py`), _clave_movil_page_flow.py (`src/cadrumo/adapters/outbound/aeat/auth/_clave_movil_page_flow.py`), _clave_movil_page_flow.py (`src/cadrumo/adapters/outbound/aeat/auth/_clave_movil_page_flow.py`), clave_movil_support.py (`src/cadrumo/adapters/outbound/aeat/auth/clave_movil_support.py`)).

Two capability gaps need cross-layer resolution. First, Cl@ve’s `probe_persisted_session` says it will not create a fresh phone challenge and discards any explicit target, but when stored landing metadata is absent, `_verify_in_work` falls back to the selector URL and installs the selector-page hook that clicks the Cl@ve button. That path can begin a new challenge despite the method’s stated diagnostic-only behavior. This is conditional on a persisted record lacking an authenticated landing URL, but the metadata schema allows `landing_url=None` (clave_movil.py (`src/cadrumo/adapters/outbound/aeat/auth/clave_movil.py`), clave_movil.py (`src/cadrumo/adapters/outbound/aeat/auth/clave_movil.py`), clave_movil.py (`src/cadrumo/adapters/outbound/aeat/auth/clave_movil.py`), clave_movil.py (`src/cadrumo/adapters/outbound/aeat/auth/clave_movil.py`), clave_movil.py (`src/cadrumo/adapters/outbound/aeat/auth/clave_movil.py`)). Second, a fresh Cl@ve flow accepts a matching target-path substring as its post-auth landing; the stronger canonical-host/application predicate is used by later verification/salvage, but the fresh path itself captures and persists the state before that separate check. Confirm that application orchestration always runs `verify` before any protected read and whether target-host pinning is required at this boundary (_clave_movil_page_flow.py (`src/cadrumo/adapters/outbound/aeat/auth/_clave_movil_page_flow.py`), clave_movil.py (`src/cadrumo/adapters/outbound/aeat/auth/clave_movil.py`), _clave_provider_common.py (`src/cadrumo/adapters/outbound/aeat/auth/_clave_provider_common.py`)).

The browser landing probe’s `session_cookie_present` field is not a direct cookie inspection: it is set when HTTP status is 200–399 and the final URL satisfies the provider’s authenticated-landing predicate. This naming is weaker than the actual observation. Probe exceptions are serialized with exception text and logged with the full probe URL, so callers should treat those diagnostics as potentially sensitive. Certificate bundle loading also reads the entire PKCS#12 file into memory without a local size cap and reports the source path in several load errors. No tests are assigned to this chunk; static inspection cannot prove AEAT page behavior, browser/certificate provisioning, storage encryption, or that orchestration enforces the additional verification step (_session_probe.py (`src/cadrumo/adapters/outbound/aeat/auth/_session_probe.py`), certificate.py (`src/cadrumo/adapters/outbound/aeat/auth/certificate.py`)).
