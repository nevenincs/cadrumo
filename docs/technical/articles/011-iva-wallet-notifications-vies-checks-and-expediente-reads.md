## Security and implementation assessment

The wallet’s safeguards are unusually explicit for a query that uses form POST: only the wallet path is authorized for the read POST; landing checks are applied to the returned page; and representation controls are checked before continuing. Its path allow-list is for the Pre303 and wallet destinations, while the selector and acting-capacity gate are treated as transit, not as successful terminal reads. The parser uses an exact monetary shape to avoid interpreting a partial amount as a valid balance. However, it checks the aggregate against detail rows only when at least one row parsed; a malformed/skipped set of rows could leave a positive aggregate with no detail while still producing an observation. Also, when the result page does not render target labels, target agreement cannot be checked from those labels. Those are bounded evidence gaps, not proof that AEAT currently returns such pages (iva_compensation_wallet.py (`src/cadrumo/adapters/outbound/aeat/sede/iva_compensation_wallet.py`), iva_compensation_wallet.py (`src/cadrumo/adapters/outbound/aeat/sede/iva_compensation_wallet.py`), iva_compensation_wallet_parsing.py (`src/cadrumo/adapters/outbound/aeat/sede/iva_compensation_wallet_parsing.py`)).

The wallet identity fields also deserve caller review. `taxpayer_nif` is an optional argument and the parser records it (or defaults to `session.identity_nif`) separately from `authenticated_identity`. The schema does not require the two values to match, and the query form never fills a taxpayer identity field; the source comments say AEAT pre-fills it from the authenticated session. A caller can therefore label session-bound wallet data with another `taxpayer_nif` unless a higher layer binds it. The wallet store’s natural key includes that taxpayer NIF, so an incorrect label can affect indexing as well as presentation (iva_compensation_wallet.py (`src/cadrumo/adapters/outbound/aeat/sede/iva_compensation_wallet.py`), iva_compensation_wallet.py (`src/cadrumo/adapters/outbound/aeat/sede/iva_compensation_wallet.py`), iva_compensation_wallet.py (`src/cadrumo/adapters/outbound/aeat/sede/iva_compensation_wallet.py`), iva_compensation_wallet_parsing.py (`src/cadrumo/adapters/outbound/aeat/sede/iva_compensation_wallet_parsing.py`), schema.py (`src/cadrumo/adapters/outbound/aeat/sede/schema.py`), observation_store.py (`src/cadrumo/adapters/outbound/aeat/sede/observation_store.py`)).

The notification document guard prevents the normal call path from contacting AEAT for a row that is unread or unknown. Yet its sole evidence is the caller-supplied `RemoteNotification.leida` value; this model can be constructed independently, and the fetch path does not re-fetch or cryptographically bind the row to a recent snapshot/session identity. If callers can pass stale or forged records, setting `leida=True` could reach the detail POST that the guard is intended to protect against. This is a high-consequence conditional risk because the source explicitly says the endpoint can perform comparecencia; synthesis should inspect every caller and whether the service boundary guarantees fresh, same-taxpayer rows. Parsing also substitutes the sentinel `X0000000Z` when titular NIF is missing, which preserves a schema-valid string but can blur missing identity with real parsed identity. Rows with malformed certificate/date fields are skipped, and the parser does not reconcile a row count against a server-declared total (notifications.py (`src/cadrumo/adapters/outbound/aeat/sede/notifications.py`), notifications.py (`src/cadrumo/adapters/outbound/aeat/sede/notifications.py`), notifications.py (`src/cadrumo/adapters/outbound/aeat/sede/notifications.py`), notifications.py (`src/cadrumo/adapters/outbound/aeat/sede/notifications.py`)).

The expediente walker guards page-supplied detail URLs before and after navigation against the AEAT host suffix and remote write-token policy, which blocks arbitrary off-domain cookie disclosure. It deliberately has no path allow-list for those href-derived details, so an unknown AEAT path without a recognized write token is outside the strength of this check; inspect observed link shapes and navigation callers before treating it as a complete no-write proof. It also performs tree expansion by JavaScript `.click()` inside `evaluate`, then waits a fixed two seconds and snapshots; a failure to expand every branch can produce an incomplete enumeration. In schema records, `mode="read"` is explicitly documentation/test metadata, not a runtime control. ## Dependencies and follow-up

These adapters depend on the shared auth-state loader, Playwright session factory, remote-state policy, Sede error taxonomy, and strict observation schemas. Wallet parsing also depends on shared decimal normalization and period types; its stored output is raw evidence for a separate reconciliation layer. Notifications depend on the shared PDF validator and remote landing guard. The expediente walker delegates parsing to pure functions and returns captures to a downstream reconciler. Synthesis should trace wallet use and taxpayer binding, notification document-fetch entrypoints, all sources of `RemoteNotification` objects, how GROI/VIES drivers are invoked and given credentials, and the details-page URL producers/callers for the expediente walker.
