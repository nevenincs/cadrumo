# Desktop frontend

The desktop window's web layer is the private npm package `cadrumo-desktop-frontend` in `native/desktop/frontend`: React 19, TypeScript 6, Vite 8, CSS-first Tailwind 4, Radix and cmdk through shadcn-style primitives, lucide icons and xterm.js 6. The product entry is `index.html` loading `src/main.tsx`, which uses `tauriHost()` when `isTauri()` and otherwise a browser host that fabricates nothing; `scenarios.html` mounts the same `App` on a simulated host. There is no router or state library: a rail, a split of documentation and TUI panes, and a bottom panel (console, Python, logs) are driven by `App` and hooks in `src/shell/`. The shell presents what the host reports and grants no authority: sign-in success comes only from the host answer, and an unreadable log is shown as unavailable, not empty. Every backend capability sits behind the `Host` interface; the Rust side is covered in [the Tauri shell reference](build-tauri-desktop-shell.md). [package](../../../../native/desktop/frontend/package.json#L6), [entry](../../../../native/desktop/frontend/src/main.tsx#L14), [Host port](../../../../native/desktop/frontend/src/shell/host.ts#L40).

The packaged flow is CMake-driven; development is npm-driven. `desktop-frontend-install` runs `frontend-install.mjs` (an `npm ci`, skipped when `node_modules` matches the lockfile); `desktop-frontend-build` runs `frontend-build.mjs`, which runs `npm run build` only when fingerprinted inputs changed. `npm run build` is `tsc --noEmit && vite build` and empties the product directory in the CMake build tree. `npm run bootstrap` configures the standalone desktop project with this host's preset and builds `desktop-frontend-generated` (chrome strings, palette); it compiles no Rust. `npm run dev`, which `just dev` calls, re-runs bootstrap on every start, then serves Vite on the fixed ports in `native/desktop/development-server.json`; an occupied port is an error. `check` runs tsc, ESLint, the `node --test` guards and Prettier. Others: `test`, `preview`, `format`, `storybook`, `storybook:build`, `shots`, `benchmark`. [scripts](../../../../native/desktop/frontend/package.json#L6), [bootstrap](../../../../native/desktop/frontend/scripts/bootstrap.mjs#L55), [CMake](../../../../native/desktop/CMakeLists.txt#L68), [build script](../../../../native/desktop/scripts/frontend-build.mjs#L79).

`src/ipc/contract.ts` is types plus terminal frame tags: a `HostCommands` table of command to `{args, result}` (window, sign-in, manager, profiles, terminal, logs, clipboard, menu, open-external), channel payloads and the documentation postMessage bridge. Every argument carries a per-launch `ShellToken`, added by `hostCall`; `tauriHost` reads it once from `window.__CADRUMO_SHELL__`. The two raw-body commands, `sign_in_submit` and `profile_create`, carry the password as the request body with the token in a header, so they are documented in comments and invoked directly rather than listed in the table. No schema library validates payloads at run time, and nothing generates or tests agreement between `contract.ts`, the Rust handlers and `native/CONTRACT.md`. The scenario host in `src/dev` implements the same port from fixtures. [contract](../../../../native/desktop/frontend/src/ipc/contract.ts#L645), [raw body](../../../../native/desktop/frontend/src/ipc/contract.ts#L607), [call wrapper](../../../../native/desktop/frontend/src/shell/hostCall.ts#L18), [Tauri adapter](../../../../native/desktop/frontend/src/shell/tauriHost.ts#L19), [scenario host](../../../../native/desktop/frontend/src/dev/scenarioHost.ts#L90).

Colour is generated from the documentation theme and mapped to roles (`bg-card`) in `theme.css`, dark under `[data-scheme="dark"]`; lengths, type, radii, layers and motion are tokens in `tokens.css`. The `ui/` primitives wrap Radix, cmdk and lucide and import nothing from shell or IPC. Custom ESLint rules: `token-styles` rejects arbitrary px/rem/ms values, literal and default-palette colours and numeric `z-`/`duration-`/`delay-`; `component-names` requires PascalCase components and kebab-case primitives. Built-in restrictions ban re-exports, development code in the product, and `@tauri-apps/*` outside the listed adapter files. A stylesheet checker, run as a node test rather than by ESLint, confines pixel lengths to `tokens.css` and colours to `theme.css`. [theme](../../../../native/desktop/frontend/src/styles/theme.css#L1), [tokens](../../../../native/desktop/frontend/src/styles/tokens.css#L1), [primitive](../../../../native/desktop/frontend/src/components/ui/button.tsx#L10), [rules](../../../../native/desktop/frontend/dev/eslint/design-system.mjs#L18), [boundaries](../../../../native/desktop/frontend/eslint.config.js#L55).

Playwright has two projects: `product` serves a fresh `vite build` through `vite preview` with no host or a faked `__TAURI_INTERNALS__`, and checks the bundle for development leakage; `scenarios` drives `scenarios.html` (axe audits in both schemes, keyboard, touch, manager flows). Storybook is a separate catalogue; `shots` photographs it without baseline comparison. The tests call themselves presentation evidence, and the README lists what only a packaged window shows, such as runtime sign-in, native menus, the real content security policy and PTY sessions. Observations to check: the `design-system` spec holds a few token-to-geometry cases, not token conformance; `terminal-theme.spec.ts` runs the repository `.venv` Python at load; the test server builds without `tsc`. [Playwright](../../../../native/desktop/frontend/playwright.config.ts#L29), [axe audit](../../../../native/desktop/frontend/tests/scenarios/accessibility.spec.ts#L11), [limits](../../../../native/desktop/frontend/README.md#L473).

## Working notes

- A new host command needs a `HostCommands` entry, a `Host` method with its `tauriHost` implementation, a scenario-host answer and the Rust handler; raw-body commands bypass `hostCall`. [raw body](../../../../native/desktop/frontend/src/ipc/contract.ts#L607)
- Define a design measure once in `tokens.css`; components name roles or tokens, never values. [design system](../../../../native/desktop/frontend/README.md#L189)
- No CSS modules, barrels or forwarding components; a component module exports components and types only; icons come from `ui/icon.tsx`; chrome strings use `python -m dev.locales set-batch`, then bootstrap. [conventions](../../../../native/desktop/frontend/README.md#L239)
- Check, build, test and catalogue commands need `CADRUMO_CMAKE_BINARY_DIR` set to the absolute build directory. [bootstrap](../../../../native/desktop/frontend/README.md#L49)
- Before finishing run `npm run check`, then `npm test`. [check and test](../../../../native/desktop/frontend/README.md#L396)
