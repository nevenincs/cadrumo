# Native build, CMake and packaging

CMake owns configure, the release-builder environment, the build graph, installation and ZIP packaging of the native distribution, not application behavior. Portable filesystem, wheel, documentation and verification work is delegated to `dev.packaging.native` Python actions through one dispatcher, Rust crates build through one Cargo wrapper, and the desktop shell (React frontend, Tauri host) is a standalone CMake project driven by Node scripts. The product is a staged tree at `stage/<Config>/app`: the bundled CPython host and bridge, the `aeat`, `cadrumo-mcp` and `cadrumo-runtime` entrypoint hosts, the locked wheel cohort, the published registry authority, bundled user documentation, and the application images a platform mapping declares (desktop host and per-user manager on Windows). Everything is a local file; nothing here submits to a tax authority ([contract](../../../../native/CONTRACT.md#L363), [dispatcher](../../../../dev/packaging/native/cmake_build.py#L154), [Cargo wrapper](../../../../native/cmake/Rust.cmake#L3), [images](../../../../native/platforms/windows-x64.json#L18)).

Root configure presets are `windows-x64` (Visual Studio 17 2022), `windows-installers-x64` (isolated tree for unsigned installer builds), `linux-x86-64`, `linux-aarch64` and `macos-arm64` (Ninja Multi-Config). Windows build presets are `debug`, `release`, `package-debug`/`package-release` (target `zip`) and `windows-installers-release` (target `native-installer`); other hosts use `<preset>-debug` and `<preset>-release` with target `bundle`. A binary directory must be `build/<configure preset name>` at the repository root; other names are refused, and `native/desktop` and `native/cmake/distribution` follow the same rule with their own presets. The recipes `just build-native`, `test-native-bundle`, `build-native-package`, `test-native-package` and `test-native-release` map the host to a preset, run `cmake --preset`, then build one target. A developer needs `just` 1.38 or newer, `uv`, exactly CMake 4.4.3, MSVC 14.44.35207 with Windows SDK 10.0.26100.0, Rust 1.96.0 in the user's rustup toolchains, and Node with npm for the desktop ([presets](../../../../CMakePresets.json#L8), [directory rule](../../../../native/cmake/BinaryDirectory.cmake#L6), [host map](../../../../justfile#L623), [pins](../../../../native/toolchain.json#L2), [prerequisites](../../../../CONTRIBUTING.md#L9)).

Configure runs `Identity.cmake`, then `Bootstrap.cmake` converges the builder in `_deps/builder` with `uv sync --locked` at the patch in `dev/packaging/release-python-version`. `native/CMakeLists.txt` defines `python_sdk`, `python_dependencies` and `native_build_tools`, the cached `native_contract` target generating `contract.rs`, `.h` and `.json`, then the platform adapter (Rust platform libraries, interpreter hosts, bridge, entrypoints), launch guard, manager, Windows installer library and application library. `Packaging.cmake` adds `registry_authority` (reuse, or `registry_authority_rebuild`), `python_product`, `user_docs`, the desktop project only when a desktop image is staged, `app-distro` (`bundle` aliases it), `zip`, `verify`, `verify-package`, then `verify-release` and `native-installer`, which configures the nested distribution project against the staged payload for MSI, DEB, RPM or DMG ([bootstrap](../../../../native/cmake/Bootstrap.cmake#L15), [targets](../../../../native/CMakeLists.txt#L46), [authority](../../../../native/cmake/Authority.cmake#L3), [assembly](../../../../native/cmake/Packaging.cmake#L153), [installer flow](../../../../native/cmake/InstallerFlow.cmake#L84)).

Controls are implemented in source, not proven by it. `native/toolchain.json` owns the pins; configure refuses another CMake version, a compiler or SDK that differs from the pins, and a compiler OS, bitness or processor that differs from the target. Linux needs an explicit toolchain file and a glibc 2.28 builder, macOS an admitted Apple clang and SDK, and builder files are hashed into `build-toolchain.json`. Compile policy sets C17 with `/W4 /sdl /guard:cf` on MSVC or the hardening flags the compiler supports elsewhere. Shared actions record input fingerprints and output inventories (cache schema 3) so a configuration switch can reuse them. CTest registers `bundle.*` probes of the staged tree, and `verify-package` extracts the ZIP into a path with Unicode and spaces. `check-msi-installation` currently refuses and compiled MSI products stay `installable: false`; the window smoke needs an interactive logon session, and install or upgrade acceptance belongs on disposable hosts. Hashes show integrity, not publisher authenticity, and none of this shows that an installed product works ([root checks](../../../../CMakeLists.txt#L12), [compile policy](../../../../native/cmake/CompilePolicy.cmake#L8), [cache](../../../../dev/packaging/native/action_cache.py#L73), [bundle tests](../../../../native/cmake/Packaging.cmake#L171), [MSI gate](../../../../native/CONTRACT.md#L1622), [window smoke](../../../../native/CONTRACT.md#L1225)).

Scoped observations needing current-code checks: the two Linux presets set no toolchain file, so configure reaches the root refusal unless one is supplied, while `just build-native` runs a plain `cmake --preset`. `CADRUMO_BUILD_NUMBER` defaults to 1 in code, whereas the contract says the Git commit count. `just setup-native-builder` converges a builder in managed storage whose interpreter variable no build recipe passes on; CMake provisions its own `_deps/builder`. `Docs.cmake` filters `dev/docs/**/tests/` out of documentation inputs while the next comment says that tree is retained. The `launch_guard.cadrumo_python_d` test targets an `EXCLUDE_FROM_ALL` host, and whether `verify` builds it without `CADRUMO_INCLUDE_DEVELOPMENT_BINARY` is unestablished. The `release` target depends only on `verify-release`, not the installers ([Linux refusal](../../../../CMakeLists.txt#L34), [build number](../../../../native/cmake/BuildNumber.cmake#L2), [builder recipe](../../../../justfile#L617), [docs filter](../../../../native/cmake/Docs.cmake#L23), [launch guard](../../../../native/cmake/LaunchGuard.cmake#L27), [release](../../../../native/cmake/ReleaseVerification.cmake#L13)).

## Working notes

- The private agent is a native dependency: `CADRUMO_AGENT_SOURCE_DIR` selects a local project folder, and `agent_project` builds and inventories its wheel, and `python_product` installs it beside Cadrumo in the custom package library. `agent-install`, `agent-uninstall`, `agent-rebuild` and `agent-checksum` own its lifecycle; explicit `agent-lock-<target>` targets maintain compatible hashed native dependency locks. `bundle.agent` exercises the staged interpreter and installed package, with no external agent checkout ([targets](../../../../native/cmake/Agent.cmake), [dependency admission](../../../../dev/packaging/native/agent.py), [installed probe](../../../../native/tests/agent_smoke.py)).

- Tool versions live only in `native/toolchain.json`; layout in `native/package-layout.json` and `native/platforms/*.json`; output paths in `BuildPaths.cmake`; the product version in `pyproject.toml` ([root](../../../../CMakeLists.txt#L7), [paths](../../../../native/CONTRACT.md#L383), [version](../../../../native/CONTRACT.md#L444)).
- A new packaged executable needs a CMake target and an artifact variable named by an `application_images` entry; staging stops with a fatal error without both ([staging](../../../../native/cmake/Packaging.cmake#L85)).
- A configured directory cannot change target ([target](../../../../native/cmake/Identity.cmake#L24)).
- Every build output needs a declared CMake owner, path and generating target; undeclared generation is a build defect, and PowerShell is not part of the build ([outputs](../../../../native/CONTRACT.md#L386), [PowerShell](../../../../native/CONTRACT.md#L393)).
- No concurrent builds or cleanup in one binary directory; build before `cmake --install` ([contract](../../../../native/CONTRACT.md#L498)).
- Registry or compiler edits do not republish authority; use `registry_authority_rebuild` or `just registry-publish-authority` ([contract](../../../../native/CONTRACT.md#L515)).
- `CADRUMO_CONFIGURE_PAYLOAD=OFF` yields no bundle, installer or package result ([contract](../../../../native/CONTRACT.md#L31)).
