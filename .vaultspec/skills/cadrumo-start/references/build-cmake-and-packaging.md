# Native build, CMake and packaging

Direct Python writer CLIs use `build_directory.py` to admit only visible preset roots with matching source/cache/manifests and physical, declared output paths. Configure-stage generators admit the manifest before CMake creates its cache. Native build and verification scratch belongs to that build; obsolete output manifests require reconfiguration. [Admission](../../../../dev/packaging/native/build_directory.py), [output map](../../../../native/cmake/BuildPaths.cmake).

CMake owns configure, validation of externally provisioned build tools, the build graph, installation and ZIP packaging of the native distribution, not application behavior. Portable filesystem, wheel, documentation and verification work is delegated to `dev.packaging.native` Python actions through one dispatcher (`sdk`, `provision`, `product`, `assemble`, `run`, `tools`, `agent`), Rust crates build through one Cargo wrapper, and the desktop shell (React frontend, Tauri host) is a standalone CMake project driven by Node scripts. The product is a staged tree at `stage/<Config>/app`: the bundled CPython host and bridge, the `aeat`, `cadrumo-mcp`, `cadrumo-runtime` and dedicated `cadrumo-agent-service` entrypoint hosts, the locked wheel cohort with the bundled agent, the published registry authority, bundled user documentation, and the application images a platform mapping declares (desktop host and per-user manager on Windows). Everything is a local file; nothing here submits to a tax authority ([contract](../../../../native/CONTRACT.md#L117), [dispatcher](../../../../dev/packaging/native/cmake_build.py#L179), [Cargo wrapper](../../../../native/cmake/Rust.cmake#L3), [images](../../../../native/platforms/windows-x64.json#L18)).

Service is a fixed-module native host (`cadrumo_agent_service.main`), distinct from generic Python and cadrumo-agent. Its package environment receives agent/relay/AEAT/Python paths; runtime/profile workers do not. Assembly stages and hashes immutable `data/service-descriptors.json` after relocation, with exact service/desktop-holder images, custody capability and non-person operation ceilings. Incremental image updates verify the prior descriptor manifest hash and refresh image/parent/descriptor identities without changing policy. [Descriptor producer](../../../../dev/packaging/native/service_descriptors.py), [assembly owner](../../../../dev/packaging/native/assemble.py), [image/profile declaration](../../../../native/application-environment.toml), [native hosts](../../../../native/cmake/platforms/Windows.cmake).

Root configure presets are `windows-x64` (Visual Studio 17 2022), `windows-installers-x64` (isolated tree for unsigned installer builds), `linux-x86-64`, `linux-aarch64` and `macos-arm64` (Ninja Multi-Config). Windows build presets are `debug`, `release`, `package-debug`/`package-release` (target `zip`) and `windows-installers-release` (target `native-installer`); other hosts use `<preset>-debug` and `<preset>-release` with target `bundle`. A binary directory must be `build/<configure preset name>` at the repository root; other names are refused, and `native/desktop` and `native/cmake/distribution` follow the same rule with their own presets. The recipes `just build-native`, `test-native-bundle`, `build-native-package`, `test-native-package` and `test-native-release` map the host to a preset, run `cmake --preset`, then build one target. A developer needs `uv`, `just` 1.38 or newer and, on Windows, PowerShell 7.4 or newer; the native build also needs the tools whose minimum versions `native/toolchain.json` declares (CMake 4.4.3, MSVC 14.44.35207 with Windows SDK 10.0.26100.0, Rust 1.96.0) and Node with npm for the desktop. Those versions are floors: configure refuses an older tool and admits any newer release ([presets](../../../../CMakePresets.json#L10), [directory rule](../../../../native/cmake/BinaryDirectory.cmake#L6), [host map](../../../../justfile#L639), [recipes](../../../../justfile#L683), [floors](../../../../native/toolchain.json#L2), [floor rule](../../../../native/cmake/ToolchainFloor.cmake#L1), [prerequisites](../../../../CONTRIBUTING.md#L9)).

Configure runs `Identity.cmake`, then `Bootstrap.cmake` selects an existing development interpreter through the system uv binary or explicit `CADRUMO_DEV_PYTHON` and validates dependencies without synchronizing an environment. `native/CMakeLists.txt` defines `python_sdk`, `python_dependencies` and `native_build_tools`; `Contract.cmake` defines the cached `native_contract` target generating `contract.rs`, `.h` and `.json` from `native/package-layout.json`, the platform mapping and `native/application-environment.toml` (the process-environment declaration, see [the environment contract reference](environment-contract.md)); then come the platform adapter (Rust platform libraries, interpreter hosts, bridge, entrypoints), launch guard, manager, Windows installer library and application library. `Agent.cmake` builds the private agent wheel (see [the agent integration reference](agent-integration.md)). `Packaging.cmake` adds `registry_authority` (read-only source-currency validation; publication is an explicit authoring prerequisite), `python_product` (after `python_dependencies`, `registry_authority` and `agent_project`), `user_docs`, the desktop project only when a desktop image is staged, `bundle` (the `ALL` target; `app-distro` is its alias), `zip`, `verify`, `verify-package`, then `verify-release` and `native-installer`, which configures the nested distribution project against the staged payload for MSI, DEB, RPM or DMG ([bootstrap](../../../../native/cmake/Bootstrap.cmake#L11), [targets](../../../../native/CMakeLists.txt#L50), [contract inputs](../../../../native/cmake/Contract.cmake#L11), [authority](../../../../native/cmake/Authority.cmake#L6), [product order](../../../../native/cmake/Packaging.cmake#L24), [assembly](../../../../native/cmake/Packaging.cmake#L230), [installer flow](../../../../native/cmake/InstallerFlow.cmake#L87)).

Controls are implemented in source, not proven by it. `native/toolchain.json` owns the floors; configure refuses a CMake, compiler, SDK or Rust below them and a compiler OS, bitness or processor that differs from the target. Linux needs an explicit toolchain file and a glibc 2.28 builder, macOS an admitted Apple clang and SDK, and builder files are hashed into `build-toolchain.json`. Compile policy sets C17 with `/W4 /sdl /guard:cf` on MSVC or the hardening flags the compiler supports elsewhere. Shared actions record input fingerprints and output inventories (cache schema 3) so a configuration switch can reuse them. CTest registers probes of the staged tree: `bundle.image.*`, `bundle.health.*` and `bundle.launch.*` (desktop images on Windows), `bundle.installer-bootstrap`, `bundle.agent`, `bundle.python`, `bundle.environment-conformance` (the package's own interpreter compared with the environment declaration), `bundle.environment-launch` (the agent image composed by the separate service owner), `bundle.entrypoint.*` (`--help`) and, on Windows, `bundle.runtime-lifecycle`. `bundle.agent` runs `native/tests/agent_smoke.py` under the package interpreter: imports from the deployed tree only, the manifest version and file hashes, `version --json`, and the hosting-contract and credential-frame versions; it starts no gateway. `verify-package` extracts the ZIP into a path with Unicode and spaces. Compiled MSI products stay `installable: false`; the window smoke needs an interactive logon session, and install or upgrade acceptance belongs on disposable hosts. Hashes show integrity, not publisher authenticity, and none of this shows that an installed product works ([root floor check](../../../../CMakeLists.txt#L15), [compiler floor](../../../../CMakeLists.txt#L53), [glibc builder](../../../../native/cmake/ManylinuxToolchain.cmake#L9), [Apple clang](../../../../native/cmake/DarwinToolchain.cmake#L33), [compile policy](../../../../native/cmake/CompilePolicy.cmake#L10), [cache](../../../../dev/packaging/native/action_cache.py#L129), [image tests](../../../../native/cmake/Packaging.cmake#L105), [package tests](../../../../native/cmake/Packaging.cmake#L238), [agent probe](../../../../native/tests/agent_smoke.py#L20), [MSI gate](../../../../native/CONTRACT.md#L1980), [window smoke](../../../../native/CONTRACT.md#L1558)).

Scoped observations needing current-code checks: the two Linux presets set no toolchain file, so configure reaches the root refusal unless one is supplied, while `just build-native` runs a plain `cmake --preset`. Native builds do not provision a separate Python environment. Frontend dependencies are explicit setup prerequisites, and `desktop-frontend-install` only validates them. Documentation cache and verification scratch stay beneath the selected binary directory. `Docs.cmake` filters `dev/docs/**/tests/` out of documentation inputs while the next comment says that tree is retained. The `launch_guard.cadrumo_python_d` test targets a host that is built only with `CADRUMO_INCLUDE_DEVELOPMENT_BINARY` (default `OFF`), and whether `verify` builds it otherwise is unestablished. The `release` target depends only on `verify-release` (`zip` plus the verification targets), not the installers ([Linux refusal](../../../../CMakeLists.txt#L40), [builder recipe](../../../../justfile#L649), [docs filter](../../../../native/cmake/Docs.cmake#L27), [launch guard](../../../../native/cmake/LaunchGuard.cmake#L29), [development binary](../../../../native/cmake/Packaging.cmake#L34), [release](../../../../native/cmake/ReleaseVerification.cmake#L18)).

## Working notes

- The private agent is a native dependency selected only by the CMake cache variable `CADRUMO_PACKAGE_AGENT_SOURCE_DIR` (a local project folder holding `pyproject.toml`; configure fails when it is unset, and the environment is never read). `agent_project` builds its wheel and records its version and checksum, and `python_product` installs it beside Cadrumo in the custom package library. `agent-install` (an alias building `bundle`), `agent-uninstall`, `agent-rebuild` and `agent-checksum` cover its lifecycle; explicit `agent-lock-<target>` targets maintain the hashed per-target dependency locks in `native/agent/`. Details are in [the agent integration reference](agent-integration.md) ([variable](../../../../native/cmake/Agent.cmake#L4), [wheel](../../../../native/cmake/Agent.cmake#L30), [locks](../../../../native/cmake/Agent.cmake#L42), [lifecycle](../../../../native/cmake/Packaging.cmake#L26), [admission](../../../../dev/packaging/native/agent.py)).
- Tool floors live only in `native/toolchain.json`; layout in `native/package-layout.json` and `native/platforms/*.json`; every image's process environment in `native/application-environment.toml`; output paths in `BuildPaths.cmake`; the product version in `pyproject.toml` ([root](../../../../CMakeLists.txt#L11), [environment](../../../../native/CONTRACT.md#L240), [paths](../../../../native/CONTRACT.md#L668), [version](../../../../native/CONTRACT.md#L738)).
- A new packaged executable needs a CMake target and an artifact variable named by an `application_images` entry; staging stops with a fatal error without both ([staging](../../../../native/cmake/Packaging.cmake#L90)).
- A configured directory cannot change target ([target](../../../../native/cmake/Identity.cmake#L27)).
- Every build output needs a declared CMake owner, path and generating target; undeclared generation is a build defect, and PowerShell only transports Windows acceptance to a disposable guest ([outputs](../../../../native/CONTRACT.md#L671), [PowerShell](../../../../native/CONTRACT.md#L678)).
- No concurrent builds or cleanup in one binary directory; build before `cmake --install` ([contract](../../../../native/CONTRACT.md#L819)).
- Native builds only validate authority and refuse a missing or stale publication; after registry or compiler edits run `just registry-publish-authority` before building ([contract](../../../../native/CONTRACT.md#L930)).
- `CADRUMO_CONFIGURE_PAYLOAD=OFF` yields no bundle, installer or package result ([contract](../../../../native/CONTRACT.md#L32)).
