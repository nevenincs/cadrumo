# Tauri desktop shell

The desktop shell is the `cadrumo` host binary (crate `cadrumo-desktop`) in `native/desktop/src-tauri`, with a React frontend in `native/desktop/frontend`. Launch selection has three modes. `--check-health [--hold-seconds N]` asks the manager to make the runtime ready and reports health without a window. `--headless`, any other arguments, or a missing desktop forward to the installed Python CLI. No arguments on an interactive desktop open one window, and `--gui` forces the window, failing with the desktop-unavailable exit code when there is no desktop. The shell presents, launches and relays. It grants no authority and starts no runtime: every command is gated by a per-launch shell token (`shell/token.rs`), and the per-user manager alone starts the runtime. The secrets it holds are the agent host's in-memory gateway bearer and, on Windows, a native runtime session for sign-in. Login, logout, profile create and list run as short-lived children of the packaged `aeat` CLI; passphrase change runs the `cadrumo-runtime` image; on Windows, sign-in first tries a native runtime connection and falls back to a held session. A startup window (`startup.html`, phases Environment, Runtime and Workspace) reports progress before the main window. Windows (WebView2) has every feature. On Linux the window, docs, logs, terminal and instance lock exist, but sign-in, context menus and manager dispatch return `unsupported`. macOS is refused when the window starts. [entry](../../../../native/desktop/src-tauri/src/main.rs), [modes](../../../../native/desktop/src-tauri/src/launch.rs#L28), [startup](../../../../native/desktop/src-tauri/src/startup.rs#L17), [macOS](../../../../native/desktop/src-tauri/src/app.rs#L120), [contract](../../../../native/CONTRACT.md).

The desktop is part of the repository build: `cmake --preset <name>` at the repository root configures it into `build/<name>`, and configuring `native/desktop` on its own is refused. `CADRUMO_DESKTOP_PACKAGE_ROOT` is a cache option that defaults to the staged application tree, the root build adds the desktop only when a desktop image is staged, and its host targets depend on the build's `native_contract`. Targets include `desktop-frontend-*` (install, build, check, test, dev, generated and the chrome, palette and icon generators), `desktop-host-*` (prepare, build, test, clippy, unit-test, unit-clippy), `desktop-run`, `desktop-headless-test`, `desktop-packaged-host` and the packaged, setup, startup, harness, paths, configuration and build tests, plus the CTest `desktop.clippy`. Under `scripts/`, `frontend-install.mjs` runs read-only (`--check`) in the build and runs `npm ci` only through `just setup-desktop-frontend`, `build-paths.mjs` admits output roots, `development-server.mjs` holds the fixed ports, `content-build.mjs` fingerprints inputs, `backend-snapshot.mjs` copies the crate and path crates into the build tree, and `tauri.mjs` writes `tauri.conf.json` there and runs the pinned Tauri CLI (`build --no-bundle -- --locked`), refusing a Cargo binary that differs from the image CMake declares. `tauri.conf.json.in` is read as plain JSON by `tauri.mjs`, not configured by CMake; `configuration.mjs` adds identity, a relative `frontendDist`, icons and a `frame-src` set to the docs origin, and requires the template's `frame-src` to be exactly `'none'`, which it replaces with the docs origin. The crate uses Tauri 2, `portable-pty`, a clipboard plugin and a dialog plugin (the agent file picker) through its Rust API only; its features are `live-package-tests` and `webview2-remote-debugging`; `build.rs` copies the generated contract into `OUT_DIR`. `just dev` publishes the registry authority if stale, then builds `desktop-frontend-dev`, which serves the frontend in a browser from the repository build and compiles no Rust. [CMake](../../../../native/desktop/CMakeLists.txt#L182), [tauri.mjs](../../../../native/desktop/scripts/tauri.mjs#L163), [configuration](../../../../native/desktop/scripts/configuration.mjs#L162), [crate](../../../../native/desktop/src-tauri/Cargo.toml#L1), [dev](../../../../justfile#L58).

The host uses request/response commands plus Tauri `Channel` streams and emits no events. Each module declares commands with `commands!`; `app.rs` composes them behind a per-launch token, handed once by an init script to the top frame on a shell origin and presented as a `token` argument or `x-cadrumo-token` header. Modules are `agent`, `app`, `auth_browser`, `docs`, `environment`, `launch`, `logs`, `manager`, `role`, `shell`, `startup`, `startup_logging` and `terminal`. The shell module serves the environment, `https:`/`mailto:` links, a bounded clipboard, a Windows-only context menu, window controls and the single-instance lock, and holds the `sign_in`, `provider_settings`, `agent_access`, `user_profile` (with the census), `setup`, `language`, `presentation` and `about` submodules. Direct login/logout/profile-create and profile metadata list retain their explicit AEAT exception after a digest check; broader status/auth/automation use the dedicated runtime image with the same config suffix. Passwords travel as a raw UTF-8 request body (at most 8192 bytes) and reach the child as JSON on `--secrets-stdin`, with the profile label percent-encoded in a header; password change takes an exact-key JSON object (16 KiB) and reports changed, refused or unknown. `provider_settings` calls authenticated service status/set/remove/reset/auth APIs with exact CAS and raw protected secret frames; `agent_access` lists/issues/revokes generic automation access through the runtime image, independent of person logout. The `docs` module serves a read-only `cadrumo-docs` scheme from a manifest allow-list with containment checks, a per-response CSP and the shell origins as frame ancestors, and declares no app commands. The `logs` module tails the Python log, manager JSONL and host diagnostics, batching records every 100 ms, into a ring feeding a bounded set of channels. The `terminal` module opens one PTY per kind (console, Python, TUI) with tagged binary frames and credit backpressure. The `manager` module requests manager launch through the existing Explorer desktop via a Python shim; on Windows it also holds a `DesktopHost` supervisor and stops only a host it owns. Installing a manager is explicit: the sign-in view asks for `manager_install` with User or Machine scope, and the manager stays the sole runtime supervisor. The `agent` module supervises the digest-verified `cadrumo-agent-service` image plus a generic runtime person holder in bounded process scopes. Native sends one bearer line, keeps stdin open, validates `service_ready` boot/connection/profile/service identities and grants that exact recipient through `cadrumo-runtime session hold`. Service admin is a separate bounded framed loopback endpoint, usable before agent readiness; provider changes use masked status/CAS and raw key exchange, never AEAT commands or gateway conversation routes. Service owns cadrumo-agent/store/tree lifecycle and emits outer ready/workspace/refusal/stopped state. Its inner hosted v1 credential/ready contract has no workspace/lane requirement. [Supervisor](../../../../native/desktop/src-tauri/src/agent/supervisor.rs), [outer events](../../../../native/desktop/src-tauri/src/agent/launcher.rs), [person holder](../../../../native/desktop/src-tauri/src/agent/person.rs), [admin transport](../../../../native/desktop/src-tauri/src/agent/admin.rs), [provider IPC](../../../../native/desktop/src-tauri/src/shell/provider_settings/mod.rs).

The sign-in wire contract in `shell/sign_in/wire.rs` parses the CLI envelope (`schema_version` `"2"`, `command` equal to `config.<leaf>`), reads the last stderr line as an envelope, and maps refusals such as `REFUSED_PROFILE_REGISTRATION` to `profile_already_exists`. `shell/sign_in/cli_contract_fixtures.py` builds the expected envelopes from the real `cadrumo` and `cadrumo_client` producers, `--check` byte-compares `cli_contract_fixtures.json`, and `wire_contract_tests.rs` embeds that file with `include_str!`; CMake runs `--check` in `desktop-host-unit-test` and `desktop-host-unit-clippy`. [wire](../../../../native/desktop/src-tauri/src/shell/sign_in/wire.rs), [fixtures](../../../../native/desktop/src-tauri/src/shell/sign_in/cli_contract_fixtures.py), [password change](../../../../native/desktop/src-tauri/src/shell/sign_in/password.rs).

The native Host preserves the actual full agent provider catalog. Offline declarations report unknown/unselectable readiness; ready catalog comes from actual authenticated gateway. Agent status and run streams use Tauri channels with bearer/token kept native. Whole-desktop attendance polls bounded runtime inventory and presents exact process/image/scope before one deliberate allow/reject gesture. Polling does not refresh person idle time. `agent_documents` forwards to the gateway attachments route and returns a page of stored documents, and `agent_attach` opens a native file dialog and uploads through the gateway attachment policy. [Gateway client](../../../../native/desktop/src-tauri/src/agent/gateway.rs), [host commands](../../../../native/desktop/src-tauri/src/agent/mod.rs), [attendance presentation](../../../../native/desktop/frontend/src/components/AttendanceRequests.tsx).

Build-script tests are `node --test` files run by `desktop-paths-test`, `desktop-configuration-test` and `desktop-build-test`. Rust tests run through `desktop-host-test` (feature `live-package-tests`, needs a built package) or `tests/run-backend.ps1`. `desktop-headless-test` compares CLI passthrough with the interpreter. `desktop-packaged-test` runs `node --test tests/packaged.test.mjs`, which drives `tests/run-packaged.ps1`; that harness needs an assembled package with documentation and an interactive, non-Session-0 desktop, builds a separate host with `webview2-remote-debugging`, drives WebView2 over DevTools, and sends real keys and clicks while the window is foreground. `shell-token.test.mjs`, `terminal-observer.test.mjs` and `development-server.test.mjs` are wired to no CMake target and run directly with `node --test`. Browser-level frontend tests run against a simulated host, so they show nothing about the token, scheme, WebView2, PTYs or window lifecycle. [packaged target](../../../../native/desktop/CMakeLists.txt), [runner](../../../../native/desktop/tests/run-packaged.ps1#L75), [host](../../../../native/desktop/tests/packaged/host.mjs), [procedure](../../../../native/CONTRACT.md).

Observations to check against current code. The macOS preset exists while the window refuses macOS. The terminal sources hold no Job Object or process-group code and kill the direct child, while the manual checklist expects window close to end every terminal child. The contract's command tables omit `manager_*` and the `agent_*` commands, and its desktop section does not describe manager installation. A killed install can leave `.cadrumo-npm.lock`. [terminal](../../../../native/desktop/src-tauri/src/terminal/session.rs#L116), [lock](../../../../native/desktop/scripts/frontend-install.mjs#L45).

## Working notes

- New command: add it to its module's `commands!` list (names must be distinct across modules, checked at startup), then mirror it in the frontend `HostCommands` map and `tauriHost.ts`; agent commands hang off `tauriAgent`. [composition](../../../../native/desktop/src-tauri/src/app.rs#L78), [contract](../../../../native/desktop/frontend/src/ipc/contract.ts#L1117).
- The token is read once and never posted to the docs frame, a URL, storage or a log. [token](../../../../native/desktop/src-tauri/src/shell/token.rs#L12).
- The gateway bearer and provider keys never reach the webview, a command line, a file or a log; keys travel only on protected native/service secret exchange and the inner agent stdin/worker pipe. [provider settings](../../../../native/desktop/src-tauri/src/shell/provider_settings/mod.rs#L1).
- Ports come from `development-server.json`; an occupied port is an error. [README](../../../../native/desktop/frontend/README.md#L11).
- The shell policy must frame exactly the docs origin; the build refuses otherwise. [configuration](../../../../native/desktop/scripts/configuration.mjs#L162), [contract](../../../../native/CONTRACT.md).
- `CADRUMO_DESKTOP_DOCS_ROOT` applies only in development builds. [docs](../../../../native/desktop/src-tauri/src/docs/mod.rs#L30).
- Packaged builds refuse `WEBVIEW2_*` overrides; `webview2-remote-debugging` admits only one remote-debugging argument and is never for distributed builds. [overrides](../../../../native/desktop/src-tauri/src/shell/webview_environment.rs#L1).
- Session 0 has no window station; check the window from an interactive logon. [contract](../../../../native/CONTRACT.md#L1811).
