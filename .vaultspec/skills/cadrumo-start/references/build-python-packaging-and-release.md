# Python build, packaging and release

Cadrumo is one Python distribution, `cadrumo`, built with Hatchling and managed by uv from a committed lockfile. `requires-python` is `>=3.13`; two interpreter pins coexist on purpose: `.python-version` names only the development minor, while `dev/packaging/release-python-version` holds the exact patch that the release cohort, native builder and bundled CPython must equal. The wheel carries `cadrumo` and `cadrumo_harness` with the scripts `aeat`, `cadrumo-mcp` and `cadrumo-runtime`. Lazily imported extras (`google`, `browser`, `anthropic`, `ofx`, `llm`, `pdf`, `all`, `workbook-windows`) and the `registry` and `dev` groups sit beside it. The sdist is deny-by-default, the wheel sheds tests, authored registry source and corpus source binaries, and a hook force-includes the published authority from the gitignored `.authority/`. Corpus binaries ship in exact-version companion distributions that `tool.uv.sources` resolves from `packaging/` in development only ([project](../../../../pyproject.toml#L139), [sdist and wheel](../../../../pyproject.toml#L279), [release pin](../../../../dev/packaging/release-python-version)).

`just` is the entry point, and recipes run Python as `uv run --no-sync python -m dev...`, so a check never re-syncs the environment. `just setup` converges it; `just init` adds browsers, search and authority publication. Static checks are `check-style`, `check-format`, `check-types` (ty over `src`; pyrefly and basedpyright over the strict subset in `pyproject.toml`), `check-import-boundaries` and `check-dependency-declarations`; `check-code` aggregates them with the reachability and usage censuses, and `check-registry-gate` is separate. Pytest `testpaths` cover only `src/cadrumo` and `src/cadrumo_harness` under a default `unit` marker expression, so tests under `dev/` and `native/tests` run only through recipes that restate the markers (`test-test-policy`, `test-repository-contracts`, `test-release-tooling`, `test-ci-contracts-gate`, `docs-check`). `dev.ci.change_scope` maps changed paths to pytest targets for `test-gate`: no list selects the full tree, while a change it cannot narrow (`pyproject.toml`, `uv.lock`, a `conftest.py`, `cadrumo.core`, more targets than its cap) runs only a fixed contract set behind a banner ([check-code](../../../../justfile#L263), [test-gate](../../../../justfile#L1129), [scope](../../../../dev/ci/change_scope.py#L59)).

`build-distributions` runs `uv build` for the root and each companion, then `dev.packaging.distribution_cap` refuses any file at or over the package index size limit. Releases go through `python_cohort`, which snapshots the tree, stages the authority, builds the wheels and sdists, and writes a wheelhouse and digest manifest. `test-packaging-preflight` runs `dependency_surface` (extras and frozen `uv export` against wheel metadata), `source_preflight` (shipped data against the wheel payload) and the packaging contract tests. The wheelhouse is a zip of lock-selected, hash-checked wheels per runtime and target; the native package does not unpack it, because native provisioning calls the same `runtime_wheel_selection` planner itself. `release_cohort` rebuilds from a clean snapshot, requires the pinned CPython, and declares Python, Scoop and Homebrew artifacts but no native desktop artifact. The `acquire_*` modules reinstall published bytes and run the installed `aeat` oracle; `campaign` runs the `smoke_*` modules ([distributions](../../../../justfile#L540), [python_cohort](../../../../dev/packaging/python_cohort.py#L347), [artifacts](../../../../dev/packaging/cohort_manifest.py#L146)).

CMake owns the native graph and calls Python: `cmake_build` dispatches the shared `sdk`, `provision`, `tools`, `product` and `assemble` actions, while `generate`, `identity`, `metadata`, `authority_build`, `docs_build`, `docs_stage`, `artifact_verify` and the installer authors run directly. Shared actions are fingerprinted over inputs and pins, locked, and refuse their receipt if an input changed mid-run. Provisioning fetches the pinned CPython SDK (NuGet on Windows, Python Build Standalone elsewhere, hash-checked) and installs hash-required wheels; `stdlib` compiles bytecode only under the exact patch; `assemble` relocates native modules; `authority_build` reuses an existing authority unless rebuild is requested. MSI and Linux packages are marked `installable: false` behind maintenance gates, and Windows acceptance needs a disposable interactive runner and two built releases (Session 0 is insufficient). Observations to check: `just setup-native-builder` creates an environment separate from the builder CMake provisions under its binary directory, and the `assemble` command line passes no provenance, so Linux and macOS assembly works only through `cmake_build` ([actions](../../../../dev/packaging/native/cmake_build.py#L200), [provision](../../../../dev/packaging/native/provision.py#L43), [MSI gate](../../../../dev/packaging/native/windows_msi.py#L20)).

User documentation is Sphinx (MyST, Furo) configured at `docs/conf.py` and driven by `dev/docs`; `docs-build` and `docs-check` build and test it. The CLI reference, glossary, API stubs and `cli-tree.json` are generated at build time and gitignored. The desktop path is separate: `Docs.cmake` calls `native/docs_build`, one strict `compile_once --flavor desktop` for the languages in `native/package-layout.json` with one Pagefind index, cached by input identity. `docs_stage` refuses remote references and inline handlers, then writes the manifest `assemble` verifies. `docs-publish` is a hosted-site deployment, not part of the package ([generated pages](../../../../.gitignore#L85), [Docs.cmake](../../../../native/cmake/Docs.cmake#L43), [docs-build](../../../../justfile#L1494)).

`merge-gate.yml` gates pull requests on self-hosted Linux x64: `lint` (style, format, types, workflows), `gate` (semgrep, registry gate, import boundaries, `test-gate` over changed paths read from the forge API, sequence goldens) and a fork-refusing `verdict`. The setup action pins `just` and uv and runs `just setup`. Release-please proposes and tags; `release.yml` is dispatch-only. Its prove phase runs the gate, the full suite on the supported and next interpreters and conformance, builds and seals the cohort once, and proves it on Linux, Windows and macOS; its publish phase verifies the sealed digest, refuses burned versions, attests and uploads the unchanged bytes to PyPI by Trusted Publishing, updates Homebrew and Scoop, reacquires each channel and publishes docs. A green prove run is a validated candidate, not a published release, and nothing here submits a return. Observations to check: the pull-request gate selects owning tests only under `src/`, so packaging suites run in release prove, and RELEASING.md says hosted runners though jobs use self-hosted labels. Development runtime lifecycle tests start a test-owned manager inside a kill-on-close job on a fresh root, create no login-start registration and reap the job ([merge gate](../../../../.github/workflows/merge-gate.yml#L42), [release](../../../../.github/workflows/release.yml#L327), [lifecycle](../../../../dev/runtime_lifecycle/README.md#L58)).

## Working notes

- Native builds add the private `cadrumo-agent` wheel from the CMake-owned source pin and the target-specific hashed closure in `native/agent/`. Shared dependency versions must equal the root lock. These supplemental locks and the source/wheel hashes are recorded in native provenance; no Python index publication or development-checkout import supplies the agent ([owner](../../../../native/cmake/Agent.cmake), [admission](../../../../dev/packaging/native/agent.py), [probe](../../../../native/tests/agent_smoke.py)).

- Pins: `.python-version` must stay a minor ([test](../../../../dev/ci/tests/test_python_version_pin.py#L37)); version surfaces belong to release-please ([config](../../../../release-please-config.json#L16)).
- Before finishing: `just check-code`, `just check-registry-gate`, `just test-gate`, then read `just report-code-health`; a failure on untouched code is reported, not fixed ([CONTRIBUTING](../../../../CONTRIBUTING.md#L97)).
- Generated files are never hand-edited and `.authority/` is never committed; after registry edits publish with `just registry-publish-authority-if-authority-stale` ([standards](../../../../CONTRIBUTING.md#L89), [recipe](../../../../justfile#L786)).
- A test no lane selects fails the reachability gate, so a new test directory needs a lane path ([gate](../../../../dev/tests/test_lane_reachability.py#L1)). Repository code never launches Git ([test](../../../../dev/quality/tests/test_no_git_cli.py#L1)).
- `just clean` only reports; `clean-apply` deletes irreversibly, outside the worktree too ([clean](../../../../justfile#L248)).
- Refusals: oversized distribution files, release builds off the pinned CPython, product builds without the OAuth client ([pin check](../../../../dev/packaging/release_cohort.py#L319), [OAuth](../../../../dev/packaging/google_oauth.py#L61)).
