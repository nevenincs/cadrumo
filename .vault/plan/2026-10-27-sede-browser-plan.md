# `sede-browser` plan

## Description

Approved 2026-10-27. Basis: the user's choice, in the orchestrating session of 2026-10-27, of "stream our Chromium's page into a panel" followed by "implement 1)", and the user's ruling of 2026-10-27 that the in-app browser is free use: "I do not understand how we could limit usage - its a browser, free usage. I would not attempt to restrict or define limits, it should not be technically enforceable." Session sharing goes through the same custody.

The plan builds the in-app AEAT Sede browser: a Browser rail item, the AEAT rail item opening it at the Sede with an "Open in external browser" context menu, and a panel that draws the profile worker's own Chromium page streamed as JPEG images and forwards the person's CDP input. The person browses any site without restriction; downloads and file choosers use native save and open dialogs, and "Open in external browser" is the person's action in the AEAT context menu and the toolbar. The panel and every CLI and TUI sync share one encrypted storage-state custody: the view seeds from it, logins in the panel, manual or assisted, publish to it after provider verification, and the view republishes on close only after provider verification and a digest precondition.

Decision coverage: `2026-10-27-sede-browser-adr` (accepted) governs every Step. Its amendment of 2026-10-27 in `2026-10-03-aeat-live-write-guard-adr` places the human-driven view context outside the guard's scope and keeps the guard unchanged for every Cadrumo-initiated request, including P05.S12's assisted login steps. The amendment in `2026-10-04-application-sign-in-adr` governs P01 (view stream lane, attach token, unbinding on session retirement). The amendment in `2026-10-04-desktop-shell-adr` governs P03 and P04. `2026-06-04-live-auth-decomposition-adr` governs P02.S05 and P05.S12 unchanged: application auth owns acquisition and publication, the browser adapter owns context construction, and a running context is never re-seeded. `2026-07-21-desktop-capture-harness-adr` is out of scope and unchanged. S02 of `2026-09-24-aeat-live-write-guard-plan` remains that plan's Step and is not touched by this plan.

## Parallelization

Hard ordering:

- P01.S01 lands first: its control models and `view_stream_vectors.json` are the contract P01.S02, P01.S03, P02.S06, P02.S07 and P03.S08 consume.
- P01.S02 precedes P02.S07, which wires the operation onto the worker view channel. The executor reaches that channel only through a typed sink port the host composes into the operation context; the tax package never imports `cadrumo_runtime`.
- P02.S04 and P02.S05 precede P02.S07. P02.S06 precedes P02.S07.
- P01.S03 precedes P03.S08. P03.S08 precedes P04.S09, which consumes the host commands and channel messages.
- P04.S09 precedes P04.S10 and P04.S11. P04.S10 precedes P04.S11.
- P05.S12 needs P02.S07 complete.
- P06.S13 needs P01 to P05 complete. P06.S14 runs last, after P06.S13, with the operator present.

Parallel lanes with disjoint write ownership, after P01.S01:

- Lane A (runtime and Rust transport): P01.S02, then P01.S03. Owns `src/cadrumo_runtime/host/` and `native/application/src/runtime_client.rs`, `view_stream.rs`, `lib.rs`.
- Lane B (Python browser adapter and auth): P02.S04, P02.S05 and P02.S06 in parallel with each other only if their files stay disjoint. S04 owns `browser/session.py` only; it adds no request guard and does not touch `remote_state_guard.py` or `core/remote_authority.py`. S05 owns `application/auth/sessions.py`, `application/live/session.py`, `auth/authenticator.py` and `auth/session_store.py`. S06 owns `browser/screencast.py` and `browser/view_input.py`. A page-observer hook needed by S06 is added by S04, so S06 rebases on S04 before closing.
- Lane C joins after A and B: P02.S07, then P05.S12 (both own `application/live/sede_view_operation.py`, so they are serial).
- Lane D (desktop): P03.S08, then P04.S09, P04.S10 and P04.S11 serially. Owns `native/desktop/`. P04.S10 also writes `src/cadrumo_client/contracts/navigation.toml`, the locale catalogues and `dev/locales/desktop_chrome.py`, which other sessions edit concurrently: re-read before patching and commit by pathspec. P03.S08 touches `native/application/src/person_operations.rs` only after lane A has closed P01.S03.

## Verification

Per-Step checks. Each Step also runs `just check-style`, `just check-format` and `just check-types` on its scope, and `just check-import-boundaries` when it adds or moves an import. Native code builds and tests only through CMake targets; nothing calls cargo directly, and no installer or MSI target is built.

- P01.S01: `uv run --no-sync pytest src/cadrumo_client/transport/tests src/cadrumo_client/contracts/tests`. Required evidence: header round trip at the 65,520-byte and 2 MiB bounds; refusal of an out-of-order chunk, an interleaved image, an oversize image and a `B` frame on a document reader; the vectors file is regenerated by its owner, not hand-edited.
- P01.S02: `uv run --no-sync pytest src/cadrumo_runtime/host/tests -k view`. Required evidence: an attach from another session, another profile, another native peer, a reused token and an expired token each refused; unbinding on sign-out, lock, operation end and person-connection close happens before worker settlement; with no window credit no image is buffered.
- P01.S03: `just check-rust`, then `just test-native-bundle Debug`. Required evidence: the Rust reader passes the shared vectors and refuses the same violations as Python.
- P02.S04: `uv run --no-sync pytest src/cadrumo/adapters/outbound/aeat/browser/tests -k view`. Required evidence, through real headless Chromium against synthetic pages: nothing is blocked, so a form POST, an off-host top-level navigation and subresource, a service worker registration and a WebSocket all complete; the context has no route installed; a popup opens as a view page, and a download, a file chooser and a page dialog each reach the page-observer hook; the hook evaluates no script, checked by a static test.
- P02.S05: `uv run --no-sync pytest src/cadrumo/application/auth/tests src/cadrumo/application/live/tests -k "view or session"`. Required evidence: identity mismatch publishes nothing; a stored digest changed by another acquisition yields kept-newer and leaves it intact; an interruption after the `UNKNOWN` report stays unknown; the acquisition lock is not held while browsing.
- P02.S06: `uv run --no-sync pytest src/cadrumo/adapters/outbound/aeat/browser/tests -k "screencast or input"`. Required evidence: frames stop without credit and resume with the newest image; out-of-range coordinates are clamped and unknown variants are refused; a burst of input is delivered without a rate cap; no `evaluate` call exists in the adapter, checked by a static test.
- P02.S07: `uv run --no-sync pytest src/cadrumo/application/live/tests -k sede_view`, `just check-operation-contract-manifest`. Required evidence: MCP and non-desktop sessions are refused; cancel, panel close and person-session retirement reach the closing phase, and a view with no input keeps running with no idle or absolute expiry; download bytes reach the host and an upload payload reaches the page with no scratch file; the journal holds no URL, title, frame, input or file bytes.
- P03.S08: `just check-rust`, `just test-native-bundle Debug`. Required evidence: every command refuses a bad token; a download writes only to the path chosen in the native save dialog and a cancelled dialog writes nothing; a file chooser sends only the file chosen in the native open dialog; the external open uses the host-held current URL and the window sends none; page close, window close and session loss cancel the view.
- P04.S09 to P04.S11: in `native/desktop/frontend`, `npm run check` and `npx playwright test tests/scenarios/sede-browser.spec.ts tests/scenarios/navigation-register.spec.ts tests/scenarios/palette.spec.ts`; `just check-locales`. Required evidence: no frame, URL or title reaches localStorage or the documentation frame; the AEAT context menu and the toolbar each open the external browser; the AEAT click opens the Browser page; download and file-chooser prompts reach the host commands.
- P05.S12: `uv run --no-sync pytest src/cadrumo/adapters/outbound/aeat/auth/tests -k "view or headless"`. Required evidence: the CLI's Cl@ve Movil path keeps its forced headed browser when no view is attached; a manual login in the view is captured, verified and published, and a failed verification publishes nothing; the person's interrupt stops an assisted step and returns input at once.
- P06.S13: `uv run --no-sync pytest src/cadrumo_runtime/host/tests/test_view_stream_integration.py` and the native integration target through `just test-native-bundle Debug`. Required evidence: a redaction scan over logs, journals, projections and diagnostics after a scripted session finds no frame bytes, URL query, title, typed text or file bytes, and every request class the synthetic pages issue completes unblocked.
- P06.S14: attended by the operator on a development build. Recorded in the ledger: a panel login reused by an `aeat` live read with no new login, a CLI login adopted by a newly opened panel, a manual Cl@ve Permanente login, an off-AEAT page, a download and an upload through the native dialogs with nothing blocked, an external open of the current page, and the close-time publication outcome.

The plan is complete when every Step is closed, each Phase-close review and the final integrated review pass, and pending verification is reported apart from defects.
