Repair the .importlinter exception ledger so the layered gate is a trustworthy measurement instrument before any other remediation is verified against it.

- [x] `P01.S03` - Re-file the entries physically sitting under the wrong contract narrative header so each ignore entry lives inside the contract it actually exempts, re-verifying the S21/S22/S23 header placements at execution time; `.importlinter`.

## Description

This is the Wave 0 instruments plan of the architecture remediation program. It
discharges deferral register items D1 (the application-to-adapters wildcard) and
D8 (the stale, duplicated, misfiled, warn-only gate ledger) surfaced by the
architecture review audit. The program ADR orders this plan first because the
`.importlinter` layered contract is the measurement instrument every other
remediation wave is verified against, and the audit found that instrument
untrustworthy: an 815-line ledger with a verbatim-duplicated 29-entry block,
further duplicated blocks, entries filed under the wrong contract narrative
header, eight pinned modules that no longer exist, and warn-only unmatched
alerting that lets any of those defects pass silently.

Phase P01 repairs the ledger (dedupe, re-file, purge dead entries, flip
alerting to error). Phase P02 replaces the blanket application-to-adapters
wildcard with individually pinned per-module edges so the seam becomes
measurable again. Phase P03 lands the ratchet gates that keep the repaired
ledger honest: a pinned-module existence check and count-ratchets on the
application-to-adapters and domain-to-adapters seams. Per the program ADR's
ratchet policy, the enforcement gates land in the same plan as the repair, so a
later wave cannot silently regrow the ledger. The domain-to-adapters count
ratchet is the burn-down instrument the ports-inversion campaign (Wave 3)
consumes.

## Steps

## Parallelization

The phases are hard-ordered and must land in sequence. P02 (wildcard to pinned
edges) depends on P01's alerting flip: pinning ~80 edges under warn-only
alerting would mask a mistyped edge, so the alerting must already be error
before the pins land. P03 (ratchet gates) depends on both prior phases because
the count-ratchet baselines are recorded from the post-repair, post-pin ledger.
Within P01, the four editorial steps (S01 dedupe, S02 dedupe, S03 re-file, S04
purge) touch overlapping regions of the single `.importlinter` file and are
performed by one owner in one sequence rather than in parallel; S05 (alerting
flip) follows them. This plan is a single-file campaign against `.importlinter`
plus one new test module, so it is single-owner throughout; it does not compete
for the contended orchestrator hub files.
