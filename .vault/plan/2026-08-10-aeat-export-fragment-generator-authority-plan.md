# `aeat-export-fragment-generator-authority` plan

Build and prove the single fail-closed authority that generates complete export-fragment revisions from official AEAT binaries and reviewed semantic maps.

## Description

This L3 plan executes `2026-08-10-aeat-export-fragment-generator-authority-adr`. Wave 1 establishes typed source and semantic-map contracts, Wave 2 implements atomic deterministic generation, Wave 3 supplies adversarial correctness gates, and Wave 4 regenerates representative split revisions and releases the blocked relayout campaign. No generator implementation begins until this plan is explicitly approved.

## Parallelization

Waves are ordered. Within Wave 1, parser-source modelling and semantic-map schema work may proceed in parallel after the shared intermediate representation is fixed. Within Wave 3, mutation-gate groups may run in parallel against the landed generator. Revision generation in Wave 4 is serialized per target tree to keep provenance and review boundaries exact. S42 is persistence-only: it defines the canonical semantic-map fragment format and loader and does not decide semantic homes or official-box classification. S43 is envelope-only: it generalizes parser-owned variable-envelope recognition and does not define row projection or producer ownership. S35 supplies the missing explicit Modelo 303 source epochs, S36 establishes the period-token revision/source bindings, and S39 removes every retired-id consumer without compatibility; those prerequisites, plus the sole approved-ADR architecture decision in S44, are hard prerequisites for S19. S44 must settle the semantic-home and fixed-slot projection architecture before S46 establishes the producer snapshot and S45 integrates the closed vocabulary and consumers; S47 through S51 then implement the remaining producers and consumers. S54 is the canonical differentiated-sector source-taxonomy prerequisite and must land before S49. S59 establishes the annual Orden registry/compiler/snapshot authority; S58 consumes it to establish immutable filing evidence at revision creation; S56 reuses S58's evidence-reference contract; and S55 consumes S58, S56, and durable register owners to close every DP30301 A16-A30 scalar. S57 then integrates the one typed projection-reference contract while deleting every replaced inference surface. S61 must then establish the typed DP30300 variable-envelope semantic and composition authority before S19 may author the reviewed five-epoch exact-anchor maps. S52 consumes those maps and depends additionally on the accepted casilla-schema `W02.P05.S14` and `W02.P05.S15` `classify_official_boxes` authority as its one official-box classifier; it must import and use that authority rather than copy the casilla-schema plan or ADR. S16 is serially blocked by S19 and S20 and must execute in the order `S35 -> S36 -> S39 -> S42 -> S43 -> S44 -> S46 -> S45 -> S47 -> S48 -> S54 -> S49 -> S50 -> S51 -> S59 -> S58 -> S56 -> S55 -> S57 -> S61 -> S19 -> S52 -> S20 -> S16`; S21 follows the S16 proof for the next revision family. S22, S23, and S24 then establish the Modelo 200 target, delete obsolete loader compatibility, and hard-fail every derivative or unmeasured legacy path before repository-wide gates. The cross-model repository gate sequence is `S17 -> S34 -> S18`, followed by reconciliation, review, focused verification, and delivery in `S25 -> S27 -> S28 -> S29`. The complete serialized release sequence is `S35 -> S36 -> S39 -> S42 -> S43 -> S44 -> S46 -> S45 -> S47 -> S48 -> S54 -> S49 -> S50 -> S51 -> S59 -> S58 -> S56 -> S55 -> S57 -> S61 -> S19 -> S52 -> S20 -> S16 -> S21 -> S22 -> S23 -> S24 -> S17 -> S34 -> S18 -> S25 -> S27 -> S28 -> S29`; the two-field `_intermediate`, `_semantic_map`, and `_write_isolated_generated_authority_tree` harness cannot satisfy the real-source acceptance contract.
