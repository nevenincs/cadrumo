# `source-casilla-integration` audit: `S54 inventory terminal refusal review`

## Scope

Formal review of the S54 inventory terminal disposition against the accepted inventory mapping decision, source-connectivity disposition semantics, the derived release predicate, and the canonical source-coverage composer. The review checks classification, accountability, refusal visibility, no-fabrication, and authority non-redeclaration.

## Findings

### disposition-classification | pass | Registry blocked is the exact current boundary

Official inventory semantics, the source-owned projection, governed resolver ingress, registry row bindings, and encrypted source lifecycle already exist. `grounding_blocked` and `ingress_blocked` would therefore misstate current evidence. The missing capability is the validated registry-owned row-casilla materialization and supported official repeated-activity rendering, so `registry_blocked` is exact. The row is not promoted to connected.

### expiry-and-ownership | pass | The terminal refusal is bounded and accountable

The existing source-connectivity owner and action remain intact. Its 2026-10-31 follow-up deadline precedes the 2026-12-31 evidence expiry. The permanent campaign-close gate evaluates the actual current date and will reject the disposition after expiry.

### stale-composer-expectation | medium | Old candidate reason contradicted the terminal blocked projection

The first review found that the source-coverage regression still expected `unreviewed_evidence`, the old `connect_candidate` classification. The canonical composer correctly projects blocked evidence as `missing_evidence`. The regression now requires refused `missing_evidence`, blocked state, and the exact inventory follow-up action. The focused composer suite passes.

### authority-redeclaration | pass | S54 changes disposition evidence only

No second census, loader, coverage composer, registry binding, row carrier, source resolver, exporter, or live-proof authority is introduced. The change uses the existing census row and canonical closure projection.

## Recommendations

- Close S54 only after final re-review confirms the composer correction and no medium-or-higher finding remains.
- Keep the inventory delivery rows open until row-casilla materialization and official repeated-activity export proof exist; never infer an activity envelope or connected status from the current resolver and bindings.
