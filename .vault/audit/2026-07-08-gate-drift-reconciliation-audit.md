# `gate-drift-reconciliation` audit: `full gate + plan reconciliation snapshot`

## Scope

A full read-only health snapshot of the `chore/eliminate-shims` factory worktree on 2026-07-08, run as a five-fleet sonnet dispatch across every `just` check, test, and audit gate plus the CLI verification verbs and the vaultspec plan surface. Each gate was run with `uv run --no-sync`, its full output captured to disk, and the FAILED/ERROR lines extracted from the on-disk log (never an upstream head/tail truncation).

Worktree context is load-bearing for reading every number below: HEAD is 887 commits ahead of `origin/chore/eliminate-shims`, and the working tree carries 5657 dirty files (5608 modified, 43 modify-modify, 1 delete, 5 untracked) from many concurrent campaigns. Every gate result therefore reflects a live uncommitted campaign state, not committed HEAD and not a release candidate. The purpose of this audit is to separate genuine, actionable regressions from campaign work-in-progress debt and environment-gated noise, and to feed the companion reconciliation plan that maps each real item to an in-flight plan or flags it as untracked.

## Findings

### static-gate-matrix | high | check-all fails on style, format, types, and a broken layering contract

`just check-all` fails. `check-style` (ruff) reports 3 errors: a `D411` missing-blank-line in `src/aeat/domain/calculations/registry/_validate_verification_predicates.py`, and a `RUF100` unused-noqa plus `S607` partial-executable-path in `src/aeat/entrypoints/mcp/_call_runtime.py` (2 of 3 auto-fixable). `check-format` would reformat 124 files (3376 already clean). `check-types` reports 170 diagnostics (121 ty + 49 pyright), dominated by `unresolved-attribute` (57) and `invalid-argument-type` (40). `check-imports` (import-linter) reports the AEAT layered-architecture contract BROKEN via 4 `application -> adapters` edges (see the layering finding); the other 4 contracts are kept. `check-relative-imports` and `check-dependencies` are GREEN.

### layering-drift | critical | application imports adapters via `prorrata_register` — triple-corroborated

The single highest-signal regression. `aeat.application` imports `aeat.adapters` across 4 edges, all through `adapters.persistence.profile.prorrata_register` (and one through `adapters.persistence.storage`), from `application.aggregation._iva_ledger`, `application.modelo._revision_persistence`, and `application.calculations._prorrata_regularizacion`. This one drift trips three independent gates: the import-linter contract (`check-imports`), the RED `layering` dimension of `audit-health-report`, and the unit test `test_application_to_adapters_pin_count_does_not_grow`. It is an inbound-adapter dependency from the application layer, i.e. a hexagonal-boundary inversion that the ports-inversion remediation exists to prevent. Because downstream calculation, persistence, and verification all sit atop this edge, it is the priority-one architectural item.

## Recommendations

Priority order follows downstream blast radius. First, close the `application -> adapters` layering inversion via `prorrata_register` — it is the one drift that trips three gates and sits under all downstream calculation/persistence/verification, so invert the dependency (a port on the application side, the adapter implementing it) rather than importing the adapter. Second, run the shadow and duplication semantic sweeps (vaultspec-rag axis-7 plus the `audit-all` clone list) to enumerate the full shadow/duplication surface before it accretes further, and enroll each cluster on a canonical home. Third, reconcile the governance-ratchet unit failures and the 302 complexity hotspots against the iva-prorrata-complexity and docstring plans — most are already-owned WIP tails, not new work; the companion plan records which are tracked versus untracked. Fourth, regenerate the iva-prorrata documentation surfaces (CLI reference, `OutputSchema` registration for the 36 leaves, docstring links) to clear all 5 docs failures in one pass. Fifth, re-run the integration suite and semgrep interactively with `AEAT_SECRET_PASSPHRASE` set to obtain a true integration failure count and a real security reading, then triage only the residue that survives the passphrase. The registry-authority core is sound; treat the red surface as campaign WIP debt to be reconciled and drained, not as a broken product.
