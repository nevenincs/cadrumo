# `object-name-declustering` audit: `s14 replay tests review`

## Scope

Reviewed the S14 replay detector-teeth suite against the accepted object-name declustering
ADR, research, reference, and plan, the settled rehearsal contracts, and the current replay
implementation. The review assessed stale and mismatched receipt authority, canonical
component validation, source and tool drift, regenerated gate and generator outcomes,
transaction ownership, exact allowlists and postconditions, deterministic write/move/delete
order, rollback at every mutation position, `BaseException`, rollback failure, successful
replay, and cleanup/error precedence. No production or test code was modified.

## Findings

### generated-replay-success | medium | Generator evidence is mismatched but never replayed successfully

The drift matrix injects a generator outcome into a receipt for an operation with no
generator, proving mismatch refusal only. Neither successful replay fixture contains a
generated artifact. A replay implementation that rejects every valid generator-backed
component, omits its generated write/delete phase, or mishandles generated ordering could
still pass the suite despite generated outcomes being part of the accepted replay contract.

### canonical-component-preflight | medium | Component drift stops before exercising canonical reconstruction

The component drift case changes `component_id`, so replay refuses at its shallow receipt
identity comparison. It does not preserve component ID and operation membership while
forging affected paths or hard edges, which must reach exact rehearsal preflight and be
rejected by canonical graph reconstruction. S12 proves the rehearsal primitive directly,
but S14 does not prove replay continues to invoke that authority boundary.

### base-exception-mutation-rollback | medium | BaseException is not tested at live mutation points

The mixed module transaction exhaustively injects ordinary exceptions before and after each
replace and unlink side effect, and a separate test injects `KeyboardInterrupt` during
post-apply gates. No test raises `BaseException` at a replace or unlink position, especially
after the live side effect. A regression from `BaseException` to `Exception` around the live
transaction could leave partially applied bytes while all current tests pass.

### cleanup-error-precedence | medium | Cleanup precedence covers only a recoverable primary apply error

The suite proves cleanup failure does not mask a primary apply error after successful
rollback. It does not exercise cleanup failure after successful replay, where cleanup must
become the reported failure without obscuring committed bytes, or cleanup failure while
rollback itself fails, where the combined replay-and-rollback error must retain precedence.
Those branches govern transaction evidence retention and error truthfulness.

## Recommendations

Replay a real generator-backed receipt and assert generated bytes, exact outcomes, ordered
mutation, and final allowlist. Forge component affected paths and hard edges without changing
its receipt-facing ID or operations and prove exact preflight refusal before staging. Repeat
the mixed transaction's before/after-side-effect matrix with a `BaseException` at live
replace and unlink positions and assert exact byte restoration. Add cleanup-failure cases for
successful apply and incomplete rollback, asserting final bytes, transaction evidence, and
primary error precedence.

Preserve the existing strong teeth: receipt integrity and regenerated-evidence drift, stale
dirty-tree bytes, failed gate refusal, occupied transaction sentinels, late concurrent-byte
preservation, deterministic module move/write/delete order, staging cleanup, ordinary failure
at every mutation position, exact rollback and rollback aggregation, post-gate
path/content/finding checks, linked-root refusal, and successful symbol and module replay.

## Validation

The settled focused revision passed 52 tests. Ruff, Ruff-format, and ty checks passed. Final
review status is four medium findings and no critical, high, or low findings.

## Re-review status

Resolved: `generated-replay-success` now constructs a real generator-backed manifest,
canonical generated hard edge, rehearsal receipt, and live replay. It asserts the exact owner
argv and successful outcome and verifies both the generated bytes and direct symbol bytes in
the live worktree, so a reject-all or skipped generated mutation cannot pass.

Resolved: `canonical-component-preflight` now preserves the receipt-facing component ID and
operation membership while independently forging affected paths and hard edges. Both cases
pass the shallow replay identity comparison, reach exact rehearsal preflight, are refused by
canonical graph comparison, and prove no replace or unlink occurred.

Resolved: `base-exception-mutation-rollback` injects `KeyboardInterrupt` after the second
replace and after the unlink in the mixed module transaction. Each case has already performed
live side effects and then proves the whole live byte set is restored, protecting the
`BaseException` rollback boundary at both mutation kinds.

Resolved: `cleanup-error-precedence` now covers cleanup failure after successful apply,
asserting committed bytes and retained transaction evidence, and simultaneous apply,
rollback, and cleanup failures, asserting the combined apply/rollback error remains primary,
cleanup text does not mask it, and evidence remains retained.

The seven targeted closure cases passed in 56.83 seconds; Ruff, Ruff-format, and ty checks
passed. The reported full focused suite passed 59 tests. Final S14 status is no open critical,
high, medium, or low findings.
