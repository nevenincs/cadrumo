# Migrate user-profile-domain recovery producers to typed conditions and canonical actions

## Scope

- `src/cadrumo/domain/user_profile`

## Description

- Locate the adjudicated refusal surface for this package and separate what the campaign's two ledgers actually assign to it from what the dispatch assumed.
- Delete the hardcoded operator command carried as a recovery fact by the stored-profile drift refusal, and replace it with facts naming the contract that diverged.
- Replace the authored English sentence at every schema-load refusal with the class's registered key plus a locale-neutral condition identity, and stop flattening the underlying failure into the message.
- Make both refusal classes keyword-only so no positional slot exists for a sentence to occupy, and sweep the two call sites the signature change requires.
- Pin every migrated site with an absence assertion and a structural sweep covering all three ways authored English survives a migration, then prove the sweep bites.

## Outcome

- The stored-profile drift refusal no longer carries a command. It had held `aeat config repair --help` under the `recovery` key, which the envelope contract already reserves for the typed action projection and which no consumer ever read: the CLI boundary discards the domain context entirely, wraps the refusal in its own stored-data boundary type, and emits the typed no-recovery outcome from the precondition owner. The command was therefore a second action authority, dead on arrival and wrong the moment the verb is renamed. It is gone, and the domain now stops at a registered key plus facts, which is where the layering says a domain producer's obligation ends.
- Five schema-load refusals stopped authoring English. Each had passed an interpolated sentence positionally while the class supplied the registered key as a keyword, so resolution rendered the key and every direct rendering carried the sentence. They now report a condition identity naming the precondition that failed: the path stat, the TOML decode, the schema table, the sections tables, the derived-selectors shape and the strict-model validation. The condition tokens are module constants, so the raise sites and the assertions cannot drift to two spellings.
- One exception-flattening site was removed. The strict-model refusal had interpolated the whole pydantic failure into its message; it now reports how many constraints failed and keeps the typed failure as the cause, and a test holds the reported count equal to the cause's own error count so the two cannot diverge.
- The decode failure stopped forwarding prose it does not own. The core TOML reader hands its factory an authored English sentence; the factory now discards it and reports the decode condition instead. Nothing is lost, because the reader already chains the parse error as the cause, and a test asserts that cause is present.
- Both classes are keyword-only. This is the structural half of the fix rather than a convention: with no positional parameter there is no slot an authored sentence can occupy, which is what makes the absence assertion hold for every future caller rather than only for today's.
- No locale key was added and no catalogue was touched. Both refusals resolve through keys already registered against their classes and already present in all four catalogues, verified by reading each file. A test holds each module constant equal to the code registry's own message key for its class, so a registry change cannot leave the constants stale.
- No identity value reaches any fact or fixture. The profile identifier carried is a generated UUIDv4 minted at profile creation, never a tax identifier, and the drift facts name the failing record type and a violation count and nothing else. Violation location paths were deliberately excluded: a location reproduces mapping keys as well as field names, so a record keyed by a tax identifier would put that identifier into a fact, and the projection that can tell those apart already exists at the boundary that owns the record type. Re-deriving it here would have been a second, unredacted copy of a redaction authority. A test asserts neither failing value appears anywhere in the fact set.
- The whole-tree recovery-rehoming gate cleared both findings this Step was dispatched against. Before the change the gate reported an owner-closed finding for the drift refusal against each of its two already-closed owner Steps; afterwards no owner-closed finding names that refusal at all, because the gate's producer test is whether any site of the qualname still passes a positional argument, and none does.
- Fifteen assertions cover the surface, and all fifteen were proven to bite. Five separate mutations were applied from an out-of-repo pytest plugin, with nothing under the source tree modified: a sentence restored positionally beside the key, the same sentence as a keyword argument, a constructor default carrying the sentence, prose composed inside the constructor as an f-string, and the deleted command restored under its reserved key. Every mutation reddened at least one assertion and the clean tree returned all fifteen to green.
- The discrimination the campaign twice failed to catch was reproduced directly. Under the positional mutation the assertion that fails is the rendered-text equality, showing the English sentence where the key belongs, while the sibling assertion reading only the key and the facts stays green. That is the whole argument for the absence shape, observed rather than asserted.

## Notes

- The dispatch's premise was wrong on the evidence, and correcting it is the main finding. This package owns no row in the recovery-rehoming ledger at all. The two owner-closed findings it was dispatched against belong to a row whose four fingerprints are all outside the declared scope: two constructor sites in the application profile repository owned by a closed Step, and two class references in the CLI error module owned by another closed Step. Neither positional argument at those sites was ever a message; they were the profile identity and the validation failure, and the class passed no positional to its base, so the rendered text was already the key. The finding was a true positive for the gate's rule and a false positive for the defect it screens for.
- Two lines outside the declared scope were changed, deliberately and reported rather than hidden. Making the drift refusal keyword-only requires its two call sites in the application profile repository to name their arguments; splitting that leaves the tree at a runtime type error, and the atomicity discipline for a signature change is explicit. The change is mechanical, the file carried no peer work in progress when it was read or when it was committed, and adjudication was requested from the coordinating Step before it was made. This is not the shape the brief forbids: the command prose is genuinely deleted in the same change, so the keyword conversion is a consequence of a real migration rather than a substitute for one.
- What the migration changes about the ledger rows, for the serialized regeneration. The drift row keeps all four fingerprints and every path, role and lexical owner. What changed is the normalised syntax hash of the two constructor sites, so the gate now reports a fingerprint multiset divergence on that qualname until the ledger is regenerated. No disposition was edited and the ledger writer was not run.
- The action-census ledger has two rows on this package, and both were already stale before this work started. The census gate is red at head with forty-two stale override owners, one of which is this package's: a prior partial migration had moved the command from the `suggestion` keyword into the context dictionary without updating the census, so the live observation the row claims has not existed for some time. Deleting the command does not change that state. The correct correction is to strike the now-dead migration-step and observation pair from those two rows, which was not done because the census ledger is shared with the other forty-one stale owners and its regeneration is being serialized elsewhere.
- Gate results, with peer failures separated from the owner surface. The new refusal suite runs fifteen passed. The scoped run over this package plus the profile repository and CLI boundary suites that exercise the drift path runs one hundred and sixty-seven passed, nine failed and nine errors; every one of the eighteen is peer-owned and none names a file changed here. Four are the registry legal catalogue missing two references a peer's legal-corpus work has not landed, nine more are the same missing references failing at fixture setup, two are a lazy-import boundary regression where the package facade now eagerly imports a registry-coupled module, one is a changed profile fact count, and four are fixtures constructing profile records at schema version one and two against a committed schema now at version five. The last group was confirmed against head bytes rather than assumed: the fixtures hardcode the old versions in the committed files. Lint and format are clean; two of the three type checkers report nothing for any changed file and the third reports one diagnostic in an untouched test module in this package.
- A coverage gap worth stating rather than papering over. The two application call sites this change swept are not exercised at runtime by any currently-green test, because the suites that reach the drift path fail during fixture construction on the peer schema-version bump described above. Their correctness rests on the strict type checker reporting no diagnostic and on the refusal class being driven directly by the new suite, not on an end-to-end run. When the peer fixtures are repaired those suites will cover the sites without further change here.
- Deliberately left, and classified rather than skipped. The profile value and schema modules raise roughly twenty-five validation and lookup refusals carrying interpolated English. They are pydantic field and model validators over the committed schema document and over records the code itself constructs, and the CLI boundary already treats validator-authored prose as a known shape, withholding and counting it behind a redaction projection rather than rendering it. None carries a rehoming row or a census candidate, so the campaign's own adjudication never enrolled them. That classification is defensible and it is still a classification: if the standing goal is that every reachable failed precondition emits a stable condition identity, those refusals remain outstanding and no row currently covers them.
- The condition identities are module constants rather than a typed enumeration. The architecture rule places closed value sets in the core package, which is outside this scope, and declaring a package-local enumeration for a six-value axis used by one module would have created a second home for a concept the rule already assigns. The constants are pinned by tests instead.
- The plan checkbox is deliberately left unchecked, pending the coordinator's adjudication of the two-line reach described above.
