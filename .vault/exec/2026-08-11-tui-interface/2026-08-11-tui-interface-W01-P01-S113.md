# Stop the operation modal rebinding a private attribute Textual owns, which HUNG the suite rather than failing it. MEASURED, and the discriminator matters because the first reading was wrong: two tests in `entrypoints/tui/operations/tests/test_operation_modal_lifecycle.py` never completed. A 150-second single-test run with the host at 14.5% CPU across 24 cores separates HUNG from SLOW-UNDER-LOAD -- it timed out, so contention is refuted rather than merely doubted, and the earlier `-n 0` reading proved nothing because it controlled pytest workers and not the 50 concurrent python processes on the box. THE CAUSE: `OperationModal.__init__` set `self._closing = False` to track whether its observation poll should stop, and `_closing` is Textual's OWN flag on `MessagePump` for a pump that has been asked to close, assigned inside `MessagePump.__init__` and therefore invisible to `dir()` and to editor completion. `_stop_poll_worker` set it True; the subsequent real close took `MessagePump._close_messages`'s already-closing early return WITHOUT posting its stop sentinel; the pump never ended; `Screen.remove` waited on it; `App._shutdown` waited on that; and `run_test.__aexit__` hung forever. Attributed by pending-task dump at the hang: the modal reports `_closing=True`, `_closed=False`, an EMPTY message queue and NO workers, with `do_pop` parked in `_replace_screen`. PRE-EXISTING AT HEAD, not introduced by the async-lock work the file list suggested -- `git show HEAD` carries all three `self._closing` sites. Remediate by renaming the modal's own flag to what it actually means, and say in a comment why the name is not available, because the next author will reach for it again. GATE IT with a structural test asserting no Textual node class in this package assigns a private name Textual's own base classes assign, deriving the reserved surface by AST over the `__init__` bodies of the textual-owned ancestors in each class's MRO rather than hardcoding a list -- these names exist only at runtime, so no static inspection of the class object can see them. Exclude PUBLIC names deliberately: `title` and `sub_title` are reactives Textual intends a screen to set, and a census found those to be the only other hits, all legitimate. Carry an anchor assertion naming one known Textual private, so a Textual refactor that empties the derivation fails loudly instead of passing vacuously. METHOD NOTE worth keeping: the first instrumentation reported the hang in the WRONG PLACE, because Textual captures stdout inside `run_test`, so a printed progress mark simply stops appearing and reads exactly like the program stopping. Write probe marks to a FILE. A watchdog task that never printed was read as a dead event loop when the loop was healthy the whole time

## Notes

Reported as unattributed before this row existed and attributed here: the
defect is PRE-EXISTING AT HEAD. `git show HEAD` carries all three
`self._closing` sites, so neither the async-lock work nor the settled-branch
reap introduced it. The settled-branch reap does extend its reach, because it
routes a second close path through the same flag.

The gate excludes PUBLIC names on purpose. A census found `title` and
`sub_title` on four screens, and those are reactives Textual intends a screen
to set, so including them would have produced four false reds and taught the
next author to widen the exclusion rather than read it.

Two findings in the same suite are OUT OF SCOPE of this row and not
investigated: `tests/test_registration_recovery_words.py::test_the_full_screen
_door_shows_the_words_then_wipes_them` hangs, and two further tests fail whose
identities were lost because a thread-method timeout kills the process before
pytest writes its summary. Neither is cleared and neither is attributed.
