# Collapse the shared source-action descriptor's two mutually-dependent credential fields into one optional sub-record, so the impossible state cannot be expressed. The label and status fields are dependent by prose only: the docstring concedes the caller supplies both or neither because the widget classifies nothing itself, and nothing enforces it -- frozen dataclass, no post-init, no validator. The card's compose renders the badge only when BOTH are non-None, so a half-populated descriptor SILENTLY OMITS a resolved requirement fact and raises nothing, which is a no-signal failure on an operator-facing surface. Replace with a single optional credential-requirement record carrying label and status together, present or absent as a unit, after which compose needs one None check. Shared widget with consumers outside any one lane, so the caller sweep lands in the same change

## Notes

`SourceActionDescriptor` carried `credential_requirement_label` and
`credential_requirement_status` as two independent optionals whose dependency
lived only in the docstring -- frozen dataclass, no post-init, no validator.
`SourceActionCard.compose` rendered the badge only when BOTH were non-None, so
a half-populated descriptor dropped a resolved requirement from an
operator-facing surface and raised nothing. They are now one optional
`CredentialRequirement` record carrying both together, so the half-populated
state cannot be expressed and compose needs one None check.

The caller sweep landed in the same change, as the row requires for a shared
widget. `_credential_requirement_badge` returned a both-or-neither tuple by
construction -- the invariant was already true, just unexpressed -- and now
returns `CredentialRequirement | None`, which is the same fact in a shape a
caller cannot get half right.
