# Make the modelo work review screen's focus cycle advance. FOCUS DOES NOT ADVANCE PAST THE FIRST FOCUSABLE -- a stronger defect than 'the table is unreachable', which understates it and would let a fix that reaches the table while leaving the cycle broken look complete. Measured at 120x40 BY OBJECT IDENTITY, not type name: the focus chain holds three entries, `['CollapsibleTitle', 'CollapsibleTitle', 'ContentDataTable']`, and four successive tab presses all land on the SAME widget at chain index 0. Repeated type names concealed this at first -- a stalled cycle and a short cycle print identically until you compare identities. NOT CAUSED BY THE SUMMARY DISCLOSURE, attributed by measurement: the table is unreachable with both disclosures present, with the summary disclosure hidden, AND with the filters disclosure hidden. NOT A GENERAL `Collapsible` PROPERTY EITHER: a minimal app with one collapsed `Collapsible` plus a `DataTable` reaches the table by tab, and so does the same app with two. THE CAUSE IS NOT THE ONE THIS ROW PREDICTED, and the correction matters more than the fix: no widget consumes tab, because TAB IS NEVER BOUND. `active_bindings` on this screen carried neither `tab` nor `shift+tab`, and `shift+tab` has exactly ONE source in the whole tree -- Textual's own `Screen.BINDINGS` -- so its absence is unambiguous evidence that the inherited table was DISCARDED rather than shadowed, which is what a routing hypothesis could never have distinguished. `_localize_bindings` replaced the screen's entire runtime binding table with a fresh `BindingsMap` carrying only the keys it named, in order to attach translated footer descriptions at mount; a screen's table starts as a shallow copy of the class-merged table, so replacing it silently drops every key the subclass never had to name. NOT ONE SURFACE: the same replacement shipped on FOUR screens -- `StatusScreen`, `QuestionScreen`, `ReviewScreen`, `ModeloWorkReviewScreen` -- found by probing `shift+tab` across all nine enrolled surfaces, which is the cheapest possible sweep precisely because that key has a single source. Remediate by re-describing the existing entries in place instead of replacing them, in one shared public module: assign a NEW list per key, because the instance table shares the class's lists and editing one in place would re-describe that key for every screen of that class the process opens; and refuse an action nothing binds, so a typo fails loudly rather than translating nothing. WATCH THE `show` FLAG, which a naive re-description gets wrong: Textual bakes `show` down to `description and show` at class-merge time, so a key declared with an empty description -- exactly how these screens defer their wording to the operator's language -- arrives already hidden, and carrying that flag forward leaves the key bound and invisible in the footer. Re-measure the footer rather than assuming it. GATE IT with a companion asserting every key in Textual's own `Screen.BINDINGS` is offered on every enrolled surface, derived from `Screen.BINDINGS` rather than a hand-copied list, and asserted over KEYS rather than actions because a focused `Input` legitimately owns the copy key with a text cursor present. Bite-prove by reinstating the wholesale replacement through an out-of-repo monkeypatch: the new gate must red on exactly the four affected surfaces and the tab-cycle gate on `modelo-review`, while `test_every_declared_binding_is_actually_offered` stays GREEN -- it cannot see a binding that was never declared, which is why nothing caught this

## Notes

The row predicted a routing defect and the cause was an unbound key. What
separated them was `shift+tab`: it has exactly one source in the tree, so its
absence proves the inherited table was discarded rather than shadowed, and no
amount of focus-chain measurement could have reached that. The one-key probe
also turned a single-surface row into a four-surface sweep for the cost of one
command.

The gate first asserted the inherited ACTIONS and red on three surfaces for
`screen.copy_text`, which is legitimate rather than a defect: a focused
`Input` owns the copy key while a text cursor is present. Restated over KEYS,
which is the property that actually holds -- the operator keeps the
affordance, whoever answers it.

A naive re-description would have regressed the footer. Textual bakes `show`
down to `description and show` at class-merge time, so all nine localized keys
arrived hidden and carrying that flag forward would have left them bound and
invisible. Caught by re-measuring the footer rather than assuming it, and the
described-key path now sets `show` from the description.

`test_operation_modal_lifecycle.py` hangs on two tests under this branch and
is UNATTRIBUTED. It is not reachable from this change -- a different package,
and no binding path participates -- but it is not cleared either: it was not
measured against a pristine tree, and the host was carrying fifty concurrent
python processes when both runs were taken. Reported rather than absorbed.
