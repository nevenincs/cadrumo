# Widen the scroll-owner check to judge what SCROLLS rather than what SUBCLASSES a container. `geometry_band`'s check filters on `isinstance(host, ScrollableContainer)`, so a styled widget that genuinely scrolls is invisible to it. MEASURED on the modelo review surface at 80x24 while the summary carried a height cap: `#modelo-review-summary` was a `Static` with `allow_vertical_scroll=True`, `max_scroll_y=3` and `show_vertical_scrollbar=True`, and enumerating every widget on that screen with a visible vertical scrollbar returned TWO -- `modelo-review-body` and `modelo-review-summary`. The screen carried exactly the defect the check is named for and the check could not see it. THE HAZARD IS THE SHAPE, NOT THAT INSTANCE: an author adding `overflow-y` to a Static will reasonably believe this is covered, because the check's name and docstring promise scroll owners are governed. A predicate that filters on CLASS while its name promises a BEHAVIOUR is a wrong-subject gate -- it reports clean about something other than what it claims. Widen it to any displayed widget whose `show_vertical_scrollbar` is true, then extend the bite proof to the new predicate. THE BLOCKER IS CLEARED: the modelo instance is gone -- the height cap was replaced by an explicit `Collapsible` disclosure, measured at one scroll owner and CLEAN geometry at all three sizes -- so widening no longer reds that screen on a live unowned defect, which is what `remediation-must-precede-the-gate-that-would-catch-it` required. Re-measure before landing rather than trusting this note. METHOD NOTE worth keeping: a failed bite proof has two explanations -- the gate is inert, or the injection is outside its reach -- and they are INDISTINGUISHABLE from the result alone; forcing `show_vertical_scrollbar` on that Static returned CLEAN and read as a dead gate until the predicate was read

## Notes

Both scroll checks in `geometry_band` filtered on
`isinstance(host, ScrollableContainer)` -- asking which widgets SUBCLASS a
container while the findings are about which widgets SCROLL. Widened to the
behaviour each is actually about: `allow_vertical_scroll` for "configured to
scroll but cannot", `show_vertical_scrollbar` for "is a visible owner". The
reason is recorded in a comment at the site so the filter is not narrowed
back to a type.

BITE PROOF, and it isolates the change rather than a surface. A minimal app
with a `VerticalScroll` host and a `Static` carrying a mounted child plus a
height bound, both predicates evaluated over the same widget tree:

    widgets painting a vertical bar   : ['host', 'styled']
    what the OLD isinstance filter saw: ['host']
    geometry_band findings            : multiple visible vertical scroll
                                        owners: VerticalScroll#host,
                                        Static#styled

Two bars painted, the old predicate saw one, the widened one names both.

THREE INJECTIONS FAILED FIRST, all for the same reason, which is worth
keeping because it is the ambiguity this campaign has hit repeatedly: a
failed bite proof means the gate is inert OR the injection is outside its
reach, and the result alone cannot distinguish them. Capping the summary
had no effect because it is now a collapsed disclosure with nothing to
overflow; capping the casillas panel REMOVED scrolling entirely (visible
bars went to zero); and a bare `Static` with inline content never paints a
bar at all. The shape only reproduces with a Static carrying a MOUNTED
CHILD WIDGET plus a height bound -- which is precisely what the summary
panel was, and part of why the defect survived unseen.

No false positives: all nine enrolled surfaces stay clean at all three
declared sizes under the widened predicate.
