# Gate the remaining `frame.py` band readers, which are in the state `geometry_band` was in before it was gated. MEASURED: `engine_band`, `focus_band`, `key_band` and `screen_text` each have exactly ONE external reference, and it is the SAME line -- a name-only export tuple at `dev/tests/test_public_devtool_homes.py:66` that asserts the symbols exist and never executes them. So `capture()` assembles five bands, one proven per surface and four proven to exist. An unused-symbol sweep clears all four because each IS referenced: not orphaned, ungated. THE FOUR ARE NOT IN THE SAME STATE AS EACH OTHER, and treating them as one uniform gap would produce three redundant gates. Adjudicated individually against what the visual suite already asserts. (1) `key_band` -- GENUINE UNCOVERED PROPERTY AND THE ONE TO TAKE FIRST. It reads `active_bindings`, i.e. the affordances actually offered on THIS screen in THIS state, and no test in the suite asserts anything about offered bindings. It would catch the class `W06.P13.S346` documents in the architecture plan: a `FlowScreen` binding that could never resolve because its pages are siblings on the stack, worked around by duplicating the binding onto both page screens. A binding declared but unreachable is invisible to every other gate. (2) `focus_band` -- PARTIALLY COVERED. Its tab-cycle property is asserted by `test_tab_visits_every_control_and_comes_back`, but that test is parametrised over `_INTERACTIVE_SURFACES`, NOT `_SURFACES`, so the covered set is narrower than the enrolled set. ADJUDICATED FROM THE SURFACES, NOT THE CONSTANT'S NAME, by measuring the focus chain of each enrolled surface: `_INTERACTIVE_SURFACES` IS a deliberate predicate whose population grew underneath it. Its docstring names TWO exclusions with reasons that both hold -- `status` is read-only chrome (1 focusable, a table) and `question` is driven by the flow engine's own paged navigation (4 focusables, all flow buttons). But the set now excludes FIVE. `status-populated` inherits `status`'s reason by construction, leaving a GENUINE GAP OF TWO: `manager-populated` at 28 focusable controls, identical to `manager` which IS in the set and clearly never added when the populated variants were introduced; and `modelo-review` at 3, enrolled too recently to have been considered. So the fix is adding two surfaces to the existing predicate, NOT a second full-coverage focus gate and NOT a five-surface sweep. The docstring must be updated to state the predicate rather than to list the two exclusions it happened to have when written -- a rationale that enumerates instances goes stale silently as the population grows, which is exactly what happened here. (3) `screen_text` -- NOT GATEABLE IN THIS SHAPE, and this is an adjudication rather than a deferral. Its only plausible defect predicate is that the surface rendered something real, and that is ALREADY asserted per surface and per theme by `test_every_surface_actually_renders_under_both_appearances`, which checks a rendered frame contains text and exceeds a size floor. Gating `screen_text` would re-assert an existing property through a second renderer. Record it as covered-elsewhere, not as outstanding work. (4) `engine_band` -- FLOW-ONLY AND DIAGNOSTIC. It returns an empty list for any surface without a flow definition and state, so it is meaningful for the flow surfaces alone, and what it reads is engine state rather than a defect predicate; a gate would have to invent the assertion. Adjudicate whether a painting-versus-truth disagreement is expressible before writing one, and say so if it is not. REMEDIATION SHAPE IS ALREADY BUILT AND PROVEN: a parametrised test driving the reader over the enrolled surfaces at the shared sizes from `src/cadrumo/tests/terminal_sizes.py`, plus a bite proof showing the OUTPUT CHANGING rather than merely being non-empty -- evaluate old and new behaviour over the same tree and print what each saw, because a CLEAN result cannot distinguish a working gate from a mis-aimed injection. EXPECT A RED ON FIRST EXECUTION: `geometry_band` came back clean only because the disclosure fix had already removed its live defect, and these have never run against any surface. Per `remediation-must-precede-the-gate-that-would-catch-it`, fix what reds and land them together rather than weakening the reader

## Notes

Four band readers adjudicated individually rather than treated as one gap,
which would have produced three redundant gates.

`key_band` GATED. `test_every_declared_binding_is_actually_offered` asserts
every key a surface declares is a key the operator can press. It lands GREEN,
and that is legitimate rather than vacuous: every declared binding resolves
today BECAUSE of the duplication workaround recorded against the flow
surface's sibling-page bindings. The gate is a regression pin on a known
fragile state -- when that redesign stops duplicating, this notices, and
nothing else would, because an unreachable affordance paints no pixels and
geometry, focus and text all stay clean while the operator loses a key.

Not parametrised over sizes, deliberately: bindings do not vary with terminal
geometry, and nine surfaces by four sizes would buy thirty-six cases proving
one size-invariant property. The geometry gate needs sizes; copying its shape
here would be cargo-culting it. The assertion is "every declared binding is
offered", NOT "some bindings exist" -- Textual contributes 17 to 43 of its
own per surface, so any non-empty check is tautological.

`focus_band` -- PREDICATE CORRECTED, TWO SURFACES ENROLLED. `_INTERACTIVE_
SURFACES` was a deliberate predicate whose population grew underneath it. Its
docstring named two exclusions with reasons that both still hold, but the set
had come to exclude five. Measured focus chains: `status` 1 and its populated
variant 1 (read-only chrome, correctly out), `question` 4 all flow-navigation
buttons (engine-paged, correctly out), `manager-populated` 28 identical to
`manager` which IS in the set, and `modelo-review` 3. So the genuine gap was
TWO, not five. Both enrolled, and the docstring rewritten to state the
PREDICATE rather than list the instances that satisfied it when written --
an enumerated rationale goes stale with no edit, no failure and no signal,
and a well-argued one is the worst kind because a reader who checks it finds
sound reasons and stops.

`screen_text` -- CONCLUSION, NOT DEFERRAL: its only plausible predicate is
that the surface rendered something real, already asserted per surface and
per theme by the both-appearances gate. A second gate would re-assert an
existing property through a different renderer.

`engine_band` -- CONCLUSION: flow-only, returns an empty list for any surface
without a flow definition and state, and reads engine state rather than a
defect predicate. A gate would have to invent its assertion.

## Notes on the honest red left behind

Enrolling `modelo-review` under the corrected predicate immediately failed,
and the failure is real: focus never advances past the first focusable on
that surface. It is left RED deliberately, with its own row. Backing the
enrolment out would restore exactly the invisibility that hid the defect --
un-enrolling is un-correcting the predicate.

The assertion message was made self-documenting so a peer sweeping a red tree
does not reach for the smallest greening change, which here is the one that
re-hides the defect. It states the remedy in DOMAIN terms and cites no plan
identifier: source must not reference vault documents, and naming the row in
a test message would have re-introduced the violation swept from seventeen
sites earlier the same day.

A stall assertion was added alongside the existing skip and cycle-close ones,
comparing widget IDENTITY rather than type name: a stalled cycle and a short
cycle print identically until identities are compared, which is what
concealed the true severity on first measurement.
