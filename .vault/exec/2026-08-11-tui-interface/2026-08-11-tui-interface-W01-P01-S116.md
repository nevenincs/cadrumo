## Notes

Authored by the team lead; verified here rather than accepted on report, and
the version recorded is NOT the version first reviewed.

The first version reused the project's canonical file scanner to avoid
re-implementing it -- normally the right instinct, and wrong exactly here. Its
import chain reached `cadrumo.core.redaction`, so the gate could not load
while the tree was unparseable, which is the only state it exists for.
Rewritten to `os.walk` and the standard library. The narrow property, stated
in the module docstring so nobody helpfully restores the shared helper: a gate
whose subject is the tree's ability to be USED AT ALL must owe that tree
nothing.

Its first real outing beat every injected case: four live offenders neither
author knew about, all working-tree residue from a peer's in-flight import
sweep, all the same shape. HEAD parsed every one, so "a commit landed four
invalid files" would have been false.

The injected cases still earned their place by exposing a second failure
inside the reporting path of the first: `relative_to` raises on a path outside
the repository, so a correctly-detected breakage would have surfaced as a
confusing `ValueError`. A gate's failure path never runs in normal operation
and is therefore the half nothing tests.

WHAT THIS RECORD DOES NOT CLAIM: that the tree is currently clean. The passing
runs are snapshots. The three-part settle condition agreed for this feature --
no new untracked modules across checks minutes apart, no source mtimes inside
the last several minutes, parse clean across both -- was NOT met at the time of
recording: four source files were modified between 21:33:58 and 21:35:27, in
`application/evidence/` and `entrypoints/cli/`, by a lane unrelated to the
sweep this gate was tracking. What is recorded here is that the GATE is built
and proven, which are properties of the gate; the tree's state is a separate
claim and is not made.

That distinction is worth keeping for the next reader: in a shared worktree
with several active lanes, a globally quiet tree may never occur, so a rule
that waits for one blocks indefinitely. Separating "the gate is proven" from
"the tree is clean" is what lets both be stated honestly.
