# Make a test run that EXECUTED NOTHING distinguishable from one that passed. THE SHARPENED FORMULATION, which replaces the original framing: the hazard is not that a narrowing selector hides tests -- it is that PYTEST'S SELECTION RESULT IS INDISTINGUISHABLE FROM ITS EXECUTION RESULT UNLESS THE COUNT IS READ. Four routes to the same false verdict, all first-hand this campaign. (1) RIGHT MARKER, WRONG MODULE: an integration selector run against a module whose 65 tests are unit-marked yields 'NOTHING RAN ... All 65 collected tests were deselected', exit 5, and inside a combined run it reads as the gate passing; four turns were then spent attributing an unrelated module's failures to it. This one is the inverse of the other three -- they HIDE a test behind a selector that excludes it, this one SUPPLIES a selector matching nothing, and a zero-match selection looks exactly like a clean pass. (2) A keyword expression that silently excluded the only test a mutation proof existed to exercise, reporting three passed while the gate had not run. (3) Default-lane marker deselections, which concealed five reds in one day. (4) A 93-test visual-verification module, owned by the arch-debt lane -- cross-reference, do not duplicate. CONCRETE GUIDANCE: never accept a green without reading the EXECUTED count, and treat '0 executed' as a distinct outcome from 'all passed'. THE FIX IS NOT A NEW SIGNAL -- THE SIGNAL EXISTS AND IS BEING LOST. The harness already prints an honest banner and prints it correctly: 'NOTHING RAN ... A green result here means the selection matched nothing, NOT that the code is sound' for zero-match, and 'PARTIAL RUN ... Green here covers the selected lane only' for partial. Both were emitted, both accurate, and both scrolled past inside a long combined run. A correct warning in the middle of a long run is not a warning, so the remedy is about WHERE these land and whether a zero-execution run can exit non-zero -- the same shape as the visual suite, where the affordance existed and nobody read it. ONE DEFECT IN THE BANNER ITSELF, verified first-hand here and NOT part of the relayed report: on the zero-match path its remediation line reads 're-run with -m integration' EVEN WHEN THE OPERATOR ALREADY RAN -m integration, so following the instruction reproduces the identical NOTHING RAN. That is the remediation-completes-the-defect shape the gate-integrity family already records for a different message; fix the advice to name the markers the module actually carries. COMPOUNDING FACTOR: a timeout inside a combined run destroys the attribution for EVERY test in it, not only the one that hung -- an async pilot waiting on the event loop produced two bare F characters and no summary at all, which is the no-signal-rather-than-a-slow-answer shape the share hangs also produce

## Notes

THE BANNER DEFECT IS FIXED AT ITS ROOT, WHICH IS NOT THE LANE NAME. An earlier
pass in this campaign handled only the case the row names literally -- an
operator who had already selected `integration`. The defect still reproduced
for every OTHER expression: `-m nonexistent_marker_xyz` still advised re-running
with `-m integration`, which yields the identical NOTHING RAN whenever the
module is unit-marked. Naming ANY lane without knowing what the collected tests
carry is the defect. The banner now records markers during collection, before
selection removes anything, and names them; where that record is unavailable
(xdist deselects inside workers while the banner prints on the controller) it
offers only the selector that cannot be empty.

THE EXIT-STATUS HALF NEEDED NO CHANGE AND NONE WAS INVENTED. The row asks
whether a zero-execution run can exit non-zero. Measured: a fully deselected run
already exits 5. Building a mechanism for it would have been fabricated work.

THE COMPOUNDING FACTOR IS COVERED BY A SECOND REPORTER. The row records that a
timeout inside a combined run destroys attribution for every test in it.
`_lost_test_hook` states the discrepancy between what collection found and what
the reporter heard back, so a run with a hole announces it. It fired on a real
run during this campaign -- a footer reading `13 failed, 6452 passed`, entirely
self-consistent, over a session where 307 collected tests never reported an
outcome after a worker died.

NEAR-MISS WORTH RECORDING: the first wiring attempt added a SECOND
`pytest_collection_modifyitems` to `conftest.py`, which already defines one.
Python would have silently taken the later definition and disabled the
repository's marker contract and banned-live-import policy for every run --
strictly worse than the bug being fixed, and invisible to `ast.parse`. Lint
caught it as F811; it is now merged into the existing hook.
