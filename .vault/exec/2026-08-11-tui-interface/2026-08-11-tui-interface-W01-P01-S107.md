# Consolidate the supported terminal size set into one shared declaration each of whose entries carries its reason. THE DIVERGENCE WAS WIDER THAN MEASURED: the finding named three private declarations; there were SIX. `test_visual_verification` `[(80,24),(120,40),(200,50)]`, `components/tests/test_widgets` `[(80,24),(100,30),(160,48)]`, `modelo/view/tests/test_work_review` `((80,24),(120,36),(160,48))` inline, plus `modelo/tests/test_c1_bounded_review` `[(80,24),(100,30),(160,48)]`, `secret/tests/test_secret_journeys` `[(80,24),(120,40),(200,50)]`, and `modelo/tests/test_c2_workspace_accessibility` `_GEOMETRIES = [(80,24),(120,40),(200,50)]`. Only the 80x24 floor was common to all six. THE ADOPTED SET IS FOUR, not three and not the union: 80x24 the floor a real terminal can be; 100x30 immediately above the wrap transition; 120x40 ordinary; 200x50 wide. The fourth size and its parametrisation cost across every TUI suite are accepted deliberately, because the transition band is where the wrapping defect class is born and nothing sampled it on purpose. The union was five and included 160, which no argument supports. 100 WAS NOT INVENTED -- IT WAS ADOPTED. It already existed in `test_widgets`, the one triple with no recorded rationale, and after this campaign's own layout work it became the single most informative width anyone had declared: the modelo review summary is unwrapped at 98 columns and wraps at 97, so 100 sits one column into the safe side, where a wrapping regression surfaces first. Nobody chose it for that reason; it became right, and this row gives it the rationale it never had. ITS INVALIDATION CONDITION IS STRUCTURAL, not a version: 100 is correct while it samples immediately above the wrap transition. Shortening summary content moves the transition DOWN and 100 stays valid; only content GROWING past it invalidates the size. Re-derive if summary content grows -- which is why this row did NOT need to wait on `W07.P17.S362` in the architecture plan, since that row can only shorten the work-unit id. DELIVERED: `src/cadrumo/tests/terminal_sizes.py` holds the declaration with a per-entry rationale and stable role-named ids; all six suites import it; every private set is gone. A suite that genuinely needs a size outside the set declares it beside the shared import with its reason, so an exception reads as an exception. Single-size uses such as `run_test(size=(80, 24))` are NOT sets and were deliberately left alone
