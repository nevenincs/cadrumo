# declaracion-extraction-architecture W08.P34.S193

## Step

Tighten `verification_source` from honor-system to fixture-metadata-verified: author test that walks every `declaracion_pdf` `corpus_round_trip_verified=true` profile, reads the fixture PDF `/Producer` field via pdfplumber, and asserts `real_aeat_corpus_pdf` implies no `aeat-test-fixture-generator` producer and `synthetic_from_aeat_published_text` implies `aeat-test-fixture-generator` producer.

## What was done

Authored `src/aeat/domain/calculations/registry/test_verification_source_fixture_metadata.py`.

The test module walks the live registry, collects all `declaracion_pdf` profiles with `corpus_round_trip_verified=true`, deduplicates by `(modelo_id, verification_source)` (multi-revision modelos share the same fixture directory), and parametrizes one test case per unique pair where fixtures exist and the value is one of the two discriminated enum variants.

Discriminator contract enforced:

- `real_aeat_corpus_pdf`: every fixture PDF for that modelo must NOT carry `aeat-test-fixture-generator` in `/Producer`. Real AEAT PDFs have no producer entry at all.
- `synthetic_from_aeat_published_text`: every fixture PDF MUST carry `aeat-test-fixture-generator` as `/Producer`.
- `historical_suppression` / `not_applicable`: no fixture-level assertion (no discriminating signal in metadata).

Two sentinel tests guard against dormancy: `test_all_real_corpus_profiles_have_fixture_pdfs` and `test_all_synthetic_profiles_have_fixture_pdfs` fail if any discriminated profile has no fixture PDFs on disk — preventing the parametrized test from silently skipping a mis-tag.

## Fixture path derivation

`bundled_path()` resolves to `src/aeat/_data`; the fixture tree lives at `src/aeat/tests/fixtures/justificantes`. The test mirrors `RegistryValidator._justificante_corpus_root`'s derivation: `bundled_path().resolve().parents[0] / "tests" / "fixtures" / "justificantes"`.

## Mis-tagged profiles surfaced

None. All 21 profiles with `corpus_round_trip_verified=true` were correctly tagged:

- `real_aeat_corpus_pdf` (4 modelos): M100, M190, M303, M390 — all fixtures have absent `/Producer` (real AEAT toolchain output).
- `synthetic_from_aeat_published_text` (12 modelos): M036, M115, M123, M180, M184, M193, M232, M347, M349, M369, M720, M840 — all fixtures carry `aeat-test-fixture-generator` producer.

The M111 and M130 fixture PDFs (which also have absent `/Producer`) belong to profiles that are NOT `corpus_round_trip_verified=true`, so they are out of scope for this gate.

## Edge-case honesty

The gate relies on the project invariant that every synthetic fixture generated by `_generate.py` calls `setProducer("aeat-test-fixture-generator")`. A real PDF without a `/Producer` field is indistinguishable from a hypothetical synthetic generator that omits the producer. If a future generator skips `setProducer`, the gate loses its ability to detect that class of mis-tag for the `real_aeat_corpus_pdf` direction (a synthetic-but-producer-absent PDF would falsely pass as real). The `synthetic_from_aeat_published_text` direction is fully discriminated — any fixture lacking the signature fails immediately.

## Test result

`18 passed in 27.78s` — 16 parametrized + 2 sentinel tests. No mis-tagged profiles.
