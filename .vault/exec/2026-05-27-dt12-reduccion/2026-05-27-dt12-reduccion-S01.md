# dt12-reduccion S01 — DT 12ª reducción 40% rescate plan pensiones capital

## What was done

Implemented DT 12ª LIRPF reducción 40% for plan-de-pensiones rescate en
forma de capital (Carla B, Olivia round-16).

### CLI surface

Three new flags added to `work calculate` in `_modelo.py`:

- `--rescate-plan-pensiones-capital` — gross rescate amount
- `--rescate-plan-pensiones-aportaciones-pre-2007` — pre-31-Dec-2006 aportaciones
- `--rescate-plan-pensiones-aportaciones-totales` — total aportaciones

All three must be supplied together (BadParameter if partial). Parsed as
`Decimal`; invalid input raises BadParameter.

### Pure computation helper

`_compute_dt12_reduccion_plan_pensiones(*, gross_rescate, aportaciones_pre_2007,
aportaciones_totales) -> Decimal` applies:

    (aportaciones_pre_2007 / aportaciones_totales) * gross_rescate * 0.40

Rounded HALF_UP to 2 decimals (money-2). Guards: totales > 0, gross_rescate
>= 0, pre_2007 >= 0.

Semantic-role resolver `_resolve_reduccion_trabajo_casilla_id(work_unit_id)`
follows the existing pattern (`irpf_rendimiento_trabajo_reduccion` role →
casilla 0011). Result injected into `casilla_inputs[reduccion_casilla_id]`.

### Advisory finding

`_dt12_reduccion_advisory_finding` in `_actions.py` emits a WARNING-severity
`BLOCKING_RULE` finding (`DT_12A_REDUCCION_POSSIBLE`) when:
  - `irpf_rendimiento_trabajo_importe_integro_dinerario` (0003) > €20,000
  - `irpf_rendimiento_trabajo_reduccion` (0011) == 0

Non-M100 modelos (roles absent from snapshot): finding returns None,
no emission. Finding carries `legal_refs=("ley-35-2006:dt-12",)`.

## Oracle test

Carla shape: €60,000 gross, €9,600 pre-2007, €33,000 total.

    9600 / 33000 * 60000 * 0.40 = 6981.818... → 6981.82

Note: task spec stated `€6,983.64` which is arithmetically incorrect.
The implementation and tests use the correct value `Decimal("6981.82")`.
Anti-tautology proof: halved pre-2007 (€4,800) → `Decimal("3490.91")`.
