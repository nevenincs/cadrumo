# Confirm the fixed-point gate's time ceiling remains adequate for the corpus this campaign grows

## Scope

- `dev/tests`

## Changes

- `verify:` `pytest dev/tests/test_modelo_workspace_fixed_point.py --durations=10` -> `1 failed, 5 passed in 121.28s`

## Notes

THE CEILING IS ADEQUATE, and the measurement rather than the total is what says so. The ceiling is
PER TEST, so the figure that matters is the slowest single test, not the file's wall time. The
dominant test walks the shipped tree for canonical authority definitions and takes 98.74 seconds
of the 121.28 second run; every other test in the file is under 13 seconds and six are under five
milliseconds. Against the module's declared 600 second ceiling that is roughly six times
headroom, and this campaign would have to make that one walk six times slower to breach it.

The step's premise needed correcting before it could be answered. The module declares its own 600
second ceiling rather than inheriting the repository default of 300, so the question is about the
override, not the default; an earlier reading of this row measured against the default and
concluded there was 92 percent of the ceiling consumed, which was against a figure this module
does not use.

THE OVERRIDE IS NOT SURPLUS, and it is worth recording why, because the obvious reading of the
measurement is that it could be dropped. The slowest test runs at 98.74 seconds on this machine
and the repository default is 300; a continuous integration runner roughly three times slower
would put that same test at the default ceiling exactly. The override is what keeps the gate from
becoming a timing flake on slower hardware, so it earns its place despite the local figure sitting
well under even the unraised default.

Recorded as a standing tension rather than resolved here: the repository states that 300 seconds
is a ceiling no legitimate unit test approaches, and this module is marked as a unit test while
overriding to twice that. Either the classification or the ceiling is wrong, and if corpus growth
ever does breach 600 the remedy is to split or reclassify the gate rather than raise the number
again, which is the same discipline this campaign applies to its size budget.

The failing test is pre-existing and belongs to another lane: it reports duplicate canonical
authority for the declared destination identifiers in the full-screen navigation module, which
this campaign has not modified and which is unmodified in the working tree.
