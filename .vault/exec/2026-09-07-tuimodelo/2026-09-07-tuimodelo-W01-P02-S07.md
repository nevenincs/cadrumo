## Notes

ONE ROW WAS DEFECTIVE, NOT TWO, AND THE PREMISE WAS CORRECTED RATHER THAN WORKED AROUND. Both rows
declare a local-state side effect with no write route, but only the recipient-encryption row emits
a collaboration event, and that event reaches the encrypted bucket store, so only its declaration
was false. The feedback-encryption row reads a bucket-scoped registry and writes a file to a path
the operator named, which the route vocabulary does not govern. Measured across the command
surface, roughly half the identities carrying encrypted facts declare no write route while reading
bucket storage, so treating the route as a promise of uninitialised-installation safety would
mis-describe most of the read surface. The step's wording and the governing decision were both
corrected, because leaving the two-row premise standing would drive a wrong edit later.

THE FIX IS A REFERENCE SWAP, NOT A CONSTANT EDIT. The two rows share one execution-policy constant
with exactly two consumers, so editing the constant in place would have silently changed the
correctly-declared row as well. The defective row's reference was repointed at the existing
field-identical profile-bound constant instead, which changes one identity and one signature
field.

THE CLASSIFICATION ROW FOLLOWED ON THREE FIELDS, NOT ONE. Beside the route, that row recorded the
command as a read-only query, which is false for a mutation; the disposition and the reason were
corrected with it. Correcting only the route would have left the table green while lying, which is
the failure mode the denominator exists to prevent.

THE ROUTE VOCABULARY CARRIED A FALSE GLOSS, and it is what made the wrong premise plausible. The
no-write route documented itself as safe against an uninitialised installation, a claim contradicted
by the majority of the rows that carry it. It now states the write-scoped claim only.

THE EVIDENCE IS DISPATCH-LEVEL BECAUSE A PRIOR REVIEW NAMED PROJECTION-LEVEL EVIDENCE AS THE REASON
AN IDENTICAL REGRESSION SHIPPED. Moving a command onto the profile-bound route lets the root
storage-write gate refuse before the handler is reached, and that gate names the profile-creation
action unconditionally while the handler it pre-empts distinguishes an operator who has no profile
from one who is merely logged out. Both states were therefore exercised through a real root
dispatch. A cold start correctly offers profile creation, and a registered-but-logged-out operator
correctly offers login, because the session-resume precondition resolves before the cold-root
verdict. The logged-out proof pins the winning condition by name, so a future change that lets the
cold-root verdict pre-empt the resume path fails visibly rather than silently degrading guidance.

The verb also joined the existing cold-start contract rather than gaining a parallel test of its
own, since being newly profile-bound is exactly what that contract enumerates.

TWO FAILURES IN THE HOST SUITE ARE PRE-EXISTING AND WERE PROVEN SO AGAINST A TRUE BASELINE. The
first attempt at that proof was itself invalid: the working tree's own history already carried this
change, so the obvious baseline contained the very edit being excluded. The tell was a countable
property of the file disagreeing with what an untouched baseline must show, and the proof was
redone against the parent of the commit that introduced the change. One of the two failures is
additionally informative: it asserts a refusal-document shape the product no longer emits, and the
first version of this step's own test copied that stale shape and reported a regression that does
not exist.

A SEPARATE DEFECT OF THE SAME CLASS WAS RECORDED RATHER THAN FIXED HERE. The telemetry flush
command performs network egress while declaring no network side effect. It is outside the
review-package family, so it was recorded against the decision that owns the class instead of being
absorbed into this step.
