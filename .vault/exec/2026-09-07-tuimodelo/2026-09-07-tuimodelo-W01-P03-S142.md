## Notes

THE STATED REASON FOR THIS STEP IS SPECULATIVE AND THE STEP IS STILL RIGHT, which is a distinction
worth recording because a sibling row failed the same test and was reverted. The row justifies
itself by a frontend import being forbidden, and no module under the full-screen package imports
this projection; measured, it had exactly two importers and both were tests inside its own
package. What makes the relocation correct anyway is independent of any consumer: the symbol is
public, it appears in a module export list, and it lived in a leading-underscore module, which the
architecture boundary forbids outright. That is a standing violation whoever imports it.

The difference from the reverted sibling is the whole point. That one CREATED a shared module for a
consumer that does not exist. This one moves a public symbol into a public module that already
exists, inside the same package, and creates nothing.

The destination was found rather than chosen. The receiving module already declares that it owns
the read-only half of the edit contract and projects the registry-declared permitted surface,
which is exactly what a capability projection is, and it already imported the work-unit catalogue
and the address resolution the projection needs. Only the disposition enum and three models were
added.

The relocation is atomic as the boundary rule requires: the definition moved, the private module
was deleted rather than left as a forwarding shim, both importers were cut over, and a module
tuple that enumerated the old module was corrected. No reference to the deleted module survives
anywhere in the tree.

Recorded because the inherited baseline changed under this campaign's feet: the import contracts
now report twelve kept and none broken, where the baseline recorded ten kept and one broken. The
repair belongs to another lane, and the contract count itself grew, so the improvement is not this
step's and must not be read as its effect.
