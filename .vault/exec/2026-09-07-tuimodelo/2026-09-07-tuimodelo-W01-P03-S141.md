## Notes

THE ROW WAS NOT MERELY STALE, IT WAS PERMANENTLY STUCK. Its reconsideration condition waited on a
green dependency receipt from a family that had been retired and whose module was deleted, so no
future state could ever satisfy it. A row in that shape reads as pending while being unreachable,
which is indistinguishable from a row nobody has considered -- the precise failure the campaign's
governing decisions exist to prevent.

The surviving mechanism was already in the tree and needed no invention. The capability row model
refuses an available row that carries no registered operation definition, so availability follows
from registration rather than from anything this facade asserts. The condition now names that, and
the module docstring names it too, since the docstring carried the same retired citation.

THE POSTURE DID NOT CHANGE AND SHOULD NOT HAVE. Seven modelo operations are registered and a
calculate operation is not among them, so the row remains unmeasured. What changed is that it is
now waiting on something reachable rather than on something deleted.

The test carried the retired premise in its own docstring while its assertions were correct, so
the docstring was corrected rather than the assertions. A new invariant was added because the
existing ones could not have caught this defect: they assert the disposition and the absent
operation definition, both of which held true throughout, so a test suite could stay green over a
permanently stuck row indefinitely. The new one asserts the condition is SATISFIABLE, naming no
receipt and naming operation registration.

A verification detour is recorded because it nearly produced a false finding. The owning suite was
reported by a delegated run as failing to collect because of a module-level error in another
lane's error hierarchy, and that attribution had already begun. The real cause was marker
deselection: the file is integration-marked and the default selection excludes it. The module
imports cleanly and the suite passes under its own marker. A summary line cannot distinguish a
deselected file from an uncollectable one, and only asking for the collection list separates them.
