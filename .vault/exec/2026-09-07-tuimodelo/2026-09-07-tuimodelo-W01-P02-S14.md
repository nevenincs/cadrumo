## Notes

This row and its predecessor describe one relocation from two sides, and the change was made once
rather than twice, because the architecture rule requires a relocation to be atomic across the
definition, every consumer, every dynamic reference and the tests. Splitting it across two commits
would have produced an intermediate tree that cannot import, so the split exists in the plan's
description of the work and not in the work.

The sequencing obligation this row carries is met and is worth stating precisely, because it is
the reason the phase is ordered as it is. The action denominator imports the command-line package
that declared the capability, so extending the denominator to observe capability BEFORE the
relocation would have had the gate read its subject through the very import the boundary exists to
remove. The denominator extension has not started; the relocation is complete and its gate is
green at eleven tests and zero violations.

Recorded because it is a hazard rather than an outcome: this repository runs an auto-commit daemon
that committed the relocation while it was still being verified. Applying the whole relocation in
one scripted pass kept it atomic, and the resulting commit does contain all thirteen files
together. The same commit also swept in four files belonging to another lane, under a message
describing only this change, so the commit's message understates its contents. That is not
repaired here: rewriting history is forbidden, and the mixed commit is a property of the daemon
rather than of this step.
