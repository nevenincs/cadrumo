## Notes

The step's premise holds, which is worth saying because several before it did not. The per-surface
admission check had no test at all: nothing in the tree referenced it, and the file that owns
admission refusals carried nine tests without mentioning modelo once. A change to that wiring would
have broken silently.

THE MODELO SURFACES ARE ADMITTED AS THE DECLARATIONS DESTINATION, and the two destination axes are
easy to conflate. The navigation catalogue declares five workbench destinations; the modelo
workspace declares six read destinations of its own in a closed alias. The launcher admits the
first kind, and the modelo screens reach it through Declarations, so that is the destination this
proof exercises.

The invariant is narrower than it first appears, and the narrowing is what makes the test
meaningful. The generation result already refuses itself when it claims availability while carrying
no value, so only two of its states are constructible. What the launcher check adds is the
disagreement BETWEEN the admission and the generation result, which are derived from different
sources and can contradict each other while each remains internally truthful.

Both directions are asserted separately because they fail an operator differently. A destination
admitted with no projection advertises a route whose factory would raise, so the operator opens
something that is not there. A readable destination its admission hides is the silent half: nothing
crashes, the surface is simply unreachable while its data sits available. Asserting only the first
would leave the second free to regress.

Both agreeing pairs are asserted too, so the two refusals are not vacuous, and the refusal
assertions match the guard's exact message rather than any error, so neither can pass because
something unrelated raised.
