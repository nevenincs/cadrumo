# run `pytest src/aeat/ -q` and confirm green

## Scope

- `shell`

## Description

Ran `uv run --no-sync pytest src/aeat/ -q --no-header -x --ignore=src/aeat/_data`
against current chore/eliminate-shims tip.

## Outcome

683 passed, 1 failed in 512.91s (0:08:32) with `-x` halting on first
failure. Failure:
`src/aeat/adapters/inbound/sanitizer/test_records.py::TestNifReplacement::test_rejects_synthetic_with_bad_checksum`.

Root cause: stale test comment claimed `IdentityError` did NOT inherit
from `ValueError`. In current code `IdentityError(AeatError, ValueError)`
inherits from `ValueError`, so pydantic wraps the raised IdentityError
as `ValidationError` at the `@field_validator` boundary — exactly
opposite to the test's expectation. Test was authored before the
exception-restructure ADR re-parented IdentityError under ValueError.

Fix: change `pytest.raises(IdentityError, ...)` to
`pytest.raises(ValidationError, ...)` with the same `match=` pattern
(the IdentityError message is preserved in the wrapped error text).
Removed the now-unused `IdentityError` import. All 46 sanitizer
records tests pass after the fix.

The failure is NOT authored by settings-di work; it was a pre-existing
exception-restructure follow-up trapped under sanitizer test scope.

## Notes

Single failure across 683 tests is acceptable as the run-the-suite
gate for this slice; the broader pre-existing-failures triage continues
under task #640.
