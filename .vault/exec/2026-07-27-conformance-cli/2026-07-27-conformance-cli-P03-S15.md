# add the audit verb with --check gating exit, shrink-only JSON baseline, anti-vacuity floor, and empty-input SystemExit refusal

## Scope

- `dev/registry/conformance/cli.py`

## Description

- Add the `audit` verb with `--check`, `--record`, `--note`, `--baseline` and
  `--no-validate`.
- Split the committed baseline into shrink-only ceilings and anti-vacuity floors as two
  strict typed models with explicit fields, so adding a counter is a schema change rather
  than a silent key.
- Add `record_baseline`, generating the committed artefact from a real run.
- Add the empty-input refusal to `check_conformance_ratchet` and three further refusals on
  the verb.
- Commit `dev/registry/conformance/conformance-baseline.json`, read only by dev-side code.

## Outcome

`audit --check` is the only gating exit in the whole surface, and it does not demand the
backlog be clean — only that it not GROW.

Two failure directions are computed and rendered separately because they mean opposite
things. A CEILING violation says a backlog or defect count grew. A FLOOR violation says a
measurement population fell, which means the run examined less than the baseline proves it
must, and therefore every clean ceiling above it is vacuous. Floors render first for
exactly that reason: reading a clean ratchet over a shrunken measurement is the failure
mode a ratchet without floors invites.

The baseline is GENERATED by `--record` from a real run, never hand-authored, so a
committed ceiling is always a number the tool measured. Four refusals keep it honest:
`--record` without `--note`, `--record` together with `--check` (opposite operations — one
refuses a moved counter, the other accepts it as the new ceiling, and the acceptance must
be a visible separate act), either backed by `--no-validate`, and a ratchet over a report
that composed no rows at all. The `--no-validate` refusal is the load-bearing one: under
the degraded read the evidence-tier coverage, support-probe and authorization axes are
never measured, so gating on them would read clean while nothing checked them.

The baseline's `note` is a mandatory non-empty field. In a shared worktree a baseline is a
snapshot of a MOVING tree, and a re-record with no stated reason is indistinguishable from
silencing a real regression.

Seeded ceiling regression — same command, same tree, one counter lowered by one:

```
audit registry_validated=true passed=false ratchet_violations=1 vacuity_violations=0 baseline_recorded_at=2026-07-27
violation kind=ratchet detail="modelo_scope_classification_findings grew from 23 to 24"

```

Seeded vacuity regression — one floor raised by one:

```
audit registry_validated=true passed=false ratchet_violations=0 vacuity_violations=1 baseline_recorded_at=2026-07-27
violation kind=vacuity detail="composed_revisions fell from 91 to 90; the measurement shrank, so the ratchet reading above cannot be trusted"
exit=1
```

The three verb-level refusals, each exiting 1 with its stated reason: `--check` with
`--no-validate` ("under the degraded read the evidence-tier coverage, support-probe, and
authorization axes are never measured, so their counters would read clean while nothing
checked them"), `--check` with `--record` ("opposite operations ... run them separately so
the acceptance is a visible act"), and `--record` without `--note` ("an unexplained
re-record is indistinguishable from silencing a real regression").
