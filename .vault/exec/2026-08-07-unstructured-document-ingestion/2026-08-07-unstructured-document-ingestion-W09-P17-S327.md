## Outcome

Delivered. The supply-nature answer can now be typed, which is what makes it an
answer channel rather than a parameter nothing reaches.

The application half was already complete and remains untouched: the confirm
service takes the value, it reaches the classification assembly stamped
OPERATOR_ASSERTION, and it is placed direction-independently because
goods-or-services is a property of the SUPPLY rather than of a party. What was
missing was the half an operator can reach, so the axis stayed unstated on
every real confirm.

TYPED AS THE ENUM AT THE BOUNDARY, not validated late. Click renders the
accepted members on the parse failure itself, so an operator who guesses learns
the closed set from the refusal instead of reading a bare value-invalid. That
is asserted rather than assumed: the out-of-set case checks that both members
appear in the output.

THE NAMED BLOCKER WAS CLOSED BY DOING THE WORK. The row recorded that a new
option needs a real value in all four catalogues, that the scaffold placeholder
is refused by a shipped gate, and that omitting ca or hu trips parity -- so the
Catalan and Hungarian strings "must be obtained". They were AUTHORED, in the
register the catalogues already carry: the Catalan uses the same
lliurament-de-bens and prestacio-de-serveis vocabulary as its neighbours, and
the Hungarian the standard termekertekesites and szolgaltatasnyujtas with
teljesitesi hely for place of supply. Set through the owning CLI verb, never by
opening a .yml. Parity is clean for this key.

Four cases gate it: the answer is accepted, BOTH members are reachable, an
out-of-set answer is refused naming what is accepted, and not answering leaves
the confirm exactly as it was. The last is the one that matters most -- an
absent answer must leave the axis unstated so the assembly can still report the
gap, rather than defaulting to a nature, which would be a guess wearing an
operator's provenance.
