# Convert the runnable display-only sequence frames and record why the blocked ones cannot execute, DONE, roughly forty converted by peers and the residual thirty-three each carry a measured page-specific reason, with the blocked reason structurally mandatory so display-only is a stated constraint rather than an unexamined default

## Scope

- `docs/_sequences/`

## Description

Convert the runnable display-only sequence frames, weighted to the export and
local filing verbs, and record why the genuinely blocked ones cannot execute so
display-only becomes a stated constraint rather than an unexamined default. The
originating audit found the docs gate stops exactly where the refusals live,
which is the structural reason the evidence dead end shipped undetected.

## Outcome

Closed on measurement. Both halves are satisfied, one by peer work and one
structurally.

The second half needs no campaign at all: `@blocked <code> <detail>` is MANDATORY
beneath every `@static` frame and the parser refuses a frame lacking one. The tree
carries 153 static frames and 153 blocked reasons. Display-only is already a
stated constraint by construction, which is exactly what the step asked for.

The first half was largely delivered by peers in the interim: the audit counted 72
directly-runnable frames and 33 remain flagged, so roughly forty converted. The
residue is triaged rather than untouched — nine blocked because no registry
revision covers filing year 2026, five on cumulative-page filing order, three on
cross-period clean state, several cascading from a blocked parent frame, one
because no CLI verb creates an evidence bundle so no id exists to address, and
five marked "Do NOT convert" outright with measured evidence that converting them
would double an import, switch the active profile and strand the rest of the page,
or drive a real browser at the AEAT sede.

Two of the residue are blocked by the deductible-IVA evidence trap itself. So this
step was never fully independent of the blocked recovery decision, correcting how
it was filed and correcting my own earlier statement that it was cleanly available
work.

## Notes

One claim made during this pass is withdrawn as overstated. Several frames cite
"work file rejects an already-presentado revision", and on reading that the
idempotent re-file is implemented and returns the existing VIGENTE record, I
concluded the premise was stale. It is conditional, not false: the path falls
through to the hard refusal when no VIGENTE record exists. The files carrying that
wording are also under live peer edit and were left untouched.

The durable finding is the reason code. `unconverted` no longer means "not yet
triaged"; it means "triaged and not convertible for a stated reason", and in five
cases it means the opposite of what it says. A later pass reading the code name
rather than the detail will redo this work. Splitting it into a converted-later
code and a deliberate do-not-convert code would close that, and belongs to whoever
owns the sequence corpus.
