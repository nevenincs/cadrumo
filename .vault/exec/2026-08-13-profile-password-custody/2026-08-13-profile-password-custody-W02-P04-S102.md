## Description

  - 15 `mcp.*` keys: NOT orphaned. Real, tested call sites exist in the separate `cadrumo-harness` distribution (`src/cadrumo-harness/src/cadrumo_harness/mcp/`), which sits outside the two roots (`src/cadrumo`, `dev/docs`) the locale scanner ever walked. False positive from a scanner blind spot, not dead catalogue content.
  - 3 `cli.help.missing_argument/option/parameter` keys: NOT orphaned. Consumed via a lookup table in `_framework_localisation.py` (`tr(key, ...)` with `key` bound from a tuple, not a `tr("literal")` call), which the scanner's literal-argument extractor cannot see by design; a dedicated compensating gate (`test_framework_localisation_catalogue_coverage.py`) already exists and documents exactly this indirection.

## Outcome

- `extra` (orphaned catalogue keys): 59 -> 5, identical across all four locales. The 5 remaining are 3 deliberately-kept live keys (`cli.help.missing_argument/option/parameter`, invisible to the scanner by design, covered by their own gate) and 2 keys that appeared from unrelated concurrent work during this Step (see Notes).
- `missing` (required keys absent from the catalogue): 22-23 -> 15, identical across all four locales (the one `en`-only inter-locale gap on `start_work_unit_from_ledger` is closed). The 15 remaining are the registry-sweep-owned `modelo.schema.*` casilla help/label keys, deliberately left for that ongoing work.
- Rule, as the Step asks: **a catalogue key must land in the same change as the code that consumes it.** The existing state-comparison gates (`dev.locales audit`, `test_codebase_to_locale_parity`, `test_committed_catalogues_pass_production_audit`) CANNOT enforce this rule as stated — they compare the current codebase key set against the current catalogue key set at any one point in time, so they correctly turn red after the fact (which is how this row's whole backlog was found), but nothing stops the offending commit from landing in the first place. Both root-caused single-commit incidents in this Step (`5a6fcd09e4`, `b9c3baf766`) are proof: each shipped a code-side key change with zero catalogue-side change, and the state gate had no diff-time hook to refuse it. Enforcing the rule as written needs a NEW, diff-aware pre-commit or CI check comparing the staged/changed `.py` call sites against the staged/changed locale YAML for the same commit — not built here per the row's own instruction not to build a new gate mechanism in this Step; noted as a follow-up.
- Gate state after: `dev/locales/tests/test_audit.py::test_committed_catalogues_pass_production_audit` and `src/cadrumo/tests/test_parity.py::test_codebase_to_locale_parity` both still FAIL (`ok` requires exactly zero `extra` and zero `missing`), but for the honestly-narrowed, explained residue above rather than the original 59/22-23 blanket red. `src/cadrumo/tests/test_parity.py` additionally has FIVE pre-existing, unrelated failures discovered but NOT fixed in this Step (see Notes) — the file as a whole is not green.
