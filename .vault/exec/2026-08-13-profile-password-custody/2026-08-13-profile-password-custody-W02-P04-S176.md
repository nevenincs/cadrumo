# Have Terra XHigh repair the five standing parity-suite failures the locale attribution left named but unowned, being a lookup of custody passphrase keys the cutover removed while the test was never swept, two operator-surface heading assertions hardcoded against text that has since changed, and one residual inter-locale key drift

## Scope

- `src/cadrumo/tests/test_parity.py`

## Description

- Ground the row's enumeration against the live tree first, because it was stale in the same way the preceding attribution row's figures were. The five failures at the start of this Step were NOT the five the row names: the residual inter-locale key drift it lists was already closed and `test_inter_locale_parity` passed, while `test_codebase_to_locale_parity` failed in its place. The live five were the English and Catalan naming-contract tests raising `KeyError: 'passphrase'`, the Spanish and Hungarian ones failing on a drifted operator-surface heading, and the codebase-to-locale parity check reporting `missing=36 extra=23` identically across all four catalogues.
- Establish that the five carry three distinct causes and one blanket fix would be wrong, then take each separately.
- **Cause one, the passphrase `KeyError` (English and Catalan).** The test asserted three exact prompt strings under `cli.config.passphrase.*`. That whole key family is absent from all four catalogues, confirmed by direct load rather than grep. The keys are not retired: the operator surface declares the `("config", "passphrase")` command family with `FamilyMountState.DECLARED_UNIMPLEMENTED` and a reason recording that credential rotation exists at no layer, so the capability is owed rather than withdrawn. Applied the closed ruling that separates declaration-class surfaces from citation-class ones: these are strings a verb would itself consume, so they are held, neither pruned nor restored by re-mounting the verb.
- Made the test read that disposition instead of judging it. `_declared_family_mount_state` maps a `cli.<root>.<child>` catalogue namespace to the declaring family and returns its mount state; `_assert_command_family_catalogue_strings` then requires presence only for a `MOUNTED` family, tolerates absence for a held one, and applies the naming contract to whatever is present in either state. A namespace resolving to no declared family at all is a hard failure, so a genuine retirement forces the expectation to be deleted in the same move rather than left asserting against nothing. When the capability ships and the family flips to `MOUNTED`, the test demands the three prompts back with no edit here.
- **Cause two, the drifted heading (Spanish and Hungarian, plus two that were masked).** The four tests pinned `cli.operator_surface.help.root.heading` and `cli.root.landing.headline` as exact sentences. All four headings had in fact drifted; the English and Catalan mismatches were invisible only because those tests raised on the passphrase lookup several lines earlier, so repairing cause one alone would have converted two `KeyError`s into two fresh assertion failures. Re-founded the assertion on what these tests actually own rather than updating the literal, which would only reset the clock: `_identity_tokens` extracts the four spellings the naming contract governs (`CADRUMO` for identity contexts, `Cadrumo` for sentence prose, the `cadrumo` / `cadrumo-mcp` machine names, `AEAT` for the authority and `aeat` for the sole human executable), and each test asserts the exact token set for the string. A reword stays green; a case slip, a product rename or an authority substitution reds. The precedent already existed in this file for `mcp.call.timeout`, whose prose was deliberately unpinned for the same reason.
- Applied the re-founding to all four locales, including the two whose literals still matched, since leaving them pinned guarantees a future failure of exactly this row's class.
- **Cause three, the parity residue.** Measured the `missing`/`extra` sets directly rather than reading the aggregate. Of the 36 missing keys, 35 were `modelo.schema.*` casilla help and label entries owned by the in-flight registry authoring sweep; exactly one, `flows.manager.next_step_modelo`, was a live non-registry key with a real call site at `src/cadrumo/entrypoints/cli/_config/_manager_frontend.py:139` and no catalogue entry anywhere. Traced it to commit `7bcadaf18b`, which added the `tr()` call site and touched zero locale files. Authored real values in all four catalogues through `python -m dev.locales set`, following the `{placeholder}` convention its immediate siblings use, and confirmed by rendering that the parameter substitutes.
- Of the 23 extra keys, three are the deliberately-kept `cli.help.missing_argument/option/parameter` trio that the scanner cannot see by design and a dedicated gate already covers, and twenty are stale `modelo.schema.151.revision.2015-y-siguientes.*` entries left behind when a peer commit renamed that revision to `2015-2022`. Deliberately did NOT prune those twenty: a revision rename is a re-key, not a retirement, and deleting them would destroy twenty real Spanish, Catalan and Hungarian casilla labels the renamed revision still needs. That content belongs to the registry campaign.
- Absorbed two further failures in owned files that the row did not name, one of which this Step's own repair unmasked.
  - `dev/locales/tests/test_audit.py` carried a hand-maintained `_PROSE_KEYS` inventory still naming the three removed passphrase prompts and two `errors.integrity.integrity_storage_bucket_manifest_version_*` keys removed by the preceding attribution row. Removed the five dead entries and added a staleness assertion that reports a dead inventory entry as itself, so it no longer surfaces as an opaque set difference indistinguishable from a genuine contract breach. Recorded in a comment that the passphrase prompts are held rather than retired, so a future reader does not read their absence as a ruling.
  - Repairing that assertion unmasked the next one in the same test: `cli.operator_surface.help.root.paragraph_local_first` carries the display-cased `CADRUMO` in what is plainly a sentence with the product as its subject, in all four locales. The naming rule reserves the display casing for identity contexts and calls for the sentence-prose form here, and enrolling a help paragraph in the identity-heading set would have silenced a true finding and corrupted that set's meaning. Rewrote the four values to the prose form and enrolled the key in `_PROSE_KEYS`, which is the deliberate acknowledgement that inventory exists for.
  - Repaired five catalogue values carrying U+2014 against the shipped no-em-dash gate (`flows.tui.header_single_section` in all four locales and `en.yml:flows.status.profile.repeated_field`), all the label-qualifier pattern the gate's own docstring names, replaced with the spaced hyphen it prescribes.
- Proved both new mechanisms bite rather than asserting they do: five tests corrupt the input on purpose and require a failure. The token extractor is shown to separate all four product spellings and to leave `cadrumo-mcp` and `cadrumo://` uncounted as the bare machine name; the heading contract is shown to accept an arbitrary reword and to refuse a lower-cased product, a sentence-cased product, an authority substituted by the product, and an executable token smuggled into a heading; the family register is shown to answer `DECLARED_UNIMPLEMENTED` today and to refuse a namespace naming no family; a `MOUNTED` family is shown to fail on an absent namespace and on an absent leaf, which is what stops the held branch going vacuous; and a held family's present string is shown to still answer to the naming contract.
