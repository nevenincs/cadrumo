# `calculation-test-oracle-discipline` adr: every numeric calculation assertion cites an external oracle | (**status:** `accepted`)

## Problem Statement

Calculation tests in this codebase frequently asserted Decimal outputs
derived by the test author from the same formula the registry encodes.
A test of the form "set inputs X, expect output f(X) where f is the
formula under test" is structurally tautological: it locks the
registry against any change, including a correction toward the real
AEAT behavior, while providing zero independent evidence that the
formula matches the regulation. The pattern was repeated across
modelo-100, modelo-130, modelo-303, and shared engine surfaces, and
each instance burned review time relitigating the same question.

## Considerations

External numeric authority exists for nearly every Spanish-tax
calculation surface: AEAT publishes worked examples in manuals, BOE
publishes the regulations the formulas implement, AEAT distributes
template workbooks with reference values, and the live AEAT oracle
returns canonical results for any input the operator submits. Hand-
computed expectations are only one of several available oracles, and
they are the only one that has no probative value against AEAT
behavior.

## Constraints

The rule applies to numeric Decimal assertions against engine output
in `src/aeat/**/test_*.py`. It does not apply to graph wiring tests,
validation-error tests, provenance tests, schema-shape tests, or
primitive evaluator contracts: those test structural properties the
registry does not author and can fail meaningfully without an
external numeric oracle. The rule is enforceable by review (G6 in the
standing-review-gate memory) and by the
`no-tautological-calculation-tests` repo-rule.

## Implementation

Every numeric Decimal assertion in a calculation test must carry an
inline citation of its oracle, in the form
`# oracle: AEAT-MANUAL-<year>-<page-or-section>` or
`# oracle: BOE-A-<year>-<number> art. <n>` or
`# oracle: live replay <date> <reference>` or
`# oracle: registry-authoritative fixture <fixture-id>`. Tests
without an oracle citation must be rewritten to test structure,
wiring, validation, provenance, or schema shape, or deleted. The
acceptance test for a candidate calculation test is: "would this test
fail if the registry formula disagreed with AEAT?" If the answer is
no, the test is tautological and must be replaced.

## Rationale

A test's value is its capacity to fail when the system is wrong.
Tests that hand-compute the formula under test cannot fail when the
formula is wrong against AEAT, so they have negative value: they
freeze incorrect behavior and impose maintenance cost on every
genuine correction. External-oracle assertions invert this: they
fail when the registry drifts away from regulation, which is exactly
the failure mode the calculation surface needs to defend against.

## Consequences

Adding a new calculation test requires sourcing an external oracle
before writing the assertion. Some calculation surfaces have no
published worked example; for those, the test author must use a
registry-authoritative fixture (a value generated by the operator
flow and reviewed against AEAT once, then frozen as the fixture
record) or pivot to structural tests. The cost is paid once at
test-authoring time and is recouped every time the test catches a
real divergence. The rule is the long-running enforcement surface
of the `no-tautological-calculation-tests` repo rule.
