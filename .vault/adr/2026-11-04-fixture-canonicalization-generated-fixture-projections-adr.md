# `fixture-canonicalization` adr: `Generated fixture projections` | (**status:** `accepted`)

Operator approval recorded 2026-11-04 in the fixture-canonicalization design session.

## Determinism-proof amendment (2026-11-04)

Recorded during P02 execution under the operator's 2026-11-04 approval of this design. A full Modelo envelope build takes about 13.5 minutes, so the double-build determinism proof is not part of `fixtures-check`. It runs as `fixtures-check-determinism [family]` at plan close and on demand. `fixtures-check` keeps every family's own `--check`, persona validation and the generated docs seed check, and stays fast enough for the merge gate.

## Problem Statement

Generated fixtures are committed but regenerated by hand: no recipe or CI job runs the window generators, one Rust copy is stale, one generator stamps wall time, and the window envelopes churn millions of lines nobody reviews. Generated data needs an owner, a freshness check and a rule for what is committed (`2026-11-04-fixture-canonicalization-research`).

## Considerations

- A committed output that is an assertion (docs goldens, expected obligations) lets review see a behaviour change; a committed projection nobody reviews only adds churn.
- The registry authority already establishes the pattern: gitignored output, `--if-stale` publication from setup, content-digest currency, loud refusal when absent.
- Rust `include_str!` and TypeScript static imports need projections at compile time.
- Per-PR CI has no frontend or Rust job today.

## Considered options

- Keep committing projections and add `--check` gates: rejected as the end state; keeps 49 MB of churn and the nondeterminism hidden in diffs. Kept as the interim gate.
- Generate inside the test runners on first use: rejected; races under xdist, unpredictable test time, test processes writing build output.
- Gitignored projections under `build/<preset>/fixtures/`, generated by just recipes on a digest miss and verified by the test runners: chosen.

## Constraints

- Committed: persona definitions, external specimens with sidecars, docs goldens, expected obligations, protocol vectors.
- Not committed: derived projections, meaning the window Modelo envelopes, `dev/desktop_*_fixture.py` outputs, served-word fixtures and recorded window fixtures. Hand copies of projections are forbidden; the Rust 303 baseline is removed.
- A projection is removed from git only after its generator is byte-identical across two runs.
- Staleness is a content digest of persona files, product source, authority identity, generator source and lockfile, recorded beside the output; modification times are not used.
- Test processes never write fixtures. Run directly, they verify the stamp and refuse with the seeding command.
- Old git history is not rewritten.
- Amends `2026-10-23-desktop-modelo-workspace-adr` where it relies on committed envelopes.

## Implementation

We will generate projections into `build/<preset>/fixtures/` and separate seeding from testing in the justfile:

- `fixtures-seed [family]` generates stale projections; `fixtures-seed-force` regenerates; `fixtures-status` reports fresh, stale or missing with the changed digest inputs; `fixtures-check` validates personas, generated docs seeds and every generator `--check`, and rebuilds twice into `.tmp/` to prove determinism; `fixtures-clean` removes projections.
- `test-frontend` and `test-native` depend on `fixtures-seed`; Python lanes materialise personas in-process and need no seeding; `setup`, `dev` and `init` seed after authority publication.
- Vite and `tsc` resolve projections through an alias to the build directory and fail naming the recipe when absent. Rust tests receive projection paths through environment variables set by CMake, as `provider-status-contract.json` already is.
- `gate-local` and the merge gate run `fixtures-check`; a per-PR frontend and Rust job is added.

Recipe names and the alias mechanism are implementation hypotheses within these constraints.

## Rationale

It reuses the repository's proven on-demand pattern instead of inventing one, removes a whole class of stale-copy defects, and keeps review effort on assertions instead of projection diffs.

## Consequences

- Frontend and Rust work requires the Python environment and authority before compiling, as authority-dependent work already does.
- Envelope diffs no longer review behaviour; expected values move to `expectations.toml` and backend tests.
- Reconsider if seeding time makes local frontend iteration impractical; the response is a narrower family seed, not recommitting projections.
