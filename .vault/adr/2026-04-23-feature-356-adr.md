# `feature-356` adr

## Context

Feature 356 captured a follow-up port from a stale category-assignment
worktree into a fresh branch off main. The execution record and review
record show a bounded transport of already-designed work rather than a
new architectural initiative, but the feature still needs a vault-level
decision record.

## Decision

- Preserve the follow-up work by replaying it onto a fresh branch that
  matches mainline patterns instead of reviving the stale worktree.
- Keep only the changes that remain valid against current mainline
  contracts and drop stale seams or assertions that diverged.
- Treat the reviewed six-commit batch as the authoritative closure of the
  feature-356 follow-up slice.

## Consequences

- The ported work gains architectural provenance inside the vault.
- Stale implementation artifacts are not carried forward just because they
  existed on the old worktree.
- Review approval, not worktree age, defines the accepted result.
