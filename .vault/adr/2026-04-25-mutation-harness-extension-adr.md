# `mutation-harness-extension` adr: percent + brackets + scalar mutators (**status:** `accepted`)

## Problem Statement

The mutation harness in `src/aeat/domain/formulas/_rulesets/test_operand_swap_mutation.py`
only kills mutants generated by swapping the two operands of an outer
`SubFormula`. The audit finding cited by EPIC #316 records three
remaining classes of silent-regression mutant the harness does **not**
kill today:

- `PercentFormula` rate drift (a Spanish IRPF rate transcribed as 20 %
  when the BOE rate is 19 %).
- `BracketsFormula` threshold drift (a tramo boundary shifted by 1 €).
- `MulFormula` / `DivFormula` scalar-literal drift (a `/100` normaliser
  miscoded as `/1000`).

These are the values most likely to be wrong in a hand-ported ruleset
and the values that actually change between fiscal years. Every
per-modelo Tier-L issue (#317 M100 — #327 M390) needs strong mutation
coverage as a baseline so a future ruleset author cannot ship a silent
rate or threshold regression. This ADR records the chosen mutator
taxonomy, the AST-walking strategy, the per-mutator detection contract,
the kill-rate target, the orphan-node defense, the fixture-straddling
strategy, and the file-organisation decision.

## Considerations

- The four landed mutator-class precedents (mutmut, cosmic-ray, pitest,
  Stryker) all share a "constant replacement" operator family applied
  to numeric leaves. The chosen mutator surface mirrors that family
  for the formula DSL.
- The eleven landed modelos (across eighteen ruleset variants — 2024 +
  2025 for some modelos, 2025-only for others) currently expose:
  many `PercentFormula` nodes; zero in-formula `BracketsFormula` nodes;
  zero in-formula `MulFormula` nodes; two in-formula `DivFormula`
  nodes (Modelo 303 casilla 66, both years, both with a `lit("100")`
  RHS). The mutator catalogue must therefore both cover the populated
  surface today and defend against future ruleset additions.
- The existing operand-swap harness is in scope for preservation only —
  the issue forbids any behaviour change there.
- The marker contract in this issue's DoD is
  `[pytest.mark.unit, pytest.mark.domain_submission]`. The existing
  operand-swap harness uses `[pytest.mark.unit, pytest.mark.domain_local_state]`.
  Changing the existing module's marker is out of scope; the new
  modules must therefore live separately so the marker boundaries are
  clean.
- The single-rounding invariant (terminal `RoundFormula` produced by
  the `formula(...)` helper) is structural: every computed casilla's
  formula tree is shaped as `RoundFormula(operands=(body, ...))`.
  Mutators must walk through the terminal `RoundFormula` to reach
  mutable inner nodes.
- The `Engine.audit_against` contract reports a discrepancy when
  `|delta| > tolerance` (strict greater-than). A discrepancy of
  exactly `tolerance` would not surface, so the harness must require
  `|delta| ≥ 2 × tolerance` (i.e. `0.02 €`) as the detection floor —
  the same convention the wave-67e operand-swap harness already
  enforces.

## Constraints

- The mutators may not modify a `Ruleset` instance in place; they must
  return a new `Ruleset` via `model_copy(update=...)` because every
  formula node is `frozen=True`.
- The `BracketsFormula` validator forbids non-strictly-ascending
  upper-inclusive boundaries; the brackets-threshold mutator must
  respect this when constructing mutated brackets (a `±1 €` shift on
  a non-terminal bracket must not collide with a neighbour).
- `PercentFormula` rates may live in three places: as a `Literal`
  inside the formula body, as a `ParamRef` resolving via the
  ruleset's `ParameterTable`, or (rarely) as a `CasillaRef`. The
  rate-mutator must handle all three. The chosen approach mutates
  the *parameter table* when the rate operand is a `ParamRef`,
  mutates the *literal value* when the rate operand is a `Literal`,
  and skips (with a documented entry in the unflagged-nodes
  catalogue) when the rate operand is a `CasillaRef`.
- The mul/div scalar mutator only mutates the **leaf scalar literal**;
  if both operands are non-literal (e.g. two casilla refs), the node
  is recorded as "no scalar leaf to mutate" and excluded from the
  kill-rate denominator.
- No mocks, fakes, or stubs. The DoD is explicit. Real ruleset
  evaluations against real fixtures only.

## Implementation

### Mutator-class taxonomy

Four mutator classes total (one preserved + three new):

| Mutator class            | AST node mutated                          | Mutation rule                                               | Returns                       |
| :----------------------- | :---------------------------------------- | :---------------------------------------------------------- | :---------------------------- |
| `sub_op` (preserved)     | outermost `SubFormula` of a casilla       | Swap the two operands                                       | new `Ruleset` via `model_copy` |
| `percent_rate` (new)     | every `PercentFormula` rate operand       | If `Literal`: ±1 pp ; if `ParamRef`: ±1 pp on parameter table | new `Ruleset` via `model_copy` |
| `brackets_threshold` (new) | every non-terminal `Bracket` in a `BracketsFormula` | Shift `upper_inclusive` by ±1 € (preserving strict-ascending invariant) | new `Ruleset` via `model_copy` |
| `mul_div_scalar` (new)   | every `MulFormula` / `DivFormula` leaf scalar `Literal` | Multiply the literal by 1.01 (i.e. ±1 %)                    | new `Ruleset` via `model_copy` |

The mutation magnitude on each class is calibrated so that the
resulting mutant produces `|delta| ≥ 0.02 €` on at least one fixture's
target casilla. The rate mutator uses `±1 pp` (a real-world rate-error
magnitude); the threshold mutator uses `±1 €` (a real-world rounding
error); the scalar mutator uses `±1 %` (the smallest credible
transcription drift on a normaliser literal).

### AST-walking strategy

A single visitor function `_walk_compound_nodes(node)` performs a
recursive descent over the discriminated-union of formula nodes,
yielding every node. Each mutator filters the visitor's stream by node
type (e.g. `_iter_percent_nodes(formula)` filters to `PercentFormula`).
The walker traverses every compound child, including walking through
terminal `RoundFormula` and through nested operands (e.g. a
`PercentFormula` inside a `SubFormula` inside a `RoundFormula`). The
walker is tested directly so a future Formula subclass that escapes it
fails loudly via the exhaustiveness defense.

The walker is deliberately not a `pydantic.BaseModel.walk()` style
abstraction; it is a plain function over the existing
`_is_compound` / `_compound_operands` helpers in `_formula.py`. This
mirrors the existing private API and avoids touching the public
formula module.

### Per-mutator discrepancy assertion

Every mutated case asserts:

1. The unmutated ruleset audits clean against the fixture (baseline
   sentinel).
2. The mutated ruleset produces a discrepancy on at least one casilla
   for which a derivation depends on the mutated node.
3. The maximum `|delta|` across the casillas affected by the mutation
   is `≥ 0.02 €` (detection floor).

The third assertion is the load-bearing one — the first two pass even
on near-tautological mutants if the discrepancy is below the tolerance.

### Kill-rate target

The harness emits per-(ruleset × mutable-node × mutation-direction)
result records. A separate aggregator test
(`test_mutator_kill_rate.py`) collects these records and asserts:

- `(killed-mutants / total-mutants) ≥ 0.90` across the mutable surface
  of the eighteen landed ruleset variants.
- Every unkilled mutant carries a justification (e.g. "rate operand is
  a `CasillaRef` resolving to a fixture value of zero" → "mutation has
  no observable effect because the result is masked by a sibling
  `clamp_pos`"). Every justification is enumerated in the exec
  summary's "unflagged-nodes catalogue" with the casilla, formula id,
  and reason.

The 90 % floor is the issue DoD. Today's expected kill-rate is
**100 %** for the populated mutator surface (every `PercentFormula`
node and every `DivFormula` leaf is reachable on at least one fixture);
the floor is set conservatively to leave room for future rulesets
where a defensible "no observable effect" mutant might appear.

### Orphan-node defense

A separate test module (`test_mutator_exhaustiveness.py`) imports the
public discriminated-union `Formula` from `aeat.domain.formulas` and asserts
that every concrete subclass either:

- has a registered mutator in the `_MUTATOR_REGISTRY` mapping (defined
  in a new `_mutators.py` helper module), OR
- appears in the `_NOT_MUTABLE_NODE_TYPES` allow-list with a
  documented reason (e.g. `Literal` participates only via the
  mul/div scalar mutator; `RoundFormula` is the terminal wrapper and
  has no mutable parameters at the rules level).

Adding a new `Formula` subclass without updating one of the two sets
fails the test loudly. The registry plus allow-list is a
`frozen=True` strict pydantic v2 model so a refactor cannot weaken
its enforcement.

### Reversibility / determinism

Mutators construct new `Ruleset` instances via `model_copy(update=...)`;
the original is never mutated in place (every formula node is
`frozen=True` so this is enforced at the type level too). No RNG is
used for mutation parameter selection — the magnitudes are fixed
constants per mutator class. Test ordering is deterministic via
`pytest.param(..., id=...)` with stable, content-derived ids.

### Fixture straddling for the brackets-threshold mutator

For every `BracketsFormula` node mutated, the harness ensures at least
one fixture per non-terminal bracket whose probe input lands within
`±5 €` of the boundary. Because no production ruleset currently
contains a `BracketsFormula` body, the harness uses a synthetic
`Ruleset` fixture (built via the public API + `_common.py` helpers)
modelled on the Modelo 130 minoración step function. When a future
ruleset adds a real `BracketsFormula`, the existing test pattern
extends to it by registering the ruleset in the parametrised input.

### File organisation

The split-per-mutator-class option is chosen. The new modules under
`src/aeat/domain/formulas/_rulesets/` are:

- `_mutators.py` — private helpers: the AST walker, the per-class
  mutators, the registry, the not-mutable allow-list, and the
  per-(ruleset × node) cataloguer.
- `test_percent_rate_mutation.py` — parametrised harness for the
  `percent_rate` mutator across all eighteen ruleset variants.
- `test_brackets_threshold_mutation.py` — synthetic-ruleset harness
  for the `brackets_threshold` mutator + the straddling fixture.
- `test_scalar_mutation.py` — parametrised harness for the
  `mul_div_scalar` mutator across all eighteen ruleset variants
  (today's surface: Modelo 303 casilla 66, two years).
- `test_mutator_exhaustiveness.py` — orphan-node defense.
- `test_mutator_kill_rate.py` — aggregate kill-rate assertion + the
  per-issue exec summary's flag-count emission.

Every new module declares
`pytestmark = [pytest.mark.unit, pytest.mark.domain_submission]` at
module level. The existing `test_operand_swap_mutation.py` keeps its
`domain_local_state` marker; preserving it untouched avoids a
behaviour change on that file outside this issue's scope.

### New pydantic v2 models

Two strict, frozen models are introduced in `_mutators.py`:

- `MutationCase` — the result of evaluating one mutated ruleset
  against one fixture. Carries the ruleset id, the casilla id of the
  mutated node, the mutator class, the mutation direction (e.g.
  `"plus_1pp"` / `"minus_1pp"`), the maximum `|delta|` observed, the
  set of affected casillas, and a "killed" boolean.
- `MutationCatalogueEntry` — one row in the per-issue exec summary
  before/after table, carrying the ruleset id, mutable-node count
  per class, killed count per class, and the unflagged-node
  justification list for that ruleset.

Both models are `model_config = ConfigDict(strict=True, frozen=True, extra="forbid")`
per the project pydantic mandate.

## Rationale

The mutator taxonomy is a direct mapping of the prior-art "constant
replacement" operator family onto the formula DSL's three mutation
surfaces. The chosen magnitudes (`±1 pp` / `±1 €` / `±1 %`) are
calibrated to mirror plausible transcription errors and produce
deltas comfortably above the detection floor. The orphan-node defense
elevates "I forgot to extend the harness" from a silent failure into
a hard test failure. The fixture-straddling strategy makes the
brackets-threshold mutator's behaviour observable today even though
no production ruleset uses `BracketsFormula` in a body. The
file-organisation split keeps each module focused and avoids
disturbing the existing operand-swap module's marker.

## Consequences

- New private API: `_mutators.py` becomes the canonical place to
  register a mutator for a `Formula` subclass. Adding a new node type
  to `aeat.domain.formulas` (extremely rare) requires either a new mutator
  or an explicit allow-list entry.
- The brackets-threshold mutator is asserted today against a synthetic
  ruleset only. When a future ruleset adopts `BracketsFormula` in a
  body, the harness must register it. This is a one-line change but
  must be remembered; the `_NOT_MUTABLE_NODE_TYPES` allow-list does
  not list `BracketsFormula` so any new ruleset will be auto-walked.
- The kill-rate aggregator emits a markdown-shaped catalogue into the
  exec summary, satisfying the issue DoD's "before/after flag counts"
  requirement.
- Coverage floor on `src/aeat` may shift slightly because the new
  `_mutators.py` module adds a small number of source lines. The
  test suite runs against it at 100 %, so the floor stays green.
- No new exception classes are raised by this issue's code. The
  cross-thread coupling note from the handover prompt (post-#398
  error-code registration) does not apply.
