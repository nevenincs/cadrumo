# `canonical-environment` reference: `Location and environment owners across Python, Rust, CMake and the frontend build`

Read on 2026-10-04 in worktree `feature/tui`. Static reading only; no build or packaged run was executed. Every claim names its locator so the ADR can cite it by stem.

## Summary

### Python owners

- The storage root default is cwd-dependent outside a checkout. `project_root()` returns the repository only when the module sits at `<root>/src/cadrumo/core/storage_environment.py` beside `pyproject.toml`; otherwise it returns `Path.cwd()` (`src/cadrumo/core/storage_environment.py:10-16`). `configured_storage_root()` reads `CADRUMO_LOCAL_STORAGE_ROOT`, then `CADRUMO_STORAGE_ROOT`, strips blanks, and anchors a relative or absent value at that root with default `var/storage` (`storage_environment.py:19-27`).
- The Settings default goes through the same anchor. `platform_user_data_root()` returns `repository_root or project_root()` on every platform, and `default_storage_root()` feeds `Settings.cadrumo_local_storage_root` (`src/cadrumo/core/config_state_root.py:92-108`, `src/cadrumo/core/config.py:343-344`). `resolve_project_path` says relative paths are resolved "never the process cwd" (`src/cadrumo/core/paths.py:194-200`); in installed mode that promise does not hold because the anchor itself is the cwd.
- Two accepted records require a platform user-data default on installed runs. `2026-07-03-claude-ecosystem-packaging-adr`: "The installed default must become a platform user-data directory; the checkout default stays for the dev loop." `2026-07-13-data-output-standardization-adr` R1: "platform user-data installed, `var/storage` checkout". The current code does not implement that; the regression is visible at `config_state_root.py:92-94`.
- The storage taxonomy is the typed declaration of every application-chosen location: `StorageCategory`, `StorageLocation` with subpath, node kind, scope, override policy, lifecycle, grouping, fingerprint participation, `settings_field`, `derives_settings_default`, and a validator refusing `FIXED` plus `settings_field` (`src/cadrumo/core/storage_taxonomy.py:196-403`). `STORAGE_TAXONOMY` is the one mapping; `storage_path()` resolves root-scoped members through the settings field first, then root plus subpath (`src/cadrumo/core/storage_taxonomy_locations.py:797-862`). The root itself is "neither a member nor an escape" (`storage_taxonomy.py:183-191`).
- Root-scoped members with an environment variable today: `tmp` (`CADRUMO_TEMP_DIR`), `runtime` (`CADRUMO_RUNTIME_SOCKET_DIR`), `logs` (`CADRUMO_LOG_DIR`), `cache/llm-cache`, `cache/corpus-search`, `components/playwright` (`CADRUMO_PLAYWRIGHT_BROWSERS_DIR`), `components/ollama/home`, `models/ollama`, `chromium-data`, `tokens`, `secrets`, `blobs`, `live-state`, `llm-usage`, `runs`, and the export families (`submissions`, `drafts`, `justificantes`, `filing-history`, `filed-declarations`, `financial/*`, `live/*`). Fixed members with no variable: `buckets`, `active-profile`, `cadrumo.db`, `reset-operations`, `operation-journals`, `profile-custody-*`, `local-reader-fitness.json` (`storage_taxonomy_locations.py:88-795`, dumped on 2026-10-04).
- There is no configuration file. Settings reads the process environment only; the dotenv source is constructed by pydantic-settings and discarded (`src/cadrumo/core/config.py:173`, `:199-214`). `CADRUMO_ACTIVE_PROFILE` is severed from every environment source (`config.py:78`).
- Allowlists: `Settings.env_var_names()` is every field name upper-cased plus `CADRUMO_STORAGE_ROOT`; `Settings.storage_env_var_names()` is the two root names plus every `TOOL_STORAGE_LOCATIONS` variable plus each taxonomy member's settings field (`config.py:1004-1028`). `TOOL_STORAGE_LOCATIONS` maps development tool caches (`UV_CACHE_DIR`, `CARGO_HOME`, `XDG_CACHE_HOME`, `RUFF_CACHE_DIR`, `HOMEBREW_*`) to `development/...` subpaths under the root (`storage_environment.py:49-67`).
- Root precedence is spelled in more than one place: `storage_environment.py:23`; `_config_runtime.py:38-40` (the settings cache key, which `2026-08-03-canonical-storage-management-adr` R19 already ruled should be lifted onto one owner); the env source alias at `config.py:115-117`; literals at `src/cadrumo/entrypoints/cli/main.py:248`, `:266` and `src/cadrumo/adapters/persistence/storage/custody/_kdf_process.py:124`.
- Child environments are built by at least three Python sites with different rules: profile workers keep ambient minus `PYTHON*`, `LD_*`, `DYLD_*` on Windows and a minimal `PATH`, `LANG`, `LC_ALL` set plus path names on POSIX, and pin `TEMP`, `TMP`, `TMPDIR` (`src/cadrumo/adapters/local_runtime/profile_worker.py:254-267`); the KDF child gets a neutral root and `HOME` (`_kdf_process.py:121-128`); CLI metadata invocations swap the root for a temporary one (`main.py:248-266`).
- Runtime records are joined as literals: `storage_root / ".runtime" / "installation.json"` (`src/cadrumo/adapters/local_runtime/installation.py:35-37`). `.runtime/` is not a taxonomy member, while `runtime` (no dot) is the `RUNTIME_SOCKETS` member.

### Generator and build graph

- `dev/packaging/native/generate.py` projects `STORAGE_ENV`, `STORAGE_ROOT_ENV`, `STORAGE_DEFAULT` (`var/storage` relative to the repository), `AUTHORITY_ENV`, `TEMPORARY_ENV` and `TEMPORARY_DEFAULT`, `TOOL_CACHE_ENV` and `TOOL_CACHE_DEFAULT` (the `XDG_CACHE_HOME` tool entry), `RESERVED_ENV` (every Settings field), `STORAGE_ENV_ALLOWLIST` (`storage_env_var_names()`) and `PACKAGE_ENV_ALLOWLIST` (`layout["overrides"]`, today `CADRUMO_EXTERNAL_BIN_DIRS`) into `contract.rs`, a two-define `contract.h`, and `contract.json` with `layout`, `python`, `settings`, `storage_environment_allowlist` and a full taxonomy dump (`generate.py:18-81`). The variable names at `generate.py:46-51` are literals, not read from the owners.
- CMake regenerates the contract when `src/cadrumo/core/config*.py`, `storage*.py` or `product_identity.py` change (`native/CMakeLists.txt:32-40`). The platform crate includes `contract.rs` through `CADRUMO_CONTRACT_RS` (`native/cmake/platforms/Windows.cmake:53`, `native/platform/src/lib.rs:10`). The desktop crate copies `contract.json` into `OUT_DIR` through `CADRUMO_NATIVE_CONTRACT` (`native/desktop/CMakeLists.txt:29`, `native/desktop/src-tauri/build.rs:1-12`) and parses it at runtime (`native/desktop/src-tauri/src/environment.rs:127-129`).
- The only generator gate is `dev/packaging/tests/test_native_storage_environment_contract.py:21-37`: allowlist parity between `contract.rs`, `contract.json` and `Settings.storage_env_var_names()`, plus the temporary constants. No test checks that the Rust resolver and the Python resolver agree on a root.
- Build output paths have one CMake owner, `native/cmake/BuildPaths.cmake:7-50`, written to `build-paths.json` and consumed without fallback by `dev/packaging/native/build_paths.py:9-29` and `native/desktop/scripts/build-paths.mjs:4-36`. The frontend build reads only `identity.json`, `desktop-server.json` and the desktop artifact locator (`native/desktop/scripts/configuration.mjs:5-28`, `:58-82`); it holds no storage location.
- Channel is a build input, not a Python runtime fact: `identity()` accepts `stable` or `preview` and suffixes `application_id`, the display name and the distribution name (`dev/packaging/native/identity.py:37-64`); CMake passes `CADRUMO_CHANNEL` (`native/cmake/Identity.cmake:24-27`); `data/build.json` records `channel` (`dev/packaging/native/metadata.py:17-34`). `PRODUCT_IDENTITY` has no channel field (`src/cadrumo/core/product_identity.py:20-55`).

### Native consumers

- Rust platform crate: `project_root()` walks the ancestors of the executable directory and of the current directory for `pyproject.toml`, falling back to the current directory (`native/platform/src/lib.rs:30-40`). `context_storage_root()` applies the same two-variable precedence and joins `STORAGE_DEFAULT` onto that root (`lib.rs:57-62`). `prepare()` creates the root, temporary and tool-cache directories, refuses reparse points, clears `PYTHON*`, non-allowlisted `CADRUMO_*`, non-allowlisted reserved names and virtualenv markers, then sets `STORAGE_ENV`, `AUTHORITY_ENV`, `TEMP`, `TMP`, `TMPDIR` and `XDG_CACHE_HOME` and rewrites `PATH` (`lib.rs:132-184`). The crate compiles only on Windows (`lib.rs:1-2`).
- C host and bootstrap: the host runs the platform preparation before CPython starts; `bootstrap.py` verifies the package manifest beside the executable (`native/interpreter/bootstrap.py:57-86`, `:123-144`). The package manifest path is `data/package-manifest.json` and `package_root_from_executable` is `.` (`native/package-layout.json:14`, `native/platforms/windows-x64.json:41`).
- Desktop host: the package root is the executable directory or `CADRUMO_DESKTOP_PACKAGE_ROOT` (`native/desktop/src-tauri/src/main.rs:27-33`). It runs the fixed query `python/environment.py` through the packaged interpreter with the parent's environment and working directory (`environment.rs:147-156`), requires the projection to pin the resolved root under a Settings-owned name (`environment.rs:233`, `:242-250`), and builds children with `env_clear()` plus the projected map (`native/application/src/child.rs:17-58`). The fixed query hardcodes `STORAGE_ROOT_FIELD = "cadrumo_local_storage_root"`, refuses a Settings versus resolver disagreement, and reports `cache` as the development tool cache `XDG_CACHE_HOME` (`python/environment.py:13-31`). The host then places the webview profile at `cache.join("desktop-webview")` (`environment.rs:114`), a location no taxonomy member declares, under `development/cache/tools`.
- The headless passthrough keeps the caller's directory and relies on the pinned root (`main.rs:59-68`).
- `native/manager` does not exist yet; `2026-10-04-runtime-manager-architecture-adr` requires the canonical definition as a prerequisite and names `.runtime/boot.json`, `.runtime/manager-*.{lock,json}`, `cadrumo-manager.log` and `manager-preferences.json`.

### Record state

- `native/CONTRACT.md:67-69` says delivered-user defaults "remain a storage-owner integration obligation; this interpreter does not invent them"; `:77` lists the mutable root as "repository-local default", "delivery default pending" and "deferred"; `:141-143` says "no LocalAppData policy is introduced" and existing local storage is out of scope; `:147-148` says the host clears reserved Settings except `Settings.storage_env_var_names()`.
- `2026-10-03-application-packaging-interpreter-foundation-adr` first accepted "Windows Known Folder LocalAppData plus `cadrumo`", then its CMake amendment superseded that with "consume the existing core storage owner and preserve repository-local development defaults", and its Consequences record unreconciled later storage edits.
- `2026-10-04-desktop-shell-adr` and the desktop-shell plan S02 record the cwd dependence and the pin and leave the delivered default open. `2026-10-04-runtime-manager-architecture-adr` lists the canonical definition and a cwd-independent, version-independent per-user root as a shipping prerequisite, and the runtime endpoint and `.runtime/` records are scoped by storage identity, not by channel.
