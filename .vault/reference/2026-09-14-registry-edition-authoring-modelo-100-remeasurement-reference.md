# `registry-edition-authoring` reference: `Modelo 100 remeasurement`

Programmatic measurement of the live Modelo 100 source and the retained pre-migration full-copy capture. This reference records a source-storage result, not authority publication or whole-registry completion.

## Summary

The live 2021 through 2025 revision manifests now declare consecutive `casilla_storage_baseline` relationships. Their casillas are already delta-authored. The 2020 edition remains the authored anchor.

| Revision | Full rows in earlier capture | Full rows now authored | Hydrated rows | Override members |

Across successor editions, complete authored rows fell from 9826 to 793: 9033 full-row copies replaced, a 91.93 percent reduction in full-row authoring. This is not a claim that all override payload is minimal. Revision-directory bytes fell from 10392610 to 8897386, a reduction of 1495224 bytes or 14.39 percent. These byte totals include all families in the six revision directories, not just casillas.

An independent canonical-loader comparison loaded both the historical full-copy capture and the live source. Ordered casilla model dumps, excluding only `inherited_from` storage-origin metadata, are equal for all six revisions with zero changed row positions. Provenance and continuity fields were not excluded. This verifies casilla equivalence, not all-family or runtime projection acceptance.

The current all-family measurement is not usable as a completion proof. `assess_migration_state` in `dev/registry/edition_delta_migration.py:554` calls `model_dump` on an iterated tuple from `CalculationCompletenessManifest`. Both direct assessment and the non-applying `migrate_modelo_100_field_deltas` probe fail with `AttributeError: 'tuple' object has no attribute 'model_dump'`. The singleton `completeness_manifest` family needs shape-aware measurement rather than collection iteration. Its typed object iterates six field/value tuples. No production fix was attempted because the excluded-family implementation is actively editing the shared migration module.

The old raw field-path comparator was also rerun. Its cross-edition percentages are only physical same-path overlap: the new representation moves values into override structures, so those percentages must not be presented as semantic minimality or compared unqualified with the former full-copy percentage.

Reports are `<local-temp-root>/AppData/Local/Temp/m100-remeasurement-20260914T183714109888Z-measurement.json` and `<local-temp-root>/AppData/Local/Temp/m100-hydrated-measurement-20260914T183926123580Z.json`. The first includes input and relevant tooling hashes; both confirm unchanged live modelo inputs during their measurements. The historical capture is `<local-temp-root>/AppData/Local/Temp/cadrumo-m100-direct-migration-20260914-b/reference/registry/aeat/modelos/100`.

Commands used `uv run --no-sync python -c` with `runpy.run_path` from the owning repository to execute the scratch scripts. Both report-producing commands exited 0; the first explicitly records its caught assessment and staging failures and does not constitute a passing migration gate. An initial direct script invocation exited 1 because its scratch import path could not resolve `dev.registry`; the repository-root invocation corrected only that launch issue.

No live data or production code was changed by this measurement. Next work is to finish excluded-family conversion and repair its all-family measurement, then prove complete scope coverage, equivalence, minimality and idempotence before claiming the whole Modelo 100 migration complete. The existing casilla migration should not be repeated or replaced with full-copy data.
