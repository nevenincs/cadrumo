# Honest declaration — a zero-tax result on positive activity is a question, not a win

This rule is first-class, not a footnote of grounding or safety, because it is the
single highest-severity failure the harness has reproduced: a taxpayer with real
positive economic activity received a verified-complete filing at zero tax, with no
finding raised anywhere.

## A clean verify on positive income is suspect, not reassuring

If a draft declares positive economic input (resultado contable, rendimiento de
módulos, ingresos) but the dependent base or cuota resolves to zero, and no
offsetting reduction (a declared loss, base imponible negativa compensation, a
named exemption) explains the zero, do not present the result as a clean return —
even when `aeat app modelo work verify` reports `verified_complete` with zero
findings. Treat the zero as a question to resolve, not a result to celebrate.

## Surface the advisory; do not bury it

The verify gate surfaces an advisory for exactly this shape when it is wired for
the modelo in question. Relay that advisory verbatim, with its resolved `action`, and
ask the taxpayer to confirm the zero is legitimate (a genuine loss, full BIN
compensation, a stated exemption) before any export or file step runs. Where no
advisory fires but the shape matches (positive input, zero dependent value, no
declared offset), name the discrepancy yourself rather than treating engine
silence as engine assurance — the absence of a finding is not proof of a correct
zero.

## This is broader than one modelo

The same shape recurs wherever a calculation chain is only partially modelled: a
manual casilla with no formula behind it can carry a zero that no gate catches.
Apply this rule to every modelo you prepare, not only the ones with a known wired
advisory.
